# 统一文档内容生成规范实施计划

## 一、执行范围

| 项目 | 内容 |
|------|------|
| 输入规格 | `superpowers/specs/2026-08-05-unified-documentation-generation-standard-design.md` |
| 规范入口 | `AGENTS.md` |
| 规范目录 | `standards/documentation/` |
| 输出内容 | 规范索引、知识体系、模块蓝图、文章契约、生成流程、质量门禁和三个模板 |
| 非目标 | 重写现有技术正文、调整 sidebar、迁移历史目录、创建自动生成器 |

设计稿建议使用 `.agents/documentation/`，但当前 `.gitignore` 忽略整个 `.agents/`。为保证规范可以进入版本管理并供不同 AI 工具读取，实施路径调整为 `standards/documentation/`，文件职责和加载流程保持不变。

## 二、实施步骤

| 顺序 | 任务 | 完成条件 |
|------|------|----------|
| 1 | 创建规范索引 | 不同任务类型具有明确的必读文件、执行顺序和停止条件 |
| 2 | 创建知识体系规范 | 能区分编程语言、框架、数据库、工程工具、基础设施、协议、架构和 AI 工程 |
| 3 | 创建模块蓝图规范 | 明确教学契约、知识项、依赖、章节聚合、文章职责和覆盖矩阵 |
| 4 | 创建单篇文章契约 | 七类文章具有不同的必需内容、证据、深度和拆分规则 |
| 5 | 创建分阶段生成流程 | 任务建档、蓝图、样板、逐章生成和整体验收具有不可绕过的门禁 |
| 6 | 创建质量门禁 | 机器检查、语义检查、异常处理和交付报告职责清晰 |
| 7 | 创建三个输出模板 | 模块蓝图、文章职责卡和样板评审能够直接填充使用 |
| 8 | 更新 `AGENTS.md` | 文档任务能够按类型加载对应分层规范，不删除现有有效规则 |
| 9 | 执行交叉检查 | 文件互链有效，术语、阶段、文章类型和硬性要求一致 |
| 10 | 执行 VitePress 构建 | 提高 Node 堆上限后的完整构建通过 |

## 三、文件职责

| 文件 | 负责内容 | 不负责内容 |
|------|----------|------------|
| `README.md` | 任务路由、加载顺序、规范优先级 | 具体内容写法 |
| `knowledge-system.md` | 方向分类、读者、版本、前置知识、范围和来源 | 逐篇正文结构 |
| `module-blueprint.md` | 知识项、依赖、章节和文章职责 | Markdown 格式细节 |
| `article-contracts.md` | 文章类型、内容闭环、深度和粒度 | 模块整体目录 |
| `generation-workflow.md` | 五个阶段、人工确认和暂停条件 | 技术方向具体知识 |
| `quality-gates.md` | 阶段验收、工程验证和异常处理 | 代替事实调研 |
| `templates/module-blueprint-template.md` | 模块规划的标准交付结构 | 预设具体章节 |
| `templates/article-responsibility-card-template.md` | 单篇边界与证据声明 | 文章正文 |
| `templates/sample-review-template.md` | 样板校准记录 | 代替用户确认 |

## 四、实施约束

1. `AGENTS.md` 只增加分层规范入口，不删除或改写用户已有规则。
2. 分层规范不得把语言基础错误地强制应用到 React 等框架模块。
3. 所有规则必须区分“跨方向前置知识”和“当前方向基础知识”。
4. 目录顺序由知识依赖、编号和 sidebar 表达，正文禁止课程式串联。
5. 模块蓝图和样板文章未经用户确认，不得进入下一生成阶段。
6. 模板使用说明性字段，不预填虚构知识点、版本、来源和验证结果。
7. 本次不修改任何现有技术正文或导航配置。
8. 保留工作区全部既有改动，不执行远程操作。

- [ ] 文章类型、阶段名称和质量门禁在所有文件中一致；
