# 运维、Web3 与 AI 正文重构实施计划

本计划执行[运维、Web3 与 AI 正文重构设计](../specs/2026-09-24-operation-web3-ai-content-rollout-design.md)。三个领域按照运维与 DevOps、Web3、AI 的顺序完成；每个模块分别通过蓝图和样板门禁，默认以一个章节为最大正文批次。

## 一、实施范围

### 1. 总体任务

| 阶段 | 任务 | 完成条件 |
|------|------|----------|
| 1 | 完成运维与 DevOps 14 个模块 | 348 篇规划正文均有真实内容或明确调整记录，模块整体验收通过 |
| 2 | 完成 Web3 10 个模块 | 协议、语言、应用与安全边界闭合，157 篇规划正文通过验收 |
| 3 | 完成 AI 10 个模块 | 模型、上下文、工作流、评测与运行边界闭合，159 篇规划正文通过验收 |

文章数量是当前 Catalog 基线，不作为内容完整性的独立证明。模块蓝图可以依据知识责任合并或拆分文章，但必须同步目录、覆盖矩阵和导航测试。

### 2. 当前批次

## 二、任务 1：事实与环境校准

### 1. 软件包管理

核对 Ubuntu Server 26.04 的 APT 与 dpkg 官方资料，确定仓库、索引、候选版本、已安装状态、模拟变更、安装和删除边界。

示例选择 Ubuntu 官方仓库中的轻量包，只执行可逆安装。没有 Ubuntu 实验机时，不声称已经完成安装或网络访问；APT 输出只展示需要观察的字段和预期格式。

### 2. 定时任务

Ubuntu 26.04 同时提供传统 `cron` 与 `systemd-cron`，同名 `crontab` 手册可能对应不同实现。本章选择系统已具备的 systemd 259 Timer 形成完整操作链路，cron 只说明归属边界，不在同篇并行教授两套调度配置。

示例只向 `/srv/ops-lab/scheduled-jobs` 写入状态文件，并通过 Journal 记录运行身份和明确环境，不调用网络、生产脚本或高权限业务命令。配置必须可禁用、可删除，并说明 systemd Timer 的服务单元、工作目录和环境边界。

### 3. 日志轮转

核对 Ubuntu 26.04 的 `logrotate` 配置、状态文件、调试与强制执行选项。示例只轮转 `/srv/ops-lab/log-rotation/ops-lab.log`，使用独立配置和独立状态文件，避免影响 `/etc/logrotate.conf` 及系统日志。

Journal 的保留策略不属于文件日志轮转。正文只保留必要区别，并链接已经发布的 journalctl 文章。

## 三、任务 2：正文生成

### 1. 写作顺序

三篇按知识依赖依次生成：

```text
软件包管理
→ 定时任务
→ 日志轮转
```

软件包管理先建立工具安装和状态确认；定时任务依赖软件与服务管理；日志轮转复用计划任务产生的文件日志概念，但使用独立受控目录，不要求复制其他文章代码。

### 2. 文章结构

每篇开头直接说明技术对象与核心判断，标题只使用概念或任务阶段。操作链路保持目标、条件、命令、预期结果、解释和失败处理相邻。

| 文档 | 主要结构 |
|------|----------|
| 软件包管理 | APT 对象 → 状态查询 → 索引刷新 → 模拟变更 → 安装验证 → 删除边界 → 异常处理 |
| 定时任务 | Timer 对象 → 日历表达式 → 执行身份 → 环境与路径 → 真实触发 → 禁用恢复 → 异常处理 |
| 日志轮转 | 文件日志边界 → 规则组成 → 调试检查 → 受控轮转 → 写入连续性 → 保留清理 → 异常处理 |

### 3. 安全边界

- 不添加第三方软件源或导入外部密钥；
- 不执行发行版升级或无范围的系统升级；
- 不删除 APT/dpkg 锁文件；
- 不修改生产用户的 crontab；
- 不把高权限脚本加入系统计划任务；
- 不修改系统 logrotate 主配置和状态文件；
- 不对未知日志文件执行轮转或删除。

## 四、任务 3：单篇检查

每篇完成后执行以下检查：

1. Frontmatter、H1、H2 和 H3 编号；
2. 标题准确性、主问题与子问题从属关系；
3. 空小节、骨架化小节、连续定义和多主题长段落；
4. 代码块语言及 10 行折叠门禁；
5. 命令、输出、解释和失败处理的相邻性；
6. 官方来源、版本和未验证状态；
7. 内部链接及实验目录一致性；
8. 与相邻文章的重复归属。

核心示例无法实际执行时，文章明确写为预期结果，并记录当前工作区缺少 Ubuntu 26.04 实验机。静态结构和 VitePress 构建不能替代运行验证。

## 五、任务 4：章节与导航验收

### 1. 章节检查

三篇完成后对照 LNX-013、LNX-014、LNX-015 检查覆盖状态：

| 知识项 | 证据 |
|--------|------|
| 软件源、包、安装、更新和回退边界 | 来源、候选版本、安装状态与模拟变更 |
| 周期任务的身份、环境和执行验证 | Timer 状态、输出文件、身份与 Journal 证据 |
| 文件日志轮转及保留 | 调试输出、新旧文件、连续写入与保留结果 |

同章术语、实验目录和验证状态保持一致，不重复完整讲解 sudo、systemd 服务或 Journal 查询。

### 2. 导航开放

只有三篇均通过章节检查后，才在 `.vitepress/themeConfig/catalogs/operation.js` 中为本章三个条目增加 `publishedLink`。

开放后确认 Sidebar 中 `5.1`、`5.2`、`5.3` 均为真实链接，其他未完成章节继续显示为规划文本。

## 六、任务 5：工程验证

按以下顺序执行：

1. 对新增 Markdown 执行结构、骨架、代码块和相对链接扫描；
2. 执行 `pnpm docs:build:unit -- operation`；
3. 复用现有 `127.0.0.1:5173` 服务检查桌面与 390px 移动端页面；
4. 导航开放后执行 `pnpm docs:test`；
5. 再次执行运维单元构建；
6. 核对 Sidebar 链接与浏览器控制台错误。

现有主题在部分桌面宽度下的右侧大纲边界属于共享样式问题。本批次记录复现结果，但不修改主题样式；正文自身造成的溢出必须修复。

## 七、后续批次

Linux 第 5 章通过后，按同样流程依次处理存储与恢复、主机网络、主机安全和主机故障排查。Linux 模块整体验收后进入 Bash 与 Shell。

没有模块蓝图的运维模块、Web3 模块和 AI 模块，先建立并确认蓝图与样板，再生成正文。不得因为跨领域设计已经确认而跳过单模块门禁。

## 八、停止条件

出现以下情况时暂停受影响范围：

- Ubuntu 26.04 官方行为与 Linux 蓝图冲突；
- 示例需要不可恢复的系统或数据变更；
- 当前文件出现无法兼容的用户并发修改；
- 核心命令、配置或输出缺少可靠来源；
- 文章职责需要重新分配；
- 构建、导航或页面检查失败且尚未定位原因。

停止时保留已经通过的文章和检查证据，不把未验证文件开放到导航。
