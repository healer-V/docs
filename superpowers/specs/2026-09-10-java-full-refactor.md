### 2. 运行机制与诊断

| 场景 | 实际结果与判断 |
|------|----------------|
| 字节码与执行 | `javap` 对照 `(JI)J`、主版本65与金额运算指令；解释执行和 JIT 路径得到相同校验结果 |
| 类加载与引用 | 同名类的不同加载器身份、初始化顺序与失败、显式引用队列操作均得到对应结果；不以显式入队证明 GC 时机 |
| 收集器 | Serial、Parallel、G1、分代 ZGC 在本机启动并完成同一分配任务；不作吞吐性能排名 |
| GC/JFR | 同一分配场景在32MiB与64MiB堆下分别观察43与7次暂停；JFR和日志可读，仅作为该次运行证据 |
| CPU | 忙轮询栈、线程CPU时间与JFR采样对应；有界等待版本移除忙轮询，使用同一场景对照 |
| 死锁 | 故障版本三次快照均出现同一等待环；统一锁顺序后两项任务完成，无死锁 |
| 堆滞留 | HPROF中10000个订单对象沿静态列表被强引用；有界版本保留64个，清理后直方图不再包含该类型 |
| 本地内存与类加载器 | 分配8MiB直接缓冲和32个独立加载器后观察NMT/类加载变化；清理并显式GC后新增加载器消失 |
| 兼容失败 | 真实复现 `NoSuchMethodError`、`UnsupportedClassVersionError`、Java 8 不识别统一日志参数；`--release 8` 拒绝新 API |

诊断程序有时限、停止命令和受控数据，本次取证进程均已退出。HPROF 已验证对象数量和强引用路径，未把未执行的 GUI 支配树结果写成实际证据。
