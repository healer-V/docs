## 二、事实与示例验证

### 1. 环境与来源

实际运行环境为 Windows、Node.js 22.19.0、系统 Edge 154.0.4258.37、VitePress 1.3.4。CSS 按模块规范解释，来源就近引用 W3C/CSSWG、WHATWG、MDN 与对应工具官方文档；可访问性数值核对 WCAG 2.2 的具体成功标准。

完整示例由验证脚本从单篇代码块提取到空目录，仅使用文章给出的文件，直接通过浏览器打开；不依赖文档站、跨章脚本或既有源码补齐。

### 3. 机制断言与性能证据

| 机制 | 核对结果 |
|------|----------|
| 两种尺寸模式 | content-box 边框框为 228px，border-box 为 200px |
| Flex 收缩 | 240px 容器内，200px 和 100px 基础尺寸收缩为 160px 与 80px |
| 层叠层 | 普通声明后层胜出，重要声明前层胜出 |
| 嵌套权重 | 外层列表的 ID 提高内部规则权重，结果符合正文 |
| 注册属性 | 不继承的长度属性父级为 20px，子级为 12px 初始值 |
| 计算时无效 | 变量替换为非法内边距后，解析值为 0px，未回到前一声明 |
| BFC | 仅有 60px 高浮动时，普通容器高度 0px，flow-root 后为 60px |
| overflow | hidden 可以程序滚动至 40px，clip 不能产生该滚动 |

性能轨迹在 1440×900、500 项、未设置 CPU 限速的固定条件下录制。两轮受控对照中交错实现出现 500～501 次 Layout，批量实现均为 2 次 Layout；页面脚本计时与全段布局耗时分别记录。共同的重置和后续工作也进入完整轨迹，因此不把脚本计时等同于总呈现成本，不生成通用加速比例。
