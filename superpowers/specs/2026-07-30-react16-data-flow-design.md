# React 16.8 数据流章节设计

## 一、设计目标

第 2 章承接第 1 章已经掌握的 JSX、事件绑定、条件渲染和列表渲染，回答数据怎样进入组件、怎样产生变化，以及多个组件怎样共享同一份数据。

本章以数据流形成顺序组织知识：

```text
最小函数组件
→ Props 输入
→ State 保存变化
→ 事件触发 State 更新
→ 表单形成输入闭环
→ 状态提升形成跨组件单向数据流
```

读者具备 JavaScript 基础，但尚未系统学习组件设计和 Hooks。本章会引入理解数据流所需的最小函数组件和 `useState` 写法，不提前展开第 3 章的组件设计能力，也不取代第 4 章对 Hooks 的完整讲解。

第 2 章包含以下五篇文档：

| 顺序 | 文档 | 学习结果 |
|------|------|----------|
| 2.1 | Props 与单向数据流 | 能定义最小函数组件，并把父组件数据作为只读 Props 传给子组件 |
| 2.2 | State 与界面更新 | 能使用 `useState` 保存会变化的数据，并通过更新函数触发界面更新 |
| 2.3 | State 更新规则 | 能正确更新基本值、对象和数组，避免直接修改 State |
| 2.4 | 受控表单 | 能用 State 管理表单值、校验、提交和重置 |
| 2.5 | 状态归属与提升 | 能判断 State 所有者，并在父子和兄弟组件之间组织单向数据流 |

## 二、章节边界

### 1. 函数组件边界

Props 和 State 必须依赖组件才能形成真实数据流，因此 2.1 需要先介绍以下最小知识：

- 函数组件是返回 React 元素的函数；
- 组件名称以大写字母开头；
- 组件通过 JSX 标签使用；
- React 调用组件并把属性整理为 Props 对象。

本章不讲组件拆分依据、展示组件与业务组件、组合模式、复合组件和类组件。这些内容仍属于第 3 章。

### 2. `useState` 边界

第 2 章把 `useState` 作为建立状态数据流所需的基础 API，覆盖：

- API 作用；
- React 16.8 基本调用形式；
- 初始值参数；
- 当前状态与更新函数组成的返回数组；
- 在事件中提交新值；
- 重新执行组件并更新 DOM 的基本流程。

第 4 章仍需详细讲解 Hook 调用规则、状态槽位、懒初始化、更新队列、连续更新、函数式更新原理、多个 Hook 的调用顺序以及 Hook 组合。

2.3 可以说明“新值依赖旧值时应使用函数式更新”，但只解释正确用法和可见结果，不在本章展开内部更新队列。

### 3. 运行机制边界

本章说明用户能够观察和应用的数据流规则。以下内部机制放在第 6 章：

| 内容 | 本章覆盖 | 第 6 章覆盖 |
|------|----------|------------|
| 更新触发 | 调用更新函数会安排下一次渲染 | 更新队列、批处理和调度 |
| 状态快照 | 当前渲染中的状态值不会被直接改写 | 闭包、快照和陈旧状态形成原因 |
| Key 与 State | 不在本章系统展开 | 组件身份、状态保留和重置 |
| Render 与 Commit | 只使用“重新执行组件并更新 DOM”的可见流程 | 阶段划分、DOM 提交和浏览器绘制 |

### 4. JavaScript 与 TypeScript

正文以 React 知识为主，不把语言类型系统当作章节主线：

- 主要示例使用 JSX，保证具备 JavaScript 基础的读者能够跟随；
- Props 契约部分补充 `PropTypes` 和 TypeScript 的适用差异；
- TypeScript 示例只在类型能解释组件输入或事件边界时使用；
- 不为每个 JavaScript 示例机械复制一份 TypeScript 版本。

## 四、2.1 Props 与单向数据流

本文先提供最小函数组件语法，再沿着“父组件准备数据 → JSX 传递属性 → 子组件读取 Props → 页面生成结果”解释单向数据流。

| 二级章节 | 必须覆盖的知识 |
|----------|----------------|
| 函数组件基础 | 函数组件含义、命名规则、定义形式、返回 JSX、作为 JSX 标签使用、最小示例 |
| Props | Props 的作用、来源、对象结构、函数参数、属性读取、Props 与普通函数参数的关系 |
| 传递 Props | 静态值、表达式、数字、布尔值、对象、回调、属性名与接收字段的对应关系 |
| 单向数据流 | 父组件拥有数据、子组件读取数据、数据从上到下传递、子组件不能修改 Props |
| 默认值 | 属性缺失、显式 `undefined`、参数解构默认值、`defaultProps` 的 React 16.8 边界 |
| Props 契约 | 必填与可选字段、运行时 `PropTypes`、TypeScript 类型约束及两者差异 |
| 传递边界 | 避免透传完整业务对象、避免无选择地展开 Props、避免重复传递可直接计算的结果 |
| 完整示例 | 父组件把任务数据传给展示组件，展示页面结果并验证 Props 只读 |
| 知识检查 | 函数组件最小规则、Props 来源、默认值和单向流向 |

`children` 只说明它也是 Props 中的特殊字段，具体组合方式放在 3.2《children 与组件组合》。

### 1. Props 契约边界

`PropTypes` 与 TypeScript 需要明确区分：

| 能力 | 检查时间 | React 运行时是否依赖 |
|------|----------|----------------------|
| `PropTypes` | 开发环境运行时 | 需要额外 `prop-types` 包 |
| TypeScript | 编译与编辑阶段 | 类型擦除后不参与 React 运行 |

二者用于约束输入，不能让 Props 变成可修改数据，也不能改变单向数据流。

## 五、2.2 State 与界面更新

本文从普通变量不能驱动界面更新的问题出发，介绍 State 和 `useState` 的最小使用闭环。

| 二级章节 | 必须覆盖的知识 |
|----------|----------------|
| 为什么需要 State | 普通变量不会驱动 React 更新、State 保存组件需要记住且影响界面的数据 |
| `useState` | API 作用、React 16.8 调用形式、初始值参数、返回数组、当前值与更新函数 |
| 读取 State | 在 JSX 中读取当前渲染的 State，根据 State 选择文本和属性 |
| 更新 State | 在事件处理函数中调用更新函数、传入新值、安排下一次渲染 |
| 更新流程 | 用户事件、调用更新函数、重新执行组件、生成新元素、更新 DOM |
| 组件局部状态 | 每个组件实例拥有独立 State，局部变量、Props 与 State 的区别 |
| 多个状态值 | 可以多次调用 `useState`，本篇只讲基本写法和状态职责 |
| 完整示例 | 使用状态切换任务完成情况，说明点击前后页面和 DOM 变化 |
| 知识检查 | 判断哪些数据需要 State、怎样读取以及怎样触发更新 |

### 1. `useState` 基本 API

文档必须先给出作用，再给出调用形式：

```js
const [state, setState] = useState(initialState);
```

| 部分 | 本篇说明 |
|------|----------|
| `initialState` | 首次创建当前组件实例状态时使用的初始值 |
| `state` | 当前这次渲染读取到的状态值 |
| `setState` | 提交新状态并安排后续渲染的函数 |
| 返回数组 | 固定包含当前值和对应更新函数，可使用数组解构命名 |

本篇会讲清 `setState(nextState)` 的直接更新形式，但不展开函数形式的初始化参数、函数式更新回调、更新队列和批处理细节。

## 六、2.3 State 更新规则

本文在读者已经会调用更新函数的基础上，解释不同数据结构应该怎样产生新状态。

| 二级章节 | 必须覆盖的知识 |
|----------|----------------|
| State 更新原则 | State 视为只读数据、通过更新函数提交新值、当前渲染中的变量不会被直接改写 |
| 更新基本值 | 直接传入新值、根据旧值计算新值、函数式更新的最小规则 |
| 更新对象 | 更新函数替换整个值、对象展开、覆盖字段、嵌套对象逐层复制 |
| 更新数组 | 使用展开、`map`、`filter` 完成新增、修改和删除，复制后排序 |
| 事件驱动更新 | 事件处理函数表达用户意图，更新函数负责提交状态 |
| 禁止直接修改 | 对象字段赋值、`push`、`splice`、原地 `sort` 的问题和可观察错误 |
| 派生结果 | 能从当前 Props 和 State 计算的数据直接计算，不额外保存为 State |
| 完整示例 | 完成任务新增、切换和删除，并说明每次引用怎样变化 |
| 知识检查 | 根据数据类型选择更新方式 |

### 1. 不可变更新边界

文档需要说明“不可变”不是要求 JavaScript 对象永远不可变，而是不能修改 React 当前正在使用的 State 值。正确更新应产生能够表示变化的新引用。

对象和数组示例必须解释：

- 哪一层引用发生变化；
- 哪些未变化项可以继续复用；
- 为什么直接修改后再传回同一引用不可靠；
- 为什么 `useState` 更新函数不会像类组件 `setState` 那样自动浅合并对象。

## 七、2.4 受控表单

本文把事件绑定和 State 更新组合成完整输入闭环。

| 二级章节 | 必须覆盖的知识 |
|----------|----------------|
| 表单数据流 | 用户输入、`onChange`、State 更新、受控值返回控件 |
| 受控与非受控 | `value`、`checked`、`defaultValue`、`defaultChecked` 的区别 |
| 文本类控件 | `input` 与 `textarea` 的值和事件读取 |
| 选择控件 | `select`、单选按钮、复选框的受控方式 |
| 多个字段 | 使用字段名更新对象 State，不同控件值的读取规则 |
| 提交表单 | `onSubmit`、`preventDefault()`、校验、构造提交数据 |
| 重置表单 | 把 State 恢复为初始数据，不绕过 React 直接修改 DOM |
| 模式边界 | 避免受控与非受控切换、`null` 与 `undefined` 初始值、文件输入边界 |
| 完整示例 | 任务创建表单，覆盖输入、选择、校验、提交和重置 |
| 知识检查 | 根据控件类型判断受控属性和事件读取方式 |

### 1. 控件对应关系

正文必须明确不同控件的受控入口：

| 控件 | 受控属性 | 常用事件读取 |
|------|----------|--------------|
| 文本输入、`textarea` | `value` | `event.currentTarget.value` |
| `select` | `value` | `event.currentTarget.value` |
| 单选按钮 | `checked` | 根据选项 `value` 更新选中值 |
| 复选框 | `checked` | `event.currentTarget.checked` |
| 文件输入 | 非受控 | 通过 DOM 文件列表读取，具体 Ref 用法留到第 4 章 |

完整示例需要展示正常输入、校验失败、提交成功和重置后的可观察结果，但不连接真实接口。

## 八、2.5 状态归属与提升

本文从“同一数据被多个组件使用”出发，解释状态所有权和单一数据源。

| 二级章节 | 必须覆盖的知识 |
|----------|----------------|
| 状态所有者 | 谁负责修改数据、谁依赖数据、State 应放在什么位置 |
| 单一数据源 | 同一业务事实只保存一份，避免父子组件分别保存副本 |
| 判断归属 | 仅一个组件使用、多个兄弟使用、跨层使用三种情况 |
| 状态提升 | 把共享 State 移到最近共同祖先，再通过 Props 下发 |
| 回调向上传递意图 | 子组件不修改父级数据，通过业务回调通知所有者 |
| 兄弟组件协作 | 一个组件修改筛选条件，另一个组件读取结果，父组件统一协调 |
| 派生状态 | 从 Props 与 State 计算筛选结果和统计值，避免同步副本 |
| Props 初始化陷阱 | State 只使用首次初始值，Props 后续变化不会自动覆盖 State |
| 提升边界 | 状态过低无法共享，状态过高扩大依赖，Context 与 Reducer 留到第 4 章 |
| 完整示例 | 搜索输入组件与任务列表组件共享查询条件 |
| 知识检查 | 根据使用者和修改者判断状态所有权 |

### 1. 所有权判断顺序

正文使用以下判断顺序，而不是给出“所有 State 都放根组件”的错误结论：

```text
找出读取这份数据的组件
→ 找出能够修改这份数据的交互
→ 找到所有使用者最近的共同祖先
→ 判断数据能否由其他数据直接计算
→ 只保存不可直接推导的最小状态
```

组件在相同位置保留 State、通过 Key 重置 State 的机制放在 6.5《Key 与组件身份》，本篇不重复。
