# React 16.8 核心语法章节设计

## 一、设计目标

第 1 章以完整知识清单为内容骨架，并按照前置依赖组织成可以连续学习的 React 16.8 基础文档。知识清单不能只剩标题和结论：每一项都要先说明当前知识是什么、解决什么问题以及怎样使用，再通过必要的示例验证前面的说明。

本章假定读者已经具备 JavaScript 基础，不重复讲解变量、对象、函数和数组方法。文档不创建示例工程，只提供理解当前知识所需的代码片段、执行上下文、预期结果和错误说明。

第 1 章包含以下五篇文档：

| 顺序 | 文档 | 学习结果 |
|------|------|----------|
| 1.1 | React 元素与 JSX | 能使用 JSX 描述静态结构，理解 React 元素并把它渲染到页面 |
| 1.2 | JSX 数据、属性与样式 | 能把 JavaScript 数据放入 JSX，并正确设置属性和样式 |
| 1.3 | 事件绑定 | 能绑定事件处理函数，使用合成事件并控制默认行为和传播 |
| 1.4 | 条件渲染 | 能根据数据条件选择文本、元素或完整界面 |
| 1.5 | 列表渲染与 Key | 能把数组转换为具有稳定身份的元素列表 |

## 二、统一组织规范

### 1. 按知识类型选择内容

统一规范不等于统一套用固定模板。不同知识点应根据自身性质选择必要内容：

| 知识类型 | 通常需要说明 | 不应强行补充 |
|----------|--------------|--------------|
| 语法 | 含义、语法形式、组成部分、使用规则、适用场景、示例 | 没有参数时不编造参数说明 |
| API | 作用、调用形式、参数、返回值、使用场景、版本边界、示例 | 没有复杂流程时不增加流程章节 |
| 概念 | 定义、组成、与相邻概念的关系、判断边界、示例 | 不要求机械提供函数签名 |
| 规则 | 规则内容、存在原因、错误表现、正确写法 | 不把每条规则拆成独立空小节 |
| 流程 | 参与对象、执行顺序、输入、结果、验证方式 | 不要求为每个步骤增加独立 API 表格 |

小节只保留当前知识真正需要的说明要素。示例不能代替定义和用法说明，定义也不能代替可以观察的验证结果。

### 2. 先说明，再示例

语法和 API 小节采用以下基本顺序：

```text
说明当前知识的含义与作用
→ 给出语法形式或调用签名
→ 解释组成部分或参数
→ 说明适用场景与边界
→ 在小节末尾提供示例
```

“示例位于末尾”表示示例作为当前小节最后一个内容单元。示例单元内部仍需形成完整闭环：

```text
示例场景
→ 代码
→ 页面、DOM、控制台或错误结果
→ 解释示例证明了什么
```

不得先堆叠代码，再由读者从代码反推语法含义。错误示例应紧跟对应规则，不集中堆放到文章末尾。

### 3. 保持渐进关系

每篇文档在一级标题后直接进入第一个知识定义，不添加学习入口、章节衔接、阅读顺序或课程宣传，也不使用“学习目标”“学习方法”“实践任务”“验收标准”等固定模板章节。

二级标题和三级标题必须直接概括对应的 JSX、React 元素、事件、条件或列表知识，不使用“核心知识”“理解与应用”等无法说明内容范围的概括性标题。

相邻小节之间必须满足以下关系之一：

- 后一节使用前一节已经解释的概念；
- 后一节解决前一节留下的问题；
- 后一节扩大前一节的使用范围；
- 后一节比较容易混淆的相邻概念。

不能仅因两个知识点同属 React 就把它们连续放置，也不能为了编号完整把一句话拆成独立小节。

## 三、1.1 学习路径

“React 元素与 JSX”按以下学习链路组织：

```text
学习 JSX 写法
→ 理解 JSX 产生的 React 元素
→ 建立 JSX 与 React 元素的转换关系
→ 把 React 元素渲染到浏览器页面
```

文章直接从 JSX 的定义开始。`JSX → React 元素 → ReactDOM → 浏览器 DOM` 只在解释真实渲染流程时出现，不作为文章目录展示。

### 1. JSX

这一部分先让读者掌握静态界面的书写方式。

| 小节 | 必须覆盖的内容 |
|------|----------------|
| JSX 是什么 | JSX 的含义、作用、不是 HTML 字符串、需要编译 |
| JSX 基本写法 | 标签、属性位置、子内容、自闭合标签、大写与小写名称的基本区别 |
| JSX 结构规则 | 单一完整表达式、标签闭合、正确嵌套、多行括号和 JSX 注释 |
| Fragment | 解决多个并列元素的问题、显式写法、简写、是否生成 DOM |
| JSX 示例 | 使用前面全部规则描述一个静态任务摘要，并给出可见结果 |

动态表达式、完整 DOM 属性规则、样式和内容安全放在 1.2，本部分只讲理解静态结构所需的最小属性知识。

### 2. React 元素

这一部分解释 JSX 最终描述的对象，不重新讲一遍 JSX 规则。

| 小节 | 必须覆盖的内容 |
|------|----------------|
| React 元素是什么 | React 元素是界面描述，不是真实 DOM 节点 |
| React 元素的组成 | `type`、`props`、`children` 之间的关系 |
| `React.createElement` | API 的作用、调用签名和返回值 |
| `createElement` 参数 | `type`、`props`、`...children` 的含义、取值与作用 |
| React 元素与 DOM | 创建方式、职责、可使用能力和产生时机的区别 |
| React 元素示例 | 使用 `createElement` 创建与 JSX 示例相同的静态结构 |

`createElement` 是 API，必须先给出作用与签名，再解释参数，最后展示完整调用。

### 3. JSX 与 React 元素

这一部分只建立两种写法的对应关系，不重复介绍各自定义。

| 小节 | 必须覆盖的内容 |
|------|----------------|
| JSX 的转换结果 | React 16.8 经典 JSX 转换会生成 `React.createElement` 调用 |
| 结构对应关系 | 标签名称对应 `type`，属性对应 `props`，子内容对应 `children` |
| 对照示例 | 并列展示一段 JSX 和等价的 `createElement` 调用，并解释生成同类 React 元素 |

这一部分完成后，读者应能从 JSX 结构判断对应的 `createElement` 参数，而不要求记忆 React 元素的内部私有字段。

### 4. React 元素渲染

这一部分回答 React 元素怎样进入浏览器页面。

| 小节 | 必须覆盖的内容 |
|------|----------------|
| 宿主节点 | `#root` 的来源、作用以及 React 管理的 DOM 范围 |
| ReactDOM 的职责 | React 创建元素描述，ReactDOM 负责浏览器环境中的提交 |
| `ReactDOM.render` | API 作用、React 16.8 调用形式和返回结果边界 |
| `render` 参数 | 要渲染的 React 元素与目标 DOM 容器 |
| 完整渲染流程 | `JSX → React 元素 → ReactDOM.render → 浏览器 DOM` |
| 完整示例 | 给出宿主节点和入口代码，展示页面文本与主要 DOM 结构 |

整篇文章的最终示例放在这一部分末尾，只使用本文已经解释的知识，不提前引入 Props、State、事件、组件通信或 Hooks。

## 四、错误说明位置

错误说明跟随对应知识，不额外创建内容混杂的“常见问题”大章：

| 问题 | 所属位置 |
|------|----------|
| 多个并列顶层元素 | JSX 结构规则或 Fragment |
| 标签未闭合、嵌套错误 | JSX 结构规则 |
| 小写名称被当成宿主标签 | JSX 基本写法 |
| `createElement` 参数位置错误 | `createElement` 参数 |
| 对 React 元素调用 DOM API | React 元素与 DOM |
| 找不到 `#root` | 宿主节点 |
| React 16.8 使用了 React 18 根 API | `ReactDOM.render` 版本边界 |

错误示例必须同时说明错误现象、原因和正确写法。

## 十、统一边界

知识清单是正文主体，不是只有标题的骨架。每个知识点根据类型补充真正需要的内容：

- 语法说明含义、形式、规则和示例；
- API 说明作用、签名、参数、返回值和边界；
- 概念说明定义、关系、区别和判断方式；
- 规则说明原因、错误表现和正确写法；
- 流程说明参与对象、顺序和结果。

并非每个知识点都需要参数表、使用场景或完整代码。没有参数的语法不编造参数，没有复杂过程的概念不增加流程。示例使用完成当前知识所需的最小数据，不要求三篇文档共享业务场景。

## 十一、验收标准

- 文章在一级标题后直接进入知识定义，不包含课程式元叙述；
- 二级章节对应学习阶段，不把零散规则提升成同级主线；
- 每个小节先解释知识，再在末尾提供需要的示例；
- 语法、API、概念、规则和流程没有被强行套入同一模板；
- 示例前置知识只来自本文前文，不提前使用后续章节能力；
- 示例具有上下文、代码、可观察结果和结论；
- JSX、React 元素、DOM 和 ReactDOM 的职责边界准确；
- 样式处理覆盖 `className`、动态类名、`style` 对象、CSS 属性名和数值单位；
- 事件绑定覆盖处理函数、合成事件、React 16.8 事件池、默认行为和传播；
- 条件渲染覆盖所有基础分支形式和多状态界面；
- 列表渲染覆盖数组转换、空列表、Key 规则、位置和身份问题；
- React 16.8 使用经典 JSX 转换和 `ReactDOM.render`，不混入 React 18 根 API；
- 不存在空小节、骨架化小节、连续代码堆叠或没有解释的错误示例；
- Frontmatter、标题编号、代码围栏、内部链接和 VitePress 构建通过；
- 仅修改当前任务需要的正文、设计规格和导航文字，不覆盖其他工作区改动。
