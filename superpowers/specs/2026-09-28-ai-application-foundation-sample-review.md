## 七、批量生成校准项

| 校准项 | 样板结论 | 后续文章必须执行的规则 |
|--------|----------|------------------------|
| 内容深度 | 解释必须支撑实际判断 | 不以 API 罗列代替对象关系、成功条件和边界说明 |
| 小节粒度 | 二级标题表达调用阶段，三级标题表达独立技术问题 | 并列短事实合并为表格或列表，不为编号机械拆节 |
| 语义层级 | 接入教程需要三级导航支撑定位 | 环境、实现、验证和诊断下的独立子问题必须进入大纲，并形成完整论述 |
| 阅读顺序与段落组织 | 先对象与条件，再正常路径、失败路径和边界 | 必要条件必须出现在使用前，输出后立即解释判断依据 |
| 文字容器与阅读重点 | 容器只承载前提、风险和关键边界 | 标题必须具体，不把整节正文塞入容器 |
| 长代码折叠 | 第 11 行起默认折叠 | 折叠外保留用途、执行入口、关键逻辑和结果解释 |
| 示例场景 | 使用连续的虚构客户反馈摘要场景 | 不更换无关项目名，不引入真实客户数据或生产凭据 |
| 证据形式 | 实践文档以真实命令、输出和失败证据闭环 | 无法执行时必须显式标明未验证原因，不伪造结果 |
| 术语与命名 | 保留官方英文对象名 | 首次出现时给出中文作用，全文大小写一致 |
| 版本表达 | 固定版本进入验证基线 | 升级 SDK、模型或 API 行为后重新执行样板验证 |
