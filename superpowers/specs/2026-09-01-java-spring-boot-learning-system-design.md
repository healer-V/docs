# Java 与 Spring Boot 学习体系重构设计

## 一、设计结论

Java 与 Spring Boot 文档采用“大章节文件夹、小章节独立文章、VitePress 两级 sidebar”的组织方式。教程不以面试题、API 罗列或百科覆盖为目标，而是让读者从语言规则出发，逐步获得编写、解释、设计、测试和诊断 Java 后端应用的能力。

版本路线固定为：

| 路线 | 教学基线 | 定位 |
|------|----------|------|
| Java 主线 | Java 21 LTS | 新手学习语言、核心 API、工程和运行机制的默认版本 |
| Java 维护线 | Java 8 | 阅读、维护和迁移企业遗留代码，不重复讲解整套 Java 基础 |
| Spring Boot 主线 | Java 21、Spring Boot 3.5.x、Spring Framework 6.2.x | 新项目和现代 Spring 后端开发的默认路线 |
| Spring Boot 维护线 | Java 8、Spring Boot 2.7.18、Spring Framework 5.3.x | 维护旧项目并识别升级风险 |

Java 模块与 Spring Boot 模块分别使用以下蓝图：

- [Java 21 主线与 Java 8 维护线模块蓝图](./2026-09-08-java-learning-module-blueprint.md)
- [Spring Boot 3.5 主线与 2.7 维护线模块蓝图](./2026-09-01-spring-boot-learning-module-blueprint.md)

2026-09-08 用户确认的修订蓝图规划 Java 14 个大章节、123 篇文章及247个知识项，Spring Boot 15 个大章节、91 篇小章节文章。该数量来自独立学习问题和证据边界，不代表一次性交付批次；正文始终按样板确认和大章节验收逐步生成。

## 二、读者与教学契约

### 1. 读者基线

目标读者是计算机相关专业毕业生或具备同等基础的前端、测试及其他方向开发者。默认读者：

- 理解变量、分支、循环、函数、数据结构、进程、线程、HTTP 和关系数据库等通用概念；
- 能够使用命令行和编辑器完成基本文件操作；
- 不要求学过 Java、JVM、Spring Framework 或 Spring Boot；
- 不要求具备后端工程、生产部署和故障诊断经验。

文档不能用“读者具有计算机基础”跳过 Java 自身的类型、作用域、参数传递、对象模型、异常传播和运行时语义。通用概念可以简洁说明，但 Java 或 Spring 的具体规则必须从可理解的起点完整建立。

### 2. 最终能力

完成主线后，读者应能够：

| 能力层次 | 可验证结果 |
|----------|------------|
| 编写 | 使用 Java 21 编写结构清晰的程序，正确处理类型、对象、集合、异常、I/O 和并发任务 |
| 解释 | 根据语言规则和 JVM 模型解释代码结果、对象生命周期、异常传播、线程可见性和常见性能现象 |
| 工程 | 使用 Maven、日志、JUnit、Mockito 和 JDBC 构建可重复编译、测试和运行的工程 |
| 后端开发 | 使用 Spring Boot 3.5 实现具有校验、错误契约、事务、鉴权和持久化能力的 REST API |
| 验证 | 使用单元测试、集成测试、Testcontainers、Actuator、指标和日志验证应用行为 |
| 诊断 | 根据线程转储、堆转储、GC/JFR、日志、指标和请求证据定位常见 Java 与 Spring Boot 问题 |
| 维护 | 识别 Java 8、Spring Boot 2.7 与现代主线的差异，安全阅读旧代码并制定迁移方案 |

### 3. 内容深度

每篇文章只回答一个主要学习问题，但完整内容必须达到相应深度：

| 深度 | 文章必须让读者做到什么 | 典型内容 |
|------|--------------------------|----------|
| 认识 | 准确定义对象、关系、边界和使用场景 | 平台概述、技术选型、版本模型 |
| 使用 | 写出正确代码或配置，并根据输出判断是否生效 | 数据类型、方法、集合、Controller、配置绑定 |
| 解释 | 说明执行阶段、关键状态、行为原因和失败传播 | 重载解析、Bean 生命周期、事务代理、类加载 |
| 设计 | 根据约束比较方案，形成边界清楚且可验证的实现 | 类型设计、错误契约、分层架构、安全策略 |
| 诊断 | 从现象获取证据，定位根因、修复、恢复并预防 | 死锁、内存泄漏、事务失效、接口延迟 |

“内容完整”不以文章字数、标题数量或代码块数量衡量。核心文章必须让读者理解结论为什么成立、如何验证以及在什么边界下失效。

## 三、模块关系与知识边界

### 1. 模块职责

| 模块 | 完整讲解 | 仅作前置引用或最小说明 |
|------|----------|--------------------------|
| Java | 语言语法、类型系统、对象模型、核心 API、异常、I/O、并发、JVM、Maven、测试、JDBC、Java 8 差异 | Spring API、数据库内部实现、容器平台 |
| Spring Boot | 必需的 Spring 核心、启动和自动配置、外部化配置、Spring MVC、数据访问集成、事务、安全、测试、可观测和部署 | Java 基础语法、SQL 系统知识、中间件内部原理、微服务架构 |
| 数据库模块 | SQL、索引、事务和锁的数据库侧语义 | Java/Spring 的调用封装 |
| 微服务模块 | 服务边界、治理、通信、消息、一致性、网关和分布式可观测 | 单体 Spring Boot 的基础使用 |
| Redis、消息与平台模块 | 产品本身的数据模型、可靠性、运维和故障恢复 | Spring 的最小客户端接入 |

### 2. Spring 与 Spring Boot 的处理方式

Spring Framework 不建立一套与 Spring Boot 平行的完整教程。理解 Spring Boot 所必需的 IoC、依赖注入、Bean、AOP、代理、Spring MVC 和事务抽象，放入 Spring Boot 模块的前置及机制章节，并始终通过可运行的 Spring Boot 工程验证。

这种安排保留 Spring 的核心心智模型，同时避免新手先学习大量 XML 配置、外置 Servlet 容器和已经不是现代项目默认入口的搭建方式。

### 3. 跨模块依赖

```text
Java 语言基础与对象模型
        ↓
核心 API、泛型集合、异常和反射
        ↓
Maven、测试与 JDBC ─────────────┐
        ↓                       │
Spring 核心与 Spring Boot 启动   │
        ↓                       │
Web API、校验、错误契约和数据访问 ←┘
        ↓
安全、测试、可观测、部署和综合实践
        ↓
Java 8 / Spring Boot 2.7 维护与迁移
```

并发、JVM 和生产诊断是 Java 深入路线。读者完成 Java 语言主线后即可开始 Spring Boot；在学习异步任务、性能和生产诊断前，再补齐对应的 Java 进阶章节。

## 四、示例体系

### 1. 双层示例策略

| 内容范围 | 示例策略 | 原因 |
|----------|----------|------|
| 变量、类型、表达式、分支、循环和方法 | 独立最小示例 | 让一个示例只证明一个语言规则 |
| 面向对象、集合、异常、测试和 JDBC | 订单、商品和客户模型 | 建立跨文章可复用的领域上下文 |
| Spring Boot 主线 | 可运行的订单管理后端 | 串联 Web、校验、错误、数据、事务、安全和部署 |
| 并发、JVM 和诊断 | 订单服务的批处理、热点、竞争和延迟场景 | 让机制和诊断证据落到真实运行现象 |
| Java 8 与 Boot 2.7 | 同一业务功能的旧版本实现 | 直接比较能力边界和迁移影响 |

### 2. 固定业务语义

综合示例统一使用以下非敏感模型：

| 对象 | 核心字段 | 关键约束 |
|------|----------|----------|
| Customer | `id`、`name`、`email` | 邮箱合法且客户存在 |
| Product | `id`、`name`、`price`、`stock` | 金额使用 `BigDecimal`，库存不能为负 |
| Order | `id`、`customerId`、`items`、`status`、`totalAmount`、`createdAt` | 订单至少包含一项，总金额由明细计算 |
| OrderItem | `productId`、`quantity`、`unitPrice` | 数量为正，成交单价在下单时固化 |

Spring Boot 综合示例默认服务名使用 `order-service`，本地 HTTP 端口使用 `8080`；Java 核心的独立网络示例按当前 Java 蓝图使用回环地址和动态空闲端口，并由示例启动和关闭本地服务。数据库、Redis 或消息服务端口只在对应接入文章中声明，不把外部服务假设散落到所有示例。

### 3. 单篇示例闭环

语法、API、接入、测试和排障文章根据职责至少提供：

1. 适用版本、依赖和必要前置条件；
2. 能直接证明核心结论的代码、配置或命令；
3. 明确的文件路径和执行入口；
4. 真实格式的输出、响应、日志、状态或指标；
5. 对观察结果的解释；
6. 一个与主题相关的失败场景或边界；
7. 验证结论及尚未覆盖的生产能力。

新增示例函数、方法、构造器和回调必须遵守仓库代码注释规范。多入参函数使用 JavaDoc 说明参数约束和返回值；简单示例也至少用一句注释说明函数职责。

## 五、单篇内容质量约束

### 1. 合格文章的论证链路

```text
问题或概念
→ 明确结论
→ 规则、机制或设计原因
→ 可执行示例或观察证据
→ 结果解释
→ 错误、边界和工程判断
```

正文不固定生成“学习目标”“学习路线”“练习任务”“本章总结”等课程模板。标题必须对应真实技术主题，小节不能只有一句定义。

### 2. 禁止的敷衍表现

出现以下任一情况，文章不能通过单篇门禁：

- 只解释术语，不解释对象关系、执行语义或使用边界；
- 只给代码，不说明输入、执行方式、输出和观察重点；
- 用“运行成功”代替真实结果；
- 罗列 API、注解或配置项，却不说明选择条件和失败表现；
- 用表格堆积定义，缺少贯穿结论；
- 多个连续小节都只有一句话；
- 把框架内部名词当成机制解释，却不能说明它如何影响公开行为；
- 编造版本行为、日志、性能数字或示例运行结果；
- 为追求篇幅重复同义结论，或复制其他文章已经完整讲解的内容。

### 3. 计算机专业深度要求

| 主题 | 最低解释深度 |
|------|--------------|
| 类型与方法 | 值域、表示、转换、作用域、参数传递、重载选择和调用结果 |
| 对象与集合 | 身份、状态、相等性、可变性、复杂度、顺序和并发边界 |
| 异常与资源 | 传播路径、恢复责任、资源所有权和失败覆盖关系 |
| 并发 | happens-before、共享状态、同步成本、任务生命周期和取消 |
| JVM | 规范模型、HotSpot 可观察行为、内存与执行证据的边界 |
| Spring 容器 | Bean 定义、依赖解析、生命周期、代理和失败阶段 |
| Web | HTTP 语义、参数绑定、序列化、校验、异常到响应的完整链路 |
| 数据与事务 | 连接所有权、事务边界、代理限制、隔离和失败回滚 |
| 安全 | 认证与授权分离、过滤器链、凭据边界、攻击面和验证方法 |
| 生产实践 | 日志、指标、Trace、资源预算、发布验证和回滚证据 |

Sidebar 保持现有两级展示方式：

```text
JAVA 核心

│   ├── 1.1 Java 概述
```

正式 sidebar 只能登记已经生成且通过当前章节检查的文章。蓝图中的规划条目不能提前变成失效链接。

## 七、迁移策略

### 1. 现有状态

Java 目录已经存在大规模未提交重构内容，Spring Boot 仍是六篇承担多个主题的扁平文档，sidebar 中还存在大量未落地条目。所有这些改动均视为用户在途成果，不回退、不覆盖后再重建。

### 2. 迁移规则

| 现有内容 | 处理方式 |
|----------|----------|
| 与新职责卡一致且事实准确 | 迁入目标文章，重新补齐机制、示例、结果和边界 |
| 一篇混合多个独立主题 | 按唯一学习问题拆分，分别进入目标文章 |
| 多篇重复完整讲解 | 指定一个主讲文章，其他文章只保留最小上下文和相对链接 |
| 与主版本不符 | 移到维护线或迁移文章；不在主线混写默认行为 |
| 过时、错误或无法验证 | 不直接继承，依据官方资料和实际验证重写 |
| 已删除但仍被引用的路径 | 统计引用后决定更新链接或增加兼容页面 |

每次编辑前重新读取目标文件和 Git 状态，避免覆盖用户在重构期间产生的新修改。
