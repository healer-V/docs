# AI 应用基础模块蓝图

“AI 应用基础”负责建立 AI 应用、生成式模型和业务代码之间的基础关系，并让读者从空目录完成一个可验证的 Python 命令行应用。模块先解释系统边界和模型行为，再进入 API 调用；不把调用成功等同于业务结果正确。

本蓝图只规划正文责任，不表示九篇文章已经完成。正文必须先生成并确认样板文章，再按章节创建；模块目录和章节目录均不创建 `index.md`。

## 一、模块教学契约

| 字段 | 内容 |
|------|------|
| 模块名称 | AI 应用基础 |
| 目标目录 | `content/ai/01-application-foundation/` |
| 主知识方向 | AI 工程；围绕模型能力、应用责任、生成机制和最小调用链路组织 |
| 辅助知识方向 | 协议与 Web API、工程化工具；只解释完成首次调用所需的请求、响应、环境和凭据 |
| 读者基线 | 能阅读基础 Python 代码，理解命令行、HTTP 请求和 JSON 对象；不要求接触过模型 API |
| 当前方向起点 | 从 AI 应用由哪些对象组成、模型能做什么以及应用必须负责什么开始 |
| 主版本基线 | Python 3.12；OpenAI Responses API，以 2026-09-28 官方文档为行为基线；Python SDK 在样板验证时锁定精确版本 |
| 最终能力 | 能划分模型与应用责任、解释基础生成行为、按任务约束选择模型、完成模型调用并将其封装为具有输入和输出校验的命令行应用 |
| 范围排除 | 流式响应、结构化输出、工具调用和重试归“模型接入”；Prompt 优化归“Prompt 与上下文”；RAG、Agent、训练、推理基础设施和生产部署不在本模块展开 |

::: info Python SDK 版本锁定方式
OpenAI 官方 SDK 页面当前使用 `pip install openai`，没有在示例中固定补丁版本。生成样板文章时必须在独立虚拟环境安装官方稳定版、记录 `python -m pip show openai` 结果，再把验证版本写入正文；未完成实际验证前不得编造版本号或输出。
:::

## 二、知识方向与边界

### 1. 方向覆盖

| 覆盖层次 | 状态 | 当前模块责任 | 后续归属 |
|----------|------|--------------|----------|
| 模型与接口 | 适用 | 模型能力、Token、上下文、单次文本请求与响应 | 流式、多模态、工具和可靠性归“模型接入” |
| 上下文与知识 | 部分适用 | 解释上下文窗口及输入输出占用 | Prompt 组装、RAG 和引用不展开 |
| 应用与工作流 | 部分适用 | 建立输入、业务代码、模型服务、输出校验的最小链路 | 对话、工作流和 Agent 不展开 |
| 质量与评测 | 部分适用 | 解释非确定性、事实性和最小结果校验 | 数据集、指标和回归归“评测与可观测性” |
| 安全与治理 | 部分适用 | 说明 API 凭据保护和模型输出不可信边界 | 提示注入、权限和治理归“安全与治理” |
| 运行与成本 | 部分适用 | 模型选择时认识质量、时延和成本约束 | 限流、缓存、成本治理和部署不展开 |

### 2. 前置知识

| 前置知识 | 要求深度 | 当前模块处理方式 |
|----------|----------|------------------|
| Python | 能运行脚本，理解变量、函数、条件和异常 | 示例附近解释命令和项目结构，不重新教授 Python 语法 |
| 命令行 | 能进入目录并运行命令 | 同时提供 PowerShell 与 Bash 的必要命令 |
| HTTP 与 JSON | 认识请求、响应、字段和值 | 在 API 文章保留理解 SDK 对象所需的最小说明 |
| 环境变量 | 认识进程读取配置的方式 | 在凭据文章完整说明本地设置、检查和清理方法 |

### 3. 排除内容

| 排除主题 | 排除原因 | 正确归属 | 当前模块边界 |
|----------|----------|----------|--------------|
| 完整 Responses API 能力 | 会挤占基础心智模型并重复协议接入 | 模型接入 | 只使用单次文本请求和基础响应字段 |
| Prompt 工程 | 需要独立讨论指令、上下文和版本 | Prompt 与上下文 | 示例只使用满足任务所需的简短指令 |
| 结构化输出 | 需要 Schema 与业务校验闭环 | 模型接入 | 命令行应用只消费文本结果 |
| RAG 与 Agent | 依赖检索、工具、状态和控制循环 | RAG 应用、Agent 开发 | 只作为架构示例中的后续能力名称 |
| 评测体系 | 需要样本、指标和回归门禁 | 评测与可观测性 | 只做单次结果的格式和事实边界判断 |
| 生产可靠性 | 需要重试、限流、并发和部署知识 | 模型接入、性能与部署 | 只处理首次应用必须识别的错误 |

### 2. 排序依据

第一章先建立对象和责任边界，否则读者容易把模型输出直接当成业务事实。第二章解释 Token、上下文和生成行为，为理解响应限制与结果波动提供原因。第三章才进入环境、API 和应用封装，使代码中的每个校验动作都有前置概念支撑。
