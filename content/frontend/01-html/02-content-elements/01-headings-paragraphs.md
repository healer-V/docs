# 标题与段落

HTML 的标题和段落表达内容的组织方式。`h1`—`h6` 表示不同等级的标题，`p` 表示段落，`br` 在当前文本中换行，`hr` 表示主题发生分隔。选择它们时，应先判断内容关系，再决定显示方式。

例如，两段各自完整的说明应使用两个段落；一个邮寄地址内部需要分行，则可以使用 `br`。页面上都出现了换行，不代表两种标记表达了同一种结构。

下面先说明标题等级，再区分段落、换行和主题分隔，最后用独立文件核对结构与错误写法。

::: info 本篇的范围
本篇讲标题、段落、换行和主题分隔的基础用法。标题内部的文字语义见[文本语义与引用](./02-text-semantics.md)，元素嵌套通则见[HTML 元素嵌套与内容模型](../01-foundation/05-nesting-content-models.md)，源码空白的显示机制见[HTML 注释、空白与字符引用](../01-foundation/07-comments-whitespace-references.md)。CSS 字号、边距和布局不在本篇展开。
:::

## 一、标题等级表达内容层次

### 1. 同级主题与从属主题

标题可以帮助阅读者判断当前文字讲什么，以及它从属于哪一部分。`h1` 等级最高，`h6` 等级最低；这些数字表示层次，不是作者希望使用的字体大小。

以下是可以放在文档 `body` 中的局部内容：

```html
<h1>文件说明</h1>
<h2>保存方式</h2>
<p>保存前确认文件内容。</p>
<h3>字符编码</h3>
<p>本文件使用 UTF-8。</p>
<h2>阅读方式</h2>
<p>使用浏览器打开文件。</p>
```

“保存方式”和“阅读方式”是同级主题，都使用 `h2`；“字符编码”从属于“保存方式”，使用 `h3`。结束一个从属主题、回到同级主题时，可以从 `h3` 返回 `h2`，不要求标题数字一直增加。

HTML 并不通过标题标签把后面的全部内容自动包进一个新容器。上例的标题与段落在源码中仍是兄弟元素；层级表达的是内容组织，不能拿它替代元素之间真实的父子关系。依据见 [HTML 标准：h1—h6](https://html.spec.whatwg.org/multipage/sections.html#the-h1,-h2,-h3,-h4,-h5,-and-h6-elements)。

### 2. 标题数字不是字号

浏览器通常为不同等级提供不同默认外观，但 CSS 可以改变这些外观。为了把字显示得小一些就从 `h1` 跳到 `h6`，会让标记声明的层次与实际内容不符；需要改变字号时，应使用样式处理。

对普通文档，通常以一个清楚的主标题建立主题，再为从属内容安排相邻的标题等级。避免仅为外观跳过从属层次，有助于使用标题列表导航的人理解内容关系。[W3C WAI：标题](https://www.w3.org/WAI/tutorials/page-structure/headings/)说明了按内容组织等级的理由。

| 选择依据 | 合理做法 | 不合理做法 |
|----------|----------|------------|
| 内容从属关系 | 上级主题用较小数字，下级主题用较大数字 | 先决定字号，再倒推标题等级 |
| 同级主题 | 使用同一等级 | 为每段都换一个等级 |
| 外观 | 用 CSS 调整字号、字重和间距 | 用 `h6` 代替小字号样式 |
| 标题数量 | 按内容需要出现 | 固定每页必须几个标题 |

这不等于用固定的 `h1` 数量或某个机械计数就能证明文档合理。审查时仍要判断每个标题对应什么主题、它与周围标题的关系，以及是否有把普通句子误标成标题的情况。

::: tip 先问“谁从属于谁”
给一段文字选标题等级前，先写出它上面最近的主题和下面并列的主题。如果说不清从属关系，通常不是标题等级问题，而是内容还没有组织好。
:::

### 3. 标题的内容模型

标题元素接受短语内容，不接受段落、列表、`div` 等流式内容。下面两种写法看着都能显示文字，但只有第一种符合标题的内容模型：

```html
<!-- 正确：标题直接包含文字 -->
<h2>联系信息</h2>

<!-- 错误示例：p 不能成为标题内部的短语内容 -->
<h2><p>联系信息</p></h2>
```

`h2` 要求短语内容，而 `p` 不属于这类内容。浏览器可能仍把“联系信息”显示出来，检查器则会把后一种写法报告为不允许的子内容。标题需要更复杂的排版时，应把说明放到标题后的正文，而不是把块级结构塞进标题。

::: warning 结构容器不会自动替你改写标题等级
不能依赖“每进入一个分节，就把内部 h1 自动解释成更低等级”的旧式大纲设想。需要几级标题，应在标记中明确表达；分节元素的完整规则由相应主题负责，不以浏览器默认字号代替判断。
:::

## 二、段落、换行与源码空白

### 1. p 表达一个段落

`p` 把一段连续内容组织成段落。两个不同的段落，应分别使用自己的 `p`：

```html
<p>保存文件后，可以关闭编辑器。</p>
<p>重新打开文件时，浏览器读取已经保存的内容。</p>
```

浏览器默认会让两段内容各占相应的行，并在段落之间留出间隔。这种外观可以由 CSS 调整；段落是否成立取决于内容关系，不取决于当前恰好有多大空白。

### 2. p 的内容模型

`p` 的内容模型要求短语内容，例如文字和合适的段内元素。不能在一个 `p` 中直接放另一个 `p`、标题或普通 `div`，再期待它们仍然属于同一个段落。

```html
<!-- 错误示例：p 中直接出现 div -->
<p>前面的文字<div>中间的文字</div>后面的文字</p>
```

解析器遇到 `div` 时通常会结束当前段落，`div` 成为后续同级内容，末尾的 `</p>` 还可能对应一个补出的空段落。页面仍能显示文字，但源码意图与 DOM 结构已经不同。嵌套限制见 [p 的定义](https://html.spec.whatwg.org/multipage/grouping-content.html#the-p-element)与[元素嵌套与内容模型](../01-foundation/05-nesting-content-models.md)。

### 3. br 表达当前内容中的换行

地址、诗行等内容的行界本身具有意义时，可以在同一段中使用 `br`：

```html
<p>示例路 1 号<br>二层资料室</p>
```

这个局部例子表达一个分两行书写的地址，不是两段互相独立的说明。`br` 是空元素，没有 `</br>`，换行后的文字仍是外层段落的内容。

不能用连续多个 `br` 代替段落间距，或用它们把整页文字挤到想要的位置。这样的源码只声明一串换行，没有表达段落之间的关系；显示宽度改变后，也不能把它当成布局约束。依据见 [br 的使用要求](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-br-element)。

### 4. 源码换行不等于 br

在普通段落源码中按回车，主要是在文件里加入一个换行字符。浏览器按默认空白与断行规则呈现文本，不会把每个源码回车都当作 `br`。

```html
<p>第一行
第二行</p>
```

这段源码默认通常仍显示为一段连续文字，是否在“第一行”后换行取决于可用宽度和空白处理，而不是源码里的回车。需要语义上的强制换行时写 `br`；需要两个段落时写两个 `p`；只为了源码整齐而插入的换行，不应被误认为页面结构。

因此，不能靠编辑器里显示成两行就断言页面一定分成两行；也不应为让源码整齐而随意改变段内空白。源码、文本节点与默认显示的区别见[HTML 注释、空白与字符引用](../01-foundation/07-comments-whitespace-references.md)。

::: warning br 不是段落间距工具
连续写多个 `<br>` 只能制造多个换行机会，不能建立段落结构，也不能稳定控制垂直间距。段落之间使用 `p`，间距交给 CSS；只有内容本身需要换行时，才使用 `br`。
:::

## 三、hr 表达主题分隔

### 1. 主题变化不是装饰线

`hr` 表示段落层面的主题分隔，例如一段叙述转向另一件事，或一组说明结束后换到不同内容。它是空元素，不包住分隔前后的文字。

以下局部片段用分隔表示两个话题之间的变化：

```html
<p>纸张应放在干燥处，避免受潮。</p>
<hr>
<p>开放时间以当天公布的信息为准。</p>
```

浏览器通常把它画成一条横线，但“画线”不是判断是否应该使用它的唯一理由。只是想给一个盒子加装饰边框，应使用 CSS；两个紧密相关的句子之间，也不应只为增加视觉间隔就声明主题分隔。

### 2. hr 与标题的分工

标题表达内容的层级和主题名称，`hr` 表达段落层面的主题转换。一个页面若已经通过标题清楚表达了主题变化，并不要求在每两个标题之间再放一条 `hr`。

| 内容变化 | 更合适的标记 | 说明 |
|----------|--------------|------|
| 进入一个新的从属主题 | 标题 | 标题本身提供名称和层级 |
| 从一段说明转向另一件无关事项 | `hr` | 没有新的标题层级，但主题发生变化 |
| 只想增加上下空白 | CSS | 不表达内容关系 |
| 想在两个段落之间画装饰线 | CSS | 线不是主题分隔 |

是否需要这项标记应根据内容含义判断，完整语义见 [HTML 标准：hr](https://html.spec.whatwg.org/multipage/grouping-content.html#the-hr-element)。

## 四、常见结构误用

### 1. 按默认字号选标题

看到文字变大就选 `h1`，看到需要小字就选 `h6`，会把默认外观当成内容层次。检查时先看标题之间的从属关系，再看 CSS 是否另有字号设置；若层级合理但外观不合意，应修改样式而不是改标签。

### 2. 用 br 堆段落间距

用多个 `br` 把两段文字推开，页面可能暂时看起来整齐，但读屏、样式变化和内容提取都无法得到两个独立段落。把每一段放回 `p`，需要间距时使用 CSS 的 margin 或布局规则。

### 3. 把标题当容器

标题只描述一个标题，不负责包住后续正文。把整节内容塞进 `h2`，或用标题包段落、列表，会违反内容模型；后续内容应作为标题的兄弟元素出现，层级由标题名称表达。

| 现象 | 根本原因 | 修复与复测 |
|------|----------|------------|
| 标题文字很大，但层级混乱 | 按默认字号选标签 | 按内容从属关系重选 `h1`—`h6`，再用 CSS 调外观 |
| 段落之间用多个 `br` 隔开 | 把换行当布局 | 拆成多个 `p`，间距交给 CSS |
| 标题中包含 `p` 或 `div` | 标题被当成容器 | 标题只保留短语内容，正文移到标题后 |
| 源码换行后页面没换行 | 把源码回车当 `br` | 需要强制换行时写 `br`，需要分段时写 `p` |

## 五、独立文件核对

### 1. 创建 brief.html

新建空目录 `html-paragraphs`，创建 `brief.html`，以 UTF-8 保存。这个文件不需要样式、脚本或其他文章中的材料；几组短文字分别用于观察层次、段落和地址内部的换行。

::: details 查看 brief.html 完整内容

```html [brief.html]
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>标题与段落观察</title>
</head>
<body>
  <!-- 标题层级：h3 从属于 h2，随后回到同级 h2 -->
  <h1>文件说明</h1>
  <h2>保存方式</h2>
  <p id="first">保存前确认<span>文件内容</span>。</p>
  <h3>字符编码</h3>
  <p>本文件使用 UTF-8。</p>

  <!-- br 只用于地址内部的行界，不用于制造段落间距 -->
  <h2>联系信息</h2>
  <p id="address">示例路 1 号<br>二层资料室</p>

  <!-- hr 表示话题转换，后面的段落仍是独立段落 -->
  <hr>
  <p>附注：开放时间以当天公布的信息为准。</p>
</body>
</html>
```

:::

用浏览器打开后，标题按声明的等级显示；地址的第二部分换行，仍在同一个 `p` 中；主题分隔与两侧的段落则是不同元素。正文不应被默认字号或间距掩盖：即使将来使用不同样式，这些标记表达的内容关系仍应合理。

### 2. 观察标题层级与 br

在 Chrome 中使用 `F12`，macOS 可用 `Option+Command+I` 打开开发者工具。Elements 面板能够看到 `h1`、`h2`、`h3` 与段落的实际结构；这里不需要编写脚本才能核对内容归属。

| 观察对象 | 预期结果 | 判断依据 |
|----------|----------|----------|
| 标题顺序 | `h1`、`h2`、`h3`、`h2` | 源码中的标题等级 |
| 地址行界 | “示例路 1 号”和“二层资料室”分两行 | 同一个 `p` 中的 `br` |
| 地址归属 | 两行文字都属于 `address` 段落 | `br` 不建立新的段落 |
| 主题分隔 | 横线两侧的段落仍是独立元素 | `hr` 是空元素，不包内容 |
| 默认外观 | 各等级字号不同 | 可由 CSS 改变，不决定语义 |

### 3. 注入错误并恢复

把文件复制为 `invalid.html`，将 `<h2>联系信息</h2>` 改成下面的片段：

```html
<!-- 错误示例：p 不能成为标题内部的短语内容 -->
<h2><p>联系信息</p></h2>
```

`h2` 要求短语内容，而 `p` 不属于这类内容。页面仍可能显示“联系信息”，但标题包段落的结构不符合要求。使用 [Nu HTML Checker](https://validator.w3.org/nu/) 上传这个错误文件，可以按错误位置核对内容限制；恢复为直接包含文字的 `h2` 后再检查。

另一个不同性质的问题是把合理的 `h2` 改成 `h6`，只为得到较小字号。此时标签本身仍是 HTML 标题，检查器不能代替作者判断“联系信息”究竟从属于什么。应先根据内容层次选回合适等级，再单独调整样式。

| 注入的错误 | 观察 | 恢复 |
|------------|------|------|
| 标题中包含 `p` | 文字仍显示，Nu 报告不允许的子内容 | 把 `p` 移出标题，标题只保留文字 |
| 合理标题改成 `h6` | 结构合法，但层级与内容不符 | 按从属关系恢复等级，用 CSS 调字号 |
| 用多个 `br` 分隔段落 | 页面有空白，DOM 中没有两个 `p` | 改为两个 `p`，间距交给 CSS |
| 标题中放 `div` 或列表 | 结构被解析器调整或检查器报错 | 标题只放短语内容，复杂结构放到正文 |

### 4. 验证记录

本例于 2026-11-14 在 macOS 的 Chrome 157.0.8103.79 中核对：正常文件的标题顺序为 `h1、h2、h3、h2`，地址内有一个 `br`；正常文件经 Nu 检查无错误、无警告。标题包含 `p` 的错误版本被报告为不允许的子内容，修复后相应错误消失。

本次重写只补充正文层次、注释和观察项，`brief.html` 的元素、属性与结构未变；未据此验证屏幕阅读器的实际朗读，也不以标题结构承诺搜索排名。
