# 列表

HTML 列表用结构表达一组内容之间的关系。`ul` 表达顺序不影响含义的条目，`ol` 表达有意安排顺序的条目，`dl` 表达名称与说明之间的关联。圆点、数字和缩进是常见外观，选择依据仍然是内容关系。

例如，材料清单不必靠排列顺序表达步骤，操作步骤却不能随意调换；“术语—解释”则需要名称与说明的配对。三者不应仅因为默认样式相似就互相替代。

下面按条目关系、编号控制、嵌套归属和名称说明分组，最后用独立页面核对结构。

::: info 本篇的范围
本篇讲 `ul`、`ol`、`dl` 的基础结构与编号属性。列表的样式定制、计数器、横向菜单和布局归 CSS；用列表搭建导航或菜单组件不在本篇；链接目标与路径见[超链接与资源路径](./04-links-paths.md)；通用内容模型见[HTML 元素嵌套与内容模型](../01-foundation/05-nesting-content-models.md)。
:::

## 一、按内容关系选择列表

### 1. ul 使用 li 组织平级条目

`ul` 的普通列表项用 `li` 表示。下面是可以放在文档 `body` 中的局部内容：

```html
<ul>
  <li>纸张</li>
  <li>铅笔</li>
  <li>橡皮</li>
</ul>
```

这三项同属于一个材料清单。交换“铅笔”和“橡皮”的位置，不会把它变成另一套操作过程，因此无序列表符合这里的含义。

不能通过在每行前手写圆点，再用 `br` 换行来代替列表结构。那种写法只形成文本与换行，浏览器无法仅从圆点字符得到一个具有三个列表项的结构。原生列表的条目数量与关系也能提供给辅助技术，但具体朗读结果仍需按实际工具验证。

### 2. ol 表达有意义的先后顺序

`ol` 同样使用 `li`，但条目的顺序会影响理解。例如，以下局部片段是三个有先后的操作：

```html
<ol>
  <li>打开文件。</li>
  <li>修改内容。</li>
  <li>保存结果。</li>
</ol>
```

有序不等于“条目前恰好显示一个数字”。有些内容需要按排名、时间或优先级排列，也可以使用 `ol`；反过来，纯装饰性地想显示数字，不应替代对条目关系的判断。定义见 [ul](https://html.spec.whatwg.org/multipage/grouping-content.html#the-ul-element)与 [ol](https://html.spec.whatwg.org/multipage/grouping-content.html#the-ol-element)。

### 3. dl 表达名称与说明

`dl` 表达一组名称与说明的关联，`dt` 放名称，`dd` 放对应说明。例如，下面的局部片段包含两个术语组：

```html
<dl>
  <dt>HTML</dt>
  <dd>描述网页内容的标记语言。</dd>
  <dt>CSS</dt>
  <dd>描述文档呈现的样式语言。</dd>
</dl>
```

它不仅能表示词典式定义，也可以表示元数据名称与值、问题与回答等关联。`dt` 不是任意内容的小标题，`dd` 也不是为了缩进就可以单独放置的段落容器。

| 列表 | 条目关系 | 典型场景 | 不应只因为外观选择 |
|------|----------|----------|--------------------|
| `ul` | 平级，顺序不影响含义 | 材料清单、并列选项 | 想要圆点 |
| `ol` | 有先后、排名或优先级 | 操作步骤、排行榜 | 想要数字 |
| `dl` | 名称与一条或多条说明配对 | 术语表、元数据 | 想要缩进 |

## 二、有序列表的编号

### 1. start、reversed 与 type 各自控制一项信息

有时列表需要延续编号、倒序呈现，或按字母引用条目。相应属性可以表达这些需求：

| 属性 | 作用 | 使用条件 |
|------|------|----------|
| `start` | 指定起始序号，值是整数 | 例如列表从第 3 项接续，而不是重新从 1 开始 |
| `reversed` | 声明递减编号 | 是布尔属性；存在表示倒序，不使用字符串 `false` 关闭 |
| `type` | 指定编号标记类型 | 可用 `1`、`a`、`A`、`i`、`I`，区分字母与罗马数字的大小写 |

例如，以下局部片段从第 4 项开始，以大写罗马数字显示：

```html
<ol start="4" type="I">
  <li>第四项</li>
  <li>第五项</li>
</ol>
```

`start` 仍使用整数 `4`，不是写成 `IV`。`type` 决定标记形式，不改变 `start` 的数值语法。这里的 `I` 和 `i` 也是不同关键词，不能套用“全部属性值都忽略大小写”的说法。

普通未自定义 CSS 的倒序列表中，若省略 `start`，起点按该列表所拥有的列表项数量确定。一个具有三个普通条目的 `<ol reversed>` 默认从 3 递减；需要明确起点时可同时给出 `start`。`reversed` 改变编号方向，不会把源码里的条目顺序自动反转。各项规则见 [ol 的编号属性](https://html.spec.whatwg.org/multipage/grouping-content.html#the-ol-element)。

### 2. li 的 value 可以重设当前序号

有序列表中，某一项可以使用整数 `value` 重设序号；后面的普通项再按列表的方向接续。例如：

```html
<ol start="3">
  <li>从第三项开始</li>
  <li value="7">接续到第七项</li>
  <li>下一项</li>
</ol>
```

默认递增时，显示的序号是 3、7、8。`value` 不会把列表条目自动移动到其他位置，只改变当前条目的序号依据。它也不是给 `ul` 的圆点设置文字的方式；此属性在有序列表中的作用见 [li 的定义](https://html.spec.whatwg.org/multipage/grouping-content.html#the-li-element)。

观察编号时，应查看列表标记。DOM 中的 `li.value` 主要反映该元素自己的 `value` 属性，不是所有情况下已经计算好的显示序号；没有显式写 `value` 的项，不能仅凭这个接口的默认读数就断言显示为 0。

### 3. 编号属性不是 CSS 计数器替代品

`start`、`reversed`、`type` 和 `value` 表达的是列表内容本身的编号关系；CSS 计数器可以改变几乎所有列表的视觉标记，但不会自动让普通段落获得列表结构。若编号只用于装饰，不应为了得到数字而使用 `ol`；若编号是内容的一部分，也不应只靠 CSS 伪元素生成而不提供列表结构。

::: tip 先判断顺序是否改变含义
如果交换两个条目会改变操作结果、排名或阅读顺序，使用 `ol`；如果交换后含义不变，使用 `ul`；如果是名称和解释的配对，使用 `dl`。不要先选外观再补语义。
:::

## 三、嵌套列表应归属于某个列表项

### 1. 子列表放进对应的 li

一个条目有进一步的子条目时，内层列表应放在对应的 `li` 里面：

```html
<ul>
  <li>纸张</li>
  <li>书写工具
    <ul><li>铅笔</li></ul>
  </li>
</ul>
```

内层清单表示“铅笔属于书写工具这一项”，不是与“纸张”“书写工具”平级的第三个普通条目。`li` 的内容可以包含合适的流式内容，因此可以在其中组织文字、段落和子列表。

### 2. 子列表直接放在父列表下是错误的

以下局部片段则把内层 `ul` 直接放到了外层 `ul` 下：

```html
<!-- 错误示例：子列表没有归入对应的 li -->
<ul>
  <li>书写工具</li>
  <ul><li>铅笔</li></ul>
</ul>
```

浏览器仍能把文字缩进显示，不代表作者结构合法。普通 `ul`、`ol` 需要按列表项结构组织子内容，不能因为 `ul` 也属于流式内容就直接放到这个位置。修复时应把子列表移进其所属的 `li`，不是增加几个缩进空格。

### 3. 列表的内容模型

`ul` 和 `ol` 的直接子内容应是列表项 `li`，以及标准允许的脚本支持元素。空白和注释不等于普通列表项，也不能用它们替代 `li` 的层级。标准还允许相应的脚本支持元素，因此准确的判断是“普通条目和嵌套位置应符合列表模型”，而不是“标签之间只许出现 li 字符串”。

::: warning 缩进不是父子关系
编辑器里多按几次空格，不会把内层列表变成某个 `li` 的子元素。检查嵌套时看 Elements 中的父子关系，或看源码中 `</li>` 的位置；不要靠视觉缩进判断列表归属。
:::

## 四、名称与说明使用 dl

### 1. dt 与 dd 按组关联

`dl` 中的每个组由一个或多个 `dt` 和随后的一条或多条 `dd` 组成。一个名称说明组可以有多个 `dt`，然后接一个或多个 `dd`。例如，两个名称共用一条说明：

```html
<dl>
  <dt>color</dt>
  <dt>colour</dt>
  <dd>同一英文单词的两种拼写。</dd>
</dl>
```

需要先把同组名称写完，再写这一组的说明。若把名称和说明随意交错，便会改变分组关系。现行完整模型还允许使用 `div` 包裹组；这里只用直接的 `dt`、`dd` 展示名称与说明，依据见 [dl 的定义](https://html.spec.whatwg.org/multipage/grouping-content.html#the-dl-element)。

### 2. 多条说明与同一说明的多个段落要区分

一个组中多个 `dd` 可以表达同一名称下不同的说明值。例如，“可用载体”可以分别关联“纸质手册”和“电子手册”。

如果只是一条说明需要分成两段，则应在同一个 `dd` 中组织两个段落，不应机械地每一段都创建一个新的 `dd`。两者在视觉上都能换行，结构关系却不同。名称与值的组序也可能有意义，不能因为 `dl` 没有默认数字就认为调换顺序永远不影响含义。

### 3. dl 不是任意两列布局

`dl` 适合名称与说明的语义配对，不是“左边一列、右边一列”的通用布局工具。页面上的两栏说明、表单项和键值对，只有在内容关系确实是名称—说明时才适合 `dl`；纯视觉对齐应使用 CSS 布局。

## 五、独立核对编号与结构

### 1. 创建列表观察页

新建空目录 `html-lists`，创建 `lists.html` 并以 UTF-8 保存。各组内容只说明一种列表关系，不构成需要连续执行的业务流程，也不依赖脚本和外部素材。

::: details 查看 lists.html 完整内容

```html [lists.html]
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>列表结构与编号</title>
</head>
<body>
  <h1>列表观察</h1>

  <!-- 内层 ul 位于“书写工具”的 li 内，表示从属条目 -->
  <h2>平级与从属条目</h2>
  <ul id="items">
    <li>纸张</li>
    <li>书写工具
      <ul id="nested"><li>铅笔</li></ul>
    </li>
  </ul>

  <!-- start 设置起点，li value 重设当前项，后续项继续递增 -->
  <h2>接续序号</h2>
  <ol id="numbered" start="3">
    <li>从第三项开始</li>
    <li value="7">接续到第七项</li>
    <li>下一项</li>
  </ol>

  <!-- reversed 改变编号方向，不反转源码条目顺序 -->
  <h2>倒序</h2>
  <ol id="countdown" reversed>
    <li>第一条展示内容</li>
    <li>第二条展示内容</li>
    <li>第三条展示内容</li>
  </ol>

  <!-- type="I" 使用大写罗马数字 -->
  <h2>罗马数字</h2>
  <ol id="roman" start="4" type="I">
    <li>第四项</li>
    <li>第五项</li>
  </ol>

  <!-- 一名多值、多名一值、一名多说明 -->
  <h2>名称与说明</h2>
  <dl id="terms">
    <dt>HTML</dt>
    <dd>描述网页内容的标记语言。</dd>
    <dt>color</dt>
    <dt>colour</dt>
    <dd>同一英文单词的两种拼写。</dd>
    <dt>可用载体</dt>
    <dd>纸质手册。</dd>
    <dd>电子手册。</dd>
  </dl>
</body>
</html>
```

:::

打开文件后，接续序号应为 3、7、8，倒序列表为 3、2、1，罗马数字列表为 IV、V。内层“铅笔”属于“书写工具”，名称说明列表则保留一名一值、多名一值和一名多值的分组。

### 2. 用父子关系定位嵌套错误

复制文件为 `invalid.html`，把完整例子中的内层 `ul` 移到“书写工具”的 `</li>` 后面，使它直接成为外层 `ul` 的子元素。保留其他内容不变，再打开文件。

Chrome 的 Elements 面板能看到 `nested` 的父元素从 `li` 变成了 `ul`；[Nu HTML Checker](https://validator.w3.org/nu/) 则会针对这个位置报告不允许的子内容。文字能显示或者仍然有缩进，都不能替代父子关系检查。

修复时把内层列表移回原来的 `li` 内，重新打开并核对其父元素。修复后的源码应与本篇正常文件一致，相应检查错误消失。

| 注入的错误 | 观察 | 恢复 |
|------------|------|------|
| 子列表直接放在父 `ul` 下 | 仍有缩进，但 `nested` 的父元素是 `ul` | 移回对应 `li`，核对父子关系 |
| 用 `br` 和圆点伪造列表 | 只有文本行，没有 `li` 结构 | 改为 `ul` 和 `li` |
| 给 `ul` 写 `value` 控制圆点 | 没有预期的编号语义 | 有序编号使用 `ol` 和 `li value` |
| 多个 `dd` 代替一条说明的多个段落 | 分组关系被拆成多条说明 | 在一个 `dd` 中放多个段落 |

### 3. 验证记录

本例于 2026-11-14 在 macOS 的 Chrome 157.0.8103.79 中核对，编号标记与所列数值一致；正常文件经 Nu 检查无错误、无警告，子列表直接放在父 `ul` 下的对照报告结构错误，修复后父子关系恢复。未据此验证其他浏览器样式、全部 CSS 计数器配置或屏幕阅读器的实际朗读。

本次重写只补充正文层次、注释和观察项，`lists.html` 的列表结构、编号属性与预期数值未变。
