# 图片

`img` 在文档中嵌入图片，是没有结束标签的空元素。`src` 指定资源地址，`alt` 提供图片在当前上下文中的等价文字，`width` 与 `height` 可以声明显示尺寸。例如，下面是可放进 `body` 的局部内容：

```html
<img src="shape.svg" alt="蓝色矩形中央有一个白色圆形。"
     width="240" height="120">
```

资源地址与替代文本分别解决两个问题：浏览器从哪里取得图片，以及不能看到图片时仍应获得什么信息。写上合适的 `alt` 不会修复错误路径，图片能显示也不代表替代信息已经正确。

下面按资源、尺寸、替代文本和加载提示分组，最后用本篇自建的 SVG 完成验证。

::: info 本篇的范围
本篇讲 `img` 的资源声明、尺寸和替代文本。完整 URL 与相对路径见[超链接与资源路径](./04-links-paths.md)；`figure`/`figcaption`、`srcset`/`sizes` 和 `picture` 的完整规则归第 4 章；SVG 绘图语法与 Canvas 归第 6 章。图片格式的内部编码、性能优化和 CDN 策略不在本篇展开。
:::

## 一、图片资源与 src

### 1. img 是空元素

`img` 不包住子内容，替代文本写在 `alt` 属性中，不能写成 `<img>说明</img>`。浏览器在 `img` 的位置呈现外部图像；图片文件中的内容不会变成当前段落的普通 HTML 子元素。

```html
<!-- 正确：替代文本在 alt 属性中 -->
<img src="shape.svg" alt="蓝色矩形中央有一个白色圆形。">

<!-- 错误示例：img 不能包住替代文字 -->
<img src="shape.svg">蓝色矩形中央有一个白色圆形。</img>
```

后一种写法中的文字可能仍显示在页面上，但它不属于 `img` 的替代文本，结束标签也没有合法对应。空元素与普通元素的内容模型不同，不能通过“有没有文字”来互换。

### 2. src 按 URL 规则解析

`src` 按 URL 规则解析，可以引用相对路径或绝对地址。上例的 `shape.svg` 要依据当前文档基准定位；文件改名、路径大小写或 `base` 设置改变，都可能使目标不同。完整规则见 [超链接与资源路径](./04-links-paths.md)。

常见图片格式包括 JPEG、PNG、GIF、WebP、AVIF 和 SVG。选择格式取决于图片内容、透明、动画及目标环境支持等条件，不是把文件后缀改为 `.png` 就能转换实际内容。SVG 是矢量图形文档，也可以作为 `img` 的外部资源；把它嵌入为图片，与把 SVG 元素直接写入 HTML 文档是不同使用方式。

### 3. 图片是替换元素

图片是替换元素：浏览器在它的位置呈现外部图像，而不是把文件中的文字作为普通 HTML 子元素插入当前段落。这解释了为什么 `img` 没有子内容，也解释了为什么图片的固有尺寸、加载状态和替代文本需要由属性与资源共同决定。

`img` 的元素定义和资源行为见 [HTML 标准：img](https://html.spec.whatwg.org/multipage/embedded-content.html#the-img-element)。图形绘制与 SVG 的具体语法不属于这里的资源声明规则。

## 二、固有尺寸、显示尺寸与比例

### 1. HTML 宽高属性使用数字

图片资源可以带有自己的尺寸和比例信息，浏览器据此得到固有尺寸。`width="240" height="120"` 则给出当前图像的尺寸声明，数值对应 CSS 像素，不在属性里写 `240px` 或 `100%`。

下面的局部标记使用同一份图片，第二张保持 2:1 比例缩小显示：

```html
<img src="shape.svg" alt="蓝色矩形中央有一个白色圆形。"
     width="240" height="120">
<img src="shape.svg" alt="同一图形的缩小版本。"
     width="120" height="60">
```

显示区域变小，不表示下载的图像文件变小。这里仍然请求同一个 `shape.svg`，改变的是页面上的使用尺寸。对于包含像素的图片，单纯缩小显示也不会自动生成另一份更小的网络资源。

### 2. 固有尺寸与显示尺寸是不同读数

`naturalWidth` 和 `naturalHeight` 读取图像资源的固有尺寸；`width` 和 `height` 读取当前图像元素的显示尺寸。两者可以不同，CSS 还可以进一步覆盖 HTML 属性。

| 读数或属性 | 表示什么 | 改变方式 |
|------------|----------|----------|
| `naturalWidth` | 资源本身的固有宽度 | 换一份资源，或资源内容改变 |
| `naturalHeight` | 资源本身的固有高度 | 同上 |
| `width` / `height` 属性 | HTML 声明的显示尺寸 | 修改属性 |
| CSS `width` / `height` | 样式计算后的显示尺寸 | 修改 CSS 规则 |
| `object-fit` | 内容在显示区域内的适配方式 | 修改 CSS，不改变资源 |

### 3. 尺寸声明和最终布局仍有区别

正确提供宽高，可以让浏览器在图片加载前取得布局所需的尺寸或比例信息，减少加载后才重新分配空间的情况。最终显示还可能受 CSS 宽高、容器与 `object-fit` 等规则影响，因此不能把属性值当成不受样式影响的物理像素测量。

宽高属性不应作为拉伸图像的手段。资源具有固有宽高时，同时声明的两项值应符合它的比例要求；例如，原始尺寸为 240×120，缩为 120×60 仍是 2:1。强行指定为 120×120 属于本篇用于观察错误的对照，不应当作正常缩放写法。不同图片格式和保留比例规则还会影响其中图像是拉伸还是留白，需要结合资源和样式判断。

本篇的自建素材明确允许图形随区域缩放，便于观察比例不一致时圆形的变化；不要把这种素材设置推广为所有 SVG 默认行为。尺寸属性的要求见 [HTML 标准：宽高尺寸属性](https://html.spec.whatwg.org/multipage/embedded-content-other.html#dimension-attributes)。

::: tip 宽高属性先写固有比例
给图片写 `width` 和 `height` 时，先保持资源的固有宽高比，再用 CSS 做响应式缩放。为了让图片“填满”容器而随手改成一个不匹配的比例，通常会把图形拉伸或留白。
:::

## 三、alt 根据图片用途选择

### 1. 信息图片保留等价信息

图片承载正文没有表达的信息时，替代文本应表达这部分含义，而不是只重复文件名或写“这里有一张图片”。本例用一句话描述蓝色背景和白色圆形，足以让人理解这个简单图形。

替代文本依赖使用上下文，同一文件不必在所有页面使用相同描述。例如，图表可能需要在正文中提供数值和结论，不能把长表格全部塞入一个 `alt`。要求的依据是[图片替代文本的一般规则](https://html.spec.whatwg.org/multipage/images.html#general-guidelines)，更复杂内容的说明方法见 [WAI 图片教程](https://www.w3.org/WAI/tutorials/images/)。

`title` 是补充提示，不能替代 `alt`。把全部描述只写进悬停提示，会使不能悬停或看不到图片的用户缺少必要信息；也不能因为 Chrome 显示了某种破图图标，就认为读者已经获得图像含义。

### 2. 装饰图片明确使用空 alt

如果图片只作装饰，移除它也不丢失信息或操作含义，可以使用 `alt=""`：

```html
<p>正文说明已经完整。</p>
<img src="shape.svg" alt="" width="60" height="30">
```

空值明确表达不需要额外替代文字；缺少 `alt` 则没有作出同样的声明。浏览器或辅助技术对缺失值可能采用文件名等回退，不能把“省略这个属性”与“明确作为装饰”混为一谈。

这个选择基于内容职责，而不是尺寸、文件格式或“看上去比较漂亮”。一张很小的状态图标仍可能传递信息；装饰图片的判断依据见 [WAI：装饰图片](https://www.w3.org/WAI/tutorials/images/decorative/)。

### 3. 链接图片表达目标或功能

如果链接只有一张图片，它的替代文本通常应让用户知道链接目的：

```html
<a href="#description">
  <img src="shape.svg" alt="查看图形说明" width="60" height="30">
</a>
```

这里强调“查看图形说明”，而不是仅描述“蓝色矩形”。图片作为链接的主要内容时，它的替代信息还会参与链接的可访问名称。反过来，若链接中已有完整可见文字，旁边图标只是重复装饰，就应避免再重复读出同一内容。具体判断见 [WAI：功能图片](https://www.w3.org/WAI/tutorials/images/functional/)。

### 4. alt 不能由 title 或文件名替代

| 写法 | 是否提供等价文字 | 适用边界 |
|------|------------------|----------|
| `alt="蓝色矩形中央有一个白色圆形。"` | 是 | 信息图片 |
| `alt=""` | 明确声明无等价文字 | 纯装饰图片 |
| 缺少 `alt` | 否 | 作者语法问题，不能当作装饰声明 |
| 只有 `title="..."` | 否 | 补充提示，不能替代 `alt` |
| 只有文件名 `shape.svg` | 否 | 文件名不等于内容说明 |

::: warning 空 alt 不能作为消除错误的通用补丁
给所有图片补 `alt=""` 可以改变检查结果，但如果图片承担了信息或链接目的，用户仍然丢失内容。应先判断用途，再选择描述、功能名称或空值。
:::

## 四、加载与解码提示

### 1. loading 是加载时机的提示

现行 HTML 还提供 `loading` 和 `decoding`。`loading="lazy"` 允许浏览器按策略延后加载，`eager` 表达通常的立即加载意图；实际时机受视口、浏览器与相关条件影响，不能把所有首屏重要图片都机械设为懒加载。

```html
<img src="shape.svg" alt="蓝色矩形中央有一个白色圆形。"
     width="240" height="120" loading="lazy" decoding="async">
```

### 2. decoding 是解码安排的提示

`decoding="async"` 提示解码与呈现的安排，不改变资源 URL，也不是一个下载完成回调。`decoding="sync"` 表达同步解码意图，`auto` 交给浏览器决定。属性是提示，不保证某一帧一定在特定时刻完成。

### 3. 不承诺跨环境性能收益

这两个属性按当前标准理解，不能一概称为最初 HTML5 新增。本篇只核对声明与基本加载结果，不对加载距离、完成时刻或性能收益作跨环境承诺。相关定义见 [img 属性](https://html.spec.whatwg.org/multipage/embedded-content.html#the-img-element)。需要按尺寸或裁切选择不同资源时，另参考[响应式图片的标准说明](https://html.spec.whatwg.org/multipage/images.html#introduction-3)；`srcset`、`sizes` 与 `picture` 不在本篇展开。

::: warning lazy 不是“越懒越好”
首屏主图、需要立即参与布局的图片，盲目设置 `loading="lazy"` 可能延后用户最需要的内容。加载策略应结合图片位置和实际请求观察，不能只凭属性名判断性能。
:::

## 五、用本篇素材检查图片

### 1. 创建图片和文档

新建空目录 `html-images`，先创建 `shape.svg`，把以下 XML 文本保存进去。它是一份完整且可直接使用的图片，不需要下载素材或打开其他文章。这里不要求掌握 SVG 绘图语法。

```xml [shape.svg]
<svg xmlns="http://www.w3.org/2000/svg" width="240" height="120"
     viewBox="0 0 240 120" preserveAspectRatio="none">
  <rect width="240" height="120" fill="#125aa0"/>
  <circle cx="120" cy="60" r="30" fill="white"/>
</svg>
```

再创建同级的 `images.html`，以 UTF-8 保存。三个图像使用同一个资源，但在文档中分别承担信息、装饰和链接功能。

::: details 查看 images.html 完整内容

```html [images.html]
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>图片声明观察</title>
</head>
<body>
  <h1>图片声明观察</h1>
  <h2 id="description">图形说明</h2>

  <!-- 信息图片：alt 表达图形内容 -->
  <p>信息图片：</p>
  <img id="information" src="shape.svg"
       alt="蓝色矩形中央有一个白色圆形。" width="240" height="120">

  <!-- 装饰图片：空 alt 明确不增加信息 -->
  <p>以下图片仅作装饰：</p>
  <img id="decoration" src="shape.svg" alt="" width="60" height="30">

  <!-- 功能图片：alt 说明链接目的 -->
  <p>只使用图片的链接：</p>
  <a id="image-link" href="#description">
    <img id="action" src="shape.svg" alt="查看图形说明"
         width="60" height="30">
  </a>
</body>
</html>
```

:::

双击打开页面。第一张以 240×120 显示，另外两张以 60×30 显示。开发者工具的 Elements 面板可以核对每张图片的 `src`、宽高和替代文本；在可访问性信息中检查，链接的名称应表达“查看图形说明”。这只核对浏览器提供的名称，不冒充屏幕阅读器的实际朗读结果。

### 2. 区分资源尺寸与显示结果

在 Console 中执行下列只读表达式。`naturalWidth` 和 `naturalHeight` 是图像资源的固有尺寸读数，`.width` 和 `.height` 读取当前图像的相应显示尺寸：

```js
document.getElementById('information').naturalWidth
document.getElementById('information').naturalHeight
document.getElementById('information').width
document.getElementById('information').height
```

在本例已加载、未追加样式的条件下，结果依次为 `240`、`120`、`240`、`120`。把该图片属性改为 `width="120" height="60"`，保存并刷新后，前两个读数仍然不变，后两个变为 `120` 和 `60`。

再故意把显示高度改为 `120`，制造比例不匹配的错误：显示区域变成方形，本篇素材中的白色圆形会被沿竖向拉长。把高度恢复为 `60` 后形状恢复。这里验证的是当前资源允许缩放条件下的错误效果，不能据此推断所有图片都会以同样方式处理不匹配比例。

| 观察项 | 表达式或操作 | 预期结果 | 说明 |
|--------|--------------|----------|------|
| 资源固有宽度 | `.naturalWidth` | `240` | 不随显示尺寸改变 |
| 资源固有高度 | `.naturalHeight` | `120` | 不随显示尺寸改变 |
| 当前显示宽度 | `.width` | `240` 或 `120` | 可由属性或 CSS 改变 |
| 装饰图片 | 检查 `alt` | 空字符串 | 明确不提供等价文字 |
| 链接名称 | 可访问性信息 | “查看图形说明” | 图片替代文本参与链接名称 |

### 3. 让资源失败，再恢复

保留正确文件，把第一张图片的 `src` 临时改为 `missing.svg`，保存并刷新。它无法加载原图，`alt` 仍然保留图像的等价说明；具体破图和文字绘制方式由浏览器决定，不要求所有环境都显示成同一种像素外观。

可用以下表达式检查失败状态：

```js
document.getElementById('information').complete
document.getElementById('information').naturalWidth
```

主测浏览器在请求结束后的结果是 `true` 和 `0`。`complete` 为真不单独证明加载成功，失败也可以使请求结束；应结合资源尺寸、实际请求和显示判断。确认 `src` 与文件名后，把地址恢复为 `shape.svg` 并刷新，图像和固有宽度应恢复。

若需要区分 HTTP 404，可以在本目录运行本地服务：先安装 [Python 3](https://www.python.org/downloads/)，macOS 使用 `python3 -m http.server 8000 --bind 127.0.0.1`，Windows 使用启动器时运行 `py -3 -m http.server 8000 --bind 127.0.0.1`，访问 `http://127.0.0.1:8000/images.html` 后查看 Network。服务用完按 `Ctrl+C` 停止；端口冲突时同时修改启动端口与访问地址，不停止未知进程。

再将正常第一张图片的 `alt` 整项删除，上传文档到 [Nu HTML Checker](https://validator.w3.org/nu/)：在本例普通作者文档中，它会报告缺少替代文本属性。恢复原来的描述后重检，不能用“改成空 alt”替代对信息用途的判断。

| 注入的问题 | 观察 | 恢复 |
|------------|------|------|
| `src="missing.svg"` | 请求失败，`complete` 为 `true`，`naturalWidth` 为 `0` | 核对路径和文件名，恢复 `shape.svg` |
| 删除信息图片的 `alt` | Nu 报告缺少替代文本 | 根据图片用途补回等价描述 |
| 给信息图片加 `alt=""` | 检查通过，但等价信息丢失 | 恢复能表达图片内容的文字 |
| 把宽高改成 120×120 | 显示比例改变，图形被拉伸 | 恢复固有比例，缩放交给 CSS |
| 用 `title` 代替 `alt` | 悬停提示不能覆盖所有用户 | 保留 `alt`，`title` 只作补充 |

### 4. 验证记录

以上素材与文档于 2026-11-14 在 macOS 的 Chrome 157.0.8103.79 中核对。正常尺寸、缩放与恢复、同一资源的三种替代文本、图片链接的可访问名称，以及错误资源的 `complete`、`naturalWidth` 与 HTTP 404 均有实际观察。正常与修复后的文档经 Nu 检查无错误、无警告，缺少 `alt` 的版本报告对应错误。

本次重写只补充正文层次、注释和观察项，`shape.svg` 与 `images.html` 的资源、尺寸和替代文本未变；未据此断言所有图片格式的缩放行为或完整无障碍合规。
