# 通用容器 div 与 span

`div` 和 `span` 是通用容器：它们可以把一组内容组织在同一个元素下，但本身不声明段落、重要性、导航或按钮等专门含义。常见用途是在确实需要统一属性、样式或节点分组，而又没有更合适元素时提供一个中性的边界。

选择它们应从内容职责出发。需要一段正文时使用 `p`，需要表达重要性时使用 `strong`；不能因为 `div` 或 `span` 容易添加样式，就用它们替换所有具有专门含义的元素。

下面先说明两种容器的内容范围，再区分显示与内容模型，最后用独立页面核对分组和错误嵌套。

::: info 本篇的范围
本篇讲 `div` 与 `span` 的通用分组职责。`id`、`class` 等全局属性的完整规则见[HTML 全局属性](../01-foundation/06-global-attributes.md)；内容模型通则见[HTML 元素嵌套与内容模型](../01-foundation/05-nesting-content-models.md)；结构语义元素归第 4 章；CSS 布局、选择器和 ARIA 不在本篇展开。
:::

## 一、通用容器的职责

### 1. div 组织较大范围的普通内容

在普通正文上下文中，`div` 可以包含流式内容，例如多段文字、列表和其他允许的元素。下面是可放在 `body` 中的局部结构：

```html
<div class="notice-group">
  <p>文件已经保存。</p>
  <p>修改后需要重新加载页面。</p>
</div>
```

两段文字仍分别由 `p` 表达段落；外层 `div` 只是给它们提供共同容器，便于施加相同的背景或间距。它没有因此变成一篇文章或一个有专门主题的章节。

`div` 的具体内容模型仍受所在上下文影响，例如处在特定结构中的分组会有额外条件。这里使用的是普通正文情形，不能把“通用”理解成任何位置、任何内容都允许。定义见 [HTML：div](https://html.spec.whatwg.org/multipage/grouping-content.html#the-div-element)。

### 2. span 标记段内的一部分

`span` 用于短语内容范围的分组，可以把一句话中的代码、名称或其他片段圈定出来，同时保持其余段落结构：

```html
<p>物品代码为 <span class="code">AB-17</span>，请核对后保存。</p>
```

这里 `span` 不会自动声明“重要”“引用”或“程序代码”。如果当前内容确实具有这些含义，应评估是否使用 `strong`、`q` 或 `code` 等更合适的元素。上例只把普通产品标识作为一个可统一设置样式的片段，因而使用中性分组。

### 3. 无语义不等于无边界

“没有专门语义”不等于“可以放在任何位置、包含任何内容”。`div` 和 `span` 仍有各自的内容模型，也仍受父元素允许内容的限制。

| 容器 | 常见内容范围 | 典型用途 | 不能做的事 |
|------|--------------|----------|------------|
| `div` | 流式内容 | 多段内容、列表或卡片的共同分组 | 放在只允许短语内容的位置 |
| `span` | 短语内容 | 一句话中的局部片段 | 直接包含段落、列表或 `div` |
| `p` | 短语内容 | 一个段落 | 包含另一个 `p` 或块级结构 |
| `strong` | 短语内容 | 重要内容 | 代替所有加粗样式 |

`span` 的内容模型要求短语内容。它与 `div` 不能只按名称替换；把包含多段内容的 `div` 改成 `span`，还必须重新检查内部内容是否合法。[span 的定义](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-span-element)说明了这项边界。

::: tip 先找有没有专门元素
需要分组时，先问内容是否已经有对应元素：段落用 `p`，重要内容用 `strong`，作品名用 `cite`，代码用 `code`，导航用 `nav`。只有找不到合适语义时，才退回 `div` 或 `span`。
:::

## 二、显示形式不会改变内容模型

### 1. 默认块与行内只是呈现线索

在常见浏览器默认样式下，`div` 通常产生块级盒，`span` 通常产生行内盒。这个差别解释了它们为何常出现在不同位置，但不是判断 HTML 内容合法性的依据。

CSS 可以改变显示。例如，下面的局部标记让段内片段单独形成显示块：

```html
<p>编号：<span style="display: block">AB-17</span>已经记录。</p>
```

`span` 仍是短语内容元素，内部普通文字仍符合要求；`display: block` 改变的是它生成的盒，而不是把它改造成另一种 HTML 元素。相反，给 `div` 设置 `display: inline` 也不会使它自动成为 `p` 允许的短语内容。

### 2. display 不改变内容模型

样式与合法结构的区别可参照[元素嵌套与内容模型](../01-foundation/05-nesting-content-models.md)。下面两种写法在页面上可能都看起来像一块内容，但结构合法性不同：

```html
<!-- 合法：span 内仍是短语内容，只是改变了显示方式 -->
<span style="display: block">AB-17</span>

<!-- 错误示例：display 不会放宽 span 的内容模型 -->
<span style="display: block"><div>错误嵌套</div></span>
```

浏览器可能仍显示“错误嵌套”，但 `span` 内出现了不符合其短语内容模型的 `div`。检查结构时看元素父子关系，不要看它当前被画成块还是行内。

### 3. id、class 与样式只是附加配置

容器可以使用 `id`、`class`、`title`、`lang` 等适用的全局属性。`id` 用于识别特定元素，`class` 用于共同分类；它们都不会把普通容器变成段落或按钮。

同样，给 `span` 设置红色和粗体，只说明有相应 CSS 呈现，不能替代 `strong` 的重要性语义。判断是否需要专门元素时，应先说明这段内容是什么，再决定需要怎样显示，而不是反向从颜色推导标签含义。

::: warning display 不是语义转换器
`display: block`、`display: flex` 或 `display: grid` 只改变盒的布局方式，不会把 `span` 变成 `div`，也不会放宽 `span` 的内容模型。CSS 负责呈现，HTML 负责结构与含义。
:::

## 三、语义元素与通用容器的选择

### 1. 用内容需求选择元素

可以用“容器是否需要向浏览器表达专门内容职责”来检查选择：

| 内容需求 | 应考虑的元素 | 原因 |
|----------|--------------|------|
| 一段正文 | `p` | 明确表达段落，而不只是外观上另起一行 |
| 内容中的重要部分 | `strong` | 表达重要性，不把加粗当成唯一目的 |
| 作品名称 | `cite` | 表达作品名，不把斜体当成唯一目的 |
| 代码文本 | `code` | 表达代码，不把等宽字体当成唯一目的 |
| 多个内容块需要共同样式，但没有额外主题语义 | `div` | 提供一般分组，内部元素继续表达各自含义 |
| 一句话中的片段需要单独属性或样式，没有更具体语义 | `span` | 提供短语范围的中性分组 |

页面分节、导航和独立内容还有对应的结构元素，选择边界应按实际内容判断；这些元素的完整规则由结构语义主题展开。没有专门语义时不必强造一种，已经有清楚含义时也不应一律退回 `div`。

### 2. 原生交互优先

`tabindex` 主要参与焦点导航，原生按钮的行为由按钮定义提供；两者不是同一职责。给 `div` 加了焦点能力，只解决了“能否用 Tab 到达”，没有补齐按钮的名称、激活方式和状态。依据见 [焦点与 tabindex](https://html.spec.whatwg.org/multipage/interaction.html#the-tabindex-attribute)以及 [button 的原生能力](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/button)。

### 3. div 模拟按钮的边界

```html
<!-- 看似按钮，但没有原生按钮的完整行为 -->
<div class="button" tabindex="0">保存</div>

<!-- 原生按钮：键盘激活、表单行为和状态语义由元素提供 -->
<button type="button">保存</button>
```

上面的 `div` 可以获得焦点，也能通过脚本添加点击处理，但不会自动获得按钮角色、Enter/空格激活、禁用状态和表单提交行为。需要按钮时使用 `button`；`div` 只适合确实没有专门语义的普通分组。

::: warning 样式和焦点不能替代原生交互
把 `div` 画成按钮、增加 `tabindex` 或添加一次点击处理，都不会自动获得按钮完整的名称、键盘触发和状态行为。需要按钮或链接时，应优先使用相应原生元素；本篇不通过扩写事件和 ARIA 来制作另一套自定义控件。
:::

## 四、独立观察分组与显示

### 1. 创建完整页面

新建空目录 `html-grouping`，创建 `grouping.html` 并以 UTF-8 保存。完整代码只有当前文件中的固定样式，没有脚本和外部资源：

::: details 查看 grouping.html 完整内容

```html [grouping.html]
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>通用容器对照</title>
  <style>
    /* div 提供共同边框，内部 p 仍各自表达段落 */
    .notice-group { border: 1px solid #777; padding: 8px; }

    /* span 只提供局部样式，不声明特殊语义 */
    .code { color: #125aa0; font-weight: bold; }

    /* 改变盒的显示方式，不改变 span 的内容模型 */
    #separate { display: block; }
  </style>
</head>
<body>
  <h1>通用容器对照</h1>

  <div class="notice-group">
    <p>文件已经保存。</p>
    <p>修改后需要重新加载页面。</p>
  </div>

  <p>物品代码为 <span class="code">AB-17</span>，请核对后保存。</p>

  <p>编号：<span id="separate" class="code">CD-28</span>已经记录。</p>
</body>
</html>
```

:::

打开后，前两段共用一个边框；`AB-17` 显示为带样式的段内片段；`CD-28` 由于明确设置了 `display`，单独形成显示块。`p` 仍承载段落，`div` 和 `span` 只承载各自分组，不能从这些外观变化推导出新的语义。

### 2. 改变样式后重新判断结构

在开发者工具中检查 `CD-28`。它仍是 `p` 的 `span` 子元素，内容只有文字；将 `display: block` 暂时移除后，呈现方式改变，但 HTML 元素关系没有改变。

| 观察对象 | 预期结果 | 说明 |
|----------|----------|------|
| 两段提示 | 共用一个边框 | `div` 提供共同分组 |
| `AB-17` | 蓝色、加粗，仍在段落内 | `span` 只做局部样式 |
| `CD-28` | 单独形成显示块 | `display` 改变盒，不改变标签 |
| 父子关系 | `CD-28` 仍是 `p` 的子元素 | 样式不改变 DOM 结构 |
| 移除 `display` | 回到行内呈现 | 元素和内容模型保持原样 |

### 3. 注入错误并恢复

再复制完整文件为 `invalid.html`，只在 `body` 结束标签之前加入下面的错误片段：

```html
<!-- 错误示例：改变显示没有放宽 span 的内容模型 -->
<span style="display: block"><div>错误嵌套</div></span>
```

浏览器仍会显示“错误嵌套”，但 `span` 内出现了不符合其短语内容模型的 `div`。把这个完整版本上传 [Nu HTML Checker](https://validator.w3.org/nu/)，可以核对非法子内容；修复时移除这个故意错误的片段，或按需要把外层改为适合该内容的结构，再重新检查。

| 注入的错误 | 观察 | 恢复 |
|------------|------|------|
| `span` 直接包含 `div` | 页面可能仍显示，Nu 报告非法子内容 | 移除错误片段，或改用允许流内容的容器 |
| 用 `div` 模拟按钮 | 可加样式和焦点，但缺少原生按钮行为 | 改用 `button` |
| 给普通文字加样式代替 `strong` | 外观相似，重要性语义丢失 | 按内容含义使用 `strong` |
| 把 `display: inline` 加给 `div` | 显示变化，内容模型不变 | 不靠 CSS 修正嵌套关系 |

### 4. 验证记录

本例于 2026-11-14 在 macOS 的 Chrome 157.0.8103.79 中核对：两种 `span` 的默认与指定显示形式不同，元素名称和父子关系保持不变；Nu 对正常文档和移除错误片段的修复文档未报告错误或警告，对错误版本报告 `div` 不允许出现在对应 `span` 内。

本次重写只补充正文层次、注释和观察项，`grouping.html` 的结构、样式与错误对照未变；这个对照验证内容模型与显示的区别，不是 CSS 布局或自定义控件实现教程。
