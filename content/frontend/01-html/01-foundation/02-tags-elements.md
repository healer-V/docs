# 标签与元素

HTML 用**标签**标记内容，用**元素**表达内容的含义。标签是源码中的标记；元素是这些标记描述的结构单位。一个段落可以有开始标签、文字和结束标签，而换行等空元素只有开始标签，不能再包住内容。

理解两者的区别，才能判断哪些符号属于标签、哪些文字属于元素内容，以及哪里需要结束标签。标签写对之后，还要继续判断元素能否这样嵌套；那属于内容模型的问题。

::: info 本文的判断依据
正文按 HTML 语法说明，不把 XML、XHTML 或 JSX 的规则混入普通 HTML。浏览器会修补部分错误标记，所以判断依据是源码中的标签写法、Elements 中的实际结构，以及验证器报告，而不是页面是否还能显示。
:::

## 一、标签与元素的组成

### 1. 开始标签、结束标签与内容

下面是可以放在页面正文中的局部标记，暂时省略完整文档外壳：

```html
<!-- p 是标签名；两个标签之间的文字是元素内容 -->
<p>这是一段文字。</p>
```

`<p>` 是**开始标签**，其中 `p` 是标签名；`</p>` 是**结束标签**，斜杠位于标签名前。两者之间的“这是一段文字。”是内容。开始标签、内容和结束标签共同描述一个 `p` 元素，表示一个段落。

因此，“把这段文字放入 p 元素”与“写一个 p 开始标签”并不等价：前者包含内容归属，后者只是源码中的一个标记。标准对标签和元素写法的说明见 [HTML 语法：元素](https://html.spec.whatwg.org/multipage/syntax.html#elements-2)。

| 组成部分 | 写法示例 | 作用 | 常见误判 |
|----------|----------|------|----------|
| 开始标签 | `<p>` | 声明元素开始，可携带属性 | 把开始标签当成完整元素 |
| 结束标签 | `</p>` | 结束对应元素的内容区域 | 用另一个元素的结束标签替代 |
| 标签名 | `p` | 指定元素类型 | 把标签名当成页面要显示的文字 |
| 元素内容 | `这是一段文字。` | 元素所描述的内容 | 把标签之间的所有文字都当成同一层 |
| 属性 | `title="补充说明"` | 为元素提供配置 | 把属性写到结束标签上 |

### 2. 属性写在开始标签中

开始标签还可以携带**属性**，为元素补充配置。下面的 `title="补充说明"` 是属性，不是显示在正文中的段落内容：

```html
<!-- title 属于开始标签，不是元素内容 -->
<p title="补充说明">这是一段文字。</p>
```

属性的位置和取值规则与元素内容不同。这里只需先识别它位于开始标签内；元素名仍是 `p`，正文内容仍是开始标签和结束标签之间的文字。属性能否使用、值是否合法，由具体属性定义，完整规则见[HTML 属性与属性值](./03-attributes-values.md)。

结束标签不能携带属性。`</p title="补充说明">` 不是给段落添加说明的正确写法；需要配置元素时，把属性放回开始标签。

### 3. 元素可以包含其他元素

元素内部还可以有其他元素。例如，以下局部标记中的 `strong` 表示重要文字：

```html
<!-- strong 是 p 的子元素，表示重要内容 -->
<p>请保留<strong>原始文件</strong>。</p>
```

整个段落是一个 `p` 元素，其中包含普通文字和一个 `strong` 元素。`strong` 也有自己的开始标签、内容和结束标签；不能把一整个段落叫作“一个标签”，也不能把两个开始标签之间的所有内容都当成同一层。

这种包含关系是否合法，还要看父元素允许的内容模型。标签闭合正确，只说明起止标记配对；`p` 能否包含某个元素、`a` 能否再包含交互元素，需要按元素定义判断，见[HTML 元素嵌套与内容模型](./05-nesting-content-models.md)。

::: tip 先找开始标签，再找对应的结束标签
阅读一段 HTML 时，先确认当前元素的开始标签，再向下寻找与它同名的结束标签；遇到子元素时先处理内层。这样比从文字内容猜测层级更可靠。
:::

## 二、成对元素与空元素

### 1. 普通元素的起止边界

`p`、`strong` 等普通元素通过起止标记界定内容。内容可以是文字、其他允许的元素，也可以为空。例如，`<p></p>` 描述一个没有正文内容的段落，但它仍是普通元素，并不会因此变成空元素。

结束标签应与开始标签对应，不能用另一个元素的结束标签替代。对于嵌套结构，通常先结束内层，再结束外层：

```html
<!-- 先结束 strong，再结束 p -->
<p>一段<strong>重要说明</strong>。</p>
```

如果结束顺序写错，浏览器可能按解析规则调整结构，页面仍然显示，但 DOM 中的父子关系未必与源码意图一致。标签配对解决的是“哪里结束”，内容模型解决的是“能否这样放”，两者不能互相替代。

### 2. 空元素没有子内容

HTML 定义了一组**空元素**（void elements）。它们不能在 HTML 源码中包住子内容，也不得写结束标签。常见代表包括：

| 元素 | 描述的内容 | 正确写法示意 | 常见错误 |
|------|------------|--------------|----------|
| `br` | 文本中的换行 | `<br>` | `</br>` 或把文字当成 `br` 的子内容 |
| `hr` | 主题分隔 | `<hr>` | 写 `</hr>` |
| `img` | 图片资源 | `<img src="图片地址" alt="文字说明">` | 在 `<img>` 与 `</img>` 之间写替代文字 |
| `input` | 输入控件 | `<input type="text">` | 把标签或说明文字塞进 `input` |
| `meta` | 文档信息 | `<meta charset="utf-8">` | 给 `meta` 写结束标签 |

表中是局部语法示意，不包含所引用资源或完整页面。空元素也可以有属性：`img` 的图片信息来自 `src` 等属性，而不是写在 `<img>` 与 `</img>` 之间。替代文本应写在 `alt` 属性中，`</img>` 不是合法的 HTML 图片结束标签。

`<br>第二行` 中的“第二行”属于 `br` 所在的外层内容，不是 `br` 的子内容。空元素与“普通元素恰好没有文字”是不同概念，不能通过内容是否为空来互相转换。

::: warning 空元素不是“内容为空的普通元素”
`<p></p>` 是内容为空的段落，仍是普通元素；`<br>` 是不容纳子内容的空元素。把 `<br>` 写成 `<br></br>`，或用 `<p></p>` 代替换行，都是把两类元素混为一谈。
:::

## 三、标签名、大小写与可省略标签

### 1. 标签名忽略 ASCII 大小写

在 HTML 语法中，`<P>` 与 `<p>` 使用同一个 HTML 元素名。为了让源码一致、便于阅读，通常统一使用小写开始和结束标签。

```html
<!-- 两种写法在 HTML 中指向同一个元素；统一小写更易读 -->
<P>大写标签名</P>
<p>小写标签名</p>
```

这条规则不能推广为“HTML 文件中的所有字符都不区分大小写”。属性值、URL 路径和正文文字由各自规则解释；例如，文件路径中的大小写还会受所使用的服务器与文件系统影响。标签名的大小写规则只解决元素名称的匹配，不改变属性值的含义。

### 2. 可省略标签受上下文约束

HTML 允许某些元素在特定位置省略开始标签或结束标签。例如，以下是一个局部列表，其中每个新 `li` 的开始可以界定前一个列表项的结束：

```html
<!-- li 的结束标签在相邻 li 之间可以省略 -->
<ul>
  <li>第一项
  <li>第二项
</ul>
```

这不表示任意结束标签都可省略。`strong` 等元素的结束标签不能照此处理；是否可省略、在什么位置可省略，都必须查对应元素的规则。初次编写时，把非空元素的必要起止标签明确写出，更容易看清内容边界。完整条件见 [HTML 语法：可省略标签](https://html.spec.whatwg.org/multipage/syntax.html#optional-tags)。

| 写法 | 是否可省略 | 成立条件 | 阅读风险 |
|------|------------|----------|----------|
| `<li>第一项<li>第二项` | 结束标签可省略 | 相邻列表项或父元素结束处 | 项目边界依赖上下文 |
| `<p>一段<p>另一段` | 结束标签可省略 | 下一个块级内容或父元素结束处 | 容易误判段落范围 |
| `<strong>重点` | 不可按此省略 | 没有对应的省略规则 | 后续内容可能被包含进强调 |

::: warning 可省略不等于可以随意省略
省略标签是 HTML 语法在特定上下文中允许的写法，不是“结束标签一律可省”。当结构复杂、需要精确定位或多人协作时，显式写出起止标签更容易核对。
:::

## 四、尾斜杠与 HTML/XML 边界

### 1. 尾斜杠不关闭普通元素

**自闭合**指一种标记在自身结束时就完成元素，而不再另写结束标签。XML 语法使用这类写法，但 HTML 普通元素不能照搬这一规则。

对于普通 HTML 元素，下面的写法不会把 `p` 关闭：

```html
<!-- 错误示例：p 不是空元素，尾斜杠不能关闭它 -->
<p />后面的文字仍会进入段落。
```

HTML 解析器不会因为这个斜杠就创建一个已经结束的空段落。即使页面仍然出现文字，也不能据此把它当作普通元素的合法替代写法。要结束段落，应写 `</p>`，或让后续内容满足 HTML 允许的段落结束条件。

### 2. 空元素上的尾斜杠

空元素可以写尾斜杠，但斜杠不改变元素性质。`<br />` 与 `<br>` 在 HTML 中都是 `br` 空元素；`<img />` 也不会因此获得子内容或结束标签。

```html
<!-- 两种写法都表示空元素；斜杠只是被忽略 -->
<br>
<br />
```

斜杠的存在与否不决定元素能否包含内容；决定它的是元素本身的定义。普通元素不会因为加了尾斜杠就变成空元素，空元素也不会因为省略斜杠就变成普通元素。

::: warning 不要把 XML 或 JSX 规则套到 HTML
XML、SVG 内部的外来元素以及 JSX 模板各有对应规则，不能根据它们支持自闭合就推导 `<div />` 或 `<p />` 在普通 HTML 中也成立。判断前先确认当前文档按哪种语法解析。
:::

## 五、独立观察与失败恢复

### 1. 创建 tags.html

新建空目录 `html-tags`，创建 `tags.html` 并以 UTF-8 保存。下面给齐文档外壳，使这个例子可以独立打开；观察重点是 `body` 中的 `p`、`br` 和 `img`，不需要先掌握其余声明。

::: details 查看 tags.html 完整内容

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>标签与元素观察</title>
</head>
<body>
  <!-- 第一段包含 br；br 是空元素，不包住“第二行文字” -->
  <p id="first">第一行文字<br>第二行文字</p>

  <!-- img 是空元素；src 使用内嵌数据地址，alt 提供替代文本 -->
  <img src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAIAAACQd1PeAAAADElEQVR4nGNgYGAAAAAEAAH2FzhVAAAAAElFTkSuQmCC" alt="黑色方块" width="16" height="16">

  <!-- 末尾段落用于确认前一段已经结束 -->
  <p>末尾段落。</p>
</body>
</html>
```

:::

图片使用完整的内嵌数据地址，不需要另外下载文件；这串地址只承担图片资源的作用，不是需要记忆的标签语法。双击 `tags.html` 或把它拖进浏览器，应看到分成两行的第一段、一块小黑色图片和末尾段落。

### 2. 观察元素与错误版本

打开页面后，按以下观察项核对：

| 观察对象 | 预期结果 | 判断依据 |
|----------|----------|----------|
| 第一段显示 | “第一行文字”和“第二行文字”分成两行 | `br` 在两者之间产生换行 |
| 图片 | 显示为一块 16×16 的黑色方块 | `img` 的 `src` 数据地址有效 |
| 图片替代文本 | Elements 中 `img` 的 `alt` 为“黑色方块” | 替代文本在属性中，不在元素内容中 |
| 第一段结构 | Elements 中文字和 `br` 都是 `p` 的子节点 | `br` 没有包住“第二行文字” |
| 末尾段落 | “末尾段落。”单独成段 | 第一个 `p` 已经结束 |

再复制为 `invalid.html`，只把 `<p id="first">` 改为 `<p id="first" />`，保留原有 `</p>`。这是有意构造的错误版本。重新打开后，段落文字仍能出现；在浏览器开发者工具的 Elements 面板中，文字与 `br` 仍属于第一个 `p`。

这说明尾斜杠没有把普通元素结束。修复时应恢复 `<p id="first">`，不要再添加另一个斜杠或凭显示结果判断语法。

### 3. 失败与恢复

| 注入的错误 | 观察 | 恢复 |
|------------|------|------|
| 把 `p` 写成 `<p />` | 后续文字仍进入段落；Nu 报告非空元素使用了自闭合语法 | 恢复 `<p>`，保留对应的 `</p>` |
| 给 `img` 写 `</img>` | 结束标签没有合法对应；图片不会因此获得内容 | 删除 `</img>`，把说明放入 `alt` |
| 把 `strong` 的结束标签省掉 | 后续内容可能被包含进强调，结构范围变大 | 补写 `</strong>`，先结束内层 |
| 把 `li` 的省略写法套到 `p` | 段落边界与预期不同 | 按元素规则补写 `</p>`，或用合法的段落结束条件 |
| 用 `<p></p>` 代替 `<br>` | 产生空段落，不产生文本内换行 | 文本内换行使用 `<br>`，段落之间使用 `p` |

出现结构差异时，先在 Elements 中看实际父子关系，再回到源码定位起止标签；不要只根据页面文字是否出现判断。

### 4. 验证记录

以上完整文件于 2026-11-14 在 macOS 的 Chrome 157.0.8103.79 中核对，并用 [Nu HTML Checker](https://validator.w3.org/nu/) 做正常与故意错误的对照。`tags.html` 的图片能解码，第一段包含 `br`；错误版本仍产生同样的段落内容，但检查器报告非空元素上使用了自闭合语法。恢复普通开始标签后，该错误消失。
