# 文档结构与页面创建

一份 HTML 文档既需要正文，也需要描述文档本身的信息。`html` 是根元素，`head` 保存标题、编码等文档信息，`body` 保存页面主体内容；文档前的 `<!doctype html>` 则让浏览器采用标准模式处理当前写法。

把这些内容保存为纯文本 `.html` 文件，就可以由浏览器打开。理解文档结构不需要先安装框架、打包器或服务器。

下面从空目录创建一个能独立打开的文件，再解释各部分职责、保存刷新流程和常见文件问题。

::: info 本篇的目标与边界
本篇完成“从空目录到可打开、可修改的页面”这条链路。编码与语言机制见[HTML 字符编码与语言声明](./08-encoding-language.md)，`head` 中的资源接入见[HTML 文档头部与资源引用](./09-head-resources.md)，浏览器如何补全和修复结构见[HTML 浏览器解析与语法检查](./10-parsing-validation.md)。本篇不引入项目工程、构建工具或服务器。
:::

## 一、从空目录到 HTML 文件

### 1. 文件、扩展名与纯文本

HTML 源码是一段文本，文件为它提供了可保存和再次打开的位置。通常使用 `.html` 扩展名，帮助编辑器、文件管理器和浏览器识别用途。文件名可以是 `hello.html`，也可以是 `index.html`；`index` 作为默认入口是服务器等工具的约定，不是 HTML 语法要求。

写代码时应使用能保存**纯文本**的编辑器。文字处理软件保存的排版文档，不能仅靠把文件名后缀改成 `.html` 就变成正确的 HTML 源码。保存时还要确认实际扩展名没有变成 `.html.txt`。

| 对象 | 例子 | 作用 | 注意 |
|------|------|------|------|
| 文件名 | `hello.html` | 保存和定位源码 | 不是浏览器标签页标题 |
| 扩展名 | `.html` | 帮助识别文件类型 | 改后缀不转换文件内部格式 |
| 编码 | UTF-8 | 让文字按一致规则保存和读取 | 保存编码与声明要一致 |
| 编辑器 | 纯文本编辑器 | 编辑源码 | 不用排版文档代替纯文本 |

::: warning 改后缀不是转换格式
把 `.txt` 或排版文档重命名为 `.html`，只改变了文件名，不会自动清理隐藏格式，也不会把其中的排版指令变成 HTML。应在新文件中以纯文本重新保存 HTML 源码，并确认实际扩展名。
:::

### 2. 一份完整的最小页面

新建空目录 `html-document`，在其中创建 `hello.html`，输入下列全部内容，以 UTF-8 编码保存。这个目录不需要预先放置其他文件。

::: details 查看 hello.html 完整内容

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <!-- 声明文件编码；文件本身也要按 UTF-8 保存 -->
  <meta charset="utf-8">

  <!-- 移动端视口声明；不是 HTML 语法必需，但常影响手机布局 -->
  <meta name="viewport" content="width=device-width, initial-scale=1">

  <!-- 文档标题，显示在标签页、书签等位置 -->
  <title>我的第一个 HTML 文件</title>
</head>
<body>
  <!-- 正文一级标题，和上面的 title 不是同一个对象 -->
  <h1>你好，HTML</h1>

  <!-- 一段正文文字 -->
  <p>这份文件可以独立打开。</p>
</body>
</html>
```

:::

这个例子采用显式写出的骨架，便于观察各部分关系。HTML 在满足条件时允许省略某些标签，但浏览器能够补全结构，不代表初次编写就需要依赖省略规则。根元素的结构定义见 [HTML：html 元素](https://html.spec.whatwg.org/multipage/semantics.html#the-html-element)。

### 3. 打开并核对

双击 `hello.html`，或把它拖进浏览器窗口。标签页应显示“我的第一个 HTML 文件”，页面正文应显示标题“你好，HTML”和一行段落文字。两处内容不同，是因为文档标题和正文标题承担不同职责。

打开后按以下观察项核对：

| 观察对象 | 预期结果 | 判断依据 |
|----------|----------|----------|
| 浏览器标签页 | 显示“我的第一个 HTML 文件” | `head` 中的 `title` |
| 页面正文 | 显示“你好，HTML”和一段说明 | `body` 中的 `h1` 与 `p` |
| 地址栏 | 指向当前 `hello.html` 的实际路径 | 浏览器读取的是这个文件 |
| 页面源码 | 能看到 `<!doctype html>` 与完整骨架 | 文件保存的是 HTML 源码 |

还可以在 Chrome 开发者工具的 Console 中逐行执行下面的只读表达式，核对当前文档实际读取的值。macOS 使用 `Option+Command+I`，Windows 通常使用 `F12` 打开工具：

```js
document.title
document.characterSet
document.documentElement.lang
```

对于原始 `hello.html`，结果依次是 `我的第一个 HTML 文件`、`UTF-8` 和 `zh-CN`。这些读数用于核对当前文件，不替代对全部 HTML 规则的检查。

::: tip 先确认地址栏中的文件
页面没有按预期变化时，先看地址栏指向哪个文件，再看编辑器是否保存了同一个文件。很多“修改没有生效”的问题来自打开了另一个副本，或修改后尚未保存，而不是 HTML 语法错误。
:::

## 二、文档各部分的分工

### 1. DOCTYPE 与浏览器模式

`<!doctype html>` 是**文档类型声明**，不是一个普通内容元素，也没有需要闭合的结束标签。它出现在根元素之前，告诉浏览器以当前 HTML 的标准模式处理文档，避免落入为历史页面保留的怪异模式。

**怪异模式**是浏览器的一种兼容处理模式，会影响某些 CSS 布局等规则。缺少声明时，页面仍能出现内容，因此不能凭“标题显示正常”来判断模式正确。当前声明的用途与写法见 [HTML：DOCTYPE](https://html.spec.whatwg.org/multipage/syntax.html#the-doctype)。

可以做一个独立对照：把 `hello.html` 复制成 `no-doctype.html`，只删除第一行，分别打开。两份文档都显示同样的文字，但渲染模式不同。

| 文件 | `document.compatMode` | 对本例的含义 |
|------|----------------------|--------------|
| `hello.html` | `CSS1Compat` | 使用本例的简短 DOCTYPE，处于标准模式 |
| `no-doctype.html` | `BackCompat` | 缺失 DOCTYPE，处于怪异模式 |

`compatMode` 只区分怪异模式与非怪异模式，不能独自区分标准模式和有限怪异模式。本例的标准模式结论还依赖实际使用的 DOCTYPE；不能将所有返回 `CSS1Compat` 的历史文档都判定成同一种模式。接口依据见 [DOM 标准：compatMode](https://dom.spec.whatwg.org/#dom-document-compatmode)。

::: warning DOCTYPE 不是特性开关
简短声明不会给旧浏览器安装新 API，也不会因为写了“HTML5 声明”就使所有新属性可用。它与页面使用哪个元素、目标浏览器是否实现该元素，是需要分别判断的事情。
:::

### 2. html 根元素与 lang

`html` 是文档的根元素，其下由 `head` 和 `body` 组织信息。示例中的 `lang="zh-CN"` 为文档声明默认内容语言，使语言相关工具能够读取这项信息；它不负责把文字翻译成中文，也不决定文件的字符编码。

内容语言和文件解码是两项配置。这里先按文档实际使用的中文声明语言，并把文件保存为 UTF-8，避免在初次创建时遗漏必要上下文。局部语言覆盖和语言标签规则见[HTML 字符编码与语言声明](./08-encoding-language.md)。

`html` 的开始标签、结束标签以及 `head`、`body` 的标签在特定条件下可以省略，浏览器会补出结构。但初次创建时显式写出，更容易看清文档边界；省略规则不能和“浏览器能显示”混为一谈。

### 3. head 与 body

`head` 中的内容不是页面顶部的一块可见横幅。它保存文档级信息和资源声明，例如标题、编码以及与外部样式表的关系。它与正文中表示页头区域的 `header` 是不同元素。

`body` 表示文档的主体内容。本例中的 `h1` 是正文一级标题，`p` 是段落，它们由浏览器按各自默认样式显示。`body` 不是“这里只能出现文字”的容器，图片、表格、表单等也可以在合适的位置组成正文。

| 部分 | 位置 | 职责 | 常见误判 |
|------|------|------|----------|
| `<!doctype html>` | 根元素之前 | 声明文档类型，触发标准模式 | 当成普通元素或版本开关 |
| `html` | 文档根 | 包含 `head` 与 `body` | 把 `lang` 当成编码声明 |
| `head` | `html` 内 | 保存标题、编码、资源声明 | 与正文的 `header` 混淆 |
| `body` | `html` 内 | 保存页面主体内容 | 认为只能放文字 |
| `title` | `head` 内 | 提供文档标题 | 与正文 `h1` 或文件名混淆 |

::: info `head` 不是 `header`
`head` 是文档级信息的容器，通常不出现在页面正文中；`header` 是正文中的页头区域，可以包含标题、导航等内容。两个词拼写相近，职责不同。
:::

## 三、创建、保存与修改

### 1. 保存后刷新

浏览器打开的是保存到文件中的内容。编辑器中已经改了文字但尚未保存时，刷新通常仍会读到旧内容；保存之后，还需要让浏览器重新读取。

可以按以下步骤确认自己编辑和查看的是同一份文件：

1. 保持浏览器打开 `hello.html`，查看地址栏，确认文件名与所在目录。
2. 在编辑器中把 `h1` 中的“你好，HTML”改为“已经修改并保存”。
3. 保存文件，再回到浏览器刷新。
4. 确认正文标题已经改变，而标签页仍显示原来的 `title`。

这项对照同时检查保存、文件位置和两种标题的职责。如果要改标签页标题，应修改 `title` 内的文字；把文件重命名或只修改 `h1`，不会自动产生同样效果。

### 2. 修改标题与正文

`title` 和 `h1` 是两处独立内容。下面的局部片段只展示它们的位置关系，完整文件仍使用前面的 `hello.html`：

```html
<head>
  <!-- 文档标题：影响标签页、书签等 -->
  <title>文档标题</title>
</head>
<body>
  <!-- 正文标题：出现在页面内容中 -->
  <h1>正文标题</h1>
</body>
```

修改 `title` 后，标签页名称会变化；修改 `h1` 后，页面正文的标题会变化。两者可以相同，也可以不同；相同不代表它们是同一个对象。

### 3. 文件名、文档标题与正文标题

| 对象 | 在哪里设置 | 主要影响 | 不负责 |
|------|------------|----------|--------|
| 文件名 | 文件系统 | 保存位置、地址栏路径 | 标签页标题、正文标题 |
| 文档标题 | `head` 中的 `title` | 标签页、书签、历史记录 | 页面正文显示 |
| 正文标题 | `body` 中的 `h1` | 页面内容中的一级标题 | 标签页名称 |
| 页面描述 | `meta name="description"` | 文档摘要信息 | 页面可见正文 |

修改文件名不会自动修改 `title`，修改 `title` 也不会自动重命名文件。排查“标签页标题不对”时，先看 `title`；排查“打开的不是这份文件”时，先看地址栏和文件名。

::: warning 文件名不是页面标题
把文件命名为 `关于我们.html`，不会让浏览器标签页自动显示“关于我们”。标签页标题来自 `title` 元素；文件名只用于定位文件。两者可以一致，但需要分别设置。
:::

## 四、常见问题与验证

### 1. 文件没有被浏览器读取

创建页面时，先确认文件确实被保存和打开，再检查标记。这样可以避免把文件路径或扩展名问题误当成语法问题。

| 现象 | 定位证据 | 修复与复测 |
|------|----------|------------|
| 打开后出现源码文字，或文件仍由文本编辑器打开 | 查看实际文件扩展名与打开方式，确认不是 `.html.txt` | 用纯文本保存为 `.html`，选择浏览器重新打开；不只改图标或显示名称 |
| 修改后仍是旧文字 | 比较编辑器保存状态与浏览器地址栏的完整位置 | 保存正确文件，再刷新同一地址；排除同名文件在其他目录的情况 |
| 标签页标题与预期不符 | 核对 `title`，不要只看文件名与 `h1` | 修改 `title` 并保存刷新，检查标签页与正文各自的结果 |
| 中文显示乱码 | 核对编辑器的实际保存编码与 charset 声明 | 把原文按 UTF-8 正确保存并保持声明一致；改声明不会转换已有文件字节 |
| 页面空白 | 查看 `body` 是否为空、文件是否保存、地址栏是否指向该文件 | 补上正文内容，保存后刷新；仍空白时检查文件路径和控制台错误 |

### 2. 结构声明不完整

| 现象 | 定位证据 | 修复与复测 |
|------|----------|------------|
| `document.compatMode` 为 `BackCompat` | 查看文件最前面是否有 DOCTYPE | 恢复 `<!doctype html>`，从原文件入口重新加载 |
| 标签页没有标题 | 检查 `head` 中是否有 `title` | 添加 `title`，保存刷新 |
| 中文乱码但 `title` 正常 | 检查实际文件编码和 `meta charset` | 按 UTF-8 重新保存，保持声明一致 |
| 页面结构被浏览器补全 | 在 Elements 中查看实际 DOM | 显式写出 `html`、`head`、`body` 的必要结构，再复检 |

这些检查只覆盖当前最小页面。浏览器显示正确，仍不能证明其他文档的任意嵌套合法；结构判断需要继续依据[HTML 元素嵌套与内容模型](./05-nesting-content-models.md)逐层核对。

::: warning 结构正确不等于资源都成功
DOCTYPE、`title` 和正文都正确，只能说明当前文档的基础结构成立。图片、样式表和脚本是否加载成功，需要看 Network 面板和实际结果；完整的资源声明见[HTML 文档头部与资源引用](./09-head-resources.md)。
:::
