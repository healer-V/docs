# 全局属性

**全局属性**是可以在 HTML 元素上通用的属性，用来声明标识、分类、补充说明、语言或交互状态等信息。`id` 和 `class` 既能写在段落上，也能写在按钮上；`href` 则有具体的适用元素，不能因为它能在链接上使用，就把它当作全局属性。

“可以通用”说明属性的适用范围，不保证它在每种元素上都有相同的可见效果。给段落添加 `class` 不会自动改变颜色，给一个没有显示内容的元素添加 `title` 也不能保证用户能得到提示。属性的具体作用还要按照元素与使用环境判断。

下面先区分全局属性与元素专属属性，再逐项说明 `id`、`class`、`title`、`style` 和 `tabindex` 的职责与边界。

::: info 本篇的范围
本篇讲全局属性的使用判断。属性的一般写法与取值类型见[HTML 属性与属性值](./03-attributes-values.md)；`lang` 和 `dir` 只在这里指出存在，完整规则见[HTML 字符编码与语言声明](./08-encoding-language.md)；`data-*`、`hidden`、`contenteditable` 等增强全局属性归第 4 章。
:::

## 一、全局属性的范围

### 1. 适用范围不等于相同效果

全局属性可以出现在多种 HTML 元素上，但“能写”不等于“写了就有相同结果”。`id` 在段落和按钮上都提供标识；`title` 在两者上都提供补充说明，但提示的呈现方式由浏览器和输入设备决定；`style` 在两者上都进入 CSS 声明，具体效果取决于声明的属性。

还有一类属性只对特定元素有定义。`href` 用于链接和资源引用，`src` 用于图片、脚本等资源元素，`colspan` 只用于表格单元格。它们不是全局属性，不能因为“写在开始标签里没有报错”就认为适用于当前元素。

| 范围 | 例子 | 作用 | 判断方式 |
|------|------|------|----------|
| 全局属性 | `id`、`class`、`title`、`style`、`tabindex`、`lang`、`dir` | 可出现在多种元素上 | 查全局属性列表和具体定义 |
| 元素专属属性 | `href`、`src`、`colspan`、`disabled` | 只在特定元素上有定义 | 查对应元素的属性表 |
| 自定义数据 | `data-*` | 携带页面自定义数据 | 归第 4 章增强全局属性 |

### 2. 常见全局属性的职责

| 属性 | 主要职责 | 使用边界 | 主讲位置 |
|------|----------|----------|----------|
| `id` | 文档内唯一标识 | 同一文档树中不能重复 | 本篇 |
| `class` | 可复用的分类令牌 | 名称本身不产生样式或行为 | 本篇 |
| `title` | 元素的补充说明 | 不能充当唯一可见标签 | 本篇 |
| `style` | 当前元素的内联 CSS 声明 | 不改变元素语义和内容模型 | 本篇 |
| `tabindex` | 焦点与顺序导航条件 | 不等于完整交互能力 | 本篇 |
| `lang` | 内容语言 | 不是编码或翻译开关 | [字符编码与语言声明](./08-encoding-language.md) |
| `dir` | 文字基本方向 | 不是逐字符反转 | [字符编码与语言声明](./08-encoding-language.md) |
| `data-*` | 自定义数据 | 不替代标准属性 | 第 4 章 |

::: tip 先问“这个属性对当前元素定义了什么”
看到一个全局属性时，不要只看它能否写进开始标签，还要看它在当前元素上是否有效、效果是否可见、是否影响语义或交互。范围通用，效果仍要逐项判断。
:::

## 二、id 与 class

### 1. id 标识一个具体元素

`id` 为元素提供标识，可以作为页面片段、标签关联、样式或脚本的目标。下面是可放在 `body` 中的局部内容：

```html
<!-- 两个段落各自有一个唯一标识 -->
<p id="summary">简要说明。</p>
<p id="detail">详细说明。</p>
```

两段文字分别用 `summary` 与 `detail` 标识。在普通页面中，需要引用第一段时，应能明确找到这个目标。因此，同一文档树中的 `id` 必须唯一；值至少有一个字符，不能包含 ASCII 空白字符，包括普通空格、制表符和换行。

`id="summary detail"` 不表示“同时具有两个标识”，而是包含空格的不合规标识。确实需要给一个元素分配多个分类，应使用 `class`。

HTML 允许数字开头等形式的 ID，并没有“只能以英文字母开头”的语法规则。不过，某些值在 CSS 选择器中需要转义。初学者可以选择 `page-title`、`summary` 这样的简单名称，减少其他语法对引用方式的影响。标识规则见 [HTML 标准：id](https://html.spec.whatwg.org/multipage/dom.html#the-id-attribute)。

### 2. class 表达可复用的分类

`class` 的值是一组以 ASCII 空白分隔的名称。多个元素可以具有相同的分类，一个元素也可以具有多个分类：

```html
<!-- note 可复用，compact 只加在第一段上 -->
<p id="summary" class="note compact">简要说明。</p>
<p id="detail" class="note">详细说明。</p>
```

第一段具有 `note` 和 `compact` 两个类，第二段具有 `note` 类。共享类可以让 CSS 或脚本把这些元素作为一组处理，但这些名称本身不会创造功能：没有对应样式或脚本时，写上 `compact` 不会自动缩小间距。

类名使用空白分隔，不使用逗号。`class="note,compact"` 是一个包含逗号的名称，不是 `note` 和 `compact` 两个类。类的先后顺序也不表示 CSS 优先级，`class="note compact"` 不能理解为“后面的 compact 一定覆盖 note”。[class 的定义](https://html.spec.whatwg.org/multipage/dom.html#classes)说明了它与分类、样式及脚本选择的关系。

### 3. 唯一与多令牌不是简单口诀

`id` 与 `class` 的区别不只是“一个唯一、一个可多个”。`id` 是文档内定位一个具体元素的标识；`class` 是一组可复用的分类令牌。一个元素可以同时拥有 `id` 和 `class`，也可以用 `class` 表达多个分类。

| 项目 | `id` | `class` |
|------|------|---------|
| 值的形式 | 单个标识 | 空白分隔的多个令牌 |
| 同一文档中的数量 | 必须唯一 | 可重复使用 |
| 常见用途 | 片段目标、标签关联、脚本定位 | 样式分组、脚本批量选择 |
| 是否自动产生行为 | 否 | 否 |
| 常见错误 | 重复 id、值中含空格 | 用逗号分隔、把顺序当优先级 |

::: warning 重复 id 不会阻止页面显示
两个元素写同一个 `id` 时，页面仍能显示，`getElementById` 通常返回文档中第一个匹配项。后续的标签关联、片段跳转或脚本定位可能指向错误元素，而且不会有醒目的运行时错误。用验证器或搜索结果核对唯一性。
:::

## 三、title 与 style

### 1. title 是补充说明

`title` 属性包含与当前元素有关的建议性说明。下面的局部片段中，正文仍然完整表达主要信息，属性只提供补充：

```html
<!-- 正文本身已经说明操作，title 只补充预览条件 -->
<p title="此说明适用于本地预览。">修改文件后需要刷新页面。</p>
```

桌面浏览器常把它显示为鼠标悬停提示，但具体呈现由浏览器决定。只有键盘、触屏或某些辅助技术的用户，不一定能方便地得到这段信息。因此，字段标签、操作名称和必需说明应在页面上明确提供，不能只放进 `title`。这是 [title 属性定义](https://html.spec.whatwg.org/multipage/dom.html#the-title-attribute)特别指出的使用边界。

`title` 属性与 `head` 中的 `title` 元素也不同：前者附着于具体元素，后者声明整份文档的标题。给段落增加 `title` 属性，不会替代浏览器标签页的文档标题。

::: warning title 不能充当唯一标签
输入框、按钮和链接的主要用途应写在可见文字或 `label` 中。只把说明放进 `title`，触屏用户、键盘用户和部分辅助技术用户可能无法获得这段信息。`title` 是补充，不是唯一入口。
:::

### 2. style 是内联 CSS 入口

`style` 属性接收 CSS 声明，通常采用“属性名、冒号、值”的写法，多项声明之间用分号分隔：

```html
<!-- 引号内是 CSS 声明，不是新的 HTML 属性 -->
<p style="color: #6f42c1; font-weight: bold;">带内联样式的文字。</p>
```

这里的 `color` 设置文字颜色，`font-weight` 设置字重。引号内是 CSS 语法，不是新增的 HTML 标签或 HTML 属性。浏览器在呈现这段文字时计算样式；段落仍然是段落，颜色变化不会改变它的语义和合法嵌套要求。

`style` 适合说明一个局部效果。多个元素需要共享样式时，可以用 `class` 关联样式规则，但类名与规则如何匹配属于 CSS 的职责，不能把 `class="note"` 当作已经声明了颜色。内联样式的定义见 [HTML 标准：style](https://html.spec.whatwg.org/multipage/dom.html#the-style-attribute)。

## 四、tabindex 与键盘焦点

### 1. 焦点与顺序导航

**焦点**表示当前接收键盘输入或操作的目标。按 `Tab` 通常会沿顺序导航路径移动焦点，`Shift+Tab` 反向移动。链接、按钮和输入控件具有各自的原生焦点行为，普通 `div` 则通常不参加这种顺序导航。

`tabindex` 可以调整元素是否可聚焦、是否参加顺序导航，以及它与其他目标的相对顺序。它要求整数值，基础用法如下：

| 写法 | 作用与边界 |
|------|------------|
| 未指定 | 由元素自身的原生行为及浏览器决定；不等于一律不能聚焦 |
| `tabindex="0"` | 让适合的元素参加通常的顺序导航，不指定一个正数优先位置 |
| `tabindex="-1"` | 通常不参加 Tab 顺序导航，但仍可由脚本等方式聚焦 |
| 正整数 | 调整顺序导航优先位置，容易让键盘顺序与内容顺序分离 |

这些值不能突破所有限制。例如，被禁用或不能呈现的元素仍有自己的焦点规则；浏览器还会考虑平台的键盘导航偏好。[HTML 标准：tabindex](https://html.spec.whatwg.org/multipage/interaction.html#the-tabindex-attribute)区分了可聚焦、顺序可聚焦等条件，不能把这几个概念当成完全相同的状态。

### 2. 正整数的顺序边界

正整数并非数值越大越先到达。在常见顺序导航中，正值按较小的数优先处理，然后才处理值为 `0` 或具有相应原生行为的目标。维护文档结构与自然导航顺序，通常比给大量元素手工排序更容易检查。

下面的顺序只是示意：`tabindex="1"` 的目标会先于 `tabindex="2"` 和 `tabindex="0"` 的目标进入 Tab 路径。这个顺序与元素在文档中的前后位置可能不同，因此容易造成键盘用户“跳着走”。

| 元素 | tabindex | 常见 Tab 顺序 | 风险 |
|------|----------|---------------|------|
| 按钮 A | `1` | 先到达 | 与视觉/阅读顺序不一致 |
| 按钮 B | `2` | 第二个到达 | 维护时容易冲突 |
| 容器 C | `0` | 之后按文档顺序到达 | 比正值目标晚 |
| 链接 D | 未指定 | 按原生行为参与 | 不应被正值目标挤乱 |

### 3. 可聚焦不等于可操作

给 `div` 添加 `tabindex="0"`，只是在这里建立焦点条件，不会自动获得按钮语义、Enter 或空格的原生激活行为。表达普通按钮操作应先使用 `button`，而不是靠焦点属性把任意容器当成完整控件。

::: warning 能聚焦不等于具有按钮行为
`tabindex` 只影响焦点条件，不提供角色、键盘激活、表单提交或状态语义。需要按钮时使用 `button`，需要链接时使用 `a`；不要用 `tabindex` 给普通容器补出一个“看起来能操作”的控件。
:::

## 五、独立观察与失败恢复

### 1. 创建 attributes.html

新建空目录 `html-global`，创建 `attributes.html`，以 UTF-8 保存以下完整内容。页面不依赖其他文件，也没有脚本。

::: details 查看 attributes.html 完整内容

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>全局属性观察</title>
</head>
<body>
  <!-- 两段共享 note 类；只有第一段有 compact 类和内联颜色 -->
  <p id="first" class="note compact" title="补充说明。"
     style="color: #6f42c1;">第一段文字。</p>
  <p id="second" class="note">第二段文字。</p>

  <!-- 三个可聚焦目标，用于观察 Tab 顺序 -->
  <button id="before" type="button">前一个按钮</button>
  <div id="zero" tabindex="0">参加顺序导航的容器</div>
  <div id="minus" tabindex="-1">不参加顺序导航的容器</div>
  <button id="after" type="button">后一个按钮</button>
</body>
</html>
```

:::

用浏览器打开页面。两段文字的 `id` 不同，`note` 类则可以共享；只有第一段通过 `style` 明确设置了文字颜色。这里的样式差异来自内联声明，不来自类名的字面含义。

在 Chrome 中按 `F12`，macOS 可按 `Option+Command+I`，打开 Elements 面板查看两段标记。`title` 的文本保存在属性中；本例不把某次鼠标提示是否出现作为所有设备的通用结果。

### 2. 核对 Tab 路径与程序化聚焦

重新加载页面，确认焦点位于页面而非地址栏或开发者工具，再连续按 `Tab`。在本例的主测环境中，三个页面目标依次为：

```text
before → zero → after
```

`minus` 没有进入这条 Tab 路径。需要核对当前目标时，在 Console 面板执行下面的只读表达式；`document.activeElement` 表示当前焦点元素，`.id` 读取其标识：

```js
document.activeElement.id
```

开发者工具本身会占用键盘焦点，观察时需把操作目标切回页面。也可以在 Console 执行以下调用，然后回到页面观察焦点；这条语句会主动改变焦点，不是只读检查：

```js
document.getElementById('minus').focus()
```

`getElementById` 按标识找到元素，`focus()` 请求聚焦该元素。调用后，页面的焦点目标可以成为 `minus`，说明“不参加 Tab 顺序导航”不等于“永远不能获得焦点”。这里使用一个 API 观察属性效果，不要求先掌握完整 DOM 编程。

| 操作 | 预期观察 | 说明 |
|------|----------|------|
| 连续按 Tab | `before → zero → after` | `minus` 不进入顺序路径 |
| 读取 `activeElement.id` | 当前焦点目标的 id | 焦点可能受开发者工具影响 |
| 调用 `minus.focus()` | 焦点可落到 `minus` | `-1` 不等于不可聚焦 |
| 检查 `zero` | 可聚焦，但没有按钮激活行为 | 焦点条件不是完整控件 |

### 3. 注入错误并恢复

把第二段的 `id="second"` 暂时改为 `id="first"`，刷新后两段文字依然能显示，但源码出现了重复标识。将文件上传到 [Nu HTML Checker](https://validator.w3.org/nu/) 可得到重复 ID 的错误；恢复为 `second` 后重新检查，不应再有这项错误。

再把 `zero` 的 `tabindex` 改为 `2`，把 `after` 的值设为 `1`。刷新并重新开始 Tab 导航，主测环境中的顺序变为 `after → zero → before`：内容最后的按钮反而先到达。删除 `after` 的 `tabindex`、把 `zero` 恢复为 `0` 后，导航顺序恢复。

| 注入的错误 | 观察 | 恢复 |
|------------|------|------|
| 两个元素使用同一个 `id` | 页面仍显示；Nu 报告重复 ID | 恢复唯一 id，检查引用目标 |
| 给后面的按钮加 `tabindex="1"` | 它先于文档中更早的目标到达 | 删除正值，回到自然顺序 |
| 给普通容器加 `tabindex="0"` | 可聚焦，但不能按按钮方式激活 | 改用 `button`，或仅用于脚本管理焦点 |
| 把 `title` 当作唯一说明 | 触屏或键盘用户可能看不到 | 把主要说明写进正文或 `label` |
