# HTML 概述

HTML 用标记描述网页内容。标题、段落、链接、图片和表单在源码中都由元素表示；浏览器读取这些标记后，生成文档结构，并为链接、表单等元素提供原生行为。HTML 文件是可保存的纯文本，不需要编译，也不要求先安装框架。

HTML 负责内容与结构，不负责全部视觉样式，也不提供通用计算能力。理解这一点，需要把三件事分开：内容被标记成什么、浏览器默认怎样显示、页面还需要什么额外行为。

下面从文档共享和超文本开始，再说明 HTML 的能力、它与 CSS、JavaScript 的分工，以及 HTML5 与现行标准的关系。

::: info 本篇的范围
本篇只建立 HTML 的整体认识；标签与元素语法见[HTML 标签与元素](./02-tags-elements.md)，属性规则见[HTML 属性与属性值](./03-attributes-values.md)，页面创建见[HTML 文档结构与页面创建](./04-document-structure.md)。HTML5 各元素和 API 的完整用法在第 4—7 章展开。
:::

## 一、文档共享与超文本

### 1. 从文档共享到标记

Web 最初服务于科学工作者之间的信息共享：不同地点的人需要阅读文档，并从一份资料找到另一份相关资料。HTML 用标记描述文档，用链接连接文档，成为 Web 的基础语言之一。这一背景可参照 [CERN：Web 简史](https://home.cern/science/computing/the-birth-of-the-web/short-history-web/)。

“标记”是为内容说明身份。下面是可以放在页面正文中的两个独立片段，暂不包含完整文档外壳：

```html
<!-- p 把文字标记为段落 -->
<p>这是一段说明。</p>

<!-- a 把文字标记为链接，href 指明目标地址 -->
<a href="https://html.spec.whatwg.org/">阅读 HTML 标准</a>
```

`p` 把文字标记为段落；`a` 把文字标记为链接。**超文本**指通过链接关联其他内容的文本，阅读者不必只按一份文档的固定顺序阅读。链接可以指向另一份文档，也可以指向同一文档中的位置。

| 概念 | 含义 | 在 HTML 中的表现 |
|------|------|------------------|
| 标记 | 为内容附加身份和结构 | 用标签包围文字，如 `<p>...</p>` |
| 元素 | 开始标签、内容和结束标签组成的结构单位 | 一个段落、链接或图片 |
| 超文本 | 通过链接关联其他文档或位置 | `a` 元素与 `href` 属性 |
| 语义 | 元素所表达的内容含义 | `h1` 表示标题，不只是“大字” |

这些片段只说明标记的作用，不构成完整页面。浏览器看到 `p` 会把它当作段落处理，看到 `a` 会提供链接的导航行为；两者的默认外观不同，但外观不是它们唯一的区别。

::: tip 标记不是排版指令
用 `h1` 不只是把文字变大；标题的层级和含义由元素表达，字号可以由 CSS 改变。判断用哪个元素，先看内容是什么，而不是看浏览器默认把它显示成什么样。
:::

### 2. 声明式写法与浏览器读取

HTML 的写法以**声明**为主：作者说明内容是什么、具有哪些属性，由浏览器按规则解析和呈现。HTML 不提供通用变量、循环和函数来编写计算程序；需要自定义计算或交互逻辑时，通常使用 JavaScript。

因此，HTML 是标记语言，不是通用编程语言。它能够描述文档结构和一部分原生行为，但不能单独完成任意计算。这个边界不影响它作为网页基础的地位：结构、资源和原生控件首先由 HTML 表达。

| 技术 | 作者提供 | 浏览器或运行环境负责 |
|------|----------|----------------------|
| HTML | 内容身份、结构、属性 | 解析标记，建立 DOM，提供链接和表单等原生行为 |
| CSS | 选择器与样式声明 | 计算样式、布局和绘制 |
| JavaScript | 语句、函数和事件处理 | 执行计算，读写 DOM、样式和网络 |

页面能够显示，也不代表所有标记都合法。浏览器会对部分错误执行容错处理，把源码修补成可显示的文档；判断结构是否正确，需要查看源码和 DOM，不能只看页面外观。

::: warning 能显示不等于结构正确
浏览器不会因为每一处作者错误都拒绝显示页面。把 `td` 直接写在 `table` 下，或把块级元素放进段落，页面可能仍然出现内容，但 DOM 中的结构已经被解析器调整。完整判断方法见[HTML 浏览器解析与语法检查](./10-parsing-validation.md)。
:::

## 二、HTML 能表达什么

### 1. 文本与页面结构

HTML 可以组织标题、段落、列表、强调文字和链接，也可以把页面划分为不同的内容区域。元素让内容带上身份：浏览器和辅助技术不必只靠字号或位置猜测“这是一段标题”还是“这是一段正文”。

```html
<!-- h1 表示当前页面的一级标题 -->
<h1>产品说明</h1>

<!-- p 表示一段相关文字；a 在本段中建立链接 -->
<p>这是一段介绍，包含一个<a href="details.html">详细说明</a>。</p>
```

打开后，`h1` 通常显示得比正文更大、更粗，`a` 通常带下划线并可点击。改变 CSS 后，字号、颜色和下划线都可能变化；`h1` 仍是标题，`a` 仍是链接。

| 内容 | 常用元素 | 表达的含义 |
|------|----------|------------|
| 标题 | `h1`—`h6` | 标题及其层级 |
| 段落 | `p` | 一段相关的文字 |
| 列表 | `ul`、`ol`、`li` | 无序或有序的项目集合 |
| 链接 | `a` | 指向另一个资源或文档位置 |
| 强调 | `strong`、`em` | 重要内容或语气强调 |

这些元素的具体用法在第 2 章展开。这里先建立一个判断：元素首先表达内容角色，默认样式只是浏览器给出的一种常见呈现。

### 2. 资源、表单与嵌入

HTML 也能声明图片、音视频、表格、表单和嵌入文档。资源元素通过属性指向外部文件；表单元素把输入控件组织成一组字段，并提供提交行为；嵌入元素把另一份文档或图形放进当前页面。

| 内容类型 | 元素示例 | 浏览器提供的能力 |
|----------|----------|------------------|
| 图片 | `img` | 加载并显示图片，提供替代文本 |
| 音视频 | `audio`、`video` | 播放媒体资源，显示原生控件 |
| 表格 | `table`、`tr`、`th`、`td` | 表达行列数据和表头关系 |
| 表单 | `form`、`input`、`button` | 收集字段并提交请求 |
| 嵌入 | `iframe`、`canvas`、`svg` | 嵌入文档或绘制图形 |

这些能力并不都要求 JavaScript。链接跳转、原生表单提交、部分开合行为可以由 HTML 元素和浏览器直接处理；在写脚本之前，先确认是否已有合适的原生元素。

::: tip 原生能力优先
用 `div` 画一个按钮，不会自动获得按钮的键盘操作、表单提交和状态语义。需要按钮时先用 `button`，需要链接时先用 `a`，再考虑用 CSS 调整外观。原生元素提供的不仅是默认样式。
:::

### 3. 语义与默认外观

**语义**是元素代表的内容含义。`h1` 表示标题，`strong` 表示重要内容，`em` 表示语气强调；这些含义不会因为 CSS 把字号改小或把字重改轻而消失。`div` 和 `span` 是通用容器，本身不表示专门的内容角色。

| 元素 | 常见默认外观 | 语义 | CSS 能否改变外观 |
|------|--------------|------|------------------|
| `h1` | 大号、加粗 | 一级标题 | 能；标题含义不变 |
| `strong` | 加粗 | 重要内容 | 能；重要性不变 |
| `em` | 斜体 | 语气强调 | 能；强调含义不变 |
| `div` | 块级盒子 | 通用容器 | 能；仍没有专门语义 |
| `span` | 行内容器 | 通用容器 | 能；仍没有专门语义 |

判断元素时，先问“这段内容在文档中承担什么角色”，再问“浏览器默认怎样显示”。反过来按默认样式选元素，容易把外观当成语义。

::: warning 不要按默认样式选元素
看到文字变大就选 `h1`，看到加粗就选 `strong`，会把外观当成内容角色。标题的层级、强调的程度和容器的用途都要根据内容判断；外观交给 CSS。
:::

## 三、HTML、CSS 与 JavaScript 的分工

### 1. 同一段文字的三种操作

同一段说明文字，可以同时涉及内容、显示和行为三种需求。下面的片段分别属于 HTML、CSS 和 JavaScript；合在一起可以运行，但这里只用它们区分职责，不展开三种语言的完整语法。

```html
<!-- HTML：声明这是一段说明 -->
<p class="notice">这是一段说明。</p>
```

```css
/* CSS：改变这段说明的显示样式 */
.notice {
  color: navy;
}
```

```js
// JavaScript：读取并更新这段文字
const notice = document.querySelector('.notice');
notice.textContent = '更新后的说明。';
```

HTML 片段声明了一个段落及其类名；CSS 片段根据类名改变文字颜色；JavaScript 片段找到这个段落并替换文字。三者可以组合，但不能互相替代。

| 技术 | 主要负责 | 不负责 | 对同一段文字的操作 |
|------|----------|--------|--------------------|
| HTML | 内容含义、结构和原生行为 | 完整视觉设计、通用计算 | 声明这是一个段落 |
| CSS | 显示、布局和视觉状态 | 内容含义、数据计算 | 改变文字颜色和排版 |
| JavaScript | 计算、自定义交互和数据变化 | 替代文档结构 | 读取并更新段落文字 |

颜色变化不需要重新定义段落含义，更新文字也不意味着 HTML 中必须存在循环或赋值语法。判断职责时，看谁定义了这个结果，而不是看代码写在哪个文件里。

### 2. 职责边界与常见误判

| 现象 | 实际负责 | 判断方法 |
|------|----------|----------|
| 文字变成红色 | CSS | 查看匹配的选择器和声明 |
| 点击文字后跳转 | HTML 链接与浏览器 | 查看 `a` 元素和 `href` |
| 点击按钮后计算总价 | JavaScript | 查看事件处理和计算代码 |
| 页面出现大号标题 | HTML 元素与 CSS 外观 | 查看元素语义，不只看字号 |
| 表单提交到服务器 | HTML 表单与浏览器 | 查看 `action`、`method` 和控件 |

一个页面可以只使用 HTML，CSS 和 JavaScript 是可选的增强。反过来说，使用了 CSS 或 JavaScript 也不会改变 HTML 元素的基本含义；它们可以改变呈现和行为，但内容角色仍由标记表达。

::: info 职责不是隔离
三种技术可以协作：JavaScript 可以修改 DOM 和样式，CSS 可以隐藏内容，HTML 也可以包含脚本。判断职责时，关注“谁定义了这个结果”，不要把文件类型或代码位置当成唯一依据。
:::

## 四、HTML5 与现行标准

### 1. HTML5 是演进阶段

HTML 是这门语言的总称，HTML4、HTML5 是其演进中的版本名称。HTML5 在继承已有内容的基础上，扩展了文档语义、表单、媒体与图形等能力，并细化了浏览器处理规则。它与 HTML 的关系不是两门语言之间的替换关系。

相对 HTML4，可以用几类变化建立整体认识：

| 变化 | 代表内容 |
|------|----------|
| 常用声明简化 | 简短的 `<!doctype html>` 与 `<meta charset="utf-8">` 写法 |
| 内容和原生能力扩展 | 页面结构元素、新输入类型、音视频元素与 Canvas 等 |
| 规则与旧写法调整 | 更明确的解析规则；`font`、`center` 等表现类旧元素不再作为合规写法使用，相关外观交给 CSS |

这张表概括的是历史演进，不是完整新增清单；各项差异的历史依据见 [W3C：HTML5 与 HTML4 的差异](https://www.w3.org/TR/2014/NOTE-html5-diff-20141209/)。

“HTML5”在资料中也常被用来统称一组 Web 技术，其中包含需要 JavaScript 调用的接口，部分能力由独立规范定义。因此，“支持 HTML5”不足以说明某一个元素、属性或 API 在目标浏览器中可用，也不能把今天出现的全部新能力都算成最初 HTML5 的新增内容。

::: warning “支持 HTML5”不是可执行的判断
这个说法没有说明具体元素、属性或 API。判断某个能力是否可用，要查对应特性的标准和浏览器支持情况；不能因为页面写了简短的 DOCTYPE，就认为所有新能力都已安装。
:::

### 2. Living Standard 与浏览器支持

HTML5 的 W3C Recommendation 于 2014 年发布，它是一个版本快照；WHATWG 维护的 [HTML Living Standard](https://html.spec.whatwg.org/multipage/introduction.html#is-this-html5?) 则持续更新。现行语法和行为应以 Living Standard 为依据，历史文档用于理解版本来源。

| 资料 | 性质 | 适用判断 |
|------|------|----------|
| WHATWG HTML Living Standard | 持续维护的现行标准 | 当前元素、属性、解析规则 |
| W3C HTML5 Recommendation（2014） | 历史版本快照 | HTML5 的范围与历史差异 |
| 浏览器兼容资料 | 具体实现情况 | 目标浏览器是否支持某项特性 |

浏览器支持是另一项判断。标准定义了元素和属性的行为，不代表每个浏览器版本都已经实现，也不代表实现没有差异；具体支持情况要在目标环境中核对。

::: info 版本判断的边界
本篇只建立 HTML5 与现行标准的关系，不列全部版本差异。具体元素和 API 的版本边界在对应章节登记；历史资料可以用来解释来源，不能代替现行规则。
:::

## 五、常见误判与判断

| 误判 | 为什么不对 | 正确处理 |
|------|------------|----------|
| HTML 是编程语言 | HTML 是声明式标记语言，不提供通用变量、循环和函数 | 用 HTML 表达结构，计算和自定义逻辑交给 JavaScript |
| 默认外观就是语义 | CSS 可以改变外观，元素的含义仍由标记决定 | 按内容角色选元素，再用 CSS 调整外观 |
| 页面能显示就说明 HTML 正确 | 浏览器会执行容错和结构修补 | 查看源码、DOM，必要时使用检查器 |
| HTML5 是另一门语言 | HTML5 是 HTML 的演进阶段 | 说“HTML 的 HTML5 阶段”或具体能力 |
| 支持 HTML5 就等于所有特性可用 | 这个说法没有指定具体特性 | 查具体元素、属性或 API 的兼容性 |

判断 HTML 用法时，可以按这个顺序检查：内容在文档中是什么角色，浏览器是否已经提供对应的原生元素和行为，最后才考虑用 CSS 或 JavaScript 补充显示和计算。

::: info 资料来源与验证边界
本篇为概念文章，不包含需要运行的完整示例。HTML5 与 HTML4 的差异参考 W3C 的版本差异文档，现行规则参考 WHATWG HTML Living Standard；文中不承诺具体浏览器对某个新特性的支持，相关判断在对应章节用实际环境核对。
:::
