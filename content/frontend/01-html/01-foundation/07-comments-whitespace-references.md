# 注释、空白与字符引用

HTML 源码里的字符不一定原样出现在页面上。注释用于记录源码说明，普通空白参与文本处理，而 `&lt;` 这样的**字符引用**会在解析时转换成对应字符。区分这三种机制，才能解释“源码里明明有文字，页面却没有显示”，以及“写了标签文字，却生成了一个元素”等现象。

这些差异还说明：编辑器中的源码、DOM 中的文本节点、浏览器实际绘制的文字是三种观察对象。排查显示问题时，需要先确定自己在看哪一层，再决定是改源码、改 CSS，还是只是读取方式不对。

::: info 本篇的范围
本篇讲注释、空白处理和字符引用的基础规则，并用一个独立文件对照源码与显示。`pre` 的完整内容模型与代码排版见第 2 章的预格式化文本文章；CSS 的 `white-space` 属性属于 CSS 的排版规则，本篇只指出它会改变呈现结果。
:::

## 一、注释的写法与边界

### 1. 注释不进入页面正文

HTML 注释以 `<!--` 开始，以 `-->` 结束。下面是可以放进文档 `body` 的局部内容：

```html
<!-- 此说明留给阅读源码的人。 -->
<p>页面上的说明文字。</p>
```

浏览器会识别注释，不把它的内容当作普通正文绘制。查看网页源码，或在开发者工具的 Elements 面板查看文档树，仍然能够找到这段注释。注释节点在 DOM 中存在，只是默认不产生可见文字。

| 观察位置 | 是否能看到注释文字 | 说明 |
|----------|--------------------|------|
| 页面正文 | 否 | 注释不作为可见内容绘制 |
| 查看网页源代码 | 是 | 源码保留注释界定符和内容 |
| Elements 面板 | 是 | DOM 中存在注释节点 |
| 页面打印结果 | 通常否 | 与正文绘制条件一致 |

### 2. 注释不能嵌套

注释也不能任意嵌套。以下是错误的局部标记：

```html
<!-- 错误示例：外层 <!-- 内层 --> 外层结尾 -->
<p>正文。</p>
```

中间的 `<!--` 不会建立一个可以独立闭合的内层注释。浏览器会按注释解析规则处理输入，原本想放进“外层”的结尾文字会跑到注释之外。修复时把说明合并进一个合法注释，或拆成两个平级注释，而不是继续增加界定符。

注释正文还有针对界定符序列的限制。按作者语法，注释文本不能包含 `<!--`、`-->` 或 `--!>`，也不能以 `<!-` 结尾等容易与结束界定符混淆的序列。若要向读者展示这些符号，应放在普通文本中并使用字符引用，而不是再嵌入一层注释。完整语法见 [HTML 标准：注释](https://html.spec.whatwg.org/multipage/syntax.html#comments)。

### 3. 注释会随文档到达浏览器

注释不承担保密作用。账号、密钥、内部接口信息和不应交付给访问者的内容，不应因为“正文看不到”就保留在注释中。注释不会成为页面正文，不等于它没有随页面一起到达浏览器；查看源代码、抓取响应或读取 DOM 都能取得它。

::: warning 注释不是保密区域
把敏感信息写进 HTML 注释，只是让它不显示在页面上。源码仍会发送到客户端，也可能进入缓存、日志或版本记录。需要保密的数据应留在服务端，并通过权限控制决定是否返回。
:::

## 二、源码空白与页面空白

### 1. 默认显示会折叠普通空白

HTML 源码中的空格、制表符和换行可以参与文本内容。普通段落在浏览器默认样式下，会按 CSS 的空白处理规则显示它们；连续普通空格不一定对应同样数量的可见空格，源码换行也不直接等于页面换行。

用拉丁字母观察这种处理较容易避免中文断行规则的干扰。下面是局部标记，其中 A 与 B 之间有三个普通空格，B 与 C 之间有源码换行：

```html
<p>A   B
C</p>
```

在足够宽的页面中，默认显示为 `A B C`。这并不表示 HTML 解析器把源码里的三个空格和换行全部删除了：文本节点仍可以保留它们，呈现时再经过空白折叠与行布局。文档内某些位置的空白另有 HTML 解析规则，也不能反过来声称所有源码空白都会无条件保留。

空白处理还与语言、所在位置和 CSS 设置有关；不能把这段拉丁文本的结果推广成“任何换行总是转换为一个空格”。这里解释的是普通段落的默认呈现条件，具体机制依据见 [CSS Text：空白处理](https://www.w3.org/TR/css-text-3/#white-space-processing)。

### 2. 元素之间的空白也是文本

以下两段局部内容的差异，只是 `span` 之间有没有空白：

```html
<p><span>A</span><span>B</span></p>
<p><span>A</span>
<span>B</span></p>
```

在默认显示下，第一段是 `AB`，第二段是 `A B`。换行位于两个元素之间，仍然会形成需要处理的文本空白。格式化源码时随意添加或删除这类空白，可以改变段内内容，不能一概当作“只影响源码美观”。

| 源码写法 | 元素之间的空白 | 默认可见结果 |
|----------|----------------|--------------|
| `<span>A</span><span>B</span>` | 没有 | `AB` |
| `<span>A</span> <span>B</span>` | 一个空格 | `A B` |
| 两个 `span` 之间换行 | 换行及缩进 | 通常折叠为一个可见间隔 |
| 注释隔开两个 `span` | 注释不是文本，但注释两侧的空白仍可能存在 | 取决于两侧实际空白 |

### 3. pre 保留格式，但仍解析 HTML

`pre` 表达预先排好格式的文本，浏览器默认样式会保留其中普通空格与换行的显示：

```html
<pre>A   B
C</pre>
```

这里 A 与 B 的多个空格会显示出来，C 则从下一行开始。实际空白策略仍能被 CSS 改写；`pre` 也不是让 HTML 解析完全停止的“原文容器”。要在其中显示 `<p>` 字样，仍应写成 `&lt;p&gt;`。

还有一个与示例复制有关的细节：紧接 `pre` 开始标签的首个换行会被 HTML 解析规则忽略。需要观察精确文本时，像上例一样把 A 紧接开始标签，便不会把排版换行误认为需要保留的首行内容。[pre 的定义](https://html.spec.whatwg.org/multipage/grouping-content.html#the-pre-element)说明了这项特殊处理。

## 三、字符引用的形式

### 1. 标记符号与普通文字要区分

HTML 用 `<` 等字符识别标记。想显示“`<p>` 是段落标签”时，不能直接依赖浏览器把 `<p>` 当普通文字。以下局部标记表达的才是标签字样：

```html
<p>&lt;p&gt; 是段落标签。</p>
```

解析完成后，`&lt;` 转换为字符 `<`，`&gt;` 转换为字符 `>`，页面显示 `<p> 是段落标签。`，不会再把转换后的 `<p>` 当成一个新元素重新解析。

常用写法可以按用途查询，不必背诵整张字符表：

| 写法 | 对应字符 | 常见用途 |
|------|----------|----------|
| `&lt;` | `<` | 显示标记开头等字面文字 |
| `&gt;` | `>` | 完整显示尖括号包围的标记字样 |
| `&amp;` | `&` | 表达与号，避免与字符引用混淆 |
| `&quot;` | `"` | 在双引号包围的属性值中表达双引号 |
| `&apos;` | `'` | 在单引号包围的属性值中表达单引号 |
| `&nbsp;` | 不间断空格 U+00A0 | 保留不希望普通断行的位置 |

`>` 在许多普通文本位置可以直接写，字符引用并不是要求把所有标点都替换掉。更实用的判断是：当前位置的字面字符是否会被当成标记、属性界定符或字符引用开头。下面的局部属性值使用 `&quot;`，避免中间的引号提前结束外层属性：

```html
<p title="使用 &quot;引号&quot; 与 &amp;">查看属性文字。</p>
```

::: tip 字符引用按所在上下文使用
优先直接编写可正确保存的 UTF-8 文字。需要表达标记符号或属性界定符时，再选择相应字符引用。它是 HTML 源码中的字符写法，不是把整份文件从一种编码转换成另一种编码的方法。
:::

### 2. 命名形式与数字形式

`&copy;` 是命名字符引用，名称对应版权符号。数字形式则写出 Unicode 字符的编号：

```html
<p>© / &copy; / &#169; / &#xA9;</p>
```

这四种写法得到同一个字符 `©`。`&#169;` 使用十进制编号，`&#xA9;` 使用十六进制编号，`x` 表示后面的数字采用十六进制。编号对应字符，不是该字符在 UTF-8 中的某一个字节值。

每个引用都写到分号结束。HTML 为兼容旧内容允许部分命名形式省略分号，但不同上下文并不完全一致，名称后的字母、数字或等号还会影响属性值中的处理。作者应使用完整写法，避免把 `&copy` 等不完整序列当作可以普遍依赖的规则。[HTML 标准：字符引用](https://html.spec.whatwg.org/multipage/syntax.html#character-references)给出了命名和数字形式的要求。

### 3. 分号、属性值与不间断空格

在属性值中，字符引用同样会被解释，但结束边界更容易被忽略。`title="A &copy B"` 没有分号时，后续空格可能使解析器采用兼容匹配；`title="A &copy; B"` 则明确以分号结束。作者写法应保留分号，避免依赖浏览器的兼容处理。

`&nbsp;` 对应的不是普通空格 U+0020，而是 U+00A0。不间断空格在通常的文本处理中不按普通空白折叠，并阻止相应位置的普通断行。连续写很多个 `&nbsp;` 只是向内容添加多个这种字符，不是声明列宽或对齐；页面布局应交给 CSS。

::: warning 不要把字符引用当排版工具
用一串 `&nbsp;` 制造缩进或列间距，会让文本内容混入大量不可见字符，复制、搜索和响应式布局都可能受影响。缩进、间距和对齐应使用 CSS；字符引用只负责表达字符本身。
:::

## 四、独立对照源码、文本与显示

### 1. 创建 notes.html

新建空目录 `html-text`，在其中创建以下 `notes.html`，以 UTF-8 保存。完整文件不依赖外部样式、脚本或素材。

::: details 查看 notes.html 完整内容

```html [notes.html]
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>注释、空白与字符引用</title>
</head>
<body>
  <!-- 这条说明留在源码中。 -->
  <p id="normal">A   B
C</p>
  <pre id="kept">A   B
C</pre>
  <p id="literal">显示 &lt;p&gt; 与 A &amp; B。</p>
  <p id="numbers">© / &copy; / &#169; / &#xA9;</p>
  <p id="space">A&nbsp;B</p>
  <p id="attribute" title="使用 &quot;引号&quot; 与 &amp;">属性中的字符引用</p>
</body>
</html>
```

:::

用浏览器打开文件。注释不出现在正文；普通段落显示 `A B C`；`pre` 保留多个空格与换行；`literal` 段落显示尖括号和与号；四个版权符号相同。

| 观察对象 | 预期现象 | 原因 |
|----------|----------|------|
| 第一条注释 | 正文不可见 | 注释节点不参与可见文字绘制 |
| `normal` 段落 | 显示为 `A B C` | 默认空白折叠 |
| `kept` 段落 | 保留多个空格和换行 | `pre` 的默认空白处理 |
| `literal` 段落 | 显示 `<p>` 字样 | 字符引用在解析后成为普通字符 |
| `numbers` 段落 | 四个版权符号 | 命名和数字形式指向同一字符 |
| `space` 段落 | `A` 与 `B` 之间为不间断空格 | `&nbsp;` 不是 U+0020 |

### 2. 用源码与文本读数解释现象

在 Chrome 中打开开发者工具，Elements 面板可以看到注释与文本结构。Console 中可执行以下只读表达式：`getElementById` 找到相应元素，`textContent` 读取文本内容，`innerText` 按当前呈现条件读取文字。

```js
document.getElementById('normal').textContent
document.getElementById('normal').innerText
document.getElementById('kept').innerText
document.getElementById('literal').textContent
```

以上文件于 2026-11-14 在 macOS 的 Chrome 157.0.8103.79 中核对。为清楚表示换行，表格使用 `\n` 记号表示实际换行字符，不表示正文里出现反斜杠和字母 n。

| 观察项 | 本例结果 |
|--------|----------|
| `normal.textContent` | `A   B\nC` |
| `normal.innerText` | `A B C` |
| `kept.innerText` | `A   B\nC` |
| `literal.textContent` | `显示 <p> 与 A & B。` |

这组差异证明源码中的空白没有因为页面只显示一个间隔就全部消失。文本读数和可见效果属于不同的观察对象；改变 CSS 后，呈现相关读数也应重新核对。

`textContent` 读取节点中的文本数据，通常保留源码里进入文本节点的空白和换行；`innerText` 更接近浏览器当前呈现的文字，会受到布局、显示状态和空白处理影响。两者都不能单独代表“源码原样”，也不能把所有读数差异都解释成 HTML 语法错误。

### 3. 修复被误解析的标记或注释

将 `literal` 段落中的 `&lt;p&gt;` 改成直接写的 `<p>`，原本要显示的标记会参与元素解析，页面结构与预期文字都发生变化。本例中，原段落会提前结束，`literal.textContent` 只剩下 `显示 `。查看 Elements 和 [Nu HTML Checker](https://validator.w3.org/nu/) 的报告后，恢复字符引用并重检。

再把完整文件里的注释改成前面展示的嵌套注释错误，原本应藏在说明中的部分结尾会出现在正文中。恢复为单条完整注释，刷新后确认这部分不再显示，并查看源码中的界定符是否已经配对。

本例原始文件经 Nu 检查无错误、无警告；嵌套注释版本报告注释内部出现 `<!--` 的错误。直接写 `<p>` 的版本则没有检查器错误：它可以形成合法段落，却没有表达作者想显示的字面文字。检查器能检查标记规则，不能替作者判断表达意图，因此还必须对照页面和文本结果。

| 注入的错误 | 观察 | 恢复 |
|------------|------|------|
| 把 `&lt;p&gt;` 写成 `<p>` | 产生新段落，原段落提前结束 | 恢复字符引用，核对显示文字 |
| 在注释中再写 `<!--` | 注释提前结束，部分文字进入正文 | 合并为一条注释或拆成平级注释 |
| 用多个 `&nbsp;` 做缩进 | 文本混入 U+00A0，布局难以维护 | 改用 CSS 设置间距 |
| 只看页面显示判断空白 | 无法区分文本节点与实际呈现 | 对照 `textContent`、`innerText` 和元素结构 |
