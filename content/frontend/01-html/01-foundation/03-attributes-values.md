# 属性与属性值

**属性**是写在元素开始标签中的配置信息，用来说明资源地址、标识、方向或状态等内容。**属性值**的含义由具体属性定义：有的接受文字，有的只接受特定关键词，还有的通过属性是否存在来表示状态。

因此，不能把所有属性都按普通字符串或 `true`、`false` 统一理解。写法正确之后，还需要检查该属性是否适用于当前元素，以及值是否满足对应规则。

下面先看属性的位置和组成，再按引号、布尔属性、枚举与其他值类型逐类判断，最后用独立文件观察属性缺失和错误字符串的实际结果。

::: info 本文的范围
本篇讲属性的一般写法与取值类型。`id`、`class`、`title`、`style`、`tabindex` 等常用全局属性的完整职责见[HTML 全局属性](./06-global-attributes.md)；语言与方向机制见[HTML 字符编码与语言声明](./08-encoding-language.md)；输入控件的完整行为归第 3 章。本篇只就地解释观察属性所需的最少控件含义。
:::

## 一、属性的位置与组成

### 1. 属性写在开始标签内

下面是可以放在页面正文中的局部标记。`p` 表示段落，`title` 为它提供一段补充说明：

```html
<!-- title 位于 p 的开始标签内，不是正文内容 -->
<p title="补充说明">正文文字。</p>
```

属性名是 `title`，等号后引号中的内容是属性值。它写在 `p` 的开始标签中；“正文文字。”仍是元素内容，不会因为有属性就被替换。结束标签 `</p>` 不能携带这组属性。

同一开始标签可以包含多个不同属性，属性之间以空白分隔：

```html
<!-- id、class、title 是三个不同的属性 -->
<p id="note" class="compact" title="补充说明">正文文字。</p>
```

这里 `id`、`class`、`title` 各自承担一种配置职责。交换它们的书写顺序，不应改变这几个配置本身的意义；把多个属性拼成一个没有分隔的字符串则不是同一写法。语法依据见 [HTML：属性写法](https://html.spec.whatwg.org/multipage/syntax.html#attributes-2)。

| 组成部分 | 写法示例 | 作用 | 边界 |
|----------|----------|------|------|
| 属性名 | `title` | 指定要配置的项目 | 名称由属性定义，不是任意自造的词 |
| 等号 | `=` | 分隔名称和值 | 布尔属性可以省略名称和值 |
| 属性值 | `"补充说明"` | 提供具体配置 | 值的类型由属性定义 |
| 属性之间的空白 | 空格或换行 | 分隔多个属性 | 不能把两个属性粘在一起 |

### 2. 属性的顺序与重复

属性顺序通常不影响含义，但同一开始标签不能重复同名属性。下面的片段不是为段落设置两个标题，也不是合并配置：

```html
<!-- 错误示例：同一开始标签重复 title -->
<p title="第一项" title="第二项">正文。</p>
```

HTML 作者语法不允许同一个开始标签中出现重复的同名属性。不能依靠浏览器保留其中哪一个值来决定业务逻辑；修复时应整理为一个符合目的的属性值。多个类名应写入同一个 `class` 值，而不是重复写两个 `class` 属性。

### 3. 全局属性与元素专属属性

属性还存在适用范围。**全局属性**可以用于 HTML 元素，具体效果仍取决于属性和元素；另一些属性只对特定元素有定义。例如，`src` 用于图片等资源元素，不是给任意段落加入图片的通用开关。

| 范围 | 例子 | 说明 | 判断方式 |
|------|------|------|----------|
| 全局属性 | `id`、`class`、`title`、`style` | 可用于多种元素，具体效果按属性定义 | 查全局属性列表和当前元素 |
| 元素专属属性 | `href`、`src`、`disabled`、`colspan` | 只在特定元素上有定义 | 查对应元素的属性表 |
| 自定义数据 | `data-*` | 用于携带页面自定义数据 | 完整规则见增强全局属性 |

浏览器能在源码中保留一个不适用的属性，也不代表这组标记符合作者要求。属性写在开始标签中只是语法位置正确，是否适用还要继续核对。

::: tip 先查属性属于哪个元素
看到一个属性时，先确认它是否适用于当前元素，再检查值的类型。`src` 写在 `img` 上有资源地址的含义，写在 `p` 上不会自动让段落变成图片。属性名相似，不代表可以跨元素通用。
:::

## 二、引号与特殊字符

### 1. 单引号与双引号都能界定值

HTML 支持单引号和双引号形式。下面两个局部片段为 `title` 提供相同的文字：

```html
<!-- 两种引号都能界定同一个属性值 -->
<p title="两段 文字">正文。</p>
<p title='两段 文字'>正文。</p>
```

引号把其中的空格保留在同一个属性值内。引号本身是源码的边界符号，不属于最终的 `title` 文字。通常统一采用一种引号风格，有助于识别边界；这不是说另一种引号不合法。

| 写法 | 示例 | 合法条件 | 注意 |
|------|------|----------|------|
| 双引号 | `title="两段 文字"` | 值中不再直接出现双引号 | 值内的双引号用 `&quot;` 或外层改用单引号 |
| 单引号 | `title='两段 文字'` | 值中不再直接出现单引号 | 值内的单引号用 `&#39;` 或外层改用双引号 |
| 无引号 | `id=note` | 值非空，且不含空白、引号、反引号、等号、尖括号 | 只适合简单值，容易产生边界歧义 |

### 2. 无引号值的限制

HTML 也允许满足条件的非空值不加引号，但值中不能包含空白、引号、反引号、等号或尖括号等受限字符。不能因为 `id=note` 能工作，就认为任意一句文字都可以直接写在等号之后。

下面是有意构造的错误片段：

```html
<!-- 错误示例：空格结束了无引号 title 的值 -->
<p title=两段 文字>正文。</p>
```

浏览器会把 `title` 读为“两段”，随后把“文字”当成另一个属性名，而不是保留整句说明。修复时应写成 `title="两段 文字"`。统一为属性值添加引号，可以直接避免这一类边界歧义。

### 3. 值中的引号与字符引用

如果值中需要包含当前使用的引号，可以换用另一种外层引号，或使用相应的字符引用。下面的 `&quot;` 表示值中的双引号：

```html
<!-- &quot; 在解析后成为值中的双引号 -->
<p title="包含 &quot;引号&quot; 的说明">正文。</p>
<p title='包含 "引号" 的说明'>正文。</p>
```

这里要区分源码写法与浏览器得到的值：前一个片段中的字符引用被解释后，`title` 中包含的是双引号，不是 `&quot;` 这六个字符。字符引用的完整规则见[HTML 注释、空白与字符引用](./07-comments-whitespace-references.md)。

::: warning 引号不是可省略的装饰
无引号写法只在值满足限制时成立。值里有空格、引号、等号或尖括号时，不加引号会把一个值拆成多个属性，或让浏览器按错误方式解析。拿不准时统一加双引号。
:::

## 三、布尔属性

### 1. 存在即真，缺失即假

**布尔属性**是标准专门定义的一类属性。对这类属性而言，存在表示真，缺失表示假；合法的存在形式可以省略等号，也可以使用空字符串或与属性名匹配的值。

以下局部片段中的 `input` 是一个文本输入控件；这里只观察它是否禁用，不展开输入控件的完整规则：

```html
<!-- 三种写法都表示 disabled 存在 -->
<input disabled>
<input disabled="">
<input disabled="disabled">
```

这三种写法都声明禁用状态。要取消禁用，应移除 `disabled`，而不是改成字符串 `false`：

```html
<!-- 错误示例：false 不是关闭布尔属性的合法值 -->
<input disabled="false">
```

该属性仍然存在，浏览器仍会把控件作为禁用状态处理；同时，源码中的 `false` 不满足布尔属性的合规取值要求。因此，“页面表现为禁用”和“这个属性值合法”还需要分别判断。规则见 [HTML：布尔属性](https://html.spec.whatwg.org/multipage/common-microsyntaxes.html#boolean-attributes)。

### 2. 合法写法与错误字符串

| 写法 | 属性是否存在 | 浏览器是否按真处理 | 是否符合作者语法 |
|------|--------------|--------------------|------------------|
| `<input disabled>` | 是 | 是 | 是 |
| `<input disabled="">` | 是 | 是 | 是 |
| `<input disabled="disabled">` | 是 | 是 | 是 |
| `<input disabled="false">` | 是 | 是 | 否 |
| `<input>` | 否 | 否 | 是 |

这张表说明，布尔属性的“值”不是用来表达真假的关键；关键是属性是否出现。`disabled="false"` 让人以为关闭了状态，实际只是写了一个不合法的值。

### 3. 不要用值猜状态

`disabled` 的存在规则不能套用到所有表示状态的属性。有些属性使用枚举关键词，有些使用其他字符串约定；即使值中出现 `true` 或 `false`，也应按该属性本身的定义理解。

::: warning 先查属性类型，再解释值
看到 `disabled="false"` 时，不要按普通字符串的“false 就是假”处理；看到 `dir="rtl"` 时，也不要按布尔属性的“存在就是真”处理。属性类型不同，值的解释方式也不同。
:::

## 四、枚举、数字、URL 与令牌

### 1. 枚举属性使用关键词

**枚举属性**通过一组关键词映射到相应状态。例如，`dir` 声明文字方向，可使用 `ltr`、`rtl`、`auto` 等关键词：

```html
<!-- dir 使用关键词，不是存在即真的布尔属性 -->
<p dir="ltr">ABC 123</p>
<p dir="rtl">ABC 123</p>
```

它不是“存在就开启某一个方向”的布尔属性。关键词如何匹配，缺省值、空值、无效关键词分别对应什么状态，都由该属性自己的定义规定；不能统一把未知关键词解释成假，或认为浏览器一定忽略整项配置。

这里仅用方向说明属性值的类型。完整语言与方向关系可参照 [HTML：dir 属性](https://html.spec.whatwg.org/multipage/dom.html#the-dir-attribute)；枚举值的一般规则见[关键词与枚举属性](https://html.spec.whatwg.org/multipage/common-microsyntaxes.html#keywords-and-enumerated-attributes)。

### 2. 数字、URL 与令牌各有规则

属性值都以字符写入源码，不代表它们的有效格式相同。判断时需要找到具体的值规则：

| 值类型 | 局部示意 | 应检查的条件 | 常见错误 |
|--------|----------|--------------|----------|
| 数值 | `width="16"` | 对应属性要求整数、非负数还是其他数字范围 | 写成 `width="16px"` |
| URL 地址 | `href="notes.html"` | 应按文档基准地址解释资源位置 | 把相对地址当成普通文字 |
| 空白分隔令牌 | `class="note compact"` | 这里是两个类名，不是包含空格的单一类名 | 重复写两个 `class` 属性 |
| 自由文字 | `title="补充说明"` | 值中的字符与引号边界需正确表达 | 不加引号导致值被拆开 |

同样，标签名可忽略 ASCII 大小写，也不能推出全部属性值忽略大小写。关键词、标识、路径和普通文字的匹配规则各不相同。

### 3. 重复同名属性

同一个开始标签出现两个同名属性时，作者语法已经不允许。浏览器可能保留其中一个值，但这不能作为设计依据；需要多个值时，应使用该属性定义的分隔方式。

```html
<!-- 错误示例：两个 class 属性不会合并成一组类名 -->
<p class="note" class="compact">正文。</p>
```

正确写法是把多个类名放入同一个 `class` 值：

```html
<!-- 一个 class 属性，两个用空白分隔的类名 -->
<p class="note compact">正文。</p>
```

::: warning 不要依赖重复属性的保留顺序
重复属性不是“后写的覆盖先写的”这样的稳定配置方式。作者语法禁止重复，浏览器如何处理属于错误恢复；修复时应合并或删除重复项，而不是编写脚本读取某个值。
:::

## 五、独立观察与失败恢复

### 1. 创建 attributes.html

新建空目录 `html-attributes`，创建 `attributes.html`，以 UTF-8 保存。下面的文档外壳保证页面能独立打开；本例不要求先掌握 `head` 的完整组成。

::: details 查看 attributes.html 完整内容

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>属性值观察</title>
</head>
<body>
  <!-- title 值包含空格和字符引用，用于观察引号边界 -->
  <p id="notice" title="包含 空格和&quot;引号&quot;的说明">属性值示例。</p>

  <!-- dir 使用关键词 rtl，观察文字基本方向 -->
  <p id="direction" dir="rtl">ABC 123</p>

  <!-- disabled 是布尔属性：存在即禁用，不写值也可以 -->
  <p><label for="locked">禁用输入：</label><input id="locked" value="不能编辑" disabled></p>

  <!-- 对照项：没有 disabled，控件可以编辑 -->
  <p><label for="free">普通输入：</label><input id="free" value=""></p>
</body>
</html>
```

:::

双击文件打开。页面有一段说明、一段从右侧排列的文字和两个输入控件。普通输入可以填写，带 `disabled` 的输入不能编辑。`label` 在这里只负责给每个输入提供可见名称，`for` 与对应 `id` 相同。

### 2. 观察属性值与控件状态

想核对字符引用是否已解释，可以在 Chrome 开发者工具的 Console 中输入下面的只读表达式；macOS 使用 `Option+Command+I`，Windows 通常使用 `F12` 打开工具。表达式读取指定元素的 `title` 属性，不修改页面：

```js
document.getElementById('notice').getAttribute('title')
```

得到的文字是 `包含 空格和"引号"的说明`。这证明空格仍在同一属性值中，`&quot;` 已成为值里的双引号。无需把鼠标悬停提示当作唯一证据，因为提示的出现方式由浏览器和输入设备决定。

| 观察项 | 表达式或操作 | 预期结果 | 说明 |
|--------|--------------|----------|------|
| 属性值中的空格 | `getAttribute('title')` | 保留一个空格 | 引号界定了完整值 |
| 字符引用 | 同上 | 显示 `"`，不显示 `&quot;` | 解析后得到字符 |
| 文字方向 | 查看 `dir="rtl"` 的段落 | 基本方向从右到左 | `dir` 是枚举属性 |
| 禁用状态 | `document.getElementById('locked').disabled` | `true` | `disabled` 存在 |
| 普通控件 | `document.getElementById('free').disabled` | `false` | 没有 `disabled` |

### 3. 失败与恢复

把文件复制为 `invalid.html`，只将 `disabled` 改为 `disabled="false"` 后重新打开：输入仍禁用。再移除整个 `disabled` 属性，保存并刷新，输入恢复可编辑。这三步分别对应正确存在、错误字符串和属性缺失，不能只检查源码里是否看到了“false”。

| 注入的错误 | 观察 | 恢复 |
|------------|------|------|
| `disabled="false"` | 控件仍禁用；Nu 报告布尔属性值错误 | 删除值或改写为合法的 `disabled`，要启用则移除属性 |
| `title=两段 文字` | 值被空格拆开，后半段被当成属性名 | 给值加引号：`title="两段 文字"` |
| 同一标签重复 `title` | 作者语法错误；不能依赖保留哪一个 | 合并为一个 `title`，或改用一个能表达多值的属性 |
| 重复两个 `class` | 类名没有按要求合并 | 写成一个 `class`，多个类名用空白分隔 |
| 在 `p` 上写 `src` | 属性不适用，不会让段落变成图片 | 删除错误属性，在 `img` 上使用 `src` |

出现差异时，先在 Elements 中确认属性是否存在、值是什么，再回到源码检查引号和属性类型；不要只根据控件外观判断。

### 4. 验证记录

本例于 2026-11-14 在 macOS 的 Chrome 157.0.8103.79 中核对，并使用 [Nu HTML Checker](https://validator.w3.org/nu/) 对照：正常文件无错误、无警告；`disabled="false"` 版本被报告为布尔属性值错误，浏览器中仍保持禁用。移除属性后可编辑，恢复正确的 `disabled` 写法后检查错误消失。
