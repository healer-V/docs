# 页面结构与分节元素

页面结构元素描述内容之间的关系，不负责把内容排成页眉、左栏和页脚。`aside` 可以显示在正文下方，`footer` 也不一定贴在窗口底部；选择它们的依据是内容承担什么职责，而不是准备把它画在哪里。

`header`、`nav`、`main`、`article`、`section`、`aside`、`footer` 都已收录于 2014 年 HTML5。它们为页面结构提供了比通用 `div` 更明确的词汇；`div` 和 `h1`—`h6` 等早已存在，不能把结构示例中的所有标签都称为新增。历史范围可对照 [HTML5 分节元素](https://www.w3.org/TR/2014/REC-html5-20141028/sections.html)、[HTML5 的 main](https://www.w3.org/TR/2014/REC-html5-20141028/grouping-content.html#the-main-element)和 [HTML4 元素索引](https://www.w3.org/TR/html4/index/elements.html)。

下面按独立内容、页面区域、页眉页脚和标题关系分组，最后用独立文档检查结构。

::: info 本篇的范围
本篇讲 `article`、`section`、`nav`、`aside`、`main`、`header`、`footer` 的内容职责与嵌套约束。标题与段落的语法见[标题与段落](../02-content-elements/01-headings-paragraphs.md)；通用容器见[通用容器 div 与 span](../02-content-elements/07-div-span.md)；CSS 布局、完整 ARIA 标准和搜索引擎排名不在本篇展开。
:::

## 一、结构标签表达内容职责

### 1. 语义标签不是布局指令

`header` 不是“页面最上方的一条”，`aside` 不是“右边一栏”，`footer` 不是“固定在窗口底部”。浏览器默认样式可能给它们一些边距或分块行为，但这些呈现可以改变，内容职责不会随 CSS 改变。

判断时先说明这块内容是什么：它是一篇可以独立理解的文字，还是某篇文章中的一个主题？它是主要导航，还是正文里顺带的一条参考？答案决定元素，而不是准备使用的栅格位置。

### 2. HTML5 新增与现行规则分开看

这些结构元素进入 HTML5 标准，改变了作者表达页面区域的方式，但没有让浏览器自动生成导航、目录或视觉布局。它们提供的是元素名称和内容模型，具体呈现仍由 CSS 和浏览器默认样式决定。

现行 HTML Standard 对嵌套、数量和可访问名称还有更细的条件。下面按现行规则说明；历史版本只用于说明元素来源，不用来推断当前浏览器的全部行为。

## 二、独立内容与主题分节

### 1. article 表示可以独立复用的完整内容

`article` 表示原则上可以独立分发或复用的完整内容，例如一篇札记、一条评论或一则独立通知。这里的“独立”是内容含义相对完整，不要求真的实现转载、订阅或导出功能。

下面是可以放在 `body` 中的局部内容：

```html
<article>
  <h2>阅读时为什么要记录疑问</h2>
  <p>疑问可以标出尚未理解的关系，供重读时检查。</p>
</article>
```

这条短札记有自己的主题和说明，离开当前列表仍能理解，因此适合用 `article`。如果只是为了给一句话设置背景色，就没有形成独立内容，不能仅凭“外面需要一个标签”选择它。

一篇独立内容内部还可以有分节；相关独立内容也可以嵌套，例如文章中的独立评论。嵌套的内层 `article` 与外层内容相关，不表示所有内层信息都自动继承外层作者身份。具体定义见 [HTML：article](https://html.spec.whatwg.org/multipage/sections.html#the-article-element)。

### 2. section 表示文档中的主题分组

`section` 表示围绕一个主题组成的内容组，通常带有标题。例如，一篇札记中的“观察”和“理解”可以分别构成分节，它们共同服务于整篇文章，而不必各自适合作为独立文章分发。

下面是放在一个已有 `article` 内部的局部分节：

```html
<section>
  <h3>观察</h3>
  <p>一段文字从现象转向原因时，阅读速度发生了变化。</p>
</section>
```

判断时可以先问：这一组内容能否用一个有意义的标题概括，是否构成文档中值得识别的主题？能回答主题问题，才有使用 `section` 的内容依据。并非每个段落、每张卡片或每层样式容器都需要成为一个分节。

### 3. section 与 div 的选择

`section` 不是通用包装元素。如果包裹的唯一目的只是设置间距、背景或给脚本一个查找位置，应考虑 `div`。两者可以有相同的显示效果，但表达的含义不同。

| 包装目的 | 更合适的选择 | 原因 |
|----------|--------------|------|
| 一组内容有主题，需要标题概括 | `section` | 向文档结构声明一个主题分节 |
| 只是设置边框、间距或脚本查找位置 | `div` | 没有额外主题含义 |
| 一篇可独立理解的完整内容 | `article` | 内容边界比主题分组更强 |
| 一组主要导航入口 | `nav` | 表达导航职责 |

`section` 的标题不是装饰：没有标题时，读者和辅助技术都难以知道这组分节在讲什么。为了使用 `section` 而补一个空泛标题，不如改回 `div` 或重新组织内容。[HTML：section](https://html.spec.whatwg.org/multipage/sections.html#the-section-element)明确区分了主题分组和通用容器；容器的内容模型见[通用容器 div 与 span](../02-content-elements/07-div-span.md)。

::: tip section 需要能回答“这一节讲什么”
写 `section` 前先拟一个具体标题，例如“观察”“配送方式”“错误恢复”。如果标题只能写成“内容”“第一部分”或留空，说明这里可能只是布局分组，应优先考虑 `div`。
:::

## 三、导航、补充信息与主要内容

### 1. nav 组织主要导航入口

`nav` 表示通向其他页面或当前文档不同部分的导航区域。它适合主导航、文章目录等主要导航组，而不是所有包含链接的段落。例如，以下是 `body` 中的局部目录：

```html
<nav aria-label="札记目录">
  <ul>
    <li><a href="#observation">观察</a></li>
    <li><a href="#interpretation">理解</a></li>
  </ul>
</nav>
```

这里的两个链接共同承担文档内导航，所以使用 `nav`。正文中顺带引用一份参考资料，或页脚只有几个附属链接时，不必为了“里面有链接”再套一个导航区域。

`aria-label` 在这里为导航区域提供可理解的名称“札记目录”，不改变链接目标；有多个导航区域时，应能按用途区分它们。它不是要求读者手写整套 ARIA 角色，也不需要给原生 `nav` 再重复声明相同角色。定义见 [HTML：nav](https://html.spec.whatwg.org/multipage/sections.html#the-nav-element)和 [WAI：页面区域](https://www.w3.org/WAI/tutorials/page-structure/regions/)。

### 2. aside 表示可从主线分离的补充信息

`aside` 适合与周围内容相关、但可以相对分离的补充信息，例如一条背景说明或相关参考。它的重点是“相关但不是当前论述主线”，不是“位于右侧”。

如果正文必须依靠某段定义才能理解接下来的推理，这段定义通常应留在正文主线中；把它移到侧边并不会自动使它成为合适的 `aside`。相反，一条可以另行阅读的背景备注，即使显示在正文下方，也可以承担补充职责。

祖先范围影响解释：文章内的 `aside` 应与该文章相关；文章外的补充区域可以与整页有关。不要把全站无关信息仅因版面方便就塞进某篇文章的补充区。依据见 [HTML：aside](https://html.spec.whatwg.org/multipage/sections.html#the-aside-element)。

### 3. main 标出当前文档的主要内容

`main` 表示文档占主导地位的内容，帮助把当前页面的主要内容与重复导航、页眉等区分开来。它可以容纳一篇文章，也可以容纳多篇相关内容或其他主要界面；不等同于“只能放一个 `article`”。

一份文档中，**不带 `hidden` 属性的 `main` 最多一个**。这不是只数肉眼看得见几个：把第二个 `main` 用 CSS 藏起来，也不能代替标准在这里要求的属性条件。本篇只使用一个普通 `main`，不展开切换隐藏页面的机制。

### 4. main 的位置还受祖先限制

位置还需满足层级条件。现行标准允许的祖先限定为 `html`、`body`、`div`、没有无障碍名称的 `form`，以及自主自定义元素。最后一类是由脚本定义、使用自定义标签的 HTML 元素，本篇不使用或展开。

因此，不能在 `article`、`section`、`nav`、`aside`、`header` 或 `footer` 里面再放 `main`；“父级允许流式内容”并不足以绕过它自己的上下文限制。本篇把 `main` 直接放在 `body` 下，避免引入额外机制。完整依据见 [HTML：main 与层级条件](https://html.spec.whatwg.org/dev/grouping-content.html#the-main-element)。

## 四、header 与 footer 的所属范围

### 1. header 是介绍性内容，不是页面顶部

`header` 表示介绍性内容或导航辅助内容，常包含标题、简短介绍等；它不是必须放在页面最上方的布局命令。页面可以有介绍整页的 `header`，一篇文章也可以有自己的 `header`，不需要为了凑齐结构给每个分节都添加一个。

### 2. footer 针对最近的所属内容

`footer` 提供所属内容的页尾信息，例如作者、相关资料或版本说明。它针对最近的分节内容祖先；没有这类祖先时，针对整个页面。文章中的 `footer` 和页面级 `footer` 因而可以同时存在，两者不表示同一范围。它也不要求在视觉上固定于窗口底边。

下面是一个 `article` 内的局部结构，介绍和版本信息都属于这篇文章：

```html
<article>
  <header>
    <h2>一则阅读札记</h2>
    <p>主题：阅读中的停顿。</p>
  </header>
  <p>停顿可以提示需要重新核对的内容关系。</p>
  <footer><p>札记版本：2026-11-14。</p></footer>
</article>
```

### 3. header 与 footer 不能互相嵌套

`header` 和 `footer` 自己不创建新分节，也不自动提升或降低标题等级。它们的内容还受到后代限制：两者内部都不能再包含 `header` 或 `footer` 后代。即使隔着 `div` 或其他容器，也不能把这项后代限制改成只检查直接子元素。

定义见 [header](https://html.spec.whatwg.org/multipage/sections.html#the-header-element)与 [footer](https://html.spec.whatwg.org/multipage/sections.html#the-footer-element)。

### 4. 页面区域与局部区域的可访问含义

页面区域还会参与浏览器提供给辅助技术的结构。页面级 `header`、`footer` 与嵌在文章、分节中的同名元素，不应一概理解为相同的整页地标；实际映射取决于祖先等条件。

这里观察浏览器无障碍树，不声称所有辅助技术都会采用完全相同的朗读方式。判断区域职责仍以内容为准，不能只数页面上出现了几个同名标签。

## 五、标题层次与结构判断

### 1. 分节标签不会自动重置标题等级

`article`、`section`、`nav`、`aside` 属于分节内容，但“增加一层分节标签”并不是浏览器自动把内部 `h1` 改成较低等级标题的命令。在本篇普通文档中，页面标题写 `h1`，文章标题写 `h2`，文章的并列主题写 `h3`，直接表达预期层次。

不要因为把两段内容分别放进 `section`，就认为其中两个 `h1` 会自动成为两个 `h3`。Elements 中的标签仍然是 `h1`，浏览器向辅助技术提供的等级也不能凭旧的大纲设想推定。标题基础规则见[标题与段落](../02-content-elements/01-headings-paragraphs.md)。

### 2. 按内容关系选择元素

选择结构时，可以按内容关系作以下判断；这张表用于比较职责，不是一份要求每页全部出现的标签清单：

| 内容关系 | 合适的判断方向 |
|----------|----------------|
| 原则上可独立复用的完整内容 | 考虑 `article` |
| 文档内有意义的主题分组 | 考虑 `section`，并给出能说明主题的标题 |
| 主要导航入口组成的一组内容 | 考虑 `nav` |
| 相关但可从论述主线分离的补充 | 考虑 `aside` |
| 当前文档占主导地位的内容 | 使用符合层级与数量条件的 `main` |
| 内容的介绍或页尾信息 | 按所属范围考虑 `header`、`footer` |
| 仅为样式或脚本做通用分组 | 考虑 `div`，不制造额外主题 |

### 3. 语义合适与语法合法要分别检查

一组包装标签即使通过检查器，也不证明主题划分有意义；反过来，内容看起来清楚，也不能解除重复 `main` 等结构错误。应同时核对内容依据、标题关系和具体元素的内容模型。

::: warning 语义合适与语法合法需要分别检查
检查器能发现重复 `main`、非法嵌套和不允许的属性，却无法判断一个 `section` 是否真的有主题。结构通过后仍需回到内容，问每个区域“为什么是这个名字、为什么在这个位置”。
:::

## 六、用独立文档检查区域与标题

### 1. 创建一份短札记

新建空目录 `html-sections`，创建 UTF-8 文件 `sections.html`。以下札记文字专为结构观察而写，不摘引具体作品；文件没有 CSS、脚本、外部资源和服务依赖，也不承接其他文章的示例。

::: details 查看 sections.html 完整内容

```html [sections.html]
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>阅读札记的结构</title>
</head>
<body>
  <header id="page-header">
    <h1>阅读札记</h1>
    <p>一条关于阅读方法的独立记录。</p>
  </header>
  <nav aria-label="札记目录">
    <ul>
      <li><a href="#observation">观察</a></li>
      <li><a href="#interpretation">理解</a></li>
    </ul>
  </nav>
  <main id="main-content">
    <article>
      <header id="article-header">
        <h2>停顿与段落</h2>
        <p>主题：阅读方法。</p>
      </header>
      <section id="observation">
        <h3>观察</h3>
        <p>当文字从现象转向原因时，可以停下来确认两者的关系。</p>
      </section>
      <section id="interpretation">
        <h3>理解</h3>
        <p>停顿用于核对理解，不以每个段落都必须停顿为规则。</p>
      </section>
      <aside>
        <h3>参考说明</h3>
        <p>这里的札记不针对某一本书，背景材料可以另行阅读。</p>
      </aside>
      <footer id="article-footer"><p>札记版本：2026-11-14。</p></footer>
    </article>
  </main>
  <footer id="page-footer"><p>本页文字用于结构观察。</p></footer>
</body>
</html>
```

:::

### 2. 检查区域嵌套与导航

打开页面，在开发者工具的 Elements 中确认一个主要内容区域、一篇札记和其中的两个主题分节。页面级页眉和页尾位于文章之外，文章自己的介绍和版本信息位于文章内部；这些关系不依赖左右栏或背景色。

按 Tab 到达“观察”链接，再按 Enter，应导航到 `#observation`；目标已经在视野中时，滚动不一定明显，应同时核对地址和目标 id。浏览器的无障碍信息中可检查“札记目录”导航、主要内容及标题等级。未命名的普通 `section` 不必都暴露成带名称的区域，不能按标签数量推定地标数量。

| 观察项 | 位置或操作 | 预期结果 |
|--------|------------|----------|
| 页面主要内容 | Elements | 只有一个 `main`，直接位于 `body` 下 |
| 文章范围 | Elements | `article` 位于 `main` 内 |
| 文章页眉 | Elements | `article > header`，包含 `h2` |
| 主题分节 | Elements | 两个 `section`，各含一个 `h3` |
| 同页目录 | Tab、Enter | 导航到对应 `id`，地址含片段 |
| 页面页尾 | Elements | 位于 `main` 和 `article` 之外 |

### 3. 注入重复 main 与错误标题

保留原文件，复制为 `invalid.html`，在页面级 `footer` 之前再加入以下局部内容：

```html
<!-- 错误示例：文档中第二个不带 hidden 的 main -->
<main><p>另一份主要内容。</p></main>
```

浏览器仍能显示两份内容，但这份文档违反数量要求。上传到 [Nu HTML Checker](https://validator.w3.org/nu/)，可得到重复主要内容区域的结构错误。修复时把应属主内容的文字并入原有 `main`；如果它只是通用分组，则改用符合含义的容器，而不是只用 CSS 藏起第二个区域。

另复制正常文件，把“观察”的 `h3` 改成 `h1`，只观察 Elements 和无障碍标题等级，再恢复。嵌套的 `section` 不会把它改回等级 3；正确修复是按预期内容层次写回 `h3`。

| 注入的问题 | 观察 | 恢复 |
|------------|------|------|
| 第二个不带 `hidden` 的 `main` | 页面显示两份内容，Nu 报告重复 `main` | 合并主内容，或改为普通容器 |
| 把 `section` 内的 `h3` 改成 `h1` | 标签仍为 `h1`，标题等级不自动重置 | 按内容层次写回 `h3` |
| 在 `article` 内放 `main` | 违反 `main` 的祖先限制 | 把 `main` 移回 `body` 等允许位置 |
| 仅为样式包一个 `section` | 结构通过也可能没有主题 | 改为 `div`，或补出真实主题 |
| 用 CSS 隐藏第二个 `main` | 视觉只剩一个，仍违反数量条件 | 删除或合并第二个 `main` |

若某段内容仅为样式而被包成 `section`，也应重新判断是否存在独立主题：没有主题时改为 `div`，不要补一个没有意义的标题来应付工具。这类含义问题需要阅读内容，不能期待检查器代替作者作出所有选择。

### 4. 验证记录
