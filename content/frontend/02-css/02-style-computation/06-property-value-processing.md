# CSS 属性值处理

**CSS 声明**是给属性写下的取值要求。浏览器需要决定某个元素的属性最后取什么值：有时会碰到多条声明，有时一条作者声明也没有。这个决定过程叫**属性值处理**。

## 一、属性值处理中的六种值

浏览器处理一个属性时，可以用六个名称描述值的状态：

1. **声明值（declared values）**：筛选后适用于该元素的候选声明，可以有多条，也可以没有。
2. **层叠值（cascaded value）**：候选声明发生冲突时，按层叠规则选出的胜出值；没有候选就没有层叠值。
3. **指定值（specified value）**：有层叠值时沿用它；没有时用继承或初始值补齐。
4. **计算值（computed value）**：按属性定义处理当前能确定的依赖，结果不一定是像素数。
5. **应用值（used value）**：需要布局信息时补齐依赖，得到用于布局或呈现的值，也译作“使用值”。
6. **实际值（actual value）**：呈现环境在自身精度限制下最终实现的值。

::: tip 六种值分成两段理解
声明值、层叠值和指定值回答“先取什么值”；计算值、应用值和实际值回答“这个值如何用于呈现”。它们描述取值关系，不表示浏览器一定按六轮独立计算。
:::

## 二、六种值怎样衔接

### 1. 从声明值到层叠值

从样式表到层叠值，先筛选，再裁决：

1. **筛选声明**：样式表要生效，条件规则要成立，选择器要匹配元素，属性名和值也要符合语法。通过筛选的候选才是声明值；它们还没有确定胜负。
2. **裁决冲突**：同一元素的同一属性有多个候选时，浏览器按来源、重要性、层叠层、选择器优先级和书写顺序裁决。胜出的结果是层叠值，完整次序见 [MDN 层叠规则](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascade/Introduction)。

::: warning 后写的声明不一定胜出
只有前面的层叠条件都无法区分候选时，书写顺序才决定胜负。语法无效的声明甚至不会进入候选集合。
:::

### 2. 指定值如何补齐

无论作者是否写了声明，属性都需要一个**指定值**。取得方式按顺序判断：

1. **已有层叠值**：直接将胜出的值作为指定值。
2. **没有层叠值且属性可继承**：取得父元素的计算值。根元素没有父元素，改用该属性的初始值。
3. **没有层叠值且属性不可继承**：使用该属性的初始值。

`inherit`、`initial` 等全局关键字会明确改变指定值的取得方式，不等同于“没有声明”。

::: warning 默认外观不一定是属性初始值
浏览器自带样式表也会提供声明并参与层叠。元素看起来有默认样式，不能据此断定它直接使用了属性的初始值。
:::

### 3. 计算值、应用值与实际值

确定指定值后，后面三个名称分别关注不同问题：

1. **计算值**：浏览器按该属性的规则处理当前已知的依赖。与字体有关的单位可能在此得到具体长度；百分比可能仍要等待布局确定参考区域。
2. **应用值**：布局取得所需的参考尺寸后，补齐尚未确定的依赖，得到用于布局或呈现的值。
3. **实际值**：呈现环境受精度限制，最终实现的值可能与应用值有差异。CSS 像素也不能直接当作屏幕物理像素。

各属性在哪一步能确定什么信息，取决于自身规则，参见 [MDN 属性值处理](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascade/Property_value_processing)。

::: warning 计算值不一定是像素数
百分比可以保留到布局阶段；`auto` 也不是通用的 `0` 或 `100%`，它如何求解取决于属性和布局方式。
:::

### 4. 样式读取与盒子测量

页面上能读到的“宽度”还要按观察对象区分：

1. **内联声明**：元素的 `style` 属性只保存直接写在该元素上的声明。
2. **属性解析值**：CSSOM（CSS 对象模型）的 `getComputedStyle()` 返回解析值（resolved value）。它可能对应计算值，也可能对应应用值，规则见 [CSSOM 解析值定义](https://drafts.csswg.org/cssom/#resolved-values)。
3. **盒子几何**：`getBoundingClientRect()` 测量元素的边界矩形，包括内边距、边框和可能的视觉变换，不是 `width` 属性本身。

::: tip 解析值不是第七个值阶段
`getComputedStyle()` 的名称不能证明返回值总是规范中的计算值。读样式与量盒子也不是同一件事，即使结果都写成像素数。
:::

## 三、用百分比宽度核对这些概念

一个内容宽度为 `480px`、字号为 `20px` 的普通块级容器，包含一个需要观察宽度的普通块级元素。以下是局部 HTML，省略文档外壳：

```html
<div class="container">
  <div class="box">内容</div>
</div>
```

相关 CSS 如下；这里只省略页面其他无关样式：

```css
.container { width: 480px; font-size: 20px; }
.box {
  box-sizing: content-box;
  width: 25%;
  width: 50%;
  padding: 12px;
  border: 2px solid;
  font-size: 1.5em;
}
```

### 1. 先确定哪个宽度生效

1. **声明值**：两个 `width` 声明都符合语法，选择器也匹配 `.box`，因此 `25%` 和 `50%` 都是候选。
2. **层叠值**：两个候选位于同一规则，其他层叠条件相同，后写的 `50%` 胜出。
3. **指定值**：已有层叠值，不需要继承或初始值补缺，所以指定值也是 `50%`。

::: warning 无效声明不会覆盖有效声明
若再写一条 `width: blue`，它不符合 `width` 的值语法，在筛选时就被排除。包含 `var()` 的声明则可能直到变量替换后才发现无效，不能一概按此规则回退到前一条。
:::

### 2. 再确定字号和宽度

本例中，`.box` 的百分比宽度参照其**包含块**：`.container` 的内容区域。它没有内边距和边框，所以参考宽度正好是 `480px`。

1. **字号的计算值**：`1.5em` 参照父元素的计算字号 `20px`，得到 `30px`。
2. **宽度的计算值**：`width` 仍是 `50%`，因为此时它保留着相对关系。
3. **宽度的应用值**：布局确定参考宽度后，内容宽度为 `480px × 50% = 240px`。
4. **盒子的边框框宽度**：两侧内边距共 `24px`、边框共 `4px`，因此为 `268px`。这是几何尺寸，不是 `width` 的又一个值阶段。

::: tip 240px 和 268px 的区别
`240px` 是内容框宽度，`268px` 是包含内边距和边框的边框框宽度。浏览器没有把 `width: 50%` 改写成 `268px`。
:::

### 3. 参考条件改变会影响哪个值

每次只改变一个条件，可以看出不同属性依赖什么：

1. **容器变窄**：`.container` 内容宽度改为 `320px`，`.box` 的计算值仍是 `50%`，内容宽度变成 `160px`，边框框宽度变成 `188px`。
2. **父级字号增大**：只把 `.container` 字号改为 `24px`，`.box` 字号变成 `36px`，百分比宽度不变。
3. **宽度改成 `auto`**：本例普通块级布局中，`.box` 没有水平外边距，内容宽度为 `480px - 24px - 4px = 452px`，边框框宽度为 `480px`。

`auto` 的减法只适用于这些条件。Flexbox、Grid、绝对定位或最小尺寸约束会改变求解方式，不能套用本例结果。

### 4. 读取样式为何得到不同数字

假设页面已包含上述 HTML 和 CSS，下面三行只展示读取动作及预期结果，省略脚本装载过程：

```js
const box = document.querySelector('.box');
getComputedStyle(box).width;       // "240px"
box.getBoundingClientRect().width; // 268
```

`getComputedStyle(box).width` 返回 `240px`，是 CSSOM 的**解析值**；在这个生成了盒子的例子里，它采用布局后得到的宽度。`getBoundingClientRect()` 返回的 `268` 是边框框宽度，单位按 CSS 像素理解。虽然 `.box` 在样式表里写了宽度，`box.style.width` 仍为空字符串，因为元素自身没有内联声明。

::: info 排查数字不一致的顺序
1. 看哪条声明胜出，先排除无效值。
2. 查百分比参照的包含块及其内容宽度。
3. 分清读到的是属性解析值、内容框尺寸，还是包含内边距、边框及变换的边界矩形。
:::
