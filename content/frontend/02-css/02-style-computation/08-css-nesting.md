# 原生 CSS 嵌套

**CSS 嵌套**允许把相关规则写在另一条规则内部，由浏览器解释它们的选择器关系。`&` 是嵌套选择器，用来引用外层规则的匹配对象。

嵌套改变规则的组织方式，但不会自动建立样式隔离，也不会让内部声明只对某一个组件实例生效。

## 一、嵌套规则的匹配关系

### 1. 后代与同一元素

下面是局部 CSS，假设 `.panel` 内有 `.title`：

```css
.panel {
  color: #1f2937;
  .title { font-weight: 700; }
  &:hover { border-color: green; }
}
```

内部 `.title` 表达外层匹配对象的后代关系，类似 `.panel .title`；`&:hover` 则选择处于悬停状态的 `.panel` 自身。

| 内部写法 | 匹配目标 |
|----------|----------|
| `.title` 或 `& .title` | 外层对象里的标题后代 |
| `& > .title` | 外层对象的直属标题 |
| `&.active` | 外层对象同时带有 `active` 类 |
| `& + .panel` | 紧接外层对象的兄弟面板 |

::: warning 空格会改变关联
`&:hover` 是外层对象悬停；`& :hover` 是它内部某个后代悬停。缺少 `&` 的 `:hover` 也不能被当成同一元素状态来使用。
:::

### 2. 外层对象也可以位于右侧

嵌套选择器不只能写在最前面。下面是局部主题规则，假设 `.dark` 是 `.panel` 的祖先：

```css
.panel {
  background: white;
  .dark & { background: #202124; color: white; }
}
```

`.dark &` 的目标仍是 `.panel`，条件是它位于 `.dark` 内部。这种写法并不会选择 `.dark` 自身。

## 二、嵌套条件规则

`@media`、`@supports` 等条件规则可以写在样式规则内部。条件成立后，内部声明和规则才参与层叠。

以下是局部样式，只在足够宽的视口下改变面板内边距：

```css
.panel {
  padding: 12px;
  @media (min-width: 48rem) {
    padding: 24px;
    & > .title { margin-bottom: 16px; }
  }
}
```

条件内直接写的 `padding` 仍作用于 `.panel`，标题规则仍有直属子代约束。嵌套层数越多，越需要展开检查完整匹配关系，而不是仅按缩进猜范围。

::: tip 嵌套深度跟随真实关系
为状态、直属子元素或条件组合使用嵌套即可。把每一层 DOM 都写进选择器，会增加结构耦合；调整 HTML 层级时更容易使规则失效。
:::

## 三、选择器列表与优先级

嵌套选择器 `&` 的优先级采用外层选择器列表中最高的权重，行为类似 `:is()`，不是仅按当前匹配分支计算。

以下局部规则中，外层同时列出类和 ID：

```css
.panel, #featured {
  & > .title { color: green; }
}
.panel > .title { color: red; }
```

嵌套规则的权重包含 `#featured` 带来的 ID 权重，因此普通 `.panel` 内的标题也可能保持绿色。把它机械展开成两条独立的平铺规则，会改变 `.panel` 分支的权重。

::: warning 重构嵌套时同时比较结果与权重
匹配集合相同不代表冲突结果相同。外层混合 ID 和类时尤其要检查其他规则，权重规则见[层叠与优先级](./03-cascade-specificity.md)。
:::

## 四、原生语法与预处理器

原生 `&` 表示选择器对象，不做字符串拼接。Sass 中常见的 `&__title` 不能直接当作原生 CSS 的类名生成方式；需要完整写出 `.panel__title`，或明确写成后代关系。

现代原生嵌套的解析规则也经历过更新，较早实现与较新实现对某些写法的支持不同。引入前按目标浏览器验证完整语法，不能只检查是否“支持嵌套”就认为所有形式都可用。规则见 [CSS Nesting](https://www.w3.org/TR/css-nesting-1/)。

排查嵌套样式时，按顺序检查：

1. 当前环境由浏览器直接解析，还是由 Sass 等构建工具转换。
2. 展开 `&` 后目标是同一元素、后代还是兄弟。
3. 外层选择器列表是否提高权重。
4. 目标浏览器是否接受当前语法；不支持时采用平铺规则或明确配置构建转换。

这四项分别处理解析、匹配、冲突和兼容问题，不能只用增加选择器层级来修复。
