# CSS 层叠与优先级

**层叠**（cascade）是在同一元素的同一属性有多个适用声明时，选出胜出声明的规则。**选择器优先级**（specificity）只是其中一个比较条件，不是完整的层叠规则。

## 一、声明按什么顺序裁决

### 1. 先筛选，再比较

浏览器先排除未加载、不符合条件、不匹配元素或语法无效的声明。剩下的声明按顺序裁决；某一步已分出高低，就不再靠后面的条件翻盘：

1. **来源、重要性及层叠层**：声明由谁提供？是否带 `!important`？属于哪一层？
2. **选择器优先级**：在可比较的同一来源与层中，哪条选择器的权重更高？
3. **作用域邻近性**：优先级相同时，作用域根到目标元素的距离是否更近？
4. **出现顺序**：前面的条件都相同时，后出现的声明胜出。

::: warning “后写覆盖前写”有条件
书写顺序是最后的裁决项。更高的选择器权重也不能越过来源、重要性和层叠层的排序。
:::

### 2. 来源与重要性

**作者样式**由页面提供，**用户样式**来自用户的浏览器定制，**用户代理样式**来自浏览器自身。`!important` 标记的是声明的重要性，写在属性值之后。

以下顺序由低到高，描述同一属性上这些来源的裁决地位：

| 顺序 | 声明或值 |
|-----:|------------|
| 1 | 用户代理普通声明 |
| 2 | 用户普通声明 |
| 3 | 作者普通声明 |
| 4 | CSS 关键帧动画值 |
| 5 | 作者重要声明 |
| 6 | 用户重要声明 |
| 7 | 用户代理重要声明 |
| 8 | 正在进行的 CSS 过渡值 |

重要声明的来源顺序与普通声明相反，允许用户与浏览器保护必要偏好和行为。过渡值位于最高位置，只在相关属性实际处于过渡期间发挥作用。定义见 [CSS 层叠规范](https://www.w3.org/TR/css-cascade-5/#cascade-sort)。

## 二、层叠层与内联声明

### 1. @layer 的顺序

`@layer` 把样式划分为具有明确顺序的**层叠层**。下面是局部 CSS，假设目标按钮的 ID 为 `save`，类名为 `action`：

```css
@layer base, components;
@layer base {
  #save { color: red; }
}
@layer components {
  .action { color: green; }
}
```

按钮变绿。普通声明中，后建立的 `components` 层高于 `base`，因此不必比较 `#save` 和 `.action` 的选择器权重。

同一来源内部的层顺序如下：

| 声明类型 | 层内与层外的关系 |
|----------|------------------|
| 普通声明 | 后层高于前层；未分层声明高于所有层内声明 |
| 重要声明 | 前层高于后层；层内重要声明高于未分层重要声明 |

层的顺序在首次声明时确定，后面给已有层追加规则不会把该层移到最后。`@import url("vendor.css") layer(vendor)` 可把导入样式放入指定层；导入规则还需满足样式表的语法位置要求。

::: tip 用层表达样式职责
先声明 `@layer reset, base, components, utilities;`，再分别放入规则，可减少为了覆盖组件而不断增加选择器权重的需求。所有需要比较的样式应按同一套层策略组织。
:::

### 2. 内联样式的边界

元素 `style` 属性中的普通声明高于作者样式表中的普通声明，包括未分层规则；作者重要声明仍可覆盖它。内联重要声明则高于其他作者重要声明，但仍服从用户、浏览器重要声明和过渡值的更高地位。

因此，不能把内联样式称为“无条件最高”，也不宜把它当成普通选择器三元组中的一个 ID。

## 三、选择器优先级

### 1. 三元组如何比较

选择器权重表示为 `(ID, 类属性伪类, 类型伪元素)`，从左向右逐项比较。后一项再多，也不能抵消前一项的差距。

| 选择器 | 权重 |
|--------|------|
| `button` | `(0, 0, 1)` |
| `.action:hover` | `(0, 2, 0)` |
| `#save` | `(1, 0, 0)` |
| `.panel > button::before` | `(0, 1, 2)` |

通配选择器与组合器不增加权重。把权重当成十进制的“100、10、1”相加会出错，因为类的数量不会进位成 ID。

### 2. 函数式伪类的例外

1. `:is()`、`:not()`、`:has()` 使用参数列表中**最高的选择器权重**，不是把参数全部相加。
2. `:where()` 及其参数的权重都是零。
3. `:nth-child()` 本身计一个伪类；若使用 `of` 列表，还要加上列表中最高的权重。

例如 `:is(.action, #save)` 的权重是 `(1, 0, 0)`，即使当前元素通过 `.action` 分支匹配，也按整个参数列表的最高值计算。

## 四、作用域与同权重冲突

`@scope` 限定规则的匹配范围；其作用域根选择器不会自动提高内部选择器的权重。下面是局部 CSS，假设 `.inner` 位于 `.outer` 内部，段落位于 `.inner` 中：

```css
@scope (.outer) {
  p { color: red; }
}
@scope (.inner) {
  p { color: green; }
}
```

两条规则的来源、层和权重相同，较近的 `.inner` 作用域胜出。如果没有作用域距离差异，则再比较出现顺序。具体能力与浏览器支持见 [MDN @scope](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@scope)。

::: info 继承不是参与竞争的低权重规则
父元素的颜色只有在子元素需要继承时才传递。子元素自身的合法普通声明，即使选择器权重很低，也不需要先打败父元素选择器的权重。
:::

查看一个被划线的声明时，依次检查来源与重要性、层、权重、作用域距离和顺序。只有找到具体输在哪一步，修改才有明确依据。
