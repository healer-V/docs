# CSS 绘制顺序与 z-index

**绘制顺序**决定盒子重叠时哪些内容先画、哪些后画。通常后画的内容覆盖先画的内容；`z-index` 为适用的盒子指定堆叠级别。

比较级别必须先有范围。**层叠上下文**是独立组织绘制顺序的分组，文档根元素建立根层叠上下文；这里先比较同一上下文内的盒子。

## 一、同一上下文内的绘制分组

对于常见二维布局，可以按以下顺序理解主要分组，从后方到前方：

| 顺序 | 主要内容 |
|-----:|----------|
| 1 | 建立该上下文的盒子的背景和边框 |
| 2 | 负堆叠级别的子层叠上下文，级别较小的先画 |
| 3 | 常规流中非定位块的背景和边框 |
| 4 | 非定位浮动内容 |
| 5 | 常规流中的行内内容，包括文字 |
| 6 | 定位的 `auto` 内容与零级别子上下文等 |
| 7 | 正堆叠级别的子层叠上下文，级别较大的后画 |

这是一张主要分组表，不是给任意复杂 DOM 逐元素排序的完整算法。表格、行内定位、绘制片段等有细化规则，正式顺序见 [CSS 绘制顺序](https://www.w3.org/TR/CSS22/zindex.html)。

::: warning 普通内容与定位内容不是只按 DOM 顺序比较
普通文字可能先于定位 `auto` 内容绘制。只有进入相同绘制分组和相同级别时，树顺序才成为主要判断条件。
:::

## 二、z-index 的取值与适用对象

### 1. auto 与整数

| 值 | 主要行为 |
|----|----------|
| `auto` | 不显式指定新的整数级别；普通 relative/absolute 元素不因此建立新上下文 |
| 负整数 | 在相应负级别分组中绘制 |
| `0` | 指定零级别；适用时会建立新上下文 |
| 正整数 | 在相应正级别分组中绘制 |

`auto` 与 `0` 有时视觉一样，但对后代的分组约束不同。fixed/sticky 或其他触发条件也可能独立建立上下文，所以不能把 `auto` 解释成“绝不创建”。

### 2. 哪些对象可以使用

`z-index` 用于定位盒子；Flex 项目和 Grid 项目即使是 `position: static`，也可以使用非 `auto` 的 `z-index`。

普通常规流块只写 `z-index: 10`，通常不会因此获得预期的级别。排查时先确认它是什么布局对象，而不是直接换成更大的数字。

## 三、验证重叠结果

以下局部 HTML 包含两个定位兄弟，省略文档外壳：

```html
<div class="stage">
  <div class="a">甲</div>
  <div class="b">乙</div>
</div>
```

对应局部 CSS，舞台明确形成一个比较范围：

```css
.stage { position: relative; isolation: isolate; height: 160px; }
.a, .b { position: absolute; width: 120px; height: 80px; }
.a { top: 20px; left: 20px; background: #9fdfb8; }
.b { top: 40px; left: 80px; background: #f6b8bd; }
```

按顺序只改变一个条件：

1. 两者均为 `auto` 时，后出现的乙在重叠区域覆盖甲。
2. 为甲添加 `z-index: 1`，甲进入正级别分组，覆盖乙。
3. 再为乙添加 `z-index: 2`，乙的级别更高，再次覆盖甲。
4. 将甲设为 `-1`，它来到普通内容后方，但仍在舞台自身背景和边框前方，因为舞台形成了上下文边界。

::: info 负级别是否被祖先背景盖住，取决于边界
如果一个祖先没有建立层叠上下文，负级别后代可能进入更外层的负级别分组，落在该祖先的背景后方。不能仅凭“是子元素”就断言它永远画在父背景上面。
:::

## 四、整数只能在正确范围内比较

两个数字大小不同，不代表可以直接比较。子元素 `z-index: 9999` 若被较低的父上下文整体约束，仍可能被另一个父上下文中的内容覆盖。

::: tip 先找共同的层叠上下文
简单定位兄弟可比较级别；复杂嵌套先找上下文祖先，再比较它们在共同上下文中的位置。具体机制见[创建与嵌套层叠上下文](./02-stacking-contexts.md)。
:::
