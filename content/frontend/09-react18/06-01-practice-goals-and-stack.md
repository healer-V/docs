# 项目目标与技术选型

## 一、学习目标

为后台管理案例定义用户流程、质量目标和带版本号的技术栈。

完成本节后，应当能够判断这一能力的适用边界，并在 TypeScript 项目中解释相关代码为什么正确。

## 二、核心知识

| 序号 | 必须掌握的结论 |
|------|----------------|
| 1 | 技术选择必须对应需求和团队约束。 |
| 2 | 锁定 React 18、TypeScript、路由、查询和测试库版本。 |
| 3 | 先定义性能、可访问性和错误恢复验收标准。 |
| 4 | 区分教学简化与生产必须补齐的能力。 |

## 三、理解与应用

学习本节时，应把知识放回“输入、渲染、提交、用户交互”这条主线中理解。先确认数据由谁拥有，再判断组件在渲染阶段读取什么、在事件阶段修改什么，以及是否需要在提交后与外部系统同步。

::: tip 学习方法
不要只记忆 API 形式。请尝试画出数据来源、组件边界和更新触发点，再说明 React 为什么需要当前约束。
:::

## 四、实践任务

1. 在独立分支或练习目录中创建一个最小示例，只验证“项目目标与技术选型”这一项能力。
2. 为示例补充正常路径、空值或空列表、重复操作三个场景。
3. 开启 TypeScript 严格检查，消除非必要的类型断言和非空断言。
4. 使用 React Developer Tools 观察组件输入、状态和渲染变化。

## 五、验收标准

- [ ] 能用自己的语言说明：技术选择必须对应需求和团队约束。
- [ ] 能用自己的语言说明：锁定 React 18、TypeScript、路由、查询和测试库版本。
- [ ] 能用自己的语言说明：先定义性能、可访问性和错误恢复验收标准。
- [ ] 能用自己的语言说明：区分教学简化与生产必须补齐的能力。
- [ ] 示例在刷新、重复交互和边界输入下行为一致。
- [ ] 能指出至少一个不适合使用本节能力的场景。
