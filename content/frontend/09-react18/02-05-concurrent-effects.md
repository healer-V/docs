# 并发渲染下的副作用约束

## 一、学习目标

让组件和外部订阅在渲染重试、延迟提交和 StrictMode 检查下保持正确。

完成本节后，应当能够判断这一能力的适用边界，并在 TypeScript 项目中解释相关代码为什么正确。

## 二、核心知识

| 序号 | 必须掌握的结论 |
|------|----------------|
| 1 | 渲染期间不得写入外部存储、修改 DOM 或发送请求。 |
| 2 | 订阅应通过 Effect 或 useSyncExternalStore 建立一致的读写协议。 |
| 3 | 异步结果需要处理竞态，过期请求不能覆盖最新界面状态。 |
| 4 | 依赖提交次数或固定执行顺序的第三方代码需要隔离和适配。 |

## 三、理解与应用

学习本节时，应把知识放回“输入、渲染、提交、用户交互”这条主线中理解。先确认数据由谁拥有，再判断组件在渲染阶段读取什么、在事件阶段修改什么，以及是否需要在提交后与外部系统同步。

::: tip 学习方法
不要只记忆 API 形式。请尝试画出数据来源、组件边界和更新触发点，再说明 React 为什么需要当前约束。
:::

## 四、实践任务

1. 在独立分支或练习目录中创建一个最小示例，只验证“并发渲染下的副作用约束”这一项能力。
2. 为示例补充正常路径、空值或空列表、重复操作三个场景。
3. 开启 TypeScript 严格检查，消除非必要的类型断言和非空断言。
4. 使用 React Developer Tools 观察组件输入、状态和渲染变化。

- [ ] 能用自己的语言说明：订阅应通过 Effect 或 useSyncExternalStore 建立一致的读写协议。
- [ ] 能用自己的语言说明：异步结果需要处理竞态，过期请求不能覆盖最新界面状态。
- [ ] 能用自己的语言说明：依赖提交次数或固定执行顺序的第三方代码需要隔离和适配。
