# 并发特性应用

## 一、学习目标

只在搜索、大列表和路由内容等真实瓶颈中应用 React 18 并发能力。

完成本节后，应当能够判断这一能力的适用边界，并在 TypeScript 项目中解释相关代码为什么正确。

## 二、核心知识

| 序号 | 必须掌握的结论 |
|------|----------------|
| 1 | 输入 State 保持紧急，结果区域使用延迟值或 Transition。 |
| 2 | Suspense 边界保持现有内容和布局稳定。 |
| 3 | 并发优化前后使用 Profiler 对比。 |
| 4 | 并发 API 不能替代请求取消、缓存和虚拟列表。 |

## 三、理解与应用

学习本节时，应把知识放回“输入、渲染、提交、用户交互”这条主线中理解。先确认数据由谁拥有，再判断组件在渲染阶段读取什么、在事件阶段修改什么，以及是否需要在提交后与外部系统同步。

::: tip 学习方法
不要只记忆 API 形式。请尝试画出数据来源、组件边界和更新触发点，再说明 React 为什么需要当前约束。
:::

## 四、实践任务

1. 在独立分支或练习目录中创建一个最小示例，只验证“并发特性应用”这一项能力。
2. 为示例补充正常路径、空值或空列表、重复操作三个场景。
3. 开启 TypeScript 严格检查，消除非必要的类型断言和非空断言。
4. 使用 React Developer Tools 观察组件输入、状态和渲染变化。

## 五、验收标准

- [ ] 能用自己的语言说明：输入 State 保持紧急，结果区域使用延迟值或 Transition。
- [ ] 能用自己的语言说明：Suspense 边界保持现有内容和布局稳定。
- [ ] 能用自己的语言说明：并发优化前后使用 Profiler 对比。
- [ ] 能用自己的语言说明：并发 API 不能替代请求取消、缓存和虚拟列表。
- [ ] 示例在刷新、重复交互和边界输入下行为一致。
- [ ] 能指出至少一个不适合使用本节能力的场景。
