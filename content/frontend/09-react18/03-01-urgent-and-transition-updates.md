# 紧急更新与非紧急更新

## 一、学习目标

从交互反馈角度拆分状态，让输入保持即时并允许复杂结果延后。

完成本节后，应当能够判断这一能力的适用边界，并在 TypeScript 项目中解释相关代码为什么正确。

## 二、核心知识

| 序号 | 必须掌握的结论 |
|------|----------------|
| 1 | 同一次交互可以同时产生紧急状态和 Transition 状态。 |
| 2 | 输入框自身 value 必须紧急更新，不能直接放入 Transition。 |
| 3 | 延迟更新期间旧内容可以继续显示，避免无意义的整页加载闪烁。 |
| 4 | Transition 适用于可中断渲染，不用于延迟网络请求或定时任务。 |

## 三、理解与应用

学习本节时，应把知识放回“输入、渲染、提交、用户交互”这条主线中理解。先确认数据由谁拥有，再判断组件在渲染阶段读取什么、在事件阶段修改什么，以及是否需要在提交后与外部系统同步。

::: tip 学习方法
不要只记忆 API 形式。请尝试画出数据来源、组件边界和更新触发点，再说明 React 为什么需要当前约束。
:::

## 四、实践任务

1. 在独立分支或练习目录中创建一个最小示例，只验证“紧急更新与非紧急更新”这一项能力。
2. 为示例补充正常路径、空值或空列表、重复操作三个场景。
3. 开启 TypeScript 严格检查，消除非必要的类型断言和非空断言。
4. 使用 React Developer Tools 观察组件输入、状态和渲染变化。

- [ ] 能用自己的语言说明：输入框自身 value 必须紧急更新，不能直接放入 Transition。
- [ ] 能用自己的语言说明：延迟更新期间旧内容可以继续显示，避免无意义的整页加载闪烁。
