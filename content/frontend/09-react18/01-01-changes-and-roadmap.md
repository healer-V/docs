# React 18 变化与学习路线

## 一、学习目标

建立 React 18 的增量学习边界，区分升级默认行为、并发特性和框架能力。

完成本节后，应当能够判断这一能力的适用边界，并在 TypeScript 项目中解释相关代码为什么正确。

## 二、核心知识

| 序号 | 必须掌握的结论 |
|------|----------------|
| 1 | React 18 在 React 16.8 Hooks 基础上升级了根 API、批处理和并发渲染能力。 |
| 2 | 并发渲染是底层机制，不等于所有组件自动异步渲染。 |
| 3 | 升级应先保证行为兼容，再针对真实交互瓶颈采用并发 API。 |
| 4 | 路由、数据请求和 Server Components 属于生态或框架能力，需要单独标注版本。 |

## 三、理解与应用

学习本节时，应把知识放回“输入、渲染、提交、用户交互”这条主线中理解。先确认数据由谁拥有，再判断组件在渲染阶段读取什么、在事件阶段修改什么，以及是否需要在提交后与外部系统同步。

::: tip 学习方法
不要只记忆 API 形式。请尝试画出数据来源、组件边界和更新触发点，再说明 React 为什么需要当前约束。
:::

## 四、实践任务

1. 在独立分支或练习目录中创建一个最小示例，只验证“React 18 变化与学习路线”这一项能力。
2. 为示例补充正常路径、空值或空列表、重复操作三个场景。
3. 开启 TypeScript 严格检查，消除非必要的类型断言和非空断言。
4. 使用 React Developer Tools 观察组件输入、状态和渲染变化。
