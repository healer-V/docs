# 更新优先级与可中断渲染

## 一、学习目标

区分紧急输入与可延迟结果，按用户体验为状态更新选择优先级。

完成本节后，应当能够判断这一能力的适用边界，并在 TypeScript 项目中解释相关代码为什么正确。

## 二、核心知识

| 序号 | 必须掌握的结论 |
|------|----------------|
| 1 | 输入、点击和直接反馈属于紧急更新，应立即响应。 |
| 2 | 搜索结果、复杂图表和非关键区域可作为 Transition 更新。 |
| 3 | 低优先级渲染被新输入打断后可以基于最新状态重新开始。 |
| 4 | 优先级是调度信号，不是业务任务队列或网络请求优先级。 |

## 三、理解与应用

学习本节时，应把知识放回“输入、渲染、提交、用户交互”这条主线中理解。先确认数据由谁拥有，再判断组件在渲染阶段读取什么、在事件阶段修改什么，以及是否需要在提交后与外部系统同步。

::: tip 学习方法
不要只记忆 API 形式。请尝试画出数据来源、组件边界和更新触发点，再说明 React 为什么需要当前约束。
:::

## 四、实践任务

1. 在独立分支或练习目录中创建一个最小示例，只验证“更新优先级与可中断渲染”这一项能力。
2. 为示例补充正常路径、空值或空列表、重复操作三个场景。
3. 开启 TypeScript 严格检查，消除非必要的类型断言和非空断言。
4. 使用 React Developer Tools 观察组件输入、状态和渲染变化。

- [ ] 能用自己的语言说明：搜索结果、复杂图表和非关键区域可作为 Transition 更新。
- [ ] 能用自己的语言说明：低优先级渲染被新输入打断后可以基于最新状态重新开始。
