# 单元测试与组件测试

## 一、学习目标

使用 Vitest 与 Testing Library 验证用户可观察行为。

完成本节后，应当能够判断这一能力的适用边界，并在 TypeScript 项目中解释相关代码为什么正确。

## 二、核心知识

| 序号 | 必须掌握的结论 |
|------|----------------|
| 1 | 测试通过角色、标签和可见文本查询界面，减少对 DOM 结构的耦合。 |
| 2 | 优先覆盖 Reducer、自定义 Hook 和关键用户流程。 |
| 3 | 异步断言应等待可观察结果，不能依赖实现细节或固定渲染次数。 |
| 4 | 网络依赖通过 MSW 等边界工具模拟成功、失败和延迟。 |

## 三、理解与应用

学习本节时，应把知识放回“输入、渲染、提交、用户交互”这条主线中理解。先确认数据由谁拥有，再判断组件在渲染阶段读取什么、在事件阶段修改什么，以及是否需要在提交后与外部系统同步。

::: tip 学习方法
不要只记忆 API 形式。请尝试画出数据来源、组件边界和更新触发点，再说明 React 为什么需要当前约束。
:::

## 四、实践任务

1. 在独立分支或练习目录中创建一个最小示例，只验证“单元测试与组件测试”这一项能力。
2. 为示例补充正常路径、空值或空列表、重复操作三个场景。
3. 开启 TypeScript 严格检查，消除非必要的类型断言和非空断言。
4. 使用 React Developer Tools 观察组件输入、状态和渲染变化。

## 五、验收标准

- [ ] 能用自己的语言说明：测试通过角色、标签和可见文本查询界面，减少对 DOM 结构的耦合。
- [ ] 能用自己的语言说明：优先覆盖 Reducer、自定义 Hook 和关键用户流程。
- [ ] 能用自己的语言说明：异步断言应等待可观察结果，不能依赖实现细节或固定渲染次数。
- [ ] 能用自己的语言说明：网络依赖通过 MSW 等边界工具模拟成功、失败和延迟。
- [ ] 示例在刷新、重复交互和边界输入下行为一致。
- [ ] 能指出至少一个不适合使用本节能力的场景。
