# ES6面试题

ECMAScript 定义 JavaScript 的语言规则，ES6 即 ES2015。实际面试常把其后新增的语法也放在“ES6”题目中，但回答时仍需区分引入版本、语言行为与浏览器或 Node.js 的加载规则。

## 一、版本、作用域与函数

先区分标准版本，再说明变量绑定和函数调用的行为。语法简写不能代替作用域、this 与输入边界的解释。

### 1. ES2015 为何改变 JavaScript 的代码组织方式，如何判断特性归属？

#### 1.1 ES2015 的能力与用途

1. **ES6 的主要变化是块级作用域、函数与数据表达、集合、迭代协议、Promise 和标准模块。** 新语法的价值是明确约束与组织方式，不只是让代码更短。

   | 版本 | 代表特性 | 解决的问题 |
   |------|----------|------------|
   | ES2015 | let、const、箭头函数、解构、模板字符串 | 作用域与值表达 |
   | ES2015 | class、Symbol、Map、Set、Iterator、Generator | 对象组织与集合遍历 |
   | ES2015 | Promise、import、export | 异步结果与模块依赖 |
   | ES2017 | async、await | 使用顺序式语法消费 Promise |
   | ES2018 | 对象 rest/spread、Promise.finally | 对象属性提取与收尾 |
   | ES2020 | 可选链、空值合并、动态 import、allSettled | 空值与加载、异步结果组合 |
   | ES2021 | Promise.any | 获取第一个成功结果 |

#### 1.2 标准年份和运行环境

1. **判断依据：** ES6 即 ES2015，讨论特性归属应看规范引入年份，而不是语法是否“现代”。`Object.keys` 和 `Array.isArray` 在 ES5 已有；`async/await`、可选链等也不属于 ES2015。项目还要按目标运行环境检查支持情况，语法转译与 API 补充实现是不同工作。

::: info 规范版本与运行环境分开回答
特性写入某版 ECMAScript，只说明语言规则何时标准化；浏览器、Node.js 和构建工具各有自己的支持时间。面试题问“ES6 新增”时，应先限定为 ES2015，再讨论项目兼容性。
:::

参考：[TC39：ECMAScript 规范](https://tc39.es/ecma262/)。

### 2. let、const 为何有暂时性死区，const 究竟限制了什么？

#### 2.1 作用域与初始化规则

1. **var 主要是函数作用域，let、const 是块级作用域；const 限制绑定重赋值，不限制对象内部修改。** let、const 在初始化前处于暂时性死区，不能概括为“完全没有提升”。

   | 规则 | var | let | const |
   |------|-----|-----|-------|
   | 普通作用域 | 函数或全局 | 块 | 块 |
   | 初始化前读取 | 通常为 undefined | ReferenceError | ReferenceError |
   | 同一作用域重复声明 | 部分场景允许 | 不允许 | 不允许 |
   | 重赋值 | 允许 | 允许 | 不允许 |
   | 初始化 | 可以延后赋值 | 可以延后赋值 | 普通声明时必须有初值 |

#### 2.2 暂时性死区及实际边界

1. **本质原因：** `let`、`const` 的绑定在进入作用域时已存在，但初始化前不能读取，这段区间就是暂时性死区；`var` 的绑定则会先初始化为 undefined。因此“没有提升”不是准确解释。`const` 限制绑定重赋值，不深度冻结对象。

2. **场景与边界：** 循环创建回调时，`var` 常使回调共享最终索引，`let` 的循环绑定可保留每次迭代的关联。浏览器经典脚本顶层的 `var` 通常会成为 `window` 属性，模块和 Node 不应照搬；暂时性死区内即使用 `typeof` 也会报错。

参考：[MDN：let](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/let)、[MDN：const](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/const)。

### 3. 箭头函数与普通函数有何区别，哪些场景不适合箭头函数？

1. **箭头函数不创建自己的 this、arguments、super 和 new.target 绑定，相关引用来自外层环境。** 它不能被 new 构造，也不能作为 Generator 函数。

   | 场景 | 选择依据 |
   |------|----------|
   | 数组转换、需要使用外层 this 的回调 | 箭头函数通常简洁 |
   | 方法需要调用时的接收者 this | 使用普通方法或函数 |
   | 构造函数 | 箭头函数不适用 |
   | 需要函数自己的 arguments | 普通函数，或使用 rest 参数替代 |

   以下独立片段可在现代浏览器控制台执行：

   ```javascript
   const order = {
     id: "A-42",
     /** 返回捕获当前订单上下文的读取函数，不修改订单。 */
     createReader() {
       /** 读取外层方法的 this；返回订单号。 */
       return () => this.id;
     }
   };
   console.log(order.createReader().call({ id: "B-17" })); // A-42
   ```

2. call 无法覆盖箭头捕获的 this。箭头仍然是函数对象，也有自己的对象原型链；“没有用于构造的 prototype”不能写成“没有原型链”。

参考：[MDN：箭头函数](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/Arrow_functions)。

### 4. bind 是否延迟异步执行，箭头函数可以重新绑定 this 吗？

1. **bind 同步返回新函数，不自动安排异步执行；箭头函数的词法 this 不能被重新绑定。** “以后再调用”与“由异步机制调度”不是同一个概念。

2. 例如给普通订单对象方法绑定 this 后传给计时器：异步来自计时器，而不是 bind。call、apply 则在当前调用中立即执行原函数，分别以独立参数或数组式参数传入。

   | 常见判断 | 正确结论 |
   |----------|----------|
   | bind 后函数会自动运行 | 不会，需要调用返回值 |
   | 再次 bind 可以更换已绑定函数的 this | 普通调用时原绑定仍有效 |
   | 箭头函数 call 到新对象就换 this | 不会，仍取外层 this |

3. 绑定函数还可以预设部分参数。被 new 调用时有单独的构造行为，不能无条件认为绑定 this 永远优先。基本调用示例见 [JS 的 this 与绑定题目](./03-javascript.md)。

参考：[MDN：Function.bind()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/bind)。

## 二、数据表达与类

数据表达题应说明值如何被提取、展开和组合，以及类如何依托原型组织行为。

### 1. 解构默认值何时生效，如何重命名和处理缺失对象？

#### 1.1 默认值与属性重命名

1. **解构从数组位置或对象属性提取值，默认值只在提取结果为 undefined 时生效。** null、零和空字符串不会自动使用默认值。

   在控制台执行以下独立片段：

   ```javascript
   const { quantity = 1, id: orderId } = { quantity: 0, id: "A-42" };
   console.log(quantity, orderId); // 0 A-42
   const { status = "pending" } = { status: null };
   console.log(status); // null
   const { city = "未填写" } = undefined ?? {};
   console.log(city); // 未填写
   ```

#### 1.2 缺失对象和输入约束

1. `id: orderId` 把属性 id 读取到新变量 orderId，不声明变量 id。嵌套解构要求对应中间对象存在，直接解构 null 或 undefined 会抛错。

2. 例如接口允许缺少 address，可以先明确空值策略，再解构 `address ?? {}`。默认参数同样只在参数缺失或 undefined 时生效，不会自动验证输入类型。

参考：[MDN：解构](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Destructuring)。

### 2. 展开语法与 rest 参数有什么区别，复制会递归吗？

#### 2.1 展开与收集的位置区别

1. **展开将已有内容展开到新位置，rest 把剩余内容收集起来。** 数组和调用位置依赖迭代协议，对象展开处理可枚举自身属性，二者不能混用规则。

   | 写法 | 行为 |
   |------|------|
   | `[...orders]` | 消费可迭代对象，生成数组 |
   | `submit(...args)` | 把可迭代值展开为实参 |
   | `function submit(...args)` | 将剩余实参收集为真正的数组 |
   | `{ ...order }` | 复制可枚举自身属性，ES2018 |
   | `const { id, ...rest } = order` | 收集未提取的自身可枚举属性，ES2018 |

#### 2.2 浅复制与迭代边界

1. rest 参数必须放在最后，不是 arguments 那样的类数组对象。只具有 length 和数字键的对象不一定能用数组展开，但可按规则用 Array.from 转换。

2. 展开也是浅复制；嵌套 address 仍可能与原对象共享。属性覆盖按书写顺序决定，完整复制边界见 [JS 对象复制题目](./03-javascript.md)。

参考：[MDN：展开语法](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Spread_syntax)、[MDN：剩余参数](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/rest_parameters)。

### 3. 模板字符串与标签模板分别解决什么问题？

#### 3.1 模板文本与标签函数

1. **模板字符串支持插值和多行文本，标签模板把模板的固定部分与插值交给函数处理。** 插值生成的是文本，不会自动完成 HTML 转义。

   以下独立代码可在控制台执行：

   ```javascript
   const orderId = "A-42";
   console.log(`订单：${orderId}`); // 订单：A-42
   ```

#### 3.2 插值安全与协议边界

1. 标签模板形式如 `format` 后接模板，标签函数会收到字符串片段以及对应的插值。它可以用于格式化或领域表达，但是否安全取决于标签函数的实现，不是语法本身保证。

2. 把用户姓名插入模板后赋给 innerHTML，仍会解析不可信标记。显示普通文字应使用 textContent 或框架的安全文本绑定；模板字符串也不是 JSON、SQL 等数据协议的替代。

参考：[MDN：模板字符串](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Template_literals)。

### 4. class 改变了原型继承模型吗，extends 与 super 有什么作用？

1. **class 基于 JavaScript 原型机制组织构造和方法，同时增加类专用的语义约束。** 它不是另一套脱离原型的对象系统，也不能概括为完全等价于任意普通函数。

2. 类的实例方法通常位于类的 prototype，静态方法位于类本身。extends 建立继承关系；派生构造函数在使用 this 前通常要先调用 super，完成父类初始化。

   | 规则 | 说明 |
   |------|------|
   | 创建实例 | 普通类需要通过 new 调用 |
   | 类方法 | 采用严格模式，通常不可枚举 |
   | 静态成员 | 通过类访问，不自动成为实例方法 |
   | 初始化前访问 | 类声明有暂时性死区限制 |

3. 订单和预售订单可以共享公共行为，但继承应表达稳定的关系，不能为了复用几行代码形成很深的层级。私有字段 `#name` 是后续标准能力，不能全部归入 ES2015。

参考：[MDN：类](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes)。

## 三、集合与迭代

集合题需要明确键或成员的身份规则，迭代题需要区分属性枚举与迭代协议。

### 1. Symbol 为什么能避免属性冲突，Symbol.for() 又有何不同？

#### 1.1 Symbol 的唯一性

1. **每次 Symbol 创建的新值通常不同，描述文字相同也不会相等；Symbol.for 使用全局符号注册表复用同名符号。** 描述便于调试，不是唯一性的比较依据。

   独立片段可在控制台执行：

   ```javascript
   console.log(Symbol("order") === Symbol("order")); // false
   console.log(Symbol.for("order") === Symbol.for("order")); // true
   const internalStatus = Symbol("status");
   const order = { [internalStatus]: "pending", id: "A-42" };
   console.log(Object.keys(order)); // ["id"]
   console.log(Object.getOwnPropertySymbols(order).length); // 1
   ```

#### 1.2 共享注册表与属性使用

1. Symbol 键不会出现在 Object.keys 和普通 JSON 序列化结果里，但可以被反射 API 获取，因此不是保密机制。可枚举 Symbol 键仍能被对象展开和 Object.assign 复制。

2. `Symbol.iterator` 等内置符号提供协议入口，作用不同于单纯防止业务字段冲突。是否采用注册表还需考虑不同模块有意共享标识的需求。

参考：[MDN：Symbol](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol)。

### 2. for...in 与 for...of 遍历的是什么，普通对象能直接 for...of 吗？

1. **for...in 遍历可枚举字符串属性键，包含继承属性；for...of 消费可迭代对象的值。** 普通记录默认没有迭代协议，不能直接 for...of。

   | 对象 | 合适用法 | 边界 |
   |------|----------|------|
   | 数组 | for...of、数组迭代方法 | for...in 还可能包含额外属性，键是字符串 |
   | 普通记录 | Object.keys、Object.entries | 只取自身的相应可枚举字符串键 |
   | Map | for...of 得到 `[key, value]` | 顺序由迭代器决定 |
   | 字符串 | for...of 按迭代协议取字符 | 不等于按 UTF-16 单元索引切分 |

   可在控制台执行以下独立片段：

   ```javascript
   const order = { id: "A-42", status: "paid" };
   for (const [key, value] of Object.entries(order)) {
     console.log(key, value);
   }
   ```

   输出分别为 `id A-42`、`status paid`。遍历顺序不能粗暴说成“对象无序、for...of 永远按索引”，应按属性规则或迭代器定义分析。外部键值数据还需处理继承与不可信属性。

参考：[MDN：for...in](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/for...in)、[MDN：for...of](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/for...of)。

### 3. Iterator 与 Generator 有何关系，调用生成器会立即执行函数体吗？

#### 3.1 迭代协议与生成器执行

1. **Iterator 是逐步取得值的协议，Generator 是编写这种迭代过程的一种语法。** 调用生成器函数获得生成器对象，函数体在调用 next 时继续执行。

   下面的完整独立片段可在控制台执行：

   ```javascript
   /** 按处理顺序提供订单状态；返回可迭代的生成器对象。 */
   function* orderStages() {
     yield "created";
     yield "paid";
   }
   const stages = orderStages();
   console.log(stages.next()); // { value: "created", done: false }
   console.log(stages.next()); // { value: "paid", done: false }
   console.log(stages.next()); // { value: undefined, done: true }
   ```

#### 3.2 惰性求值的使用边界

1. next 的结果包含 value 与 done；可迭代对象通过 `Symbol.iterator` 提供迭代器。Generator 允许暂停、继续和接收 next 传入的值，但不等于自动异步执行。

2. for...of 不把 done 为 true 的最终返回值当成普通迭代项。异步迭代及 for await...of 是后续能力，不能把同步生成器中的 yield 当作 await。

参考：[MDN：迭代器与生成器](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Iterators_and_generators)。

### 4. Set 与 Map 怎样判断重复，查找一定是 O(1) 吗？

1. **Set 保存唯一值，Map 保存键值条目，二者按 SameValueZero 规则判断成员或键相同。** NaN 视为相同，正负零视为相同，对象仍按身份判断。

   下面的独立片段可在控制台执行：

   ```javascript
   console.log(new Set([1, 1, NaN, NaN, 0, -0]).size); // 3
   console.log(new Set([{ id: 1 }, { id: 1 }]).size); // 2
   const order = { id: "A-42" };
   const states = new Map([[order, "paid"]]);
   console.log(states.get(order)); // paid
   console.log(states.get({ id: "A-42" })); // undefined
   ```

2. 两个相同字段的对象不会自动去重，按订单号去重需显式选择业务键。Set.forEach 的前两个参数都是成员值，Map.forEach 则是 value、key，不能反着描述。

   ::: warning 性能复杂度不能由名称决定
   规范要求平均访问时间具有相应的次线性特征，不指定必须使用哈希表，也不保证所有操作恒为 O(1)。把 Map 查找统一写成 O(log n) 同样不准确，应看实现与测试数据。
   :::

参考：[MDN：Set](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set)、[MDN：Map](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map)。

### 5. WeakMap、WeakSet 的弱引用指什么，为什么不能遍历？

#### 5.1 弱键关联与可回收性

1. **WeakMap 不因键关联本身阻止该键被回收，WeakSet 对成员有对应的弱关联。** 它们不能公开稳定的枚举和 size，否则程序可观察不可预测的回收时机。

   | 容器 | 关联内容 | API 边界 |
   |------|----------|----------|
   | WeakMap | 键与任意值 | 有 get、set、has、delete，没有枚举和 clear |
   | WeakSet | 成员存在性 | 有 add、has、delete，没有枚举和 size |

#### 5.2 不可遍历的原因

1. ES2015 中主要使用对象作为弱键或成员；后续标准允许非注册 Symbol，目标运行时必须支持。不能说当前规则永远只接受对象，也不能把 `Symbol.for()` 的注册符号当弱键。

2. 例如给 DOM 节点附加内部元数据，可考虑 WeakMap，避免关联表成为节点唯一的强保留来源。但如果全局数组仍保存节点，节点仍可达，不会因为另有 WeakMap 就自动消失。

3. 回收并非外部引用清空后立即发生，也不适合承担必须执行的关闭文件、清理连接等逻辑。资源释放需要明确生命周期。

参考：[MDN：WeakMap](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap)、[MDN：WeakSet](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakSet)。

### 6. 类数组转换、数组构造与对象填充为何不能混用？

#### 6.1 类数组与数组构造的结果

1. **Array.from 把可迭代或类数组数据转换成数组，Array.of 把参数作为元素，fill 将同一个值写入指定位置。** 三者均在 ES2015 提供，但不承担同一种任务。

   控制台可执行以下独立片段：

   ```javascript
   console.log(Array.of(3)); // [3]
   console.log(new Array(3).length); // 3，元素位置为空
   console.log(Array.from({ 0: "A-42", length: 1 })); // ["A-42"]
   const rows = new Array(2).fill({ status: "pending" });
   rows[0].status = "paid";
   console.log(rows[1].status); // paid
   ```

#### 6.2 转换与填充值的边界

1. **共享身份：** `fill` 在每个位置写入同一个对象引用，修改任一项的属性会影响其他项。需要独立订单记录时，让 `Array.from` 的映射函数在每次调用中创建新对象。

2. **输入协议：** 数组展开要求可迭代，`Array.from` 也可处理具有 `length` 的类数组；两者不能因为结果都像数组就互换。`Array.of(3)` 创建单元素数组，而 `Array(3)` 创建长度为 3 的稀疏数组。先辨别输入协议、构造意图和元素是否需要独立。

::: warning 数组有多个位置不代表有多个对象
`Array(3).fill({ status: "pending" })` 的三个位置都指向同一对象。要生成相互独立的记录，需要在每次迭代中创建对象，而不是复制数组外壳。
:::

参考：[MDN：Array.from()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/from)、[MDN：Array.of()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/of)、[MDN：fill()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/fill)。

## 四、异步与错误传播

异步题围绕任务启动时机、结果组合和错误传播展开，不能只比较不同写法是否更简洁。

### 1. Promise 链为什么要 return，catch 和 finally 如何影响结果？

1. **then 返回新的 Promise；回调的返回值、返回 Promise 或抛错决定后续链的状态。** 少写 return 会使后续链无法等待你启动的那项工作。

#### 1.1 结果与错误如何传播

1. 在空目录创建 `promise-chain.mjs`，用 Node.js 22 或更高版本执行 `node promise-chain.mjs`：

   ::: details 查看 promise-chain.mjs 的完整错误恢复示例

   ```javascript
   // promise-chain.mjs
   /** 把编号转成订单记录；返回最小订单对象。 */
   function createOrder(id) { return { id, status: "pending" }; }
   /** 模拟支付失败；始终抛错，不返回正常值。 */
   function failPayment(order) { throw new Error(`支付失败：${order.id}`); }
   /** 记录失败并转成可重试状态；返回恢复值。 */
   function recoverPayment(error) {
     console.log(error.message);
     return "retryable";
   }
   /** 输出最终链结果；无返回值。 */
   function reportResult(value) { console.log(value); }
   await Promise.resolve("A-42")
     .then(createOrder)
     .then(failPayment)
     .catch(recoverPayment)
     .then(reportResult);
   ```

   :::

   预期输出说明 catch 返回值会让后续链恢复成功，而不再保持拒绝：

   ```text
   支付失败：A-42
   retryable
   ```

2. **错误传播：** `catch` 回调正常返回就把链恢复为成功；需要继续传播失败时应重新 `throw` 或返回拒绝 Promise。只输出日志会改变链的结果，不能当作“记录后继续失败”。

#### 1.2 finally 是否替换原结果

1. finally 用于无论成功或失败都执行的收尾，通常保留原结果，也不接收成功值或失败原因。若 finally 抛错或返回最终拒绝的 Promise，则后续结果会改为这次失败。

2. Promise executor 同步执行，then 后续回调使用微任务；带 then 的 thenable 可以被采用，但并不因此一定是内置 Promise 实例。创建请求、消费结果和取消请求应分别处理。

::: tip 先画出每一段返回的 Promise
面试推导顺序是：`then` 回调返回了什么、是否抛错、`catch` 是否恢复、`finally` 是否抛出新错误。忘记 `return` 时，外层链无法等待回调启动的内部异步工作。
:::

参考：[MDN：使用 Promise](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Using_promises)、[MDN：finally()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/finally)。

### 2. async/await 暂停的是哪段执行，并发取决于什么？

1. **async 函数返回 Promise，await 暂停的是当前异步函数的继续执行，不是整个线程。** 但 await 之前的同步计算仍会阻塞所在执行线程。

2. **并发条件：** 先 `await` 第一个请求的完成再创建第二个请求，会形成串行依赖；先创建两个请求再等待结果，才有机会并发。`Promise.all` 负责组合已创建的工作，不会把同步 CPU 计算变成多线程。

   | 写法思路 | 行为 |
   |----------|------|
   | `await loadOrder()` 后再调用 `loadInventory()` | 后一个任务较晚启动 |
   | 先调用两个任务，再用 Promise.all 等待 | 两个异步操作可以同时进行 |
   | 前一个结果是后一个的参数 | 应保持必要顺序 |

3. await 遇到拒绝会在当前函数中抛出，可用 try/catch 处理；未捕获时，该 async 函数返回的 Promise 拒绝。await 普通值也会安排异步继续，不能用它强制把后续逻辑变成同步。

   ::: tip 并发需要资源与业务约束
   批量上传不能无上限启动全部任务；要限制并发数、处理取消和部分失败。async/await 是 ES2017 语法，不自动带来并行计算或更高性能。
   :::

参考：[MDN：async 函数](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/async_function)、[MDN：await](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/await)。

### 3. all、allSettled、race 和 any 的完成条件有何区别？

#### 3.1 四种组合的完成条件

1. **四者组合多个异步结果，但成功与失败条件不同。** all 和 race 属于 ES2015，allSettled 属于 ES2020，any 属于 ES2021。

   | 方法 | 成功条件 | 失败或等待边界 |
   |------|----------|----------------|
   | Promise.all | 全部成功，结果按输入顺序 | 任一拒绝则整体拒绝，其他操作不会自动取消 |
   | Promise.allSettled | 全部结算，返回每项状态 | 不因单项拒绝使聚合结果拒绝 |
   | Promise.race | 首个结算的成功结果 | 首个结算为拒绝时整体拒绝 |
   | Promise.any | 首个成功结果 | 全部拒绝时抛 AggregateError |

   控制台可执行以下片段，查看部分失败的结果结构：

   ```javascript
   const results = await Promise.allSettled([
     Promise.resolve("订单已加载"),
     Promise.reject(new Error("库存不可用"))
   ]);
   console.log(results[0].status, results[0].value); // fulfilled 订单已加载
   console.log(results[1].status, results[1].reason.message); // rejected 库存不可用
   ```

#### 3.2 失败处理和使用场景

1. 订单和库存必须都成功才能提交时可用 all；仪表盘允许部分区域失败时可用 allSettled。使用 race 做超时还要中止实际请求，否则旧请求可能继续占资源和产生副作用。

2. 空集合也有差异：all、allSettled 得到成功的空结果，any 拒绝，race 一直等待。then 回调仍不会变成同步直接调用。

参考：[MDN：Promise 组合](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Using_promises#composition)。

## 五、模块与构建

模块题需要区分语言绑定、宿主加载规则与构建工具的优化，运行时加载不等于构建时删除代码。

### 1. ESM 为什么能够静态分析，导入值为何能随导出变化？

#### 1.1 模块声明与静态依赖

1. **静态 import/export 使依赖关系可分析，导入名关联到导出绑定，能看到该绑定后续的变化。** 导入名不是可以随意重赋值的局部副本。

   在空目录创建以下两个文件，使用 Node.js 22 或更高版本执行：

   ```powershell
   node main.mjs
   ```

   `order-count.mjs` 保存导出状态：

   ```javascript
   // order-count.mjs
   export let count = 0;
   /** 记录订单；无返回值，递增模块内部计数。 */
   export function recordOrder() { count += 1; }
   ```

   `main.mjs` 读取同一绑定：

   ```javascript
   // main.mjs
   import { count, recordOrder } from "./order-count.mjs";
   console.log(count);
   recordOrder();
   console.log(count);
   ```

   预期输出说明导入 count 可以观察导出端的修改：

   ```text
   0
   1
   ```

#### 1.2 实时绑定与加载边界

1. **绑定语义：** 静态导入写在模块顶层，使工具在执行前识别依赖；导入名引用导出绑定，因此可观察导出方后续更新，但导入方不能直接重赋该绑定。导出对象的属性若可变，修改属性是另一回事。

2. **工程后果：** 静态依赖有利于构建分析，但不保证任意未使用代码都能移除。循环依赖可建立，过早读取尚未初始化的绑定仍会出错；要检查模块初始化顺序，而非只看导入语句能否解析。

::: tip 实时绑定不是对象属性的魔法同步
导入名关联到导出方的绑定：导出方更新变量，导入方下次读取可见新值。若只是解构一个普通对象的数字属性，得到的是当时的数值，不会自动成为 ESM 实时绑定。
:::

参考：[MDN：JavaScript 模块](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)。

### 2. ES Modules 与 CommonJS 的导出和加载有何区别？

#### 2.1 导出模型与求值时机

1. **ESM 是语言标准模块，CommonJS 是使用 require、module.exports 等接口的模块机制。** 关键差异是依赖分析、导出语义和宿主加载规则，不是“只能导出变量还是函数”。

   | 维度 | ESM | CommonJS |
   |------|-----|----------|
   | 写法 | import、export 语法 | require、module.exports 接口 |
   | 分析 | 静态 import 可提前分析依赖 | require 可按运行时条件调用 |
   | 导出 | 导出绑定 | module.exports 的值，可为对象或函数等 |
   | 作用域 | 模块作用域，自动严格模式 | Node 通常用模块包装函数组织作用域 |
   | 浏览器 | 原生模块脚本，加载需满足 MIME、CORS 等规则 | 通常依赖打包或适配 |

#### 2.2 互操作与运行环境

1. CommonJS 的属性读取不等于所有数据永远是副本：若保留导出对象，可以读到对象属性后续变化；解构出的普通数值不会自动变成实时绑定。

2. Node 的 ESM/CJS 互操作随版本演进，较新版本可对满足条件的同步 ESM 使用 require，含顶层 await 的模块不能简单这样加载。动态 import 返回 Promise，也可用于 CommonJS 场景。

3. 选定项目的模块模式后，要同时检查文件后缀、package.json 的 type、依赖导出约定和运行版本。不是加一行 import 就能把整个 CommonJS 工程自动转换为 ESM。

参考：[Node.js：CommonJS 与 ESM 互操作](https://nodejs.org/api/modules.html#loading-ecmascript-modules-using-require)。

### 3. 动态 import 与 Tree Shaking 分别改变加载时机还是产物内容？

#### 3.1 加载时机与分块示例

1. **动态 import 是运行时加载模块的语法，Tree Shaking 是构建时分析并移除可证明无用代码的过程。** 一个控制加载时机，另一个控制产物保留内容。

2. 有 `order-report.js` 模块并导出 renderReport 时，下面是页面 `app.js` 的局部入口，省略模块实现和调用按钮：

   ```javascript
   // app.js
   /** 用户请求报表时加载模块；返回 Promise，加载或渲染失败时拒绝。 */
   async function openReport() {
     const report = await import("./order-report.js");
     report.renderReport();
   }
   ```

#### 3.2 Tree Shaking 的成立条件

1. 调用方应显示加载和错误状态。打包器可以将动态导入变成独立分块，但动态路径、配置和部署资源地址会影响结果，不能只看源码就保证产物分块。

2. 静态 ESM 有利于 Tree Shaking，却不保证所有未使用代码都被删除：模块副作用、动态使用和工具配置会影响分析。错误声明 sideEffects 可能让必须执行的初始化被删除。

::: warning 分包不等于删掉代码
动态 `import()` 可能把模块放入后续加载的产物，但模块代码通常仍需下载；Tree Shaking 才尝试移除静态分析证实未使用的代码。两者均受构建配置和模块副作用影响，应检查产物验证。
:::

参考：[MDN：import()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import)、[webpack：Tree Shaking](https://webpack.js.org/guides/tree-shaking/)。

## 六、参数、代理与异步细节

### 1. 默认参数何时求值，为什么不能简单理解为 `x = x || 默认值`？

**默认参数仅在实参为 `undefined` 或缺失时求值，`null`、`0`、`false` 和空字符串都会保留。** 默认表达式按每次函数调用求值，可以引用前面参数，但参数作用域与函数体作用域并非总是同一个。

例如 `function price(amount = 100) { return amount; }`：`price()` 和 `price(undefined)` 得到 100，`price(0)` 得到 0，`price(null)` 得到 `null`。因此用 `amount || 100` 会错误地覆盖合法的 0。

::: tip 先确定“缺失”还是“假值”
需要以 `undefined` 表示未传值时用默认参数；业务明确要把空字符串、0 等也当作缺失时，才额外写显式归一化规则。
:::

参考：[MDN：默认参数](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/Default_parameters)。

### 2. Proxy 与 Reflect 如何协作，为什么代理不能违反对象不变量？

**Proxy 可拦截读取、设置等内部操作；Reflect 提供与这些操作对应的默认行为。** 代理常用于响应式追踪、访问控制或日志，但不能把它理解为“任意改写对象行为且没有限制”。

1. `get` trap 可记录读取依赖，再用 `Reflect.get(target, key, receiver)` 执行正常读取；传入 `receiver` 能让继承链上的 getter 使用正确接收者。
2. `set` trap 可校验或记录写入，按操作结果返回布尔值；在严格模式下返回 `false` 可能导致赋值抛错。
3. 对不可配置且不可写的数据属性，`get` trap 不能谎报不同的值。这类不变量保证对象底层约束不会被代理绕过。

代理是运行时机制，构建时的类型检查与 Tree Shaking 无法替它推断所有动态行为。出现意外值时，检查 trap 是否正确转发及是否触及不变量。

参考：[MDN：Proxy](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy)、[MDN：Reflect](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Reflect)。

### 3. `Promise.resolve()` 为什么会采用 thenable 的结果，而不是直接包成成功值？

**Promise 解析过程会检查传入值是否是 Promise 或可调用 `then` 的 thenable，并采用它最终的状态。** 因而 `Promise.resolve(Promise.reject(error))` 最终仍是拒绝，不能说外层“成功包住了错误”。

1. 普通值会得到已兑现的 Promise；原生同构造器 Promise 可直接返回已有实例。
2. thenable 的 `then` 可能异步确定结果，也可能抛错；解析过程需处理这些情况，防止多次确定结果。
3. `await` 也会等待 thenable 的最终结果。处理不可信 thenable 时，避免自己简化成“直接取 `.then` 调用一次”的手写实现。

面试追问“`Promise.all` 收到普通值怎么办”时，可顺着解析规则回答：普通值按已兑现项处理，但整体结果仍按 Promise 的异步规则交付。

参考：[MDN：Promise.resolve](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/resolve)、[ECMAScript：Promise Resolve Functions](https://tc39.es/ecma262/#sec-promise-resolve-functions)。

### 4. `async` 函数中的 `try/catch/finally` 怎样影响返回值和错误？

**`await` 等待的 Promise 拒绝时，在该位置抛出异常，可由周围 `catch` 处理。** 若未处理，`async` 函数返回的 Promise 拒绝；`finally` 无论前面成功还是失败都会执行。

1. `catch` 若正常返回一个值，函数最终兑现该值；若再次抛错，最终仍拒绝。
2. `finally` 常用于释放加载状态或资源，但其中的 `return` 或抛错会覆盖此前的返回或错误，容易隐藏真实失败。
3. 并发启动多个任务后，只等待其中一个，不代表其他任务失败已被处理；应根据业务选 `Promise.all`、`allSettled` 或分别接收结果。

::: warning 不要在 finally 中无意覆盖异常
支付请求失败后，若 `finally` 写了 `return true`，调用方就可能看到成功值。清理逻辑应只清理资源，不替代错误传播。
:::

参考：[MDN：async function](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/async_function)、[MDN：try...catch](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/try...catch)。

### 5. ES Modules 循环依赖为什么有时可用，有时出现初始化错误？

**ESM 导入是绑定到导出项的引用，模块依赖会先建立连接，再按依赖关系求值。** 循环依赖本身并非必然报错；关键是读取发生时，目标绑定是否已完成初始化。

1. 两个模块只在函数被调用时读取对方导出，且调用发生在双方初始化后，循环可能正常运行。
2. 如果某模块在顶层立即读取对方尚未初始化的 `let` 或 `const` 导出，可能触发暂时性死区错误。
3. 设计上应优先把共享常量或接口抽到独立模块，减轻初始化顺序和测试复杂度；不能靠改成动态 `import()` 掩盖所有循环关系。

排查时画出模块依赖和顶层执行顺序，定位首次读取的时刻，而不是只数 `import` 的行数。

参考：[MDN：import](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import)、[MDN：循环导入示例](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import#cyclic_imports)。
