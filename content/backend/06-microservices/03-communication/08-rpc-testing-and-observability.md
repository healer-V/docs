# RPC 测试与基础可观测性

远程调用测试不能全部依赖共享联调环境。Provider 与 Consumer 应在各自仓库快速验证契约，少量集成测试再覆盖 Eureka、LoadBalancer 和真实网络。可观测性需要区分业务错误、HTTP 错误和网络错误。

## 一、测试分层

- **业务单元测试**：不启动 Spring 和网络，验证产品规则、投保资格与错误转换。
- **Provider 接口测试**：启动 Web 层或应用，验证路径、参数、JSON、状态码和 ProblemDetail。
- **Consumer 测试**：把 Feign 固定 URL 指向 WireMock，验证请求构造、响应解码、超时和错误映射。
- **契约测试**：用消费者期望生成或维护契约，并由 Provider 验证实现仍满足这些期望。
- **本地联调**：启动 Eureka、Provider 和 Consumer，验证服务名解析、实例选择和完整调用链。

每一层测试回答的问题不同，不能用少量端到端用例替代前面的快速反馈：

| 测试层 | 主要回答 | 不负责证明 |
|--------|----------|------------|
| 业务单元测试 | 规则、分支和本地异常转换是否正确 | HTTP 映射和 JSON 格式 |
| Provider 接口测试 | 路径、状态码、成功与错误响应是否符合契约 | Consumer 是否正确解码 |
| Consumer Stub 测试 | 请求编码、超时和错误映射是否符合预期 | Eureka 与真实网络行为 |
| 契约测试 | Provider 与已登记 Consumer 的边界是否兼容 | 完整业务流程和基础设施可用性 |
| 服务发现联调 | 服务名、实例选择和真实调用链是否打通 | 所有业务规则组合 |
| 少量端到端测试 | 关键用户流程能否跨组件完成 | 精确定位每个失败原因 |

测试失败应首先在最靠近责任边界的层次修复。若所有问题都只能在共享环境发现，说明本地契约或组件测试仍有缺口。

## 二、Provider 测试

- **正常响应**：验证产品编码对应的字段、金额格式、Content-Type 和 HTTP 状态。
- **参数错误**：缺失、超长和非法编码应返回稳定参数错误，不进入内部异常。
- **未找到错误**：验证 404 ProblemDetail 的 `type`、`code` 和安全 `detail`。
- **未知异常**：验证 5xx 不泄露堆栈、SQL 和内部地址，同时服务端日志保留追踪标识。

## 三、Consumer Stub 测试

- **WireMock 目标**：测试 Profile 为 `@FeignClient` 配置固定 URL，绕过 Eureka，精确控制响应和延迟。
- **请求验证**：检查 HTTP 方法、路径变量、查询参数、Content-Type 和受控请求头。
- **响应验证**：覆盖正常 JSON、缺失可选字段、新增未知字段和格式错误。
- **故障验证**：模拟 404、429、500、连接断开和延迟，确认异常分类和重试策略。

## 四、契约测试

- **Consumer 驱动**：Consumer 声明自己真正依赖的请求和响应，避免 Provider 只测试自认为正确的接口。
- **Provider 验证**：Provider 在 CI 中执行契约，破坏消费者的变更应直接失败。
- **契约不是完整业务测试**：契约验证边界交互，不替代 Provider 内部规则和数据库测试。
- **版本管理**：契约制品与服务版本关联，不能使用会漂移的未发布内容。

## 五、服务发现集成测试

- **多实例**：启动两个 Provider 实例，验证 Consumer 通过服务名调用并观察实例分配。
- **实例下线**：分别测试优雅停机和强制终止，记录缓存传播与失败时间窗。
- **Eureka 故障**：中断 Server，确认已有实例列表仍可使用，同时控制面错误能够被发现。
- **无实例**：停止全部 Provider，验证 Consumer 返回明确依赖不可用错误。

## 六、日志字段

- **调用方**：记录目标服务、接口、结果分类、耗时、实例标识和追踪标识，不记录敏感请求体。
- **Provider**：记录调用方身份、接口、业务结果和处理耗时，使双方能够对齐时间线。
- **错误分类**：使用固定分类，例如 `no_instance`、`connect_timeout`、`read_timeout`、`http_4xx`、`http_5xx` 和 `decode_error`。
- **避免重复堆栈**：异常在负责处理和告警的边界记录一次完整堆栈，上层只记录必要上下文。

## 七、指标

- **RED 指标**：记录请求率、错误率和延迟，并按目标服务与接口聚合。
- **实例维度**：诊断负载不均和单实例故障时需要实例维度，但长期指标标签需控制基数。
- **重试指标**：区分逻辑调用和实际尝试次数，识别重试放大。
- **连接池**：观察活动连接、空闲连接、等待线程和池获取超时，判断慢调用是否已形成资源饱和。

## 八、追踪

- **传播上下文**：Feign 拦截器传播标准追踪上下文，Provider 继续创建子 Span。
- **错误标记**：Span 标记错误类型和 HTTP 状态，不写入客户号、手机号和完整请求体。
- **采样边界**：采样意味着并非每次调用都有 Trace，指标和日志仍是基础证据。
- **时间同步**：服务节点保持时钟同步，避免跨服务时间线出现明显倒序。

## 九、Feign 日志

- **NONE**：不记录 Feign 请求详情，适合生产默认且已有统一观测拦截器的环境。
- **BASIC**：记录方法、URL、状态和耗时，仍需检查 URL 查询参数是否含敏感信息。
- **HEADERS 与 FULL**：可能输出认证、Cookie 和正文，只能在受控环境短时启用并配置脱敏。
- **日志级别联动**：配置 Feign Logger Level 后，还需要对应客户端 Logger 开启适当日志级别。

## 十、交付检查

### 1. 测试

- Provider 是否覆盖成功和错误契约；
- Consumer 是否模拟超时与非法响应；
- 契约是否由 Provider 在 CI 验证；
- 是否有最小真实服务发现联调。

### 2. 观测

- 是否区分业务、HTTP、网络和解码错误；
- 是否记录目标服务与耗时；
- 指标标签是否避免高基数；
- 日志和 Trace 是否完成脱敏。

### 3. 故障

- 无实例和超时是否快速失败；
- 重试次数是否可观察；
- Provider 下线传播时间是否经过测量。
