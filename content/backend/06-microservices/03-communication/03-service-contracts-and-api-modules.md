# 服务契约与 API 模块

服务契约不仅是 Java 接口，还包括 HTTP 方法、路径、字段、校验、错误、幂等、性能和版本行为。共享 API 模块可以提供类型检查，也会形成编译依赖和发布耦合，必须根据组织协作方式选择。

## 一、契约组成

- **请求契约**：定义路径、方法、参数位置、字段约束、Content-Type、认证和幂等要求。
- **成功响应**：定义状态码、字段语义、金额单位、时间格式、分页和空结果。
- **错误响应**：定义业务拒绝、参数错误、依赖失败和服务异常，说明哪些错误允许重试。
- **非功能契约**：调用量、最大响应、超时预算和可用性假设也会影响消费者设计。

## 二、契约所有权

- **Provider 拥有业务语义**：产品服务决定产品状态和错误含义，并对兼容演进负责。
- **Consumer 拥有使用模型**：调用方只定义自己需要的客户端视图，不应要求 Provider 暴露全部内部字段。
- **共同评审关键变化**：破坏性变化需要 Provider 与实际 Consumer 确认迁移方式，不能只在单方仓库编译通过。

## 三、DTO 边界

### 1. 专用契约类型

```java
// insurance-contracts/src/main/java/com/example/insurance/product/ProductSummary.java
package com.example.insurance.product;

import java.math.BigDecimal;

/**
 * 表示消费者查询产品时需要的稳定摘要。
 *
 * @param code 产品编码
 * @param name 产品名称
 * @param minimumPremium 最低保费，单位为元
 * @param saleEnabled 是否允许新投保
 */
public record ProductSummary(
        String code,
        String name,
        BigDecimal minimumPremium,
        boolean saleEnabled
) {
}
```

- **不共享实体**：JPA 实体包含延迟加载、持久化注解和内部关系，不是稳定远程契约。
- **不直接暴露内部枚举**：内部状态枚举扩展可能破坏旧消费者。契约应定义未知值策略或使用稳定编码。

## 四、三种组织方式

- **Consumer 自有客户端**：消费者自己定义 Feign 接口和需要的 DTO，Provider 通过 OpenAPI 或文档发布契约。双方编译解耦，但需要契约测试保证一致。
- **共享 DTO 模块**：Provider 发布稳定请求响应类型，Consumer 依赖制品。减少重复类型，但升级和兼容必须受版本管理。
- **共享 API 接口模块**：接口和 DTO 一起发布，适合公司内部统一 RPC 框架，但会让调用方依赖 Provider 的 Java 制品和发布节奏。

## 五、共享 API 模块边界

### 1. 可以包含

- 稳定接口与方法文档；
- 请求、响应和错误类型；
- 业务编码与兼容常量；
- 必要校验注解。

### 2. 不应包含

- Service 实现；
- JPA 实体和 Repository；
- 数据源、缓存和线程池配置；
- Provider 内部异常堆栈；
- 与运行环境绑定的地址和密钥。

- **依赖保持轻量**：API 模块不应传递整个 Spring Boot Starter 和数据库驱动，避免消费者被迫引入无关依赖。

## 六、接口粒度

- **面向业务操作**：`checkEligibility` 比通用 `execute` 更能表达输入、结果和错误语义。
- **避免聊天式接口**：一个业务页面需要连续调用十几个细粒度 Getter 时，应重新设计批量查询或消费者视图。
- **控制万能接口**：使用 Map 或任意 JSON 接收所有请求会失去类型、文档和兼容保护。

## 七、字段设计

- **金额**：明确币种、单位和精度，使用十进制类型，不使用浮点数表示保费。
- **时间**：区分时间点、日期和本地时间，明确时区和序列化格式。
- **可空字段**：说明缺失、null、空字符串和空集合分别代表什么。
- **标识**：使用稳定业务标识，不让消费者依赖数据库自增主键和可变编码格式。

## 八、行为契约

- **幂等**：说明重复请求是否返回同一结果，以及幂等键由谁生成和保存。
- **一致性**：说明响应是实时主数据、缓存、快照还是最终一致投影。
- **分页**：定义页大小上限、排序稳定性和游标失效行为。
- **权限**：Provider 仍需校验身份和授权，不能因为调用来自内网就信任所有参数。

## 九、版本发布

- **先兼容再升级**：Provider 先增加兼容字段或接口，发布 API 制品，再逐步升级 Consumer。
- **不使用快照版本**：Consumer 依赖不可变发布版本，避免同一版本号内容漂移。
- **记录消费者**：共享 API 模块需要维护消费者清单和旧版本调用量，才能安全删除契约。

常见契约变化需要按照消费者实际行为判断，而不是仅凭 JSON 能否反序列化：

| 变化 | 表面判断 | 真实风险 | 推荐迁移方式 |
|------|----------|----------|--------------|
| 增加可选响应字段 | 通常兼容 | 旧消费者必须忽略未知字段 | Provider 先增加，观察后再让 Consumer 使用 |
| 新增枚举值 | 容易被误判兼容 | 旧 Switch 或严格反序列化可能失败 | 提供 UNKNOWN 策略并测试旧消费者 |
| 字段改名 | 破坏性 | 新旧消费者无法同时读取 | 新旧字段并存，迁移后删除旧字段 |
| 改变金额单位 | 结构不变但语义破坏 | 产生静默业务错误 | 使用新字段或新版本，禁止原字段直接改义 |
| 更改错误码重试语义 | 破坏性 | Consumer 可能放弃或重复业务操作 | 保持旧错误语义，建立明确迁移窗口 |

共享 API 制品只能帮助发现 Java 类型变化，无法发现单位、默认行为、时效和幂等语义变化。契约评审与运行证据仍然不可替代。

## 十、Catfish 映射边界

- **公司 API 模块**：本地项目显示 Catfish 使用独立 API 与实现模块，这是共享 API 接口模式的一种企业实现。
- **不等同于共享实现**：消费者只应依赖 API 制品，不能依赖 `api-impl` 模块。
- **内部规则需查证**：注解继承、序列化、超时和错误码以 Catfish 内部文档与已验证代码为准，不能从 Feign 通用行为直接推断。
