# Eureka 架构与运行机制

Eureka 是服务注册与发现组件。服务实例向 Eureka Server 注册并续约，消费者从注册表获取实例列表。Eureka 优先保证注册信息在网络异常期间仍可读取，因此消费者必须接受注册表可能短暂陈旧。

## 一、核心角色

- **Eureka Server**：保存服务名、实例地址、状态和元数据，为客户端提供注册、续约、注销和查询 API。
- **Service Provider**：业务服务启动后作为 Eureka Client 注册自身，例如 `product-service` 的多个实例。
- **Service Consumer**：消费者也使用 Eureka Client 获取目标服务实例。一个应用可以同时是 Provider 和 Consumer。

## 二、注册信息

- **服务名**：服务名来自 `spring.application.name`，是调用方使用的逻辑标识。
- **实例地址**：实例上报主机、端口和协议。容器或多网卡环境必须确认上报地址能够被消费者访问。
- **状态与端点**：实例可以提供主页、状态页和健康检查地址，便于控制面和运维工具识别状态。
- **元数据**：版本、区域、权重和灰度标签可以附加到实例信息。元数据不应包含密钥或用户数据。

## 三、租约与心跳

- **租约模型**：注册不是永久记录。实例通过周期性续约表明自己仍然存活。
- **正常注销**：应用优雅停机时主动注销，注册表可以更快移除实例。
- **异常退出**：进程崩溃或网络隔离时无法注销，Server 需要在租约过期后判断实例失效。
- **时间窗口**：心跳、注册表拉取、客户端缓存和负载均衡缓存共同决定故障实例还能被看到多久，不能只调整一个参数推导最终效果。

## 四、客户端缓存

- **注册表副本**：客户端周期性获取注册信息并保存在本地，业务请求不必每次访问 Eureka Server。
- **可用性收益**：Eureka 短暂不可用时，消费者仍可使用已有实例列表处理请求。
- **陈旧风险**：下线实例可能暂时仍在缓存中。远程调用必须设置超时，并在适用时切换其他实例。

实例变化从 Provider 传播到真实调用通常经过多层时间窗口：

```text
Provider 注册、续约或注销
  → Eureka Server 注册表更新
    → Consumer Eureka Client 拉取注册表
      → LoadBalancer 实例供应与缓存更新
        → 下一次请求选择新的候选实例
```

因此，“Eureka 控制台已经删除实例”不能直接证明消费者已经停止调用。排查时应同时记录服务端注册表、消费者本地发现结果、LoadBalancer 选择日志和真实请求时间线。

## 五、实例剔除

- **剔除不是实时探测**：Eureka 主要依据续约和租约判断实例存在，不等同于对每个业务接口进行实时探测。
- **健康状态集成**：Spring Cloud Netflix 可以使用健康处理器上报应用状态，但仍需正确配置 Actuator 和端点可见性。
- **计划下线优先主动注销**：发布系统应先摘除流量和注销，不依赖租约自然过期完成正常发布。

## 六、自我保护

- **目标**：当短时间内大量续约丢失时，Eureka 会谨慎处理批量剔除，避免把网络分区误判为所有实例同时死亡。
- **取舍**：自我保护提高注册表可用性，但可能保留更多陈旧实例。调用方必须承担超时和失败切换责任。
- **不应随意关闭**：开发环境为了观察剔除可以调整策略，生产环境不能复制未经验证的教程参数。应结合节点、网络、发布和客户端缓存测试。

## 七、多节点部署

- **节点复制**：多个 Eureka Server 互相复制注册信息，客户端配置多个地址，避免单节点成为唯一控制面入口。
- **最终一致**：节点间复制需要时间，不应假设所有节点瞬时拥有相同注册表。
- **故障域**：节点应分布在合理故障域，并监控复制、续约和注册表规模。仅启动多个同机进程不等于高可用。

## 八、一致性模型

- **优先可用发现**：Eureka 设计倾向于在部分网络故障时继续提供注册表查询，而不是阻塞全部调用等待全局一致。
- **消费者承担验证**：实例出现在注册表中只表示它是候选目标，不保证本次网络请求一定成功。
- **业务状态不进入注册表**：库存、产品状态和用户资格等业务事实不应存入 Eureka 元数据代替业务服务。

## 九、生产观察项

| 观察项 | 需要识别的问题 |
|--------|----------------|
| 注册实例数 | 是否与部署期望一致 |
| 续约失败 | 网络、Server 容量或客户端异常 |
| 注册表拉取失败 | 消费者是否长期使用陈旧缓存 |
| 剔除数量 | 是否出现发布异常或网络分区 |
| Server 节点状态 | 节点复制与故障域是否有效 |

## 十、使用边界

- **不是负载均衡器**：Eureka 提供实例列表，具体选择由 Spring Cloud LoadBalancer 等客户端组件完成。
- **不是健康监控平台**：注册状态不能替代业务指标、日志和告警。
- **不是配置中心**：运行参数、密钥和业务开关应由 Apollo 等配置系统管理。

官方配置与版本差异以 [Spring Cloud Netflix Eureka](https://docs.spring.io/spring-cloud-netflix/reference/) 和 [Spring Cloud Netflix 配置属性](https://docs.spring.io/spring-cloud-netflix/reference/configprops.html) 为准。调整租约、自我保护或客户端拉取参数前，需要在目标版本和真实拓扑中验证组合效果。
