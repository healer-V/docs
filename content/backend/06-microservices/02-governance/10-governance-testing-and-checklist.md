# 服务治理测试与检查清单

服务治理不能只通过“控制台看到了实例”验收。可靠测试需要覆盖正常生命周期、状态传播延迟和控制面故障，验证应用在注册表陈旧、配置中心不可用和混合版本条件下的真实行为。

## 一、测试环境

- **版本固定**：记录 Java、Spring Boot、Spring Cloud、Eureka 和 Apollo Client 的完整版本。
- **拓扑明确**：至少包含 Eureka Server、两个 Provider 实例和一个 Consumer，才能验证实例变化和负载选择。
- **默认不依赖生产控制面**：本地与 CI 使用隔离 Eureka 和本地配置；Apollo 测试使用 Mock Server 或专用环境。
- **时间窗口可配置**：测试可以缩短心跳和缓存时间以提高反馈速度，但生产结论必须用生产参数重新演练。

## 二、注册测试

- **首次注册**：启动 Provider，验证服务名、实例 ID、地址、端口和元数据符合预期。
- **多实例**：启动两个端口不同的实例，确认它们属于同一服务名且都能被消费者发现。
- **重启**：重启实例后检查旧实例清理、新实例注册和调用恢复时间。
- **地址可达**：从 Consumer 所在网络实际访问注册地址，不只从 Provider 本机验证。

## 三、下线测试

- **优雅停机**：正常关闭 Provider，记录停止接流、注销、客户端列表更新和进程退出的顺序。
- **强制终止**：强制结束进程，观察租约、注册表和 LoadBalancer 缓存多久不再返回故障实例。
- **在途请求**：使用受控慢请求验证优雅关闭是否等待处理完成，超时退出时客户端得到什么结果。

## 四、健康测试

- **存活失败**：验证真正不可恢复的本地故障才影响 Liveness，短暂下游失败不触发重启循环。
- **就绪变化**：初始化和请求排空期间 Readiness 应反映实例暂不接流。
- **健康详情**：未认证访问不能获得数据库地址、异常堆栈或敏感配置。
- **Eureka 状态传播**：记录 Actuator 状态变化到消费者停止选择实例的实际延迟。

## 五、负载均衡测试

- **基本分配**：向同一服务连续发起请求，记录实例标识并验证选择策略。
- **实例加入**：运行中新增实例，观察消费者何时开始分配流量。
- **实例故障**：停止一个实例，确认调用超时、失败切换和错误指标符合策略。
- **无可用实例**：停止全部 Provider，Consumer 应返回明确的下游不可用结果，而不是无限等待。

## 六、Eureka 故障测试

- **Server 短暂中断**：已有 Consumer 是否继续使用本地注册表，业务调用是否维持。
- **新实例启动**：Server 不可用时新实例能否注册；恢复后多久进入注册表。
- **长时间中断**：监控注册、续约和拉取失败，确认告警不会被业务成功率掩盖。
- **节点故障**：多节点环境中验证客户端切换和节点间注册信息，而不是只测试进程存活。

## 七、Apollo 测试

- **启动加载**：验证 AppId、环境、集群和 Namespace 组合读取到预期值。
- **本地缓存**：在已有缓存和无缓存两种条件下断开 Config Service，确认启动策略不同且有日志和指标。
- **配置变化**：发布合法和非法值，验证监听、配置绑定、拒绝策略和回滚。
- **多实例收敛**：记录各实例收到新 Release 的时间，确保业务允许短暂新旧配置共存。
- **敏感信息**：检查启动日志、变更日志、Actuator 和错误响应没有输出配置值。

## 八、版本与灰度测试

- **混合版本矩阵**：测试旧 Consumer/旧 Provider、旧 Consumer/新 Provider、新 Consumer/旧 Provider和新 Consumer/新 Provider。
- **路由命中**：使用稳定灰度标识验证请求只进入目标实例组。
- **无匹配回退**：停止灰度实例，确认系统按设计回退稳定组或明确拒绝。
- **指标分组**：验证错误率、延迟和业务结果能够按版本与灰度组比较。

## 九、故障矩阵

| 故障 | 期望控制面行为 | 期望业务行为 |
|------|----------------|--------------|
| Eureka 短暂不可用 | 注册与拉取告警 | 已知实例可继续调用 |
| Provider 强制退出 | 租约最终清理 | 超时受控，其他实例继续服务 |
| Apollo 短暂不可用 | 配置同步告警 | 使用最近配置或安全默认值 |
| 非法配置发布 | 客户端拒绝或隔离 | 不把非法值扩散到业务 |
| 灰度错误升高 | 停止扩大并摘流 | 稳定组继续服务 |
| 无可用实例 | LoadBalancer 返回失败 | Consumer 返回明确不可用错误 |

## 十、交付检查

### 1. 配置

- 服务名、实例 ID 和环境是否标准化；
- Eureka 与 Apollo 地址是否由部署环境注入；
- 是否不存在生产地址和凭据硬编码。

### 2. 生命周期

- 是否具备正确健康端点；
- 是否先摘流、排空再退出；
- 强制退出时是否有受控错误。

### 3. 版本与发布

- 是否验证混合版本；
- 是否按版本观察指标；
- 灰度规则是否有回滚和清理计划。

### 4. 证据

- 测试是否记录命令、参数和时间线；
- 无法执行的 Apollo 或多节点测试是否明确列出；
- 结论是否来自实际运行而不是配置推断。
