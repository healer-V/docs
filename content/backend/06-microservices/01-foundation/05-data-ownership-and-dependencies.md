# 数据所有权与服务依赖

代码边界只有与数据边界一致时才具备独立演进能力。服务不一定独占数据库服务器，但必须独占业务数据的写入规则。其他服务通过公开契约读取或申请变更，不能绕过所有者直接操作表。

## 一、数据所有权

- **所有权是规则责任**：客户服务拥有客户资料，意味着只有它能够验证和修改客户主数据，并对字段语义、审计和兼容负责。
- **数据库实例不是唯一判断**：多个服务可以在迁移阶段共享同一数据库实例，但应使用独立 Schema、账号和权限，禁止跨边界写入。
- **读权限也要受控**：直接跨库读取会把表结构变成隐式公共 API。所有者无法安全调整字段、索引和存储方式。

## 二、Database per Service

- **逻辑隔离**：最低要求是独立 Schema 与数据库账号，使权限能够阻止越界访问。
- **物理隔离**：对容量、合规或故障域要求不同的服务，可以使用独立数据库实例。物理隔离会增加运维成本，不应机械采用。
- **独立迁移**：每个服务维护自己的数据库迁移脚本，并将迁移与应用兼容性纳入发布流程。

## 三、跨服务查询

- **实时 API 查询**：数据量小、需要较新结果且下游可用性满足要求时，可以同步调用数据所有者。
- **API Composition**：由聚合服务调用多个服务并组合结果。需要控制并行度、超时、部分结果和调用扇出。
- **只读投影**：通过事件或变更流构建面向查询的本地视图，降低实时依赖，但必须接受投影延迟并监控同步状态。
- **数据分析平台**：报表和分析不应通过线上服务逐条调用。通过合规的数据同步进入数仓或湖仓，避免影响交易链路。

查询方式应由实时性、可用性和数据规模共同决定：

| 业务要求 | 推荐方式 | 必须接受的代价 |
|----------|----------|----------------|
| 必须读取所有者的最新判断 | 实时 API | 调用方可用性和延迟受下游影响 |
| 页面需要组合少量实时数据 | API Composition | 需要并行调用、总超时和部分结果策略 |
| 高频查询允许秒级或分钟级延迟 | 本地只读投影 | 需要处理事件重复、乱序和投影落后 |
| 大规模统计与历史分析 | 数据平台 | 数据链路有延迟，不能直接承担在线交易判断 |

选择投影不代表数据所有权发生转移。投影只能按约定事件更新，并需要暴露数据版本或同步时间，防止调用方把旧数据误认为权威实时状态。

## 四、业务快照

- **保存发生时事实**：投保申请可以保存提交时的产品名称、版本和保障摘要。产品后续变化不应改写历史申请事实。
- **快照不是主数据复制**：快照只能用于其业务目的，不能被其他服务当作最新产品信息来源。
- **记录来源与版本**：快照应保留来源标识、业务版本和采集时间，便于审计和问题定位。

## 五、标识设计

- **服务内主键**：数据库主键服务于本地存储，不应默认成为跨服务业务标识。
- **业务标识**：保单号、投保单号等标识需要稳定、唯一并明确生成方。消费者不能推测其格式生成新值。
- **标识不可表达可变状态**：不要把渠道、地区或状态编码进必须长期稳定的标识，否则业务变化会迫使迁移标识体系。

## 六、依赖方向

- **识别上游与下游**：调用方依赖被调用方的契约和可用性。业务流程图应标出同步、异步和数据依赖。
- **控制调用扇出**：一个请求同步调用的服务越多，尾延迟和失败概率越高。聚合前应判断哪些数据可以缓存、批量获取或异步准备。
- **核心服务避免依赖边缘服务**：核心业务不应为了非关键增强能力同步依赖通知、推荐或统计服务。

## 七、循环依赖

- **形成原因**：边界不清、共享流程状态和双向数据查询容易形成 A 调 B、B 又调 A 的循环。
- **运行风险**：循环会放大故障传播，造成部署顺序、超时预算和版本兼容难题。

### 1. 解除循环依赖

- 重新聚合高度内聚的能力；
- 抽取真正独立的第三方能力；
- 调整流程所有者；
- 对非实时协作使用事件或投影。

## 八、共享库边界

- **可以共享的内容**：稳定协议类型、通用安全能力和可观测性基础设施可以形成受版本管理的库。
- **不应共享的内容**：JPA 实体、Repository、内部异常和业务服务实现不应跨服务共享。
- **共享接口仍是耦合**：公共 API 模块能提供编译期类型检查，也会让消费者依赖发布节奏。第三章将进一步讨论契约所有权。

## 九、检查清单

### 1. 所有权

- 核心数据是否只有一个写入方；
- 数据修改是否经过所有者业务规则；
- 是否存在跨服务数据库账号。

### 2. 查询

- 查询需要多新、多快的数据；
- 下游不可用时是否允许部分结果；
- 是否需要只读投影或分析平台。

### 3. 依赖

- 是否存在同步调用循环；
- 单请求扇出是否可控；
- 非核心依赖是否会阻断核心流程。
