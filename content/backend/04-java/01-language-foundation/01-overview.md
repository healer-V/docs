# Java 概述

Java 不只是编程语言。日常所说的“Java”通常同时指 Java 语言、Java 虚拟机、Java 标准库和 JDK 开发工具。先区分这四个层面，后续遇到语法错误、类加载失败、依赖冲突或运行时性能问题时，才能判断问题究竟发生在哪里。

## 一、Java 平台由哪些部分组成

Java 平台可以从源代码到程序运行分成四层：

| 层次 | 负责的事情 | 常见实例 |
|------|------------|----------|
| Java 语言 | 规定源代码如何表达类型、对象、方法和控制逻辑 | `class`、`interface`、泛型、异常、Lambda |
| Java 标准库 | 提供可直接调用的通用能力 | 集合、文件、网络、日期时间、并发 API |
| JVM | 加载并执行字节码，管理内存和运行时优化 | 类加载、垃圾回收、JIT 编译 |
| JDK 工具 | 把源代码编译、运行、分析和打包 | `javac`、`java`、`javadoc`、`jdb`、`jcmd` |

它们在一次普通程序执行中的关系如下：

```text
HelloJava.java
      │  javac 编译
      ▼
HelloJava.class（字节码）
      │  java 启动器创建 JVM 进程
      ▼
JVM 加载类并调用 main 方法
      │
      ├── 调用 Java 标准库
      └── 通过 JVM 适配当前操作系统和 CPU
```

::: warning 跨平台运行需要兼容环境

“Java 代码一次编译即可在不同平台运行”依赖的是目标平台存在兼容的 JVM，并不表示所有 Java 程序天然与操作系统无关。程序如果直接依赖 Windows 路径、Linux 命令、本地动态库或特定字符编码，仍然需要处理平台差异。

:::

## 二、Java 语言的核心特征

### 1. 静态类型与强类型约束

Java 变量、参数和返回值在编译期都有确定类型。编译器会在程序运行前检查大量类型错误，例如不能把字符串直接赋给整数变量，也不能向只接收订单对象的方法传入用户对象。

静态类型的主要价值不只是“写法严格”，而是让接口约束、IDE 重构和跨团队协作更可靠。代价是需要显式建模类型，临时脚本通常会比动态语言更啰嗦。

::: tip TypeScript 经验如何迁移
TypeScript 的类型主要用于静态检查，运行到浏览器或 Node.js 中的是 JavaScript；Java 的类型不仅参与编译检查，也保留在类文件和 JVM 运行模型中。二者都强调类型契约，但不能把 TypeScript 的类型擦除模型直接套到 Java 上。
:::

### 2. 面向对象与类为中心的组织方式

Java 以类和接口组织代码。对象封装状态和行为，接口表达调用方可以依赖的能力。现代 Java 同时支持函数式表达，例如 Lambda 和 Stream，但这些能力仍然工作在 Java 的类型系统和对象模型之上。

::: tip 优先用组合表达能力复用

“Java 是面向对象语言”不等于所有逻辑都应设计成复杂的继承树。实际工程更常使用接口表达边界、使用组合复用能力，并把继承限制在确实存在稳定父子关系的场景中。

:::

### 3. 自动内存管理

Java 对象通常由 JVM 分配并由垃圾收集器回收，开发者不需要手动释放普通对象内存。自动回收减少了悬空指针等风险，但不代表程序不会发生内存问题：对象被错误地长期引用仍会造成内存泄漏，文件句柄、网络连接和数据库连接也必须显式关闭。

### 4. 并发能力与运行时优化

Java 标准库提供线程、锁、原子类、线程池、异步任务和虚拟线程等并发能力。JVM 还会根据热点代码进行即时编译（JIT），把频繁执行的字节码优化为本地机器码。

并发 API 丰富不等于并发程序自动正确。共享状态、可见性、原子性和资源容量仍然需要明确设计；JIT 也意味着某段代码的运行性能不能只根据源码行数判断。

## 三、编译型与解释执行如何同时成立

把 Java 简单归类为“编译型语言”或“解释型语言”都会遗漏关键过程。典型 Java 程序至少经历两个阶段：

1. `javac` 把 `.java` 源文件编译成 `.class` 字节码文件；
2. JVM 加载字节码，通过解释器开始执行，并可能把热点代码交给 JIT 编译器优化为机器码。

因此，下面三个错误发生在不同阶段：

| 现象 | 所在阶段 | 常见原因 |
|------|----------|----------|
| `';' expected` | 源代码编译 | 语法不合法 |
| `Could not find or load main class` | JVM 启动或类加载 | 类名、包名或类路径错误 |
| `NullPointerException` | 程序运行 | 代码访问了空引用 |

::: tip 先定位失败阶段再选择工具

分清阶段是 Java 排障的第一步。编译失败时不应先调整 JVM 内存参数；类找不到时也不应先修改业务逻辑。

:::

## 四、Java 适合解决哪些问题

Java 的成熟类型系统、标准库、运行时和工程生态，使它特别适合需要长期维护、多人协作和稳定运行的系统。

| 场景 | Java 的优势 | 需要注意的成本 |
|------|-------------|----------------|
| 企业后端服务 | 框架、数据库和可观测性生态成熟 | 项目结构和配置比脚本语言更重 |
| 交易与规则系统 | 类型约束清晰，便于表达复杂领域模型 | 需要控制对象模型和抽象复杂度 |
| 高并发服务 | JVM 优化成熟，并发工具完整 | 调优需要理解线程、内存和 GC |
| 数据处理平台 | 大量成熟中间件以 JVM 为基础 | 启动时间和内存占用需要评估 |
| Android 历史项目 | 大量存量代码和工具链使用 Java | 新项目还需结合 Kotlin 与平台现状选型 |

Java 并非所有任务的默认答案。一次性自动化脚本、以浏览器交互为核心的页面逻辑或资源极端受限的程序，可能更适合其他语言。技术选型应由部署环境、团队能力、生态依赖和维护周期共同决定。

## 五、从前端思维切换到 Java

前端开发经验可以帮助理解模块、异步任务和类型约束，但 Java 后端程序有不同的运行边界。

| 前端常见概念 | Java 中接近的概念 | 关键差异 |
|--------------|-------------------|----------|
| TypeScript 类型 | Java 类、接口和泛型 | Java 类型进入编译产物并受 JVM 模型约束 |
| npm 包 | Maven 或 Gradle 依赖 | Java 依赖通常参与编译类路径和运行类路径 |
| Node.js 进程 | JVM 进程 | JVM 负责类加载、线程、堆内存和 JIT |
| `Promise` / 事件循环 | `CompletableFuture`、线程、虚拟线程 | Java 服务不以单一事件循环作为默认执行模型 |
| 浏览器 DevTools | IDE 调试器、`jdb`、JFR、`jcmd` | Java 更关注线程栈、堆、类加载和 GC |

::: info 服务进程中的状态会持续存在

一个 Spring Boot 服务启动后通常会持续占用一个 JVM 进程，接收多个请求并并发执行。变量是否在线程间共享、连接池是否耗尽、对象是否长期存活，都是后端程序必须主动考虑的问题。

:::

## 六、版本主线与维护线 {#六、java-21-主线与-java-8-维护线}

### 1. 版本号表达什么

Java 目前按固定节奏发布功能版本，并由不同发行商提供补丁更新和支持周期。项目选择版本时应同时区分：

- **语言与平台版本**：例如 Java 8、Java 17、Java 21；
- **补丁版本**：例如 `21.0.11`，包含安全和缺陷修复；
- **JDK 发行版**：例如 Oracle JDK、Eclipse Temurin、Amazon Corretto；
- **供应商支持策略**：决定某个版本被维护多久，不能只根据“LTS”三个字判断。

::: warning LTS 不是 Java 规范中的通用保修承诺
“长期支持版本”由 JDK 发行商的支持策略定义。Java 21 被主流发行商作为 LTS 版本提供，但具体免费更新期限、商业支持和补丁节奏应以所选发行商的当前政策为准。
:::

### 2. 两条版本线如何分工

本模块使用以下明确基线：

| 路线 | 作用 | 编写和练习原则 |
|------|------|----------------|
| Java 21 主线 | 建立现代 Java 的完整知识体系 | 新代码默认按 Java 21 编译和运行，使用现代 API 与语言能力 |
| Java 8 维护线 | 阅读、排障和维护企业存量系统 | 单独标注 Java 8 可用写法、缺失能力和迁移风险 |

新手不应先完整学习 Java 8 再重新学习 Java 21。更有效的方式是以 Java 21 建立当前模型，在涉及版本差异的知识点旁理解 Java 8 的限制。例如：

- Java 8 没有 `record`、文本块、模式匹配和虚拟线程；
- Java 8 已有 Lambda、Stream 和 `java.time`，这些不是 Java 21 才出现的能力；
- Java 21 编译出的类文件不能直接交给 Java 8 JVM 运行；
- 维护 Java 8 项目时，构建插件、第三方依赖和部署环境也必须保持兼容。

## 七、常见认识误区

| 误区 | 正确认识 |
|------|----------|
| 安装 JVM 就能开发 Java | 开发需要 JDK，其中包含编译器和诊断工具 |
| JDK、JRE、JVM 是三个并列软件 | JVM 是运行引擎，运行时镜像提供类库，JDK 在此基础上提供开发工具 |
| 字节码能在任何设备无条件运行 | 目标设备必须有兼容 JVM，程序自身也不能依赖不兼容的本地能力 |
| 有垃圾回收就不需要管理资源 | 文件、连接和其他外部资源仍需要确定性关闭 |
| Spring Boot 就是 Java | Spring Boot 是构建 Java 应用的框架与工具体系，不属于 Java 语言本身 |
| 企业还在使用 Java 8，所以新手只学 Java 8 | 应用 Java 21 建立主线能力，再专项补足 Java 8 维护差异 |

## 八、规范与官方资料

Java 的语言规则、虚拟机规则和 API 文档分别由不同资料负责：

| 资料 | 适合查什么 |
|------|------------|
| [Java Language Specification 21](https://docs.oracle.com/javase/specs/jls/se21/html/) | 语法、类型系统、表达式和编译期规则 |
| [Java Virtual Machine Specification 21](https://docs.oracle.com/javase/specs/jvms/se21/html/) | 类文件、字节码、运行时数据区和指令语义 |
| [Java SE 21 API](https://docs.oracle.com/en/java/javase/21/docs/api/index.html) | 标准库中的类、方法、参数和异常 |
| [JDK 21 Documentation](https://docs.oracle.com/en/java/javase/21/index.html) | JDK 工具、部署、故障排查和迁移说明 |

规范用于回答“Java 必须如何工作”，API 文档用于回答“某个标准类如何调用”，具体 JDK 发行版文档用于回答“这个实现如何安装和运维”。遇到技术争议时，应先判断问题属于哪一个层面，再选择资料。
