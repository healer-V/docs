# Java 版本与支持基线

Java SE 版本规定语言、虚拟机和标准 API，JDK 发行版提供可安装的运行与开发工具。长期支持 LTS 是供应商的维护安排，不能从语言版本号推导所有发行版的许可、费用和更新期限。


## 一、四类版本信息

| 对象 | 需要记录 | 解决的问题 |
|------|----------|------------|
| Java SE | 8、21 等平台版本 | 可使用的语言与 API |
| JDK 发行版 | 供应商、完整更新版本、架构 | 安装产物与支持来源 |
| 构建工具 | Wrapper、插件与构建 JDK | 如何生成产物 |
| 实际运行时 | 服务和测试 JVM 的完整版本 | 产物在哪里执行 |

OpenJDK 是实现与开发项目，各供应商据此提供不同构建和支持。现代 Java 功能版本采用约半年的发布节奏，项目仍可根据维护周期选择主版本，并持续接收该发行版的安全更新。

## 二、支持与采用


### 1. LTS 责任

供应商的支持路线可能包含不同阶段和许可条件。核对时应记录资料日期、适用构建及使用方式，不写“所有 Java 21 永久免费”或“LTS 不需要更新”一类结论。

当前模块以 Java 21 正式能力为主线，Java 8 用于遗留代码理解与迁移对照。Java 25 等后续方向属于独立扩展范围，不能成为阅读这套主线的隐藏前置。


### 2. 项目决策

一个仍需交付 Java 8 消费者的共享库，即使 CI 使用 JDK 21，也要保持最低运行目标和相应测试。一个独立服务在完成迁移后可以采用 Java 21，但其依赖、Agent、驱动和平台仍需匹配。

::: warning 运行时升级与源码升级分开决策
服务能在 Java 21 启动，不代表已经可以让所有消费者加载 65 版 Class。公共库最低运行版本是对使用方的契约。
:::


## 三、双运行时证据

可复现基线应同时固定构建工具、插件和测试框架。例如，独立的[多 JDK 示例](./06-multi-jdk-toolchains.md)在文中完整提供 Maven 3.9.11、Compiler 3.14.1、Surefire 3.5.4 和 JUnit 4.13.2 配置。测试框架需能在 Java 8 运行，因此不直接复用主线的 JUnit 6 工程。

本次实际验证如下，完整操作见[多 JDK 与 Toolchains](./06-multi-jdk-toolchains.md)：

| 编译与测试 JDK | 编译目标 | 测试结果 | 探针结果 |
|----------------|----------|----------|----------|
| 本机 JDK 1.8.0_491 | Java 8 | 8 项通过 | 金额 4970 分、UTC 日期一致 |
| Corretto 21.0.11 | Java 8 | 8 项通过 | 同一产物在 8 与 21 均通过探针 |

这些结果说明该文列出的业务契约可在两套运行时验证，没有替代组织实际应用的全部兼容测试，也不构成对某个商业发行版的许可建议。


## 四、维护记录

基线应固定源码目标、最低运行时、发行版、更新策略、关键依赖及验证入口。只写“使用 LTS”无法让另一台机器重现构建，也无法解释某个 Agent 为何启动失败。

::: tip 用实际进程核对
保存 `java -version`、`javac -version`、Wrapper 版本和测试进程中的 `java.version`。IDE 的 SDK 选项不能替代测试及部署进程证据。
:::


## 五、扩展范围

Java 22～25 的语言、标准库和工具变化不在当前 Java 21 主线的讲解与验证范围内。原有 Java 21→25 两篇专题已退出目录；这不表示它们的功能已在 Java 21 可用，也不把后续版本的预览能力当作正式能力。

升级方法中的依赖盘点、行为回归、灰度观察与回退条件归入 [Java 8 升级 Java 21](./07-java8-to-21-migration.md)。需要采用 Java 25 时，应另行建立对应版本的功能范围、环境和迁移证据，不能直接沿用本文的双运行时测试结论。
