# 非确定性与事实校验

同一模型接收相同输入时，可能生成措辞不同的结果；措辞完全相同，也不能证明内容一定正确。AI 应用必须把“文本稳定”“事实正确”和“业务可用”作为三个独立问题处理。

本文使用同一条客户反馈重复生成摘要，并以实际输出说明非确定性。示例中的事实校验只覆盖输入文本能够直接证明的内容，不依赖模型自我声明正确。

::: tip 模型输出属于待验证数据
响应状态为 `completed` 只表示生成过程完成。应用仍需依据原始输入、可信数据源和业务规则判断输出能否使用。
:::

## 一、非确定性

### 1. 结果变化

生成过程会从候选 Token 分布中逐步选择结果。即使请求配置相同，不同运行也可能在近义词、语序、标点和信息取舍上产生差异。

非确定性主要影响两个层面：

| 层面 | 示例 | 是否一定错误 |
|------|------|--------------|
| 表达变化 | “升级到”与“升级至” | 否 |
| 语义变化 | “约 8 秒”变为“8 分钟” | 是 |

应用不应要求所有自然语言文本逐字相同，而应先定义哪些变化可以接受、哪些变化会破坏事实或业务契约。

### 2. 稳定性边界

降低温度通常可以让采样更集中，但不能把生成模型变成确定性函数。服务端模型、基础设施、请求上下文和其他配置变化也可能影响输出。

因此，“测试时连续三次相同”不能推导出“生产中永远相同”。需要严格一致的值，应由程序生成或从数据库读取。

### 3. 重复运行

重复运行的目的不是消除非确定性，而是观察结果分布。实验至少应固定：

- 模型和可识别版本；
- 指令、输入和参数；
- SDK 与 API 端点；
- 样本 ID 和执行时间；
- 质量评分规则。

只保存最终文本而不保存请求配置，无法判断变化来自生成本身还是环境已经改变。

## 二、事实边界

### 1. 输入事实

本文客户反馈包含三个可以直接核对的事实：

| 事实项 | 原文证据 |
|--------|----------|
| 版本 | `4.2.0` |
| 已恢复功能 | 批量导出 |
| 仍存在的问题 | 首次打开报表约等待 `8 秒` |

摘要可以改变措辞，但必须保留这三个事实及其关系。尤其不能把“已恢复”错误地修饰到报表等待问题上。

### 2. 无来源断言

下面是为了说明风险而构造的错误示例，不是本文实际模型输出：

```text
升级到 4.2.0 后，缓存优化解决了批量导出问题，但数据库性能仍导致报表打开缓慢。
```

原文没有提到缓存、数据库或问题原因。即使这段话听起来合理，也属于无来源事实扩展。

### 3. 外部事实

当任务要求回答输入之外的问题时，应用需要提供可追溯的事实来源，例如经过权限过滤的数据库记录、检索文档或业务 API。

模型已有知识不能替代应用的数据责任。时间敏感、用户专属或高风险信息尤其需要在运行时从权威来源取得，并把引用或记录 ID 与结果关联。

## 三、实际证据

### 1. 实验设置

本文在 Python 3.12.14、OpenAI Python SDK 3.19.2 和 `gpt-6-luna` 下，使用完全相同的指令与输入连续运行三次。

关键请求参数为：

```python
reasoning={"effort": "none"}
temperature=0.8
max_output_tokens=120
```

每次响应的状态均为 `completed`，输入和输出用量分别为 `60` 与 `33` Token。

### 2. 重复结果

| 次数 | 实际摘要 |
|-----:|----------|
| 1 | 升级至 4.2.0 后批量导出已恢复正常，但首次打开报表仍需等待约 8 秒。 |
| 2 | 升级到 4.2.0 后批量导出已恢复正常，但首次打开报表仍需等待约 8 秒。 |
| 3 | 升级到 4.2.0 后批量导出已恢复正常，但首次打开报表仍需等待约 8 秒。 |

第一次与后两次存在“至”和“到”的字面差异，三个关键事实及其关系保持一致。这是可接受的表达变化。

### 3. 证据结论

这组三次运行能够证明：

- 相同请求可以出现字面差异；
- 字面差异不必然构成事实错误；
- 本组三次结果都通过了当前事实检查。

它不能证明：

- 后续每次结果都会正确；
- 其他输入具有相同质量；
- `temperature=0.8` 是最佳配置；
- 模型能够判断输入本身是否真实。

小样本用于解释机制，生产质量需要代表性评测集和持续监测。

## 四、校验分层

### 1. 结构校验

结构校验判断结果是否满足机器可检查的形态，例如非空、字段齐全、类型正确和长度合规。

| 校验 | 摘要场景中的规则 |
|------|------------------|
| 响应状态 | 必须为 `completed` |
| 文本存在 | 去除空白后非空 |
| 句数 | 业务要求为一句 |
| 长度 | 不超过应用定义的上限 |

结构正确只能证明输出可解析，不能证明内容正确。

### 2. 事实校验

事实校验把模型输出与输入或可信来源对照。客户反馈摘要可以检查：

1. 输出是否仍包含版本 `4.2.0`。
2. 批量导出的状态是否为“已恢复”。
3. 报表问题是否仍是首次打开约等待 `8 秒`。
4. 是否出现输入中没有的原因、责任方或承诺。

数字和枚举值可以由程序严格检查；复杂语义通常还需要规则、另一个评测流程或人工审核。

### 3. 业务校验

业务校验判断即使事实正确，结果是否允许进入下一步。

| 使用方式 | 需要的控制 |
|----------|------------|
| 客服草稿 | 展示原文、允许人工编辑 |
| 工单标签 | 限定标签集合、低置信转人工 |
| 自动通知 | 模板、事实源和审批规则 |
| 退款或权限变更 | 确定性规则与明确授权，不由文本直接触发 |

同一段摘要可以用于人工参考，却不一定能作为自动执行动作的依据。

## 五、失败处理

### 1. 可接受变化

应用应把不影响事实和契约的变化归一化或允许通过，例如近义词、标点和轻微语序调整。

不应使用整段字符串相等作为自然语言质量的唯一测试。更合理的断言是检查关键事实、禁止项、结构和语义评分。

### 2. 阻断错误

以下错误应阻止结果进入正常业务流程：

- 数字、版本、时间或状态发生改变；
- 省略会影响判断的关键事实；
- 增加无来源原因、承诺或业务动作；
- 输出为空、未完成或无法解析；
- 包含不应暴露的数据。

阻断后应保留原始输入、响应 ID、模型、请求配置和失败规则，便于复现和改进。

### 3. 降级路径

失败处理不等于自动重复请求。合理降级取决于错误类型：

| 失败 | 降级路径 |
|------|----------|
| 结构不合法 | 在预算内重试或转人工 |
| 事实检查失败 | 展示原文，禁止自动写入 |
| 权威数据缺失 | 明确提示无法确认 |
| 服务不可用 | 排队、转人工或停止功能 |
| 高风险动作 | 始终要求确定性校验和授权 |

重复调用同一个模型可能得到不同结果，但“换一次答案”不是事实校验方法。

## 六、质量评测

### 1. 样本集合

评测集应来自经过脱敏的真实输入分布，并覆盖容易失败的边界：

- 数字、日期和版本号；
- 否定、转折和已恢复状态；
- 多个问题同时出现；
- 输入信息不足；
- 噪声、口语和长文本；
- 诱导模型补充原因的表达。

只测试语句清晰的短样本，会高估生产质量。

### 2. 评测指标

客户反馈摘要至少需要分开记录以下指标：

| 指标 | 计算对象 | 是否阻断上线 |
|------|----------|--------------|
| 关键事实保持率 | 数字、版本、状态 | 是 |
| 无来源断言率 | 新增事实 | 是 |
| 信息覆盖率 | 主要问题 | 依据业务门槛 |
| 结构通过率 | 句数、长度、字段 | 是 |
| 人工接受率 | 编辑后可用性 | 用于效果判断 |
| 单次成功成本 | 通过全部校验的请求 | 用于效率判断 |

成本应按成功结果计算。便宜但经常失败的配置，实际业务成本可能更高。

### 3. 回归门禁

模型、Prompt、参数、检索数据或校验规则发生变化时，都应重新执行固定评测集。

::: warning 固定模型快照与评测配套使用
模型快照可以减少版本漂移，但不能证明输出确定或事实正确。官方文本生成指南建议固定生产模型版本并建立评测，用两者共同控制行为变化。
:::

回归记录至少包含变更前后指标、失败样本、模型标识、请求配置和决策结论。没有这些证据，无法区分质量提升、样本偶然性和评测规则变化。
