# DevOps

运维关注系统和应用在真实环境中的部署、运行、观察、恢复与持续改进。**DevOps 不是一个单独工具，也不是开发与运维之间新增的岗位名称**，而是让开发、测试、交付和运行围绕同一条反馈链路协作的方法与工程实践。

## 一、监控与运维的关系

监控属于运维与 DevOps 的核心能力，但不能只停留在“装一个监控工具”。本目录把它独立为“监控与可观测性”模块，完整讲解指标、日志、追踪、告警与信号关联；SRE 再使用这些证据制定可靠性目标、组织值班和处理事故。

::: tip 模块边界

产品自身的观察入口仍在 Linux、Nginx、Docker 和 Kubernetes 中讲解；跨系统采集、查询和告警归监控模块；告警后的可靠性决策和事故协作归 SRE。

:::

## 二、能力路线

| 顺序 | 能力阶段 | 学习结果 |
| ---: | -------- | -------- |
| 1 | 系统与网络 | 能操作 Linux 主机，编写 Bash 脚本，并定位主机到服务的请求链路 |
| 2 | 容器与编排 | 能构建镜像、运行容器，并在 Kubernetes 中管理工作负载 |
| 3 | 持续交付 | 能让变更经过测试、制品、部署、验证和回退 |
| 4 | 稳定性治理 | 能从遥测证据判断系统状态，治理可靠性和安全风险 |
| 5 | 自动化与平台 | 能审查基础设施变更，并向团队提供有边界的自助能力 |

## 四、学习边界

- Linux、网络和 Git 的必要基础在本知识域内提供，不要求读者先掌握另一套运维教程。
- 数据库内部实现、业务框架开发和云厂商全产品手册不属于本目录的主讲范围。
- Ansible 管理已有主机的期望配置，Terraform 管理基础设施资源与状态，两者不会合并成笼统的“自动化运维”。
- 平台工程位于学习路径末端，用于组合已经掌握的交付、集群、基础设施和可观测能力。
