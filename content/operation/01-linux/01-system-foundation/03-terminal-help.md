# 终端与命令帮助

Linux 服务器通常通过命令行管理。管理员在终端中输入文本，Shell 解析命令并启动程序，程序再把正常结果或错误信息返回终端。一次可靠的命令操作至少要回答三个问题：**命令处理了什么对象、结果是否成功、失败证据指向哪里。**

本文使用 Ubuntu Server 默认常见的 Bash 环境，示例身份为 `operator@ops-lab`。示例只包含查询、帮助和会话控制操作，不修改系统配置。

::: info 输出说明
文中的固定退出状态来自 Bash 官方规范，提示符与命令输出为标准实验环境中的预期形式。发行版、语言环境和程序版本可能改变错误文字，但不会改变本文说明的判断方法。
:::

## 一、终端与 Shell

终端提供交互界面，Shell 负责解释命令，提示符显示当前操作上下文。三者职责不同，但共同构成命令行会话。

### 1. 终端界面

**终端**负责接收键盘输入并显示程序输出。它可以是虚拟机控制台、桌面终端窗口，也可以是通过 SSH 建立的远程终端。终端本身不解释 `pwd`、`ls` 或 `exit` 的含义。

控制台登录成功后，屏幕通常出现类似内容：

```text
operator@ops-lab:~$
```

光标所在位置表示终端正在等待输入。输入命令并按 `Enter` 后，前台程序开始运行；程序结束或交还控制权时，命令提示符再次出现。

如果提示符没有重新出现，不能直接认定终端故障。当前程序可能仍在运行、等待输入，或者正在分页显示内容。此时应先识别前台程序，再选择退出方式。

### 2. Bash

**Shell** 是命令解释器，负责读取命令文本、识别命令名与参数，并按照规则启动程序。Bash 是 Ubuntu Server 中常见的 Shell 实现。

下面三个对象不能混为一谈：

| 对象 | 职责 | 示例 |
|------|------|------|
| 终端 | 输入与显示界面 | 虚拟控制台、SSH 终端 |
| Shell | 解析命令并组织执行 | Bash |
| 命令 | 执行具体任务 | `pwd`、`ls`、`hostname` |

部分命令由独立可执行文件提供，例如 `ls`；部分命令由 Bash 自身实现，例如 `cd` 和 `exit`。二者的帮助入口不同，但都通过当前 Shell 调用。

执行以下命令可以确认当前 Shell 进程：

```bash
ps -p $$ -o comm=
```

在 Bash 会话中的预期输出为：

```text
bash
```

这里的 `$$` 是 Bash 提供的当前 Shell 进程号。它只用于定位当前进程，不需要在本篇扩展为 Shell 变量知识。

### 3. 命令提示符

命令提示符用于标识当前操作上下文。常见形式 `operator@ops-lab:~$` 包含以下信息：

| 片段 | 含义 |
|------|------|
| `operator` | 当前用户 |
| `ops-lab` | 当前主机名 |
| `~` | 当前目录位于该用户的家目录 |
| `$` | 普通用户提示符 |

root 用户的提示符常以 `#` 结尾，但提示符样式可以自定义，不能只根据一个字符判断权限。需要确认身份时，应执行：

```bash
whoami
hostname
pwd
```

标准实验环境中的预期结果为：

```text
operator
ops-lab
/home/operator
```

::: tip 高风险操作前核对上下文
安装、删除、覆盖或修改权限前，先确认用户、主机和当前目录。语法正确的命令如果在错误主机或错误路径执行，仍然会造成事故。
:::

## 二、命令结构

Bash 需要先识别命令名，再把选项和参数交给对应命令处理。正确区分这三部分，才能准确查询帮助和定位语法错误。

### 1. 命令名

一条简单命令以命令名开头。Bash 读取命令名后，会判断它是别名、函数、内置命令还是需要从可执行文件搜索路径中查找的程序；无法找到时返回 `command not found`。

下面三条命令分别查询当前目录、当前用户和主机名：

```bash
pwd
whoami
hostname
```

Linux 命令名和路径区分大小写。`pwd` 与 `PWD` 不是同一输入，`/etc` 与 `/ETC` 也不是同一路径。命令名输入错误时，应先检查拼写与大小写，不要直接提升权限。

[Bash 命令搜索与执行说明](https://www.gnu.org/software/bash/manual/html_node/Command-Search-and-Execution.html)给出了 Bash 识别和查找命令的规则。日常操作不需要记住全部搜索细节，但必须区分“命令不存在”与“命令运行后失败”。

### 2. 选项与参数

简单命令通常由命令名、选项和参数组成：

```text
命令名 [选项] [参数]
```

例如：

```bash
ls -l /etc
```

| 部分 | 当前值 | 作用 |
|------|--------|------|
| 命令名 | `ls` | 列出目录内容 |
| 选项 | `-l` | 使用长格式显示 |
| 参数 | `/etc` | 指定处理对象 |

选项改变命令行为，参数指定处理对象。短选项通常以单个连字符开头，例如 `-l`；长选项通常以两个连字符开头，例如 `--help`。这只是常见约定，不是所有程序共享的强制语法。

参数的数量、顺序和含义由具体命令定义。不能把一个命令支持的选项直接套用到另一个命令，也不能仅凭选项名称猜测影响范围；准确语法应以当前主机安装版本的帮助信息为准。

## 三、帮助系统

帮助入口取决于命令由独立程序还是 Bash 自身提供。快速帮助、手册页和内置帮助分别适合不同查询深度。

### 1. 快速帮助

许多独立程序支持 `--help`，用于快速查看命令语法和主要选项。例如：

```bash
ls --help
```

输出通常以 `Usage` 或本地化后的“用法”开头，并列出选项说明。快速帮助适合以下场景：

- 已经知道命令名，需要确认选项拼写；
- 需要查看参数顺序；
- `man` 不可用，先获取程序内置说明；
- 不确定选项是否被当前版本支持。

`--help` 是常见约定，不是 Bash 为所有程序强制提供的能力。程序报告 `unrecognized option` 时，应查阅它实际支持的帮助入口，不能反复尝试相似参数。

### 2. 手册页

`man` 用于阅读系统安装的手册页。打开 `ls` 的手册：

```bash
man ls
```

手册通常包含名称、摘要、说明、选项、退出状态和相关条目。标题中的数字表示手册章节，例如 `LS(1)` 属于用户命令章节。同名主题存在多个章节时，可以明确指定章节号：

```bash
man 1 ls
```

分页器中的常用按键如下：

| 按键 | 动作 |
|------|------|
| `Enter` | 向下移动一行 |
| `Space` | 向下移动一页 |
| `/文本` 后按 `Enter` | 向后搜索文本 |
| `n` | 跳到下一个匹配项 |
| `q` | 退出手册并返回 Shell |

出现 `man: command not found`，表示手册程序可能未安装；出现 `No manual entry`，表示当前主题没有可用手册页。此时应保留错误信息并使用程序的快速帮助，不要把“帮助缺失”误判为目标命令不能运行。

[Ubuntu Server 终端教程](https://ubuntu.com/server/docs/tutorial/welcome-to-the-terminal/)介绍了提示符、选项和手册页，[Ubuntu Server 命令行速查](https://ubuntu.com/server/docs/reference/cli-cheatsheet/)可作为常用命令索引。

### 3. Bash 内置帮助

`cd`、`exit` 等 Bash 内置命令不是独立程序，它们的完整说明应通过 Bash 的 `help` 命令查询：

```bash
help cd
help exit
```

可以先使用 `type` 判断命令由谁提供：

```bash
type cd
type ls
```

典型输出会表明 `cd` 是 Shell 内置命令，而 `ls` 对应一个可执行文件。输出路径可能因系统安装位置不同而变化，因此判断重点是命令类型，不是固定路径。

::: tip 帮助入口选择
独立程序优先尝试 `命令 --help` 和 `man 命令`；Bash 内置命令优先使用 `help 命令`。帮助来源与实际安装版本一致，通常比记忆网络文章中的参数更可靠。
:::

## 四、退出状态

退出状态是命令结束后返回给 Shell 的数值结果。它与屏幕输出相互补充，用于判断命令是否按自身规则完成。

### 1. 状态读取

每个前台命令结束后都会向 Bash 返回一个**退出状态**。状态 `0` 表示命令按其定义成功完成，非零状态表示失败或需要调用方处理的特殊结果。

执行成功命令后，立即读取状态：

```bash
pwd
echo $?
```

预期结果类似：

```text
/home/operator
0
```

`$?` 只保存上一条命令的退出状态。必须紧接着读取，因为 `echo $?` 本身执行后也会成为新的“上一条命令”。

状态为 `0` 只表示命令按自身规则成功，不表示业务结果一定正确。例如，`ls` 成功列出一个不该操作的目录时仍会返回 `0`；因此退出状态必须与命令参数和结果内容一起判断。

### 2. 常见状态值

输入一个不存在的命令，并立即读取退出状态：

```bash
ops-command-does-not-exist
echo $?
```

错误文字可能随语言环境变化，但 Bash 的预期状态为：

```text
ops-command-does-not-exist: command not found
127
```

根据 [Bash 退出状态规范](https://www.gnu.org/software/bash/manual/html_node/Exit-Status.html)，常见状态可以这样解释：

| 状态 | Bash 层面的含义 | 判断边界 |
|------|------------------|----------|
| `0` | 命令成功 | 仍需核对结果是否满足业务目标 |
| `1`～`125` | 命令报告失败或特殊结果 | 具体含义由该命令定义 |
| `126` | 找到命令，但无法执行 | 检查权限、文件格式和挂载限制 |
| `127` | 找不到命令 | 检查拼写、大小写、安装状态和搜索路径 |
| `128 + N` | 命令因编号为 `N` 的致命信号终止 | 需要结合信号与进程证据判断 |

非零状态不能统一解释为同一种错误。脚本或监控系统只有在理解目标命令的状态定义后，才能据此作出可靠判断。

## 五、输出与错误

正常结果与诊断信息通过不同通道产生，但终端默认同时显示二者。错误分类必须同时结合命令、信息和退出状态。

### 1. 标准输出与标准错误

程序通常具有两个独立的文本输出通道：

- **标准输出**承载正常结果；
- **标准错误**承载诊断信息。

终端默认把两个通道显示在同一个窗口，因此肉眼看到的文字可能来自不同通道。屏幕没有输出也不表示命令失败，出现错误文字也不能代替退出状态判断。

一次命令执行应至少记录四项信息：

| 证据 | 作用 |
|------|------|
| 完整命令 | 确认实际调用对象与参数 |
| 正常输出 | 判断程序产生了什么结果 |
| 错误信息 | 定位失败阶段与原因 |
| 退出状态 | 判断程序如何报告执行结果 |

本篇只建立输出通道概念，不展开重定向与管道语法。后续将输出写入文件或连接多个命令时，仍应保留正常结果与诊断信息的边界。

### 2. 错误分类

常见错误文字对应不同调查方向。保留原始文本后，可以先按以下类别收敛范围：

| 错误现象 | 主要含义 | 首要检查项 |
|----------|----------|------------|
| `command not found` | Bash 没有找到命令 | 拼写、大小写、软件是否安装 |
| `No such file or directory` | 路径或文件不存在 | 当前目录、参数路径、文件名 |
| `Permission denied` | 当前身份不能访问或执行目标 | 当前用户、目标权限、挂载限制 |
| `invalid option` | 程序不支持当前选项 | `--help`、手册页、程序版本 |
| 提示符未返回 | 程序仍运行、等待输入或分页显示 | 当前前台程序及其退出方式 |

::: danger 不要用 sudo 掩盖未知错误
`sudo` 只改变执行身份，不能修复拼写、路径和参数错误。未确认命令作用与目标对象时提升权限，可能让原本被权限阻止的错误操作获得修改系统的能力。
:::

有效的错误记录应保留命令、参数、完整错误文字和退出状态。“命令失败”没有说明失败发生在 Shell 查找、程序参数、文件访问还是权限检查阶段，不能作为可复现的诊断证据。

## 六、会话控制

分页器、前台程序、Shell 会话和操作系统具有不同的退出方式。执行退出操作前，需要先确认当前控制对象。

### 1. 前台程序退出

退出分页器、请求中断前台程序和关闭 Shell 是不同操作：

| 操作 | 适用场景 | 结果 |
|------|----------|------|
| `q` | 正在阅读 `man` 等分页内容 | 退出分页器，返回当前 Shell |
| `Ctrl+C` | 前台程序持续运行或等待输入 | 向前台进程发送中断请求 |
| 程序专用退出命令 | 交互式工具提供自己的退出机制 | 按程序规则保存或放弃状态 |

`Ctrl+C` 不是回滚操作。程序在收到中断请求前已经完成的写入不会自动撤销，部分程序也可以捕获或忽略该信号。执行修改性命令前仍需确认目标与恢复方法。

如果只是在 `man` 中阅读帮助，应按 `q` 退出，而不是把 `Ctrl+C` 当作所有界面的通用退出键。

### 2. Shell 会话退出

`exit` 结束当前 Shell 会话：

```bash
exit
```

在虚拟控制台中，退出后通常回到登录提示：

```text
ops-lab login:
```

在 SSH 终端中，退出当前登录 Shell 通常会断开远程连接。`exit` 不等于关闭主机；关闭实验虚拟机需要在已登录会话中执行明确的关机命令，并等待系统完成停止过程。

使用以下只读练习可以验证本篇的完整判断链路：

1. 从提示符识别当前用户、主机和目录；
2. 执行 `pwd`，再用 `echo $?` 确认状态为 `0`；
3. 执行 `ls --help`，确认 `-l` 选项含义；
4. 执行 `man ls`，搜索 `directory`，按 `q` 返回；
5. 执行 `ops-command-does-not-exist`，确认错误类型和状态 `127`；
6. 执行 `exit`，确认回到登录提示而不是关闭虚拟机。

命令操作的完成条件不是“终端出现过输出”，而是能够确认操作上下文、核对语法来源、解释退出状态并保留错误证据。
