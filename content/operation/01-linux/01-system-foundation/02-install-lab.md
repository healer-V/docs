# 安装隔离实验环境

隔离实验环境是一台运行在宿主机虚拟化软件中的 Ubuntu Server 虚拟机。实验命令只修改虚拟磁盘中的系统，出现配置错误时可以通过快照恢复，不影响宿主机的系统盘和业务数据。

本实验建立以下固定基线：

| 项目 | 配置 |
|------|------|
| 虚拟机名称 | `ops-lab` |
| 客户机系统 | Ubuntu Server 26.04.1 LTS amd64 |
| 普通用户 | `operator` |
| 网络模式 | NAT |
| 恢复方式 | 基线快照 |

::: info 验证范围
本文使用 Ubuntu 官方发布信息、安装文档和校验清单核对版本与步骤。当前文档生成环境没有可复用的 Ubuntu 虚拟机，因此安装界面和命令输出标记为预期结果，未声明为本机实测结果。不同虚拟化产品的按钮名称可能不同，但资源与隔离要求一致。
:::

## 一、环境隔离

隔离环境先限定客户机可以使用的宿主资源，再开始安装。处理器能力、磁盘连接和网络暴露范围都需要在虚拟机启动前确认。

### 1. 宿主机条件

宿主机需要安装能够创建 amd64 客户机、挂载 ISO 镜像并管理快照的虚拟化软件，例如 VirtualBox、VMware Workstation 或 Hyper-V。开始安装前，应确认以下条件：

| 条件 | 本实验建议值 | 验证标准 |
|------|--------------|----------|
| 处理器 | 64 位 Intel 或 AMD，已启用硬件虚拟化 | 可以创建并启动 64 位 Ubuntu 客户机 |
| 宿主机内存 | 总内存至少 8 GB | 分配 4 GB 后宿主机仍可正常运行 |
| 可用磁盘 | 至少 40 GB | 能容纳 ISO、30 GB 动态磁盘和快照增量 |
| 虚拟化软件 | 支持 ISO、NAT 和快照 | 设置界面存在对应能力 |

如果客户机启动时出现 `VT-x is disabled`、`AMD-V is disabled` 或“虚拟化不可用”，说明安装程序尚未开始运行。应先检查固件中的虚拟化开关，以及是否存在与当前虚拟化软件冲突的虚拟化平台；不要通过反复重建虚拟机规避宿主机能力问题。

[Ubuntu Server 安装文档](https://ubuntu.com/server/docs/how-to/installation/)提供当前安装入口和官方教程。宿主机资源只决定实验体验，生产服务器规格还需要根据实际工作负载评估。

### 2. 存储与网络边界

虚拟机只连接本次新建的虚拟磁盘和 Ubuntu 安装 ISO，不连接宿主机物理磁盘、数据分区或 USB 存储设备。初始实验环境也不启用共享目录、双向剪贴板、拖放和 USB 直通。

::: danger 安装程序会覆盖目标磁盘
安装界面中的“使用整个磁盘”会清除安装程序看到的目标磁盘。目标列表中只应出现本实验创建的 30 GB 虚拟磁盘；如果磁盘数量或容量与预期不符，立即退出安装并检查虚拟机存储配置。
:::

网络使用 NAT 模式。客户机可以主动访问软件仓库，局域网中的其他设备默认不能直接访问客户机。首次安装不配置桥接网络和端口转发，避免实验服务意外暴露到局域网。

隔离边界可以用下列关系表示：

```text
宿主机
├─ 宿主系统盘与业务数据：不连接客户机
└─ ops-lab 虚拟机
   ├─ 30 GB 虚拟磁盘：允许安装程序写入
   ├─ Ubuntu ISO：只作为安装介质
   └─ NAT 网卡：仅提供客户机主动访问
```

## 二、安装介质

安装介质必须同时满足来源可信和内容完整两个条件。下载地址、签名清单与本地摘要共同构成镜像验证证据。

### 1. 官方镜像

从 [Ubuntu Server 官方下载页](https://ubuntu.com/download/server)进入 Ubuntu 26.04.1 LTS 发布目录，下载以下三个文件并放在同一目录：

- `ubuntu-26.04.1-live-server-amd64.iso`：服务器安装镜像；
- `SHA256SUMS`：发布目录中各镜像的 SHA-256 摘要；
- `SHA256SUMS.gpg`：Ubuntu 对摘要清单提供的签名。

镜像名称中的 `amd64` 表示适用于 64 位 Intel 或 AMD 处理器。ARM 服务器需要选择对应架构的镜像，不能因为文件同为 ISO 就混用。

下载入口必须是 `ubuntu.com` 或 Ubuntu 官方发布站点。第三方下载工具可以传输文件，但不应把论坛附件、网盘副本或搜索结果页当作发布来源。

### 2. 完整性校验

SHA-256 校验用于确认本地 ISO 与发布清单中的摘要一致。Ubuntu 26.04.1 Server amd64 镜像在官方 `SHA256SUMS` 中对应的摘要为：

```text
cc8a95cde20f6ced61a322420de00f10cc3c90ced545daa46cb9c1a117f1d927
```

在下载目录打开 PowerShell，计算本地文件摘要并与清单比较：

```powershell
$iso = '.\ubuntu-26.04.1-live-server-amd64.iso'
$actual = (Get-FileHash -Algorithm SHA256 -LiteralPath $iso).Hash.ToLowerInvariant()
$expected = ((Select-String -LiteralPath '.\SHA256SUMS' -SimpleMatch '*ubuntu-26.04.1-live-server-amd64.iso').Line -split '\s+')[0]
$actual
$actual -eq $expected
```

最后一行的预期结果为：

```text
True
```

结果为 `False` 时，不要挂载该镜像。先确认文件名和清单属于同一发布目录，再重新下载 ISO；重复下载仍不一致时，停止安装并更换官方镜像站点。

摘要一致只能证明 ISO 与当前清单一致。需要验证清单来源时，还应按照 [Ubuntu 镜像验证指南](https://documentation.ubuntu.com/security/software-integrity/image-verification/)校验 `SHA256SUMS.gpg` 的签名和 Ubuntu 签名密钥信任链。

::: tip 校验顺序
先验证摘要清单的签名，再用已验证的清单校验 ISO，才能同时覆盖来源真实性和传输完整性。只把网页中的哈希值手工复制到本地，不能替代签名验证。
:::

## 三、虚拟机配置

虚拟机配置定义客户机能够看到的计算、存储和网络资源。本实验采用满足基础运维练习的固定规格，并关闭不必要的宿主集成。

### 1. 计算资源

新建名为 `ops-lab` 的 Linux/Ubuntu 64 位虚拟机，并设置以下计算资源：

| 资源 | 配置 | 说明 |
|------|------|------|
| 虚拟处理器 | 2 vCPU | 足以完成基础命令和服务实验 |
| 内存 | 4096 MB | 为系统更新和后续服务预留空间 |
| 固件 | 使用产品默认的受支持模式 | 不为排除启动问题随意切换 BIOS/UEFI |

动态分配的资源不等于宿主机可以无限超配。虚拟机启动后，如果宿主机持续换页或无响应，应先关闭客户机并降低分配值，而不是在客户机中继续安装软件。

如果虚拟化软件无法选择 64 位客户机，通常应回到宿主机检查硬件虚拟化能力；修改 Ubuntu 镜像或磁盘容量不能解决该问题。

### 2. 虚拟磁盘与光驱

为 `ops-lab` 创建一块 **30 GB 动态分配的虚拟磁盘**。动态分配表示宿主机文件按实际写入逐步增长，不表示客户机可以使用超过 30 GB 的容量。

将已通过校验的 `ubuntu-26.04.1-live-server-amd64.iso` 挂载到虚拟光驱，并把光驱放在首次启动的可引导设备中。配置完成后，虚拟机应只看到一块 30 GB 磁盘和一个安装光驱。

启动后若直接进入空白磁盘、网络启动或 `No bootable medium`，说明 ISO 未正确挂载或启动顺序错误。应关闭虚拟机，检查光驱连接状态和 ISO 路径；不要通过创建更多虚拟磁盘解决引导介质缺失。

### 3. 网络与宿主集成

为虚拟机配置一块 NAT 网卡，并关闭以下宿主集成功能：

- 共享目录；
- 双向剪贴板与拖放；
- USB 和物理磁盘直通；
- 主机端口转发；
- 自动挂载宿主文件系统。

这些限制减少误操作到宿主机的路径，也避免未加固的实验服务对外暴露。后续确实需要 SSH 或文件交换时，应先明确端口、访问来源和权限，再单独增加规则。

NAT 不保证任何网络环境都能访问互联网。安装界面无法获取地址时，先确认虚拟网卡已启用并连接到 NAT 网络；代理、认证网络和宿主机防火墙需要按实际环境处理，不应改成桥接模式来绕过未知故障。

## 四、Ubuntu Server 安装

系统安装阶段只对已确认的虚拟磁盘写入数据。安装选项、存储目标与系统身份需要在提交前逐项核对。

### 1. 安装选项

从 ISO 启动虚拟机后，选择 **Try or Install Ubuntu Server**，等待安装程序进入语言和键盘设置。本文使用下列安装策略：

| 选项 | 选择 | 原因 |
|------|------|------|
| 语言与键盘 | 按实际键盘选择 | 保证控制台输入准确 |
| 安装类型 | Ubuntu Server | 建立最小服务器环境 |
| 网络 | DHCP/NAT 默认配置 | 由虚拟 NAT 分配地址 |
| 代理 | 留空 | 本实验不预设代理 |
| 镜像站点 | 保持安装程序默认值 | 使用 Ubuntu 软件源 |
| OpenSSH Server | 暂不安装 | 首次验收只使用虚拟控制台 |
| Featured Server Snaps | 不选择 | 保持基线最小化 |

安装程序检测不到网络时，可以在不依赖联网更新的情况下继续基础安装，但应记录网络失败现象。不要填写未知代理地址，也不要为了让检测通过而临时暴露桥接网络。

### 2. 存储布局

存储页面选择使用整块 30 GB 虚拟磁盘，并再次核对磁盘数量、容量和虚拟磁盘标识。安装程序生成的默认分区布局足以支撑本章实验，不需要手工创建复杂分区或 LVM 策略。

确认写盘前完成三项核对：

1. 目标只有一块 30 GB 虚拟磁盘；
2. 页面没有出现宿主机物理磁盘或外接设备；
3. 虚拟机中不存在需要保留的数据。

确认后，安装程序会分区并写入系统。磁盘容量与配置不一致时必须返回虚拟机设置检查，不能凭设备名称猜测目标。

### 3. 账号与主机名

在身份设置页面填写实验专用信息：

| 字段 | 值 | 用途 |
|------|----|------|
| Your name | `Operations Lab` | 用户显示名称 |
| Your server's name | `ops-lab` | 主机名 |
| Pick a username | `operator` | 日常登录用户 |
| Password | 仅用于本地实验的强密码 | 控制台登录与授权 |

用户名和主机名使用小写字母、数字与连字符，避免空格和非标准字符。密码不得复用生产账号密码，也不要写入本文、脚本或版本库。

安装完成后选择重启。出现移除安装介质的提示时，先在虚拟机设置中弹出 ISO，再按 `Enter` 继续；否则虚拟机可能再次进入安装程序。

如果重启后仍显示安装菜单，不要重新执行安装。关闭虚拟机，移除虚拟光驱中的 ISO，并确认虚拟磁盘位于启动顺序中。

## 五、基线验证

首次启动后需要用控制台登录和系统命令验证安装结果。能够进入登录界面并不等于用户、主机名、发行版和架构均符合预期。

### 1. 控制台登录

系统启动完成后，控制台应出现类似登录提示：

```text
ops-lab login:
```

输入用户名 `operator` 和安装时设置的密码。输入密码时终端不会显示星号，这是正常的安全行为。成功登录后，提示符应包含当前用户和主机名，例如：

```text
operator@ops-lab:~$
```

连续登录失败时，先核对键盘布局、大小写锁定和用户名，不要立即重装系统。登录提示中的主机名错误，则说明安装时填写的系统身份不符合基线，需要修正后重新验证。

### 2. 系统身份

登录后执行以下只读命令，核对用户、主机、发行版、架构和运行内核：

```bash
whoami
hostname
cat /etc/os-release
uname -m
uname -r
```

应重点确认以下结果：

| 命令 | 预期信息 | 验证结论 |
|------|----------|----------|
| `whoami` | `operator` | 当前使用普通用户 |
| `hostname` | `ops-lab` | 主机身份符合基线 |
| `cat /etc/os-release` | Ubuntu 26.04 LTS 相关字段 | 发行版与发布系列正确 |
| `uname -m` | `x86_64` | 处理器架构正确 |
| `uname -r` | 实际运行内核版本 | 内核已加载并可记录 |

`/etc/os-release` 描述发行版，`uname -r` 描述当前运行的内核，二者不能互相替代。点版本字段可能随镜像和系统更新变化，应以主机实际输出为准。

## 六、快照恢复

快照用于把实验机恢复到已知状态。只有创建基线、制造可观察变化并完成恢复复测，才能证明回退点可用。

### 1. 基线快照

完成基线验证后正常关闭客户机：

```bash
sudo poweroff
```

确认虚拟机状态为“已关机”，再创建名为 `ubuntu-26.04.1-clean` 的快照。快照说明应记录创建日期、普通用户、网络模式和已完成的验证项。

关机快照比运行时快照更容易形成一致基线。快照不是独立备份：宿主机磁盘损坏或虚拟机文件被删除时，依附于该虚拟机的快照也可能丢失。

### 2. 恢复演练

快照只有经过恢复验证才能作为可用回退点。启动虚拟机并执行以下演练：

1. 登录 `operator` 账号；
2. 在家目录创建探针文件：`touch ~/restore-probe`；
3. 执行 `test -f ~/restore-probe && echo present`，确认输出 `present`；
4. 正常关闭虚拟机；
5. 在虚拟化软件中恢复 `ubuntu-26.04.1-clean` 快照；
6. 重新启动并登录；
7. 执行 `test ! -e ~/restore-probe && echo restored`。

恢复成功时，最后一条命令的预期输出为：

```text
restored
```

探针文件仍然存在，说明恢复目标选错、快照创建时间晚于探针文件，或虚拟化产品没有完成恢复。应检查快照时间线，不要删除文件后把结果当作恢复成功。

### 3. 验收条件

实验环境需要同时满足以下条件，才能作为后续 Linux 运维操作的基线：

| 验收项 | 通过标准 |
|--------|----------|
| 镜像来源 | ISO、摘要和签名文件来自 Ubuntu 官方发布目录 |
| 镜像完整性 | 本地 SHA-256 与已验证清单一致 |
| 存储隔离 | 客户机只连接 30 GB 虚拟磁盘，不连接宿主物理磁盘 |
| 网络隔离 | 使用 NAT，未配置桥接和端口转发 |
| 系统身份 | 普通用户为 `operator`，主机名为 `ops-lab` |
| 系统版本 | `/etc/os-release` 与目标 Ubuntu 发布系列一致 |
| 恢复能力 | 恢复基线快照后，探针文件消失且系统可以重新登录 |

虚拟机能够启动只证明安装链路完成；镜像可信、边界隔离、身份正确并且快照可恢复，才构成可重复使用的实验环境。
