# React 16.8 核心语法章节设计

## 一、设计目标

本次只设计并重写 React 16.8 模块的第 1 章“核心语法”。章节应让读者沿着“描述静态界面、填充动态内容、选择界面分支、生成元素列表”的顺序掌握 React UI 描述语法，并能通过文档中的代码片段观察每条语法规则的实际结果。

本章不设置“核心模型与学习路线”和“项目创建与首次渲染”两篇独立文章，不创建配套示例工程。React 16.8 版本边界、React 与 ReactDOM 的职责以及最小渲染上下文，直接放入第一篇语法文章中，只保留理解代码所需的内容。

## 二、模块边界

React 16.8 模块固定使用以下六章结构：

| 顺序 | 章节 |
|------|------|
| 1 | 核心语法 |
| 2 | 数据流 |
| 3 | 组件 |
| 4 | Hooks |
| 5 | 高级能力 |
| 6 | 运行机制与性能优化 |

第 1 章只回答“数据如何被描述为 React 元素”。以下知识不在本章展开：

| 知识 | 所属章节 | 本章允许出现的程度 |
|------|----------|--------------------|
| Props、State、事件和表单 | 第 2 章 数据流 | 只在章节衔接处说明，不作为示例前置 |
| 函数组件、children、组合和类组件 | 第 3 章 组件 | 只解释 JSX 中大小写标签的解析规则 |
| Hooks、Effect、Ref 和自定义 Hook | 第 4 章 Hooks | 不使用 |
| Portal、Suspense 和错误边界 | 第 5 章 高级能力 | 不使用 |
| 协调、组件身份和性能优化 | 第 6 章 运行机制与性能优化 | Key 文章只说明使用规则并指向后续原理 |

## 三、参考原则

本章参考 Vue 2 目录的组织形式，而不是复制其主题顺序：

1. 直接进入实际知识主题，不增加只介绍路线的占位文章；
2. 每篇文章负责一个完整知识域，不把单一语法点机械拆成多篇短文；
3. 每条规则都配套代码、结果或错误表现；
4. 文档之间通过知识依赖衔接，不依赖额外示例工程；
5. 控制文章边界，避免形成同时混合生命周期、组件通信和语法规则的超长文档。

## 四、章节学习路径

第 1 章包含四篇文档：

| 顺序 | 文档标题 | 核心输入 | 学习结果 |
|------|----------|----------|----------|
| 1.1 | JSX、TSX 与 React 元素 | 静态标签结构 | 理解 JSX 如何形成 React 元素并进入浏览器 DOM |
| 1.2 | JSX 表达式、属性与内容 | 单个任务对象 | 能把不同类型的数据安全地填入 JSX |
| 1.3 | 条件渲染与界面分支 | 任务页面状态 | 能根据加载、失败、空数据和成功状态选择 UI |
| 1.4 | 列表渲染与 Key | 任务数组 | 能把数组转换为身份稳定的元素列表 |

学习步幅固定为：

```text

→ JSX 中的动态值
→ 单个状态对应的界面分支
→ 一组数据对应的元素列表
→ 第 2 章的数据流
```

四篇文章使用任务展示场景保持字段和命名一致，但每个代码片段都在当前文档中说明必要上下文，不引用独立工程。

## 五、1.1 JSX、TSX 与 React 元素

### 1. 文档目标

从一段静态 JSX 出发，建立“TSX 源码、JSX 编译、React 元素、ReactDOM 提交、浏览器 DOM”之间的关系。本文承担必要的 React UI 描述模型，但不扩展为框架历史、生态介绍或完整项目搭建教程。

### 2. 内部结构

| 二级标题 | 必须覆盖的内容 |
|----------|----------------|
| 一、React 如何描述界面 | 声明式 UI；原生 DOM 命令式更新与 React 元素描述的差别；界面描述和真实 DOM 的边界 |
| 二、JSX 基础语法 | 标签闭合、嵌套、单一根节点、Fragment、JSX 注释和空白处理 |
| 三、JSX 的编译结果 | JSX 转换为 `React.createElement`；React 16.8 的经典 JSX 转换；为什么示例需要导入 React |
| 四、React 元素 | `type`、`props`、`children` 的关系；元素是普通描述对象；元素创建后不通过修改对象更新界面 |
| 五、元素类型与名称解析 | 小写名称对应宿主 DOM；大写标识符对应自定义类型；错误大小写导致的实际结果 |
| 六、React 与 ReactDOM | 两个包的职责；宿主节点检查；`ReactDOM.render` 的最小调用链路 |
| 七、TSX 类型边界 | `.ts` 与 `.tsx`；`JSX.Element` 和 `React.ReactNode` 的基础边界；泛型箭头函数的尖括号消歧 |
| 八、常见错误与验证 | 相邻元素未包裹、标签未闭合、对象作为子节点、名称大小写错误及对应修正 |

### 3. 示例要求

文章至少包含以下对照：

1. 使用原生 DOM 和 JSX 表达相同静态界面；
2. JSX 与对应 `React.createElement` 调用；
3. React 元素、宿主节点和最终 DOM 的关系；
4. Fragment 的简写与显式写法；
5. 一个可以判断原因的 JSX 编译错误和一个运行时渲染错误。

文末应明确下一篇将从静态 JSX 进入动态表达式，不引入 Props 或 State。

## 六、1.2 JSX 表达式、属性与内容

### 1. 文档目标

解释 JavaScript 数据进入 JSX 的位置、可接受值和输出结果，并建立 DOM 属性、样式、属性展开、children 与内容安全的基本规则。

### 2. 内部结构

| 二级标题 | 必须覆盖的内容 |
|----------|----------------|
| 一、在 JSX 中使用表达式 | 大括号语法；变量、属性访问、函数调用和运算表达式；表达式与语句的区别 |
| 二、不同值的渲染结果 | 字符串、数字、元素、数组、`null`、`undefined`、布尔值和普通对象的实际表现 |
| 三、DOM 属性命名 | `className`、`htmlFor`、`tabIndex`、camelCase 属性、布尔属性、`data-*` 和 `aria-*` |
| 四、class 与 style | 动态类名；样式对象；CSS 属性 camelCase；常见数值单位规则 |
| 五、属性展开与覆盖 | 展开语法；从左到右的覆盖顺序；限制透传字段；避免把业务对象完整传给 DOM |
| 六、JSX 中的子内容 | 文本、元素、数组和 Fragment；嵌套结构；空白和换行的观察方式 |
| 七、内容转义与 XSS 边界 | 默认字符串转义；HTML 字符串不会自动解析；`dangerouslySetInnerHTML` 的可信清洗要求 |
| 八、常见错误与验证 | 对象渲染错误、无效属性、错误样式值、属性覆盖和不可信 HTML 对照 |

### 3. 示例要求

文章使用一个静态任务对象展示标题、优先级、完成状态和说明文字。必须通过表格或实际输出说明不同 JavaScript 值的渲染结果，并分别给出安全文本输出和危险 HTML 输出的边界说明。

文末应把“动态值已经能够进入 JSX”作为结论，引出下一篇的数据分支问题。

## 七、1.3 条件渲染与界面分支

### 1. 文档目标

说明 React 没有单独的条件模板语法，界面分支来自 JavaScript 条件表达式和控制流。读者应能为互斥页面状态选择清晰的写法，并识别常见真假值陷阱。

### 2. 内部结构

| 二级标题 | 必须覆盖的内容 |
|----------|----------------|
| 一、条件渲染的本质 | 数据状态决定返回的 React 元素；控制流与 JSX 的职责边界 |
| 二、使用 if 计算元素 | JSX 外计算元素变量；适用于多个分支或需要附加判断的场景 |
| 三、提前返回 | 加载、失败、无权限等前置状态；减少主体 JSX 嵌套 |
| 四、三元表达式 | 二选一内容和元素；适用范围；嵌套三元的可读性问题 |
| 五、逻辑与运算 | 满足条件时渲染；`0 && <Element />` 显示数字零的原因与修正 |
| 六、不渲染内容 | `null`、`false` 和 `undefined` 的结果；有意不返回可见节点 |
| 七、多状态界面建模 | 加载、失败、空数据和成功状态的判断顺序；避免互相矛盾的布尔条件 |
| 八、隐藏与移除 | CSS 隐藏与条件移除 DOM 的区别；状态保持问题留待后续章节 |
| 九、常见错误与选择依据 | 重复条件、不可达分支、嵌套三元和遗漏空数据；分支写法决策表 |

### 3. 示例要求

文章使用同一份任务页面输入，依次展示加载、失败、空数据和成功四种结果。示例通过静态变量切换输入，不使用 State、事件处理或 Hooks。

文末应说明条件渲染解决的是单个状态分支，下一篇继续处理一组数据。

## 八、1.4 列表渲染与 Key

### 1. 文档目标

建立“数组转换为元素数组”的列表渲染模型，并说明 Key 的唯一性、稳定性和来源选择规则。本文只解释可直接使用和观察的规则，协调与组件身份机制留到第 6 章。

### 2. 内部结构

| 二级标题 | 必须覆盖的内容 |
|----------|----------------|
| 一、从数组到元素列表 | `map` 返回元素；箭头函数表达式体和对象体；缺少 `return` 的结果 |
| 二、筛选与转换顺序 | `filter` 后 `map`；空数组结果；避免在 JSX 中堆积复杂计算 |
| 三、Key 的作用范围 | 同层兄弟唯一；跨次渲染保持稳定；Key 与元素身份的基础关系 |
| 四、选择稳定 Key | 业务 ID、数组索引和随机值的区别；索引 Key 的有限适用条件 |
| 五、Key 与普通 Props | Key 不会传给普通 Props；业务 ID 需要单独声明 |
| 六、列表结构 | 嵌套列表；一项返回多个节点；带 Key 的显式 Fragment |
| 七、警告与错误表现 | 缺少 Key、重复 Key、索引 Key 错位和随机 Key 重建的可观察结果 |
| 八、与运行机制的边界 | 当前只掌握规则；协调、状态保留和重置在第 6 章展开 |
| 九、进入数据流 | 静态数组的限制；第 2 章继续学习 Props、State 和事件更新 |

### 3. 示例要求

文章至少包含业务 ID、数组索引和随机 Key 三组对照，并展示 React 的缺少 Key 或重复 Key 警告。为了不提前依赖 State，可以使用两组静态数据和连续渲染说明顺序变化。
