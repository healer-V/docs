# About 页面 sec-head 横线对齐设计

## 一、问题与结论

### 1. 错位原因

`AboutPage.vue` 的 `.sec-title` 使用 `h2` 元素，因此会命中全局 `.vp-doc h2` 规则。全局规则通过 `!important` 添加了上边框、顶部内边距和顶部外边距，而标题右侧的 `.sec-line` 由 `.sec-head` 的 Flex 交叉轴居中定位。两条横线分别以标题顶部和 Flex 行中心为基准，无法自然处于同一水平位置。

移动端还会改变全局 `h2` 的顶部内边距和外边距。若只给 `.sec-line` 增加固定像素偏移，桌面端与移动端将使用不同的误差值，修复结果不稳定。

### 2. 修复结论

组件应隔离全局文章标题样式，并由 `.sec-head` 统一管理标题行中的两条横线。两条线都作为 Flex 布局中的分隔项，使用相同的高度、颜色和交叉轴定位，从而在不同视口下保持共线。

## 二、方案比较

| 方案 | 实现方式 | 优点 | 风险 | 结论 |
|------|----------|------|------|------|
| 统一 Flex 定位 | 重置 `.sec-title` 的全局边框和间距，通过 `.sec-head` 伪元素与 `.sec-line` 绘制两条线 | 定位基准一致，响应式稳定，组件职责清晰 | 需要调整标题行布局 | 采用 |
| 固定偏移 | 对 `.sec-line` 使用 `transform` 或负外边距 | 修改量少 | 依赖当前字号和间距，移动端容易再次错位 | 不采用 |
| 修改全局 `h2` | 调整 `.vp-doc h2` 的边框和间距 | 可直接消除当前覆盖 | 影响所有技术文章标题，修改范围过大 | 不采用 |

## 三、布局设计

### 1. 结构与样式边界

保留现有图标、标题、数量和右侧横线节点，不修改资源数据与链接。`.sec-title` 将显式覆盖全局 `h2` 的 `border-top`、`padding-top` 和 `margin-top`，避免文章排版样式进入自定义组件。

左侧横线由 `.sec-head::before` 绘制，右侧继续使用 `.sec-line`。两者都设置为 `1px` 高度，并在 Flex 交叉轴上居中。图标、标题和数量保持为中间内容组，两条线不会穿过文字或图标。

### 2. 响应式行为

桌面端与移动端使用同一定位规则，不增加基于视口的像素修正。窄屏时横线允许通过 Flex 收缩，但标题、图标和数量不收缩，避免内容重叠或换行导致布局跳动。

## 四、验收标准

### 1. 视觉与工程验证

修复完成后按以下标准验收：

1. 每个 `sec-head` 的左右横线处于同一水平位置；
2. 横线不穿过图标、标题或数量标记；
3. 桌面端和宽度不超过 `640px` 的移动端表现一致；
4. 深色与浅色主题继续使用 `--vp-c-divider`；
5. VitePress 构建成功，且修改仅涉及设计说明与 `AboutPage.vue`。
