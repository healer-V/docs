# Vite 打包优化全链路

## 一、构建产物分析

在优化之前，先用工具弄清楚「体积大在哪里」。

### 1. 安装分析插件

::: details rollup-plugin-visualizer 配置

```bash
npm install -D rollup-plugin-visualizer
```

```ts{5-12}
// vite.config.ts
import { visualizer } from 'rollup-plugin-visualizer'

export default defineConfig({
  plugins: [
    visualizer({
      open: true,                    // 构建完自动打开报告
      filename: 'dist/stats.html',
      gzipSize: true,
      template: 'treemap',           // 矩形树图最直观
    }),
  ],
})
```

执行 `npm run build` 后浏览器会自动打开分析页面，模块体积一目了然。

:::

### 2. 读懂分析报告

拿到分析报告后，重点关注：

| 关注点 | 对应优化方案 |
|--------|-------------|
| 某第三方库体积异常大 | 按需引入 / 用更轻量替代品 |
| 同一个库被多个 chunk 重复打包 | 调整 `manualChunks` |
| `vendor` chunk 过大（>500KB） | 拆分 vendor，按框架分组 |
| 业务代码未分割，首屏加载全部 | 路由懒加载 + 代码分割 |

## 二、代码分割

### 1. 路由懒加载

路由懒加载是最直接的代码分割手段，让用户只在访问某个页面时才下载对应代码：

::: details React 路由懒加载示例

```ts{4-7}
// src/router/index.tsx
import { lazy, Suspense } from 'react'
import { createBrowserRouter } from 'react-router-dom'

// 每个 lazy() 调用都会生成独立的 chunk
const Dashboard = lazy(() => import('@/pages/Dashboard'))
const UserManage = lazy(() => import('@/pages/UserManage'))
const Settings = lazy(() => import('@/pages/Settings'))

export const router = createBrowserRouter([
  {
    path: '/',
    element: (
      <Suspense fallback={<div>加载中...</div>}>
        <Dashboard />
      </Suspense>
    ),
  },
  { path: '/users', element: <Suspense fallback={null}><UserManage /></Suspense> },
  { path: '/settings', element: <Suspense fallback={null}><Settings /></Suspense> },
])
```

:::

::: details Vue 路由懒加载示例

```ts
// src/router/index.ts
import { createRouter, createWebHistory } from 'vue-router'

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    {
      path: '/',
      // 动态 import() 自动触发代码分割
      component: () => import('@/pages/Dashboard.vue'),
    },
    {
      path: '/users',
      component: () => import('@/pages/UserManage.vue'),
    },
  ],
})
```

:::

### 2. manualChunks 精细化分包

Vite 默认的自动分包策略在某些场景下会产生过大的 `vendor` chunk，需要手动干预：

::: details 生产级 manualChunks 配置

```ts{6-23}
// vite.config.ts
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks(id) {
          // React 核心库单独一个 chunk（缓存稳定）
          if (id.includes('node_modules/react/') || id.includes('node_modules/react-dom/')) {
            return 'react-core'
          }

          // React 周边生态
          if (id.includes('node_modules/react-router') || id.includes('node_modules/react-query')) {
            return 'react-ecosystem'
          }

          // UI 组件库（体积最大，单独分包）
          if (id.includes('node_modules/antd') || id.includes('node_modules/@ant-design')) {
            return 'antd'
          }

          // 工具库（较稳定，可以长期缓存）
          if (id.includes('node_modules/')) {
            return 'vendor'
          }
        },
        chunkFileNames: 'js/[name]-[hash].js',
        entryFileNames: 'js/[name]-[hash].js',
        assetFileNames: (info) => {
          const ext = info.name?.split('.').pop() || ''
          if (/png|jpe?g|gif|svg|webp/.test(ext)) return 'images/[name]-[hash][extname]'
          if (/woff2?|ttf|eot/.test(ext)) return 'fonts/[name]-[hash][extname]'
          return 'assets/[name]-[hash][extname]'
        },
      },
    },
  },
})
```

:::

::: warning manualChunks 的陷阱
手动分包时可能出现**循环依赖**导致某些模块被重复打包。建议在调整后重新跑 `visualizer` 检查是否还有重复打包现象。
:::

## 三、Tree Shaking

### 1. Tree Shaking 的前提

Tree Shaking 依赖 ES 模块的**静态结构**，以下写法会导致 Tree Shaking 失效：

```ts
// 错误：动态 require（CommonJS），无法静态分析
const utils = require('./utils')

// 正确：静态 import，可以被 Tree Shaking
import { formatDate } from './utils'
```

### 2. 第三方库的按需引入

体积大的库如果不按需引入，会把整个库打包进去：

::: code-group

```ts [Lodash（推荐写法）]
// 错误：引入整个 lodash（70KB+）
import _ from 'lodash'
_.debounce(fn, 300)

// 正确：只引入需要的函数
import debounce from 'lodash/debounce'
// 或者使用 ES 模块版本
import { debounce } from 'lodash-es'
```

```ts [Ant Design（推荐写法）]
// 错误：全量引入（虽然 antd v5 已支持按需引入，但不建议全量）
import Antd from 'antd'
app.use(Antd)

// 正确：只引入用到的组件
import { Button, Input, Form, Table } from 'antd'
```

```ts [Day.js（推荐写法）]
// 错误：引入所有插件
import dayjs from 'dayjs'
import 'dayjs/locale/zh-cn'
import isBetween from 'dayjs/plugin/isBetween'

// 正确：只按需引入需要的插件
import dayjs from 'dayjs'
import 'dayjs/locale/zh-cn'
dayjs.locale('zh-cn')
```

:::

### 3. 检查 sideEffects 字段

在自己的库中，要在 `package.json` 中正确声明 `sideEffects`，告诉打包工具哪些文件可以安全删除：

```json
{
  "sideEffects": false,
  "sideEffects": ["**/*.css", "**/*.scss", "./src/polyfills.ts"]
}
```

## 四、资源压缩

### 1. JavaScript 压缩

Vite 默认使用 esbuild 压缩 JS（快但产物略大），生产环境推荐改用 terser（产物更小）：

::: details terser 配置

```bash
npm install -D @rollup/plugin-terser
# 或使用 vite 内置的 terser（需安装）
npm install -D terser
```

```ts
export default defineConfig({
  build: {
    minify: 'terser',
    terserOptions: {
      compress: {
        drop_console: true,       // 移除所有 console.log
        drop_debugger: true,      // 移除 debugger
        pure_funcs: ['console.info', 'console.warn'],  // 移除指定函数调用
      },
      format: {
        comments: false,          // 移除注释
      },
    },
  },
})
```

:::

### 2. Gzip / Brotli 压缩

服务端可以发送预压缩的 `.gz`/`.br` 文件，浏览器自动解压，显著减少传输体积：

::: details vite-plugin-compression 配置

```bash
npm install -D vite-plugin-compression
```

```ts{5-12}
import compression from 'vite-plugin-compression'

export default defineConfig({
  plugins: [
    // Gzip 压缩（兼容性更好）
    compression({
      algorithm: 'gzip',
      ext: '.gz',
      threshold: 10240,           // 只压缩大于 10KB 的文件
      deleteOriginFile: false,    // 保留原始文件（Nginx 需要回退）
    }),
    // Brotli 压缩（压缩率更高，现代浏览器支持）
    compression({
      algorithm: 'brotliCompress',
      ext: '.br',
      threshold: 10240,
    }),
  ],
})
```

Nginx 配合配置：

```nginx
# /etc/nginx/conf.d/app.conf
server {
    # 优先使用预压缩文件
    gzip_static on;
    brotli_static on;   # 需要 ngx_brotli 模块

    location ~* \.(js|css|html|svg)$ {
        gzip_static on;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

:::

### 3. 图片优化

::: details vite-plugin-imagemin 配置

```bash
npm install -D vite-plugin-imagemin
```

```ts
import viteImagemin from 'vite-plugin-imagemin'

export default defineConfig({
  plugins: [
    viteImagemin({
      mozjpeg: { quality: 80 },         // JPEG 压缩质量
      optipng: { optimizationLevel: 5 }, // PNG 优化级别
      pngquant: { quality: [0.7, 0.9], speed: 4 },
      svgo: {
        plugins: [{ name: 'removeViewBox', active: false }],
      },
      webp: { quality: 75 },            // 转换为 WebP
    }),
  ],
})
```

:::

::: tip 小图标推荐 SVG Sprite
多个小 SVG 图标可以用 `vite-plugin-svg-icons` 打包成 SVG Sprite，减少 HTTP 请求。
:::

## 五、依赖优化

### 1. CDN 外部化大型依赖

将 React、Vue 等不常变化的大型库通过 CDN 引入，让浏览器直接缓存：

::: details CDN 外部化配置

```ts
// vite.config.ts
export default defineConfig({
  build: {
    rollupOptions: {
      // 告诉 Rollup 这些包不需要打包，从全局变量读取
      external: ['react', 'react-dom'],
      output: {
        globals: {
          react: 'React',
          'react-dom': 'ReactDOM',
        },
      },
    },
  },
})
```

```html
<!-- index.html 中通过 CDN 引入 -->
<script crossorigin src="https://unpkg.com/react@18/umd/react.production.min.js"></script>
<script crossorigin src="https://unpkg.com/react-dom@18/umd/react-dom.production.min.js"></script>
```

:::

### 2. 优化依赖预构建

开发时某些依赖加载慢，可以手动指定预构建范围：

```ts
export default defineConfig({
  optimizeDeps: {
    // 强制预构建（解决某些 CJS 库在 ESM 环境报错的问题）
    include: [
      'react',
      'react-dom',
      'antd',
      'lodash-es',
      '@ant-design/icons',   // 图标库按需引入后需要预构建
    ],
    // 排除不需要预构建的包
    exclude: ['your-local-package'],
  },
})
```

## 六、构建性能优化

### 1. 开启构建缓存

```ts
export default defineConfig({
  build: {
    // Rollup 构建缓存（Vite 5.1+）
    // 默认已开启，首次构建后二次构建速度提升明显
    commonjsOptions: {
      include: [/node_modules/],
    },
  },
})
```

### 2. 并行压缩

```ts
export default defineConfig({
  build: {
    minify: 'terser',
    terserOptions: {
      // terser 默认使用多进程并行压缩
      parallel: true,
    },
  },
})
```

### 3. 构建产物缓存策略

合理的文件命名策略能让浏览器充分利用缓存，只下载真正变化的文件：

```ts
rollupOptions: {
  output: {
    // 带 hash 的文件名：内容不变则 hash 不变，可以长期缓存
    chunkFileNames: 'js/[name]-[hash].js',
    entryFileNames: 'js/[name]-[hash].js',
    assetFileNames: 'assets/[name]-[hash][extname]',
  },
}
```

对应 Nginx 缓存配置：

```nginx
# JS/CSS/图片等带 hash 的文件可以长期缓存
location ~* \.(js|css|png|jpg|svg|woff2)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}

# HTML 文件不缓存（包含最新的 chunk hash 引用）
location ~* \.html$ {
    expires -1;
    add_header Cache-Control "no-cache";
}
```

## 七、优化效果检验

### 1. 构建产物检查清单

::: details 打包优化完成后的检查项

- [ ] 运行 `npm run build` 查看各 chunk 大小，单个 chunk 不超过 500KB（gzip 后）
- [ ] 打开 `dist/stats.html` 确认没有重复打包的模块
- [ ] 检查 `dist/` 目录是否有 `.gz` / `.br` 预压缩文件
- [ ] 用 `vite preview` 启动预览，用 Chrome DevTools Network 确认各资源的加载时间
- [ ] 用 Lighthouse 跑分，目标 Performance > 90

:::

### 2. 常见问题排查

| 问题 | 可能原因 | 排查方法 |
|------|---------|---------|
| vendor chunk 过大 | 未按需引入第三方库 | visualizer 找到大模块，改为按需引入 |
| 首屏加载慢 | 未做路由懒加载 | 检查路由配置，改用 `lazy()` |
| 热更新后变慢 | 依赖预构建失效 | 删除 `node_modules/.vite` 重启 |
| 构建报循环依赖警告 | manualChunks 分包不当 | 调整分包策略，避免跨 chunk 循环引用 |
