# 企业级脚手架：create-vite 与 vite.config.ts 全解

## 一、create-vite 快速创建项目

### 1. 创建命令

```bash
# 交互式创建（推荐）
npm create vite@latest my-app

# 直接指定框架和变体，跳过交互
npm create vite@latest my-app -- --template react-ts
npm create vite@latest my-app -- --template vue-ts
```

支持的官方模板：

| 模板名 | 说明 |
|--------|------|
| `react-ts` | React 18 + TypeScript |
| `vue-ts` | Vue 3 + TypeScript |
| `react-swc-ts` | React 18 + SWC 编译器（更快） |
| `vanilla-ts` | 原生 TypeScript |
| `preact-ts` | Preact + TypeScript |

### 2. 初始目录结构

::: details React + TypeScript 模板生成的目录

```
my-app/
├── public/
│   └── vite.svg
├── src/
│   ├── assets/
│   │   └── react.svg
│   ├── App.tsx
│   ├── App.css
│   ├── main.tsx
│   └── vite-env.d.ts      # Vite 客户端类型声明
├── index.html             # 入口 HTML（在项目根目录，不在 public/）
├── package.json
├── tsconfig.json
├── tsconfig.node.json     # vite.config.ts 专用 TS 配置
└── vite.config.ts
```

:::

::: tip index.html 在根目录的原因
Vite 将 `index.html` 视为应用入口，开发服务器直接以项目根目录作为静态文件根，不需要放到 `public/` 下。`<script type="module" src="/src/main.tsx">` 中的路径是相对于项目根目录的绝对路径。
:::

## 二、vite.config.ts 核心配置详解

### 1. 配置文件基础结构

::: details 完整的企业级 vite.config.ts 示例

```ts{3-5,8}
// vite.config.ts
import { defineConfig, loadEnv } from 'vite'
import react from '@vitejs/plugin-react'
import path from 'path'

// defineConfig 提供 TypeScript 类型提示
// 回调函数形式可以拿到 mode（development/production）和 command（serve/build）
export default defineConfig(({ mode, command }) => {
  const env = loadEnv(mode, process.cwd(), '')

  return {
    plugins: [react()],

    resolve: {
      alias: {
        '@': path.resolve(__dirname, './src'),
        '@components': path.resolve(__dirname, './src/components'),
        '@utils': path.resolve(__dirname, './src/utils'),
        '@hooks': path.resolve(__dirname, './src/hooks'),
        '@types': path.resolve(__dirname, './src/types'),
      },
    },

    server: {
      host: '0.0.0.0',      // 局域网可访问
      port: 3000,
      open: true,
      proxy: {
        '/api': {
          target: env.VITE_API_BASE_URL,
          changeOrigin: true,
          rewrite: (path) => path.replace(/^\/api/, ''),
        },
      },
    },

    build: {
      outDir: 'dist',
      sourcemap: command === 'serve',   // 开发时开启，生产关闭
      rollupOptions: {
        output: {
          manualChunks: {
            'react-vendor': ['react', 'react-dom'],
            'router': ['react-router-dom'],
          },
        },
      },
    },

    css: {
      preprocessorOptions: {
        scss: {
          additionalData: `@import "@/styles/variables.scss";`,
        },
      },
    },
  }
})
```

:::

### 2. resolve 配置

`resolve` 控制模块解析行为，最常用的是 `alias`（路径别名）。

#### (1) 路径别名配置

::: details 完整的别名配置示例

```ts
// vite.config.ts
import path from 'path'

export default defineConfig({
  resolve: {
    alias: {
      // 常用别名
      '@': path.resolve(__dirname, './src'),

      // 按功能细分（推荐企业项目使用）
      '@api': path.resolve(__dirname, './src/api'),
      '@assets': path.resolve(__dirname, './src/assets'),
      '@components': path.resolve(__dirname, './src/components'),
      '@hooks': path.resolve(__dirname, './src/hooks'),
      '@layouts': path.resolve(__dirname, './src/layouts'),
      '@pages': path.resolve(__dirname, './src/pages'),
      '@store': path.resolve(__dirname, './src/store'),
      '@utils': path.resolve(__dirname, './src/utils'),
    },
    // 导入时省略这些后缀（不推荐省略，容易混淆）
    // extensions: ['.ts', '.tsx', '.js', '.jsx'],
  },
})
```

:::

别名配置后，还需要同步到 `tsconfig.json`，否则 TypeScript 无法识别：

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"],
      "@components/*": ["./src/components/*"],
      "@utils/*": ["./src/utils/*"]
    }
  }
}
```

#### (2) extensions 与 conditions

```ts
resolve: {
  // 解析 package.json 中 exports 字段时的条件
  conditions: ['development', 'browser'],
  // 自定义 package.json 的主字段优先级
  mainFields: ['browser', 'module', 'main'],
}
```

### 3. server 配置

`server` 控制开发服务器行为。

#### (1) 基础配置

| 字段 | 类型 | 说明 |
|------|------|------|
| `host` | `string` | 监听地址，`0.0.0.0` 允许局域网访问 |
| `port` | `number` | 端口号，默认 5173 |
| `open` | `boolean\|string` | 启动后自动打开浏览器 |
| `https` | `boolean\|object` | 启用 HTTPS |
| `cors` | `boolean\|object` | 跨域配置 |
| `strictPort` | `boolean` | 端口被占用时直接报错而不自动换端口 |

#### (2) 代理配置

::: details 多接口代理示例

```ts
// vite.config.ts
server: {
  proxy: {
    // 简单代理：匹配 /api 开头的请求
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true,            // 修改请求头的 Host 为 target
      rewrite: (path) => path.replace(/^\/api/, ''),  // 去掉 /api 前缀
    },

    // WebSocket 代理
    '/ws': {
      target: 'ws://localhost:8080',
      ws: true,
    },

    // 正则匹配
    '^/auth/.*': {
      target: 'http://auth-service:9000',
      changeOrigin: true,
    },
  },
}
```

:::

::: tip changeOrigin 是什么
`changeOrigin: true` 会让代理请求的 `Host` 头变成目标服务器的域名，避免后端因 `Host` 不匹配而拒绝请求。开发时几乎都应该设置为 `true`。
:::

### 4. build 配置

`build` 控制生产构建行为。

#### (1) 核心字段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `outDir` | `string` | `dist` | 构建输出目录 |
| `assetsDir` | `string` | `assets` | 静态资源子目录 |
| `assetsInlineLimit` | `number` | `4096` | 小于该值（字节）的资源转为 base64 |
| `sourcemap` | `boolean\|string` | `false` | 是否生成 sourcemap |
| `minify` | `boolean\|string` | `esbuild` | 压缩方式：`esbuild`（快）或 `terser`（产物更小） |
| `target` | `string\|string[]` | `modules` | 编译目标 |
| `cssCodeSplit` | `boolean` | `true` | 是否分割 CSS |

#### (2) 代码分割策略

::: details manualChunks 分包示例

```ts{6-14}
// vite.config.ts
build: {
  rollupOptions: {
    output: {
      // 函数形式更灵活，可以按 id 动态决定归属
      manualChunks(id) {
        if (id.includes('node_modules')) {
          // 将 React 相关库打包到单独 chunk，充分利用缓存
          if (id.includes('react') || id.includes('react-dom') || id.includes('scheduler')) {
            return 'react-vendor'
          }
          if (id.includes('antd') || id.includes('@ant-design')) {
            return 'antd-vendor'
          }
          return 'vendor'  // 其余第三方库合并到 vendor
        }
        // 按页面分包（配合路由懒加载）
        if (id.includes('/src/pages/')) {
          const pageName = id.match(/\/src\/pages\/([^/]+)/)?.[1]
          if (pageName) return `page-${pageName}`
        }
      },
      chunkFileNames: 'js/[name]-[hash].js',
      entryFileNames: 'js/[name]-[hash].js',
      assetFileNames: (assetInfo) => {
        const ext = assetInfo.name?.split('.').pop() || ''
        if (/png|jpe?g|svg|gif|webp/.test(ext)) return 'images/[name]-[hash][extname]'
        if (/woff2?|eot|ttf/.test(ext)) return 'fonts/[name]-[hash][extname]'
        return 'assets/[name]-[hash][extname]'
      },
    },
  },
}
```

:::

### 5. css 配置

#### (1) CSS 预处理器

::: details SCSS 全局变量注入

```ts
// vite.config.ts
css: {
  preprocessorOptions: {
    scss: {
      // 每个 SCSS 文件都会自动注入这行，无需手动 @import
      additionalData: `@use "@/styles/variables" as *;`,
    },
    less: {
      modifyVars: {
        'primary-color': '#1890ff',
      },
      javascriptEnabled: true,
    },
  },
}
```

```scss
// src/styles/variables.scss
$primary: #1890ff;
$border-radius: 4px;
$font-size-base: 14px;
```

:::

#### (2) CSS Modules

```ts
css: {
  modules: {
    // 修改 CSS Modules 生成的类名格式
    generateScopedName: '[name]__[local]--[hash:5]',
    localsConvention: 'camelCase',  // 驼峰访问：styles.myClass
  },
}
```

## 三、环境变量管理

### 1. 内置环境变量

Vite 暴露的内置变量可通过 `import.meta.env` 访问：

| 变量 | 说明 |
|------|------|
| `import.meta.env.MODE` | 当前模式：`development` / `production` / 自定义 |
| `import.meta.env.BASE_URL` | 部署基础路径（对应 `base` 配置） |
| `import.meta.env.PROD` | 是否为生产环境 |
| `import.meta.env.DEV` | 是否为开发环境 |
| `import.meta.env.SSR` | 是否为 SSR 环境 |

### 2. 自定义环境变量

只有以 `VITE_` 开头的变量才会暴露给客户端代码，其他变量（如数据库密码）不会被打包进去。

::: details 多环境 .env 文件

```bash
# .env                    所有环境生效
VITE_APP_TITLE="My App"

# .env.development        开发环境
VITE_API_BASE_URL="http://localhost:8080"
VITE_ENABLE_MOCK=true

# .env.staging            测试环境（npm run build -- --mode staging）
VITE_API_BASE_URL="https://api-staging.example.com"
VITE_ENABLE_MOCK=false

# .env.production         生产环境
VITE_API_BASE_URL="https://api.example.com"
VITE_ENABLE_MOCK=false
```

:::

### 3. TypeScript 类型声明

Vite 的 `import.meta.env` 默认类型较宽泛，需要手动补充类型声明：

```ts
// src/vite-env.d.ts（create-vite 自动生成）
/// <reference types="vite/client" />

// 扩展 ImportMetaEnv 接口
interface ImportMetaEnv {
  readonly VITE_APP_TITLE: string
  readonly VITE_API_BASE_URL: string
  readonly VITE_ENABLE_MOCK: string  // 注意：.env 文件中所有值都是字符串类型
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}
```

### 4. 在 vite.config.ts 中读取环境变量

配置文件运行在 Node.js 环境，不能直接使用 `import.meta.env`，需要用 `loadEnv`：

```ts
// vite.config.ts
import { defineConfig, loadEnv } from 'vite'

export default defineConfig(({ mode }) => {
  // 第三个参数 '' 表示加载所有前缀的变量（包括非 VITE_ 前缀）
  const env = loadEnv(mode, process.cwd(), '')

  return {
    server: {
      proxy: {
        '/api': {
          target: env.VITE_API_BASE_URL,  // 从 .env 文件读取
          changeOrigin: true,
        },
      },
    },
  }
})
```

## 四、别名配置最佳实践

### 1. 统一管理别名

将别名统一定义在一个地方，在 `vite.config.ts` 和 `tsconfig.json` 中同步引用：

::: details 使用 tsconfig-paths 统一管理

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import tsconfigPaths from 'vite-tsconfig-paths'

export default defineConfig({
  // vite-tsconfig-paths 插件自动读取 tsconfig.json 的 paths 配置
  // 不需要在 vite.config.ts 中重复定义 alias
  plugins: [tsconfigPaths()],
})
```

```json
// tsconfig.json（单一数据源）
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@components/*": ["src/components/*"],
      "@utils/*": ["src/utils/*"],
      "@api/*": ["src/api/*"],
      "@store/*": ["src/store/*"]
    }
  }
}
```

:::

::: warning 避免循环依赖
配置路径别名时，不要让 `@utils` 指向 `@components` 内部的文件，否则容易造成循环依赖。建议单向依赖：`pages` → `components` → `utils`。
:::

### 2. 别名 vs 相对路径

| 场景 | 推荐方式 |
|------|---------|
| 跨层级引用（超过 2 层 `../`） | 使用别名 `@/components/Button` |
| 同目录或相邻目录 | 使用相对路径 `./Button` 或 `../utils` |
| 第三方库 | 直接写包名，不需要别名 |
