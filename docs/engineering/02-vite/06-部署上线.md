# Vite 项目部署上线与 CI/CD 自动化

## 一、构建产物说明

### 1. 执行构建

```bash
# 生产构建
npm run build

# 指定模式（对应 .env.production）
npm run build -- --mode production
```

执行后生成 `dist/` 目录，典型结构如下：

```
dist/
├── index.html              # 入口 HTML（不能缓存）
├── assets/
│   ├── index-Bk3xYz.css   # 带 hash 的 CSS
│   └── index-Bk3xYz.js    # 带 hash 的 JS
└── images/
    └── logo-C8kZp.svg
```

::: tip 为什么静态资源带 hash
文件名中的 hash 是内容的指纹，内容不变则 hash 不变。这样可以对这些文件设置**超长缓存**（1年），浏览器第二次访问直接读缓存，不发请求。只有 `index.html` 不能缓存，它引用了最新的 hash 文件名。
:::

### 2. 本地预览

```bash
# 用 vite preview 启动本地静态服务器预览产物
npm run preview

# 指定端口
npx vite preview --port 4000
```

`vite preview` 和 Nginx 行为接近，可以发现路由 404 等问题。

## 二、Nginx 部署

### 1. 基础 SPA 配置

Vite 构建的 SPA 项目，所有路由都由前端 JavaScript 处理，Nginx 需要将 **所有未匹配的路径** 都返回 `index.html`：

::: details Nginx SPA 基础配置

```nginx
# /etc/nginx/conf.d/my-vite-app.conf
server {
    listen 80;
    server_name example.com www.example.com;

    # 网站根目录指向构建产物
    root /var/www/my-vite-app/dist;
    index index.html;

    # Gzip 压缩（减少传输体积约 70%）
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_comp_level 6;
    gzip_types
        text/plain text/css text/xml text/javascript
        application/javascript application/json application/xml
        image/svg+xml font/woff2;

    # 带 hash 的静态资源：长期缓存（1年）
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|webp|woff|woff2|ttf|eot|ico)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # HTML 文件：禁止缓存（确保用户始终拿到最新的 hash 引用）
    location ~* \.html$ {
        expires -1;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        add_header Pragma "no-cache";
    }

    # SPA 路由支持：所有路径回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

:::

### 2. HTTPS 配置

::: details 完整的 HTTPS Nginx 配置

```nginx
# /etc/nginx/conf.d/my-vite-app.conf

# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;
}

# HTTPS 主配置
server {
    listen 443 ssl http2;
    server_name example.com www.example.com;
    root /var/www/my-vite-app/dist;
    index index.html;

    # SSL 证书（Let's Encrypt 或阿里云免费证书）
    ssl_certificate     /etc/nginx/ssl/example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/example.com.key;

    # SSL 优化
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # 安全响应头
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-XSS-Protection "1; mode=block" always;

    # 如果已有预压缩文件（.gz/.br），优先使用
    gzip_static on;

    # 静态资源长缓存
    location ~* \.(js|css|png|jpg|svg|webp|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # HTML 不缓存
    location ~* \.html$ {
        expires -1;
        add_header Cache-Control "no-cache";
    }

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_read_timeout 60s;
    }

    # 日志
    access_log /var/log/nginx/my-vite-app.access.log;
    error_log  /var/log/nginx/my-vite-app.error.log;
}
```

:::

### 3. 手动部署脚本

::: details deploy.sh

```bash
#!/bin/bash
# deploy.sh - 本地构建后上传到服务器

set -e   # 任何命令失败立即退出

SERVER_USER="deploy"
SERVER_HOST="your.server.ip"
DEPLOY_PATH="/var/www/my-vite-app"

echo "=== 开始构建 ==="
npm run build

echo "=== 上传到服务器 ==="
# 用 rsync 同步（只传变化的文件，速度快）
rsync -avz --delete \
  dist/ \
  ${SERVER_USER}@${SERVER_HOST}:${DEPLOY_PATH}/dist/

echo "=== 重载 Nginx ==="
ssh ${SERVER_USER}@${SERVER_HOST} "sudo nginx -s reload"

echo "=== 部署完成 ==="
```

```bash
# 给脚本添加执行权限
chmod +x deploy.sh

# 执行部署
./deploy.sh
```

:::

## 三、Docker 容器化部署

### 1. 多阶段 Dockerfile

::: details Dockerfile（构建 + 运行两阶段）

```dockerfile
# Dockerfile

# ===== 阶段1：Node.js 构建 =====
FROM node:20-alpine AS builder

WORKDIR /app

# 优先复制依赖文件（利用 Docker 层缓存，依赖不变则不重新安装）
COPY package*.json ./
RUN npm ci --frozen-lockfile

# 复制源代码并构建
COPY . .
RUN npm run build

# ===== 阶段2：Nginx 运行时（仅包含静态产物）=====
FROM nginx:1.25-alpine

# 复制 Nginx 配置
COPY nginx.conf /etc/nginx/conf.d/default.conf

# 从构建阶段复制产物（镜像只有 ~50MB）
COPY --from=builder /app/dist /usr/share/nginx/html

EXPOSE 80

# 非 root 用户运行（安全加固）
RUN chown -R nginx:nginx /usr/share/nginx/html
CMD ["nginx", "-g", "daemon off;"]
```

`nginx.conf`（放在项目根目录）：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://backend:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

`.dockerignore`：

```
node_modules
dist
.git
.env
*.log
```

:::

### 2. Docker Compose 完整配置

::: details docker-compose.yml

```yaml
# docker-compose.yml
version: '3.9'

services:
  frontend:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "80:80"
    depends_on:
      - backend
    restart: unless-stopped
    networks:
      - app-network

  backend:
    image: my-backend:latest
    environment:
      - NODE_ENV=production
      - DATABASE_URL=postgresql://app:secret@db:5432/mydb
    ports:
      - "8080:8080"
    depends_on:
      - db
    restart: unless-stopped
    networks:
      - app-network

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: mydb
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - app-network

networks:
  app-network:
    driver: bridge

volumes:
  postgres_data:
```

```bash
# 启动所有服务
docker-compose up -d

# 查看日志
docker-compose logs -f frontend

# 重新构建前端（代码更新后）
docker-compose up -d --build frontend
```

## 四、GitHub Actions CI/CD

### 1. 自动构建并部署到服务器

在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中添加以下 Secrets：

| Secret 名称 | 说明 |
|-------------|------|
| `SERVER_HOST` | 服务器 IP 地址 |
| `SERVER_USER` | SSH 登录用户名（建议使用非 root 用户） |
| `SERVER_SSH_KEY` | SSH 私钥（`cat ~/.ssh/id_rsa`） |
| `VITE_API_BASE_URL` | 生产环境 API 地址 |

::: details .github/workflows/deploy.yml

```yaml
# .github/workflows/deploy.yml
name: Build and Deploy

on:
  push:
    branches: [main]     # 推送到 main 分支时触发
  workflow_dispatch:     # 支持手动触发

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装 Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: 安装依赖
        run: npm ci

      - name: 构建
        run: npm run build
        env:
          VITE_API_BASE_URL: ${{ secrets.VITE_API_BASE_URL }}

      - name: 上传产物到服务器（rsync over SSH）
        uses: burnett01/rsync-deployments@7.0.1
        with:
          switches: -avzr --delete
          path: dist/
          remote_path: /var/www/my-vite-app/dist/
          remote_host: ${{ secrets.SERVER_HOST }}
          remote_user: ${{ secrets.SERVER_USER }}
          remote_key: ${{ secrets.SERVER_SSH_KEY }}

      - name: 重载 Nginx
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: sudo nginx -s reload

      - name: 通知部署结果
        if: always()
        run: |
          echo "部署状态：${{ job.status }}"
```

:::

### 2. 带测试的完整 CI/CD 流水线

::: details .github/workflows/ci-cd.yml（含测试、预览环境、生产部署）

```yaml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  # 第一阶段：代码检查 + 单元测试
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - name: TypeScript 类型检查
        run: npx tsc --noEmit
      - name: ESLint 检查
        run: npm run lint
      - name: 单元测试
        run: npm run test:unit

  # 第二阶段：构建
  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - name: 构建产物
        run: npm run build
        env:
          VITE_API_BASE_URL: ${{ secrets.VITE_API_BASE_URL }}
      - name: 上传构建产物
        uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist/
          retention-days: 1

  # 第三阶段：部署到生产（仅 main 分支）
  deploy-production:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    environment:
      name: production
      url: https://example.com
    steps:
      - name: 下载构建产物
        uses: actions/download-artifact@v4
        with:
          name: dist
          path: dist/
      - name: 部署到生产服务器
        uses: burnett01/rsync-deployments@7.0.1
        with:
          switches: -avzr --delete
          path: dist/
          remote_path: /var/www/my-vite-app/dist/
          remote_host: ${{ secrets.SERVER_HOST }}
          remote_user: ${{ secrets.SERVER_USER }}
          remote_key: ${{ secrets.SERVER_SSH_KEY }}
      - name: 重载 Nginx
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: sudo nginx -s reload
```

## 五、常见部署问题

### 1. 刷新页面 404

**原因**：Nginx 找不到对应的物理文件，没有回退到 `index.html`。

**解决**：确认 Nginx 配置了 `try_files $uri $uri/ /index.html`。

### 2. API 请求跨域

**原因**：前端和后端不同域，浏览器阻止跨域请求。

**解决方案**：

::: code-group

```nginx [方案一：Nginx 反向代理（推荐）]
# 前端和后端通过同一域名访问，不存在跨域
location /api/ {
    proxy_pass http://127.0.0.1:8080/;
    # ... 其他 proxy 头
}
```

```ts [方案二：后端开启 CORS]
// Express 后端
import cors from 'cors'
app.use(cors({
  origin: 'https://example.com',
  credentials: true,
}))
```

:::

### 3. 静态资源 404

**原因**：`vite.config.ts` 的 `base` 配置与实际部署路径不一致。

```ts
// 如果部署到子路径 https://example.com/app/
export default defineConfig({
  base: '/app/',  // 必须与部署路径匹配
})
```

::: warning 根路径部署时 base 的设置
根路径部署时，`base` 应为 `/`（默认值）。如果设置为相对路径 `./`，在某些路由下会导致资源路径错误。
:::
