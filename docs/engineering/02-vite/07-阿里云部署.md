# 阿里云 ECS 完整部署流程

## 一、部署前准备

### 1. 所需资源清单

| 资源 | 说明 | 获取方式 |
|------|------|---------|
| ECS 服务器 | 建议 2核4G，Ubuntu 22.04 LTS | 阿里云控制台购买 |
| 弹性公网 IP | ECS 实例绑定 | 随 ECS 购买或单独购买 |
| 域名 | 用于 HTTPS 和用户访问 | 阿里云域名服务购买 |
| SSL 证书 | 单域名免费版即可 | 阿里云证书管理 → 免费申请 |

::: tip 服务器系统推荐
优先选择 **Ubuntu 22.04 LTS**，软件包更新及时，社区资料丰富。生产环境使用 LTS 版本，避免频繁升级系统。
:::

### 2. 安全组配置

在阿里云控制台 **ECS → 安全组 → 配置规则** 中，入方向至少开放：

| 端口 | 协议 | 用途 |
|------|------|------|
| 22 | TCP | SSH 远程连接 |
| 80 | TCP | HTTP 访问 |
| 443 | TCP | HTTPS 访问 |

::: warning 生产环境建议
上线后将 SSH 端口改为非标准端口（如 2222），并限制 SSH 访问 IP 为公司出口 IP，降低被暴力破解的风险。
:::

## 二、服务器初始化

### 1. 首次 SSH 连接

```bash
# 使用阿里云控制台设置的密码登录
ssh root@your-server-ip

# 或使用密钥文件登录（推荐）
ssh -i ~/.ssh/aliyun-key.pem root@your-server-ip
```

### 2. 系统基础配置

::: details 服务器初始化脚本

```bash
#!/bin/bash
# 以 root 身份执行

# 1. 更新系统
apt update && apt upgrade -y

# 2. 安装常用工具
apt install -y wget curl git vim htop unzip

# 3. 设置时区为北京时间
timedatectl set-timezone Asia/Shanghai

# 4. 创建部署用户（避免直接使用 root）
adduser deploy
usermod -aG sudo deploy

# 5. 将 root 的 SSH 公钥复制给 deploy 用户
mkdir -p /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys

# 6. 允许 deploy 用户无密码执行 nginx reload（部署脚本需要）
echo "deploy ALL=(ALL) NOPASSWD: /usr/sbin/nginx" >> /etc/sudoers.d/deploy

echo "初始化完成，请切换到 deploy 用户"
```

:::

切换到 deploy 用户验证：

```bash
su - deploy
sudo nginx -v   # 测试 sudo 权限
```

### 3. 配置 UFW 防火墙

```bash
# 开放必要端口
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp

# 启用防火墙
ufw enable
ufw status
```

## 三、安装运行环境

### 1. 安装 Node.js（用 nvm 管理版本）

::: details nvm 安装步骤

```bash
# 1. 安装 nvm（版本号可能更新，建议查看 github.com/nvm-sh/nvm 获取最新）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 2. 加载 nvm（或重新登录）
source ~/.bashrc

# 3. 安装 Node.js LTS
nvm install --lts
nvm use --lts
nvm alias default node

# 4. 验证
node -v   # v20.x.x
npm -v    # 10.x.x

# 5. 配置 npm 使用国内镜像（加速依赖下载）
npm config set registry https://registry.npmmirror.com
```

:::

### 2. 安装 Nginx

```bash
# 安装
sudo apt install -y nginx

# 启动并设置开机自启
sudo systemctl start nginx
sudo systemctl enable nginx

# 验证安装
nginx -v
sudo systemctl status nginx
```

### 3. 安装 PM2（可选，用于 Node.js 后端）

```bash
npm install -g pm2

# 设置 PM2 开机自启
pm2 startup
# 按照提示执行输出的命令
pm2 save
```

## 四、项目部署

### 1. 创建部署目录

```bash
# 创建项目目录（以 deploy 用户操作）
sudo mkdir -p /var/www/my-vite-app
sudo chown -R deploy:deploy /var/www/my-vite-app

# 创建备份目录
sudo mkdir -p /var/backups/my-vite-app
sudo chown -R deploy:deploy /var/backups/my-vite-app
```

### 2. 首次手动部署

```bash
# 从 Git 仓库克隆代码（服务器上）
cd /var/www/my-vite-app
git clone https://github.com/your-org/your-project.git .

# 安装依赖
npm ci

# 构建
NODE_ENV=production npm run build

# 验证产物
ls -la dist/
```

### 3. 编写自动部署脚本

::: details /var/www/my-vite-app/scripts/deploy.sh

```bash
#!/bin/bash
# /var/www/my-vite-app/scripts/deploy.sh

set -e

PROJECT_DIR="/var/www/my-vite-app"
BACKUP_DIR="/var/backups/my-vite-app"
TIMESTAMP=$(date +%Y%m%d-%H%M%S)

cd "$PROJECT_DIR"

# 1. 备份当前版本
if [ -d "dist" ]; then
    echo "[1/5] 备份当前版本..."
    tar -czf "$BACKUP_DIR/dist-$TIMESTAMP.tar.gz" dist/
    # 只保留最近 7 个备份
    ls -t "$BACKUP_DIR"/dist-*.tar.gz | tail -n +8 | xargs -r rm
fi

# 2. 拉取最新代码
echo "[2/5] 拉取最新代码..."
git pull origin main

# 3. 安装依赖（只在 package-lock.json 变更时才重新安装）
echo "[3/5] 安装依赖..."
npm ci --prefer-offline

# 4. 构建
echo "[4/5] 构建项目..."
npm run build

# 5. 重载 Nginx（零停机）
echo "[5/5] 重载 Nginx..."
sudo nginx -s reload

echo "===== 部署成功：$TIMESTAMP ====="
```

```bash
# 设置执行权限
chmod +x /var/www/my-vite-app/scripts/deploy.sh
```

:::

## 五、Nginx 完整配置

### 1. 基础 HTTP 配置

先用 HTTP 验证站点可以正常访问，再申请 SSL 证书切换到 HTTPS。

::: details /etc/nginx/conf.d/my-vite-app.conf（HTTP 阶段）

```nginx
server {
    listen 80;
    server_name example.com www.example.com;
    root /var/www/my-vite-app/dist;
    index index.html;

    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;

    # 静态资源长缓存
    location ~* \.(js|css|png|jpg|svg|webp|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # HTML 不缓存
    location = /index.html {
        expires -1;
        add_header Cache-Control "no-cache";
    }

    # SPA 路由
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

:::

### 2. 申请 SSL 证书

::: details 使用 Certbot 申请 Let's Encrypt 免费证书

```bash
# 1. 安装 Certbot
sudo apt install -y certbot python3-certbot-nginx

# 2. 申请证书（自动修改 Nginx 配置）
sudo certbot --nginx -d example.com -d www.example.com

# 3. 测试自动续期
sudo certbot renew --dry-run

# 4. 设置自动续期定时任务（certbot 安装时通常已自动设置）
sudo systemctl status certbot.timer
```

:::

::: details 使用阿里云免费证书

1. 登录阿里云控制台 → 数字证书管理 → SSL 证书 → 购买证书（选择免费版）
2. 填写域名，完成 DNS 验证
3. 下载 Nginx 格式证书（得到 `.pem` 和 `.key` 文件）
4. 上传到服务器：

```bash
sudo mkdir -p /etc/nginx/ssl
# 将证书文件上传到服务器
scp example.com.pem deploy@your-ip:/tmp/
scp example.com.key deploy@your-ip:/tmp/

ssh deploy@your-ip
sudo mv /tmp/example.com.pem /etc/nginx/ssl/
sudo mv /tmp/example.com.key /etc/nginx/ssl/
sudo chmod 600 /etc/nginx/ssl/example.com.key
sudo chmod 644 /etc/nginx/ssl/example.com.pem
```

:::

### 3. 最终 HTTPS 配置

::: details /etc/nginx/conf.d/my-vite-app.conf（生产版）

```nginx
# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;
}

# HTTPS 主服务
server {
    listen 443 ssl http2;
    server_name example.com www.example.com;
    root /var/www/my-vite-app/dist;
    index index.html;

    # SSL 证书（Let's Encrypt 路径）
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    # 阿里云证书路径（二选一）
    # ssl_certificate     /etc/nginx/ssl/example.com.pem;
    # ssl_certificate_key /etc/nginx/ssl/example.com.key;

    # SSL 安全配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    # HSTS（告诉浏览器以后只用 HTTPS）
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
    # 安全头
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_comp_level 6;
    gzip_types
        text/plain text/css text/xml text/javascript
        application/javascript application/json application/xml
        image/svg+xml font/woff2;
    # 优先使用预压缩文件（需配合 vite-plugin-compression）
    gzip_static on;

    # 静态资源长期缓存（带 hash 的文件内容不变，可以缓存 1 年）
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|webp|woff|woff2|ttf|eot|ico)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # HTML 不缓存
    location = /index.html {
        expires -1;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理（后端服务运行在 8080 端口）
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        proxy_read_timeout 60s;
    }

    # 禁止访问隐藏文件（.git、.env 等）
    location ~ /\. {
        deny all;
        access_log off;
        log_not_found off;
    }

    access_log /var/log/nginx/my-vite-app.access.log;
    error_log  /var/log/nginx/my-vite-app.error.log warn;
}
```

```bash
# 测试配置语法
sudo nginx -t

# 重载（零停机）
sudo systemctl reload nginx
```

## 六、域名解析

### 1. 在阿里云 DNS 控制台添加解析

进入 **阿里云控制台 → 域名解析** 添加以下记录：

| 主机记录 | 记录类型 | 记录值 | TTL |
|---------|---------|-------|-----|
| `@` | A | 服务器公网 IP | 600 |
| `www` | A | 服务器公网 IP | 600 |

### 2. 验证解析生效

```bash
# DNS 传播通常需要 5-10 分钟
nslookup example.com
dig example.com +short

# 验证 HTTPS 可以访问
curl -I https://example.com
```

## 七、GitHub Actions 自动化部署

在 GitHub 仓库设置中添加以下 Secrets：

| Secret | 内容 |
|--------|------|
| `ALIYUN_HOST` | 阿里云 ECS 公网 IP |
| `ALIYUN_USER` | 部署用户名（`deploy`） |
| `ALIYUN_SSH_KEY` | SSH 私钥（本地 `~/.ssh/id_rsa` 的内容） |
| `VITE_API_BASE_URL` | 生产 API 地址 |

::: details .github/workflows/deploy-aliyun.yml

```yaml
name: Deploy to Aliyun ECS

on:
  push:
    branches: [main]
  workflow_dispatch:   # 允许手动触发

jobs:
  deploy:
    runs-on: ubuntu-latest
    timeout-minutes: 10

    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 配置 Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: 安装依赖
        run: npm ci

      - name: 构建
        run: npm run build
        env:
          NODE_ENV: production
          VITE_API_BASE_URL: ${{ secrets.VITE_API_BASE_URL }}

      - name: 同步产物到服务器
        uses: burnett01/rsync-deployments@7.0.1
        with:
          switches: -avzr --delete --exclude='.git'
          path: dist/
          remote_path: /var/www/my-vite-app/dist/
          remote_host: ${{ secrets.ALIYUN_HOST }}
          remote_user: ${{ secrets.ALIYUN_USER }}
          remote_key: ${{ secrets.ALIYUN_SSH_KEY }}

      - name: 重载 Nginx
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.ALIYUN_HOST }}
          username: ${{ secrets.ALIYUN_USER }}
          key: ${{ secrets.ALIYUN_SSH_KEY }}
          script: |
            sudo nginx -t && sudo nginx -s reload
            echo "部署完成：$(date)"
```

:::

```bash
# 查看 Nginx 状态

# 查看实时访问日志
```

### 2. SSL 证书续期

Let's Encrypt 证书有效期 90 天，certbot 会自动续期：

```bash
# 查看证书到期时间
sudo certbot certificates

# 手动续期测试
sudo certbot renew --dry-run

# 查看自动续期定时器
sudo systemctl status certbot.timer
```

### 3. 回滚操作

::: details 回滚到上一个版本

```bash
#!/bin/bash
# rollback.sh - 回滚到最近一次备份

BACKUP_DIR="/var/backups/my-vite-app"
PROJECT_DIR="/var/www/my-vite-app"

# 找到最新的备份文件
LATEST_BACKUP=$(ls -t "$BACKUP_DIR"/dist-*.tar.gz | head -1)

if [ -z "$LATEST_BACKUP" ]; then
    echo "没有可用的备份文件"
    exit 1
fi

echo "回滚到：$LATEST_BACKUP"

# 解压备份
tar -xzf "$LATEST_BACKUP" -C "$PROJECT_DIR"

# 重载 Nginx
sudo nginx -s reload

echo "回滚完成"
```

### 4. 故障排查清单

::: details 常见问题和解决方案

| 现象 | 排查步骤 |
|------|---------|
| 访问 404 | 检查 Nginx 配置的 `root` 路径是否正确；检查 `dist/` 目录是否存在 |
| 刷新页面 404 | 确认 Nginx 有 `try_files $uri $uri/ /index.html` 配置 |
| API 请求失败 | 检查 `proxy_pass` 地址；查看后端服务是否运行；检查防火墙 |
| HTTPS 证书报错 | 检查证书路径；`sudo certbot certificates` 确认证书状态 |
| 构建成功但页面空白 | 检查 `vite.config.ts` 的 `base` 配置是否匹配部署路径 |
| 部署后样式不更新 | 可能是浏览器强缓存，硬刷新（Ctrl+Shift+R）验证；检查 HTML 缓存配置 |

:::
