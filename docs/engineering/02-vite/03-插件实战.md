# Vite 插件实战：官方插件 + 自定义插件开发

## 一、插件系统概述

### 1. 插件与 Rollup 的关系

Vite 插件兼容 Rollup 插件接口，并在其基础上扩展了若干 **Vite 专属钩子**：

| 来源 | 钩子 | 触发时机 |
|------|------|---------|
| Rollup | `resolveId` | 解析模块路径 |
| Rollup | `load` | 加载模块内容 |
| Rollup | `transform` | 转换模块代码 |
| Rollup | `buildStart` / `buildEnd` | 构建开始/结束 |
| Rollup | `generateBundle` | 输出产物前 |
| Vite 扩展 | `config` | 修改 Vite 配置 |
| Vite 扩展 | `configResolved` | 配置解析完成后（只读） |
| Vite 扩展 | `configureServer` | 配置 Dev Server，添加中间件 |
| Vite 扩展 | `transformIndexHtml` | 转换 index.html |
| Vite 扩展 | `handleHotUpdate` | 自定义 HMR 更新逻辑 |

### 2. 插件的执行顺序

Vite 按以下顺序执行插件：

1. `enforce: 'pre'` 的插件（如 `@vitejs/plugin-react`）
2. 普通插件（未设置 `enforce`）
3. `enforce: 'post'` 的插件

::: tip 插件的 apply 字段
`apply: 'serve'` 只在开发时运行，`apply: 'build'` 只在构建时运行，不填则两种场景都运行。
:::

## 二、常用官方插件配置

### 1. @vitejs/plugin-react

React 官方插件，提供 JSX 转换和 Fast Refresh（HMR）支持。

::: details 完整配置示例

```ts
// vite.config.ts
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [
    react({
      // 包含/排除哪些文件应用 Fast Refresh
      include: '**/*.{jsx,tsx}',

      // 传递额外的 Babel 插件（需要安装对应包）
      babel: {
        plugins: [
          // 装饰器支持
          ['@babel/plugin-proposal-decorators', { legacy: true }],
        ],
      },

      // 使用 SWC 编译器替代 Babel（需要改用 @vitejs/plugin-react-swc）
      // jsxRuntime: 'automatic',
    }),
  ],
})
```

:::

::: tip plugin-react vs plugin-react-swc
`@vitejs/plugin-react` 使用 Babel，支持所有 Babel 插件（如装饰器），灵活性高。
`@vitejs/plugin-react-swc` 使用 SWC，编译速度快 20x，但不支持自定义 Babel 插件。
:::

### 2. @vitejs/plugin-vue

Vue 3 官方插件。

::: details 配置示例

```ts
import vue from '@vitejs/plugin-vue'
import vueJsx from '@vitejs/plugin-vue-jsx'

export default defineConfig({
  plugins: [
    vue({
      // 自定义 Web Components 标签（不报 unknown element 警告）
      template: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith('my-'),
        },
      },
      // 启用响应式语法糖（Vue 3.3+ 已内置，无需此选项）
      // reactivityTransform: true,
    }),
    // Vue JSX 支持
    vueJsx(),
  ],
})
```

:::

### 3. vite-plugin-checker

在开发时在浏览器中展示 TypeScript 类型错误和 ESLint 报错，不阻断热更新。

::: details 配置示例

```ts
import checker from 'vite-plugin-checker'

export default defineConfig({
  plugins: [
    checker({
      typescript: true,
      eslint: {
        lintCommand: 'eslint "./src/**/*.{ts,tsx,vue}"',
        dev: { logLevel: ['error'] },  // 只显示 error，不显示 warning
      },
      // 在浏览器覆盖层展示错误
      overlay: {
        initialIsOpen: false,   // 默认不展开
      },
    }),
  ],
})
```

## 三、自定义插件开发

### 1. 插件基础结构

一个 Vite 插件是一个返回插件对象的工厂函数：

```ts
// plugins/my-plugin.ts
import type { Plugin } from 'vite'

interface MyPluginOptions {
  enabled?: boolean
}

export function myPlugin(options: MyPluginOptions = {}): Plugin {
  const { enabled = true } = options

  return {
    name: 'vite-plugin-my',   // 必填，用于错误提示和日志
    enforce: 'pre',            // 可选：'pre' | 'post'
    apply: 'serve',            // 可选：'serve' | 'build'

    // 各钩子按需实现...
    transform(code, id) {
      if (!enabled) return null
      // 返回 null 表示不处理，交给下一个插件
      return null
    },
  }
}
```

```ts
// vite.config.ts
import { myPlugin } from './plugins/my-plugin'

export default defineConfig({
  plugins: [myPlugin({ enabled: true })],
})
```

### 2. 实战一：虚拟模块插件

虚拟模块（Virtual Module）是一种不对应真实文件的模块，常用于动态生成代码（如路由表、国际化资源）。

**需求**：根据 `src/pages/` 目录自动生成路由配置，通过 `virtual:routes` 导入。

::: details 自动路由插件实现

```ts{12,18-30}
// plugins/vite-plugin-auto-routes.ts
import type { Plugin } from 'vite'
import { readdirSync } from 'fs'
import { resolve } from 'path'

const VIRTUAL_MODULE_ID = 'virtual:routes'
const RESOLVED_VIRTUAL_MODULE_ID = '\0' + VIRTUAL_MODULE_ID  // 虚拟模块约定以 \0 开头

export function autoRoutesPlugin(): Plugin {
  return {
    name: 'vite-plugin-auto-routes',

    // 匹配虚拟模块的 id
    resolveId(id) {
      if (id === VIRTUAL_MODULE_ID) {
        return RESOLVED_VIRTUAL_MODULE_ID  // 返回解析后的 id
      }
    },

    // 加载虚拟模块内容（动态生成代码）
    load(id) {
      if (id !== RESOLVED_VIRTUAL_MODULE_ID) return

      const pagesDir = resolve(process.cwd(), 'src/pages')
      const pages = readdirSync(pagesDir, { withFileTypes: true })
        .filter((d) => d.isDirectory())
        .map((d) => d.name)

      // 生成 routes 数组代码
      const imports = pages
        .map((name, i) => `import Page${i} from '/src/pages/${name}/index.tsx'`)
        .join('\n')

      const routes = pages
        .map((name, i) => `{ path: '/${name === 'home' ? '' : name}', element: Page${i} }`)
        .join(',\n  ')

      return `
${imports}

export const routes = [
  ${routes}
]
`
    },
  }
}
```

在业务代码中使用：

```ts
// src/router/index.ts
import { routes } from 'virtual:routes'

// TypeScript 类型声明（src/vite-env.d.ts）
declare module 'virtual:routes' {
  const routes: Array<{ path: string; element: any }>
  export { routes }
}
```

### 3. 实战二：开发环境 Mock 插件

**需求**：在开发时拦截 `/api/` 开头的请求，返回 `mock/` 目录下对应的 JSON 文件。

::: details Mock 数据插件实现

```ts{16-30}
// plugins/vite-plugin-mock.ts
import type { Plugin } from 'vite'
import { existsSync, readFileSync } from 'fs'
import { resolve } from 'path'

interface MockPluginOptions {
  mockDir?: string   // mock 文件目录，默认 'mock'
  prefix?: string    // 拦截路径前缀，默认 '/api'
}

export function mockPlugin(options: MockPluginOptions = {}): Plugin {
  const { mockDir = 'mock', prefix = '/api' } = options

  return {
    name: 'vite-plugin-mock',
    apply: 'serve',  // 只在开发时生效

    configureServer(server) {
      // 在 Vite 内置中间件之前插入 mock 中间件
      server.middlewares.use((req, res, next) => {
        if (!req.url?.startsWith(prefix)) return next()

        // /api/user/list → mock/user/list.json
        const apiPath = req.url.replace(prefix, '')
        const mockFile = resolve(process.cwd(), mockDir, `.${apiPath}.json`)

        if (!existsSync(mockFile)) return next()

        const data = JSON.parse(readFileSync(mockFile, 'utf-8'))
        res.setHeader('Content-Type', 'application/json')
        res.setHeader('Access-Control-Allow-Origin', '*')
        res.end(JSON.stringify({ code: 200, data, message: 'success' }))
      })
    },
  }
}
```

对应的 mock 文件：

```json
// mock/user/list.json
[
  { "id": "1", "name": "张三", "email": "zhangsan@example.com" },
  { "id": "2", "name": "李四", "email": "lisi@example.com" }
]
```

### 4. 实战三：HTML 注入插件

**需求**：在 `<head>` 中注入统计脚本（仅生产环境）。

::: details HTML 注入插件实现

```ts
// plugins/vite-plugin-inject-script.ts
import type { Plugin, HtmlTagDescriptor } from 'vite'

interface InjectScriptOptions {
  src: string
  attrs?: Record<string, string>
}

export function injectScriptPlugin(options: InjectScriptOptions): Plugin {
  return {
    name: 'vite-plugin-inject-script',
    apply: 'build',  // 只在构建时注入

    transformIndexHtml() {
      const tag: HtmlTagDescriptor = {
        tag: 'script',
        attrs: {
          src: options.src,
          ...options.attrs,
        },
        injectTo: 'head',  // 'head' | 'body' | 'head-prepend' | 'body-prepend'
      }
      return [tag]
    },
  }
}
```

使用：

```ts
// vite.config.ts
plugins: [
  injectScriptPlugin({
    src: 'https://hm.baidu.com/hm.js?your-site-id',
    attrs: { async: '' },
  }),
]
```

:::

## 四、插件开发最佳实践

### 1. 错误处理

插件内部报错应使用 Rollup 提供的 `this.error()` 和 `this.warn()`，而不是直接 `throw`：

```ts
transform(code, id) {
  try {
    return parseAndTransform(code)
  } catch (e) {
    // this.error 会显示文件位置，用户体验更好
    this.error({
      message: `解析失败：${(e as Error).message}`,
      id,
    })
  }
}
```

### 2. 性能注意事项

::: warning 避免在 transform 钩子中做耗时操作
`transform` 对每个模块都会调用，开发时可能每秒调用数百次。应提前用 `id.includes(...)` 或正则快速过滤不需要处理的文件，避免不必要的消耗。
:::

```ts
transform(code, id) {
  // 快速过滤：不是 .vue 文件直接跳过
  if (!id.endsWith('.vue')) return null

  // 只有 .vue 文件才执行后续逻辑
  return heavyTransform(code)
}
```

### 3. 插件调试技巧

```ts
// 在插件中临时添加日志
configResolved(config) {
  // 打印最终解析的配置（排查配置合并问题）
  console.log('[my-plugin] resolve.alias:', config.resolve.alias)
},

buildStart() {
  // 使用 this.info 输出信息（比 console.log 更规范）
  this.info('插件开始工作')
},
```
