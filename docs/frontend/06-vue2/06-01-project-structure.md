# 6.1 项目结构与架构设计

## 6.1.1 标准项目结构

::: tip 推荐的项目结构
```
my-vue-project/
├── public/                 # 静态资源
│   ├── index.html
│   └── favicon.ico
├── src/
│   ├── assets/            # 资源文件
│   │   ├── images/
│   │   └── styles/
│   ├── components/        # 公共组件
│   │   ├── common/        # 通用组件
│   │   └── business/      # 业务组件
│   ├── views/             # 页面组件
│   ├── router/            # 路由配置
│   │   └── index.js
│   ├── store/             # Vuex 状态管理
│   │   ├── index.js
│   │   └── modules/
│   ├── api/               # API 接口
│   │   └── index.js
│   ├── utils/             # 工具函数
│   │   └── request.js
│   ├── directives/        # 自定义指令
│   ├── filters/           # 过滤器
│   ├── App.vue            # 根组件
│   └── main.js            # 入口文件
├── .gitignore
├── package.json
└── vue.config.js          # Vue CLI 配置
```
:::

## 6.1.2 目录说明

### 6.1.2.1 src/assets

::: tip assets 目录
存放静态资源文件，如图片、样式文件等。
:::

### 6.1.2.2 src/components

::: tip components 目录
存放可复用的组件，分为通用组件和业务组件。
:::

### 6.1.2.3 src/views

::: tip views 目录
存放页面级组件，对应路由中的页面。
:::

### 6.1.2.4 src/router

::: tip router 目录
存放路由配置文件。
:::

### 6.1.2.5 src/store

::: tip store 目录
存放 Vuex 状态管理相关文件。
:::

### 6.1.2.6 src/api

::: tip api 目录
存放 API 接口封装文件。
:::

### 6.1.2.7 src/utils

::: tip utils 目录
存放工具函数，如请求封装、日期格式化等。
:::

## 6.1.3 架构设计原则

### 6.1.3.1 单一职责

::: tip 单一职责原则
每个模块、组件、函数都应该有单一、明确的职责。
:::

### 6.1.3.2 模块化

::: tip 模块化设计
将功能拆分为独立的模块，便于维护和复用。
:::

### 6.1.3.3 分层架构

::: tip 分层架构
- **表现层**：组件、视图
- **业务层**：业务逻辑、状态管理
- **数据层**：API 接口、数据请求
:::

## 6.1.4 最佳实践

::: tip 项目结构最佳实践
1. **按功能模块组织**：将相关功能放在一起
2. **公共资源提取**：将公共组件、工具函数提取到公共目录
3. **命名规范**：使用统一的命名规范
4. **配置文件分离**：将配置信息单独管理
5. **文档完善**：为重要模块添加注释和文档
:::

## 6.1.5 总结

::: tip 总结
合理的项目结构可以提高代码的可维护性和可扩展性，遵循最佳实践有助于团队协作和项目长期发展。
:::
