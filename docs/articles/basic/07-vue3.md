### 1、重写双向数据绑定
>[!TIP]
>- `Vue2`基于`Object.defineProperty()`实现
>
>- `Vue3` 基于`Proxy`实现
>
> `proxy`与`Object.defineProperty(obj, prop, desc)`方式相比有以下**优势**：
>
>  1. 丢掉麻烦的备份数据
>  2. 省去for in 循环
>  3. 可以监听数组变化
>  4. 代码更简化
>  5. 可以监听动态新增的属性；
>  6. 可以监听删除的属性；
>  7. 可以监听数组的索引和 length 属性；

```js
 
    let proxyObj = new Proxy(obj,{
        get : function (target,prop) {
            return prop in target ? target[prop] : 0
        },
        set : function (target,prop,value) {
            target[prop] = 888;
        }
    })
```

### 4、Vue3 Tree shaking

### 5、Vue 3 Composition Api
>[!NOTE]
> - `Vue3` 引入了`Composition API`，它是基于`组合式 API`的思想，提供了一系列函数式的方法来帮助我们更好地组织代码。


::: details 点击查看
1. **性能优化：**
   - Vue.js 3引入了虚拟DOM的重写，提供了更快的渲染性能。这意味着Vue.js 3在处理大型组件树时更高效，减少了内存使用和渲染时间。
   - Vue.js 3使用了Proxy来实现响应式数据，相比Vue.js 2的Object.defineProperty，它具有更好的性能，支持深层嵌套对象的响应式。
   - 静态树提升（Static Tree Hoisting）是Vue.js 3的新特性，可以进一步提高渲染性能，特别是对于包含大量静态内容的组件。

2. **Composition API：**
   - Vue.js 3引入了Composition API，它是一种更灵活和可组合的API风格，允许开发者更好地组织和重用逻辑代码，而不受限于Options API的约束。Composition API在大型项目中尤其有用。

3. **全局 API 改进：**
   - 在Vue.js 3中，全局API（如`Vue.directive`、`Vue.component`等）已经被移动到单独的模块中，以提高代码的可维护性。这意味着你需要在组件中显式导入这些API，而不是在全局范围内自动注册它们。

4. **Teleport：**
   - Vue.js 3引入了Teleport组件，它允许你将组件的内容渲染到DOM中的不同位置，这在处理模态框、弹出菜单等情况下非常有用。

5. **Suspense：**
   - Vue.js 3引入了Suspense特性，它允许你在异步加载组件时显示占位符，以改善用户体验。这在处理懒加载路由、异步组件等方面非常有用。

6. **多根元素支持：**
   - 在Vue.js 3中，组件可以返回多个根元素，而不像Vue.js 2那样只能有一个根元素。这简化了组件的编写和布局。

7. **Tree Shaking：**
   - Vue.js 3的代码构建更容易进行Tree Shaking，这意味着你可以更轻松地剔除不使用的代码，减小项目的包体积。

8. **自定义渲染器：**
   - Vue.js 3引入了更强大的自定义渲染器API，允许你在不同平台上（如Web、移动、桌面、原生应用等）使用Vue。

9. **TypeScript支持：**
   - Vue.js 3对TypeScript的支持更加友好，内置了更多的类型声明，使得在TypeScript项目中使用Vue更加容易。

### 2、Vue2 Diff算法
#### 2.1、关键策略
>[!tip]
> **整体策略**：`深度优先，同层比较`
>
> **关键特性**：
> 1. `同级比较`：只比较同一层级的节点，避免跨层级比较
> 2. `双端比较`：采用双端比较策略，从列表的两端（头部和尾部）开始比较，以尽量减少节点的移动次数
> 3. `更新策略`：当头尾比较无法匹配时，Vue2 会尝试复用旧节点，通过更新节点的属性或子节点来匹配新的虚拟节点，同时将其移动到正确的位置，以减少 DOM 操作次数

#### 2.2、diff流程
>[!tip]
> **双端比较算法流程**：
> 1. **头头对比**：比较新旧列表的头部节点，如果相同则继续比较下一个
> 2. **尾尾对比**：比较新旧列表的尾部节点，如果相同则继续比较前一个
> 3. **头尾交叉对比**：比较旧列表头部与新列表尾部，如果相同则移动节点
> 4. **尾头交叉对比**：比较旧列表尾部与新列表头部，如果相同则移动节点
> 5. **Key映射查找**：如果以上都不匹配，则通过key建立映射表，查找可复用的节点
> 6. **处理剩余节点**：处理新增或删除的节点

::: details 查看Vue2 diff算法 实现原理
```js
/**
 * 判断两个虚拟节点是否为相同节点
 * @param {VNode} oldVnode - 旧节点
 * @param {VNode} newVnode - 新节点
 * @returns {boolean}
 */
function sameVnode(oldVnode, newVnode) {
    return (
        oldVnode.key === newVnode.key &&
        oldVnode.tag === newVnode.tag &&
        oldVnode.isComment === newVnode.isComment &&
        isDef(oldVnode.data) === isDef(newVnode.data)
    );
}

/**
 * 更新单个虚拟节点
 * @param {VNode} oldVnode - 旧节点
 * @param {VNode} newVnode - 新节点
 */
function patchVnode(oldVnode, newVnode) {
    // 如果节点相同，直接返回
    if (oldVnode === newVnode) return;
    
    const el = (newVnode.el = oldVnode.el);
    const oldCh = oldVnode.children;
    const ch = newVnode.children;
    
    // 更新文本内容
    if (newVnode.text !== undefined) {
        if (oldVnode.text !== newVnode.text) {
            el.textContent = newVnode.text;
        }
    } else {
        // 更新子节点
        if (isDef(oldCh) && isDef(ch)) {
            if (oldCh !== ch) {
                updateChildren(el, oldCh, ch);
            }
        } else if (isDef(ch)) {
            // 新节点有子节点，旧节点没有
            addVnodes(el, null, ch, 0, ch.length - 1);
        } else if (isDef(oldCh)) {
            // 旧节点有子节点，新节点没有
            removeVnodes(el, oldCh, 0, oldCh.length - 1);
        }
    }
}

/**
 * 更新子节点列表（核心双端比较算法）
 * @param {HTMLElement} parentElm - 父元素
 * @param {Array} oldCh - 旧子节点数组
 * @param {Array} newCh - 新子节点数组
 */
function updateChildren(parentElm, oldCh, newCh) {
    let oldStartIdx = 0;              // 旧列表起始索引
    let newStartIdx = 0;              // 新列表起始索引
    let oldEndIdx = oldCh.length - 1; // 旧列表结束索引
    let newEndIdx = newCh.length - 1; // 新列表结束索引
    
    let oldStartVnode = oldCh[0];     // 旧列表起始节点
    let oldEndVnode = oldCh[oldEndIdx]; // 旧列表结束节点
    let newStartVnode = newCh[0];     // 新列表起始节点
    let newEndVnode = newCh[newEndIdx]; // 新列表结束节点
    
    let keyToIdx, idxInOld, elmToMove;
    
    // 双端比较循环
    while (oldStartIdx <= oldEndIdx && newStartIdx <= newEndIdx) {
        // 跳过已处理的空节点
        if (isUndef(oldStartVnode)) {
            oldStartVnode = oldCh[++oldStartIdx];
        } else if (isUndef(oldEndVnode)) {
            oldEndVnode = oldCh[--oldEndIdx];
        }
        // 情况1：头头对比 - 如果相同，继续比较下一个
        else if (sameVnode(oldStartVnode, newStartVnode)) {
            patchVnode(oldStartVnode, newStartVnode);
            oldStartVnode = oldCh[++oldStartIdx];
            newStartVnode = newCh[++newStartIdx];
        }
        // 情况2：尾尾对比 - 如果相同，继续比较前一个
        else if (sameVnode(oldEndVnode, newEndVnode)) {
            patchVnode(oldEndVnode, newEndVnode);
            oldEndVnode = oldCh[--oldEndIdx];
            newEndVnode = newCh[--newEndIdx];
        }
        // 情况3：头尾交叉对比 - 旧头移动到新尾位置
        else if (sameVnode(oldStartVnode, newEndVnode)) {
            patchVnode(oldStartVnode, newEndVnode);
            parentElm.insertBefore(oldStartVnode.el, oldEndVnode.el.nextSibling);
            oldStartVnode = oldCh[++oldStartIdx];
            newEndVnode = newCh[--newEndIdx];
        }
        // 情况4：尾头交叉对比 - 旧尾移动到新头位置
        else if (sameVnode(oldEndVnode, newStartVnode)) {
            patchVnode(oldEndVnode, newStartVnode);
            parentElm.insertBefore(oldEndVnode.el, oldStartVnode.el);
            oldEndVnode = oldCh[--oldEndIdx];
            newStartVnode = newCh[++newStartIdx];
        }
        // 情况5：通过key查找可复用节点
        else {
            // 建立key到索引的映射表
            if (isUndef(keyToIdx)) {
                keyToIdx = {};
                for (let i = oldStartIdx; i <= oldEndIdx; i++) {
                    const key = oldCh[i].key;
                    if (isDef(key)) {
                        keyToIdx[key] = i;
                    }
                }
            }
            
            // 查找新节点在旧节点中的位置
            idxInOld = isDef(newStartVnode.key)
                ? keyToIdx[newStartVnode.key]
                : findIdxInOld(newStartVnode, oldCh, oldStartIdx, oldEndIdx);
            
            // 如果找不到，说明是新节点，需要创建
            if (isUndef(idxInOld)) {
                createElm(newStartVnode, parentElm, oldStartVnode.el);
                newStartVnode = newCh[++newStartIdx];
            } else {
                // 找到了可复用的节点
                elmToMove = oldCh[idxInOld];
                if (sameVnode(elmToMove, newStartVnode)) {
                    patchVnode(elmToMove, newStartVnode);
                    oldCh[idxInOld] = undefined; // 标记为已处理
                    parentElm.insertBefore(elmToMove.el, oldStartVnode.el);
                    newStartVnode = newCh[++newStartIdx];
                } else {
                    // key相同但节点不同，创建新节点
                    createElm(newStartVnode, parentElm, oldStartVnode.el);
                    newStartVnode = newCh[++newStartIdx];
                }
            }
        }
    }
    
    // 处理剩余节点
    if (oldStartIdx > oldEndIdx) {
        // 新节点有剩余，需要添加
        const refElm = isUndef(newCh[newEndIdx + 1]) ? null : newCh[newEndIdx + 1].el;
        addVnodes(parentElm, refElm, newCh, newStartIdx, newEndIdx);
    } else if (newStartIdx > newEndIdx) {
        // 旧节点有剩余，需要删除
        removeVnodes(parentElm, oldCh, oldStartIdx, oldEndIdx);
    }
}

/**
 * 添加节点
 */
function addVnodes(parentElm, refElm, vnodes, startIdx, endIdx) {
    for (; startIdx <= endIdx; ++startIdx) {
        createElm(vnodes[startIdx], parentElm, refElm);
    }
}

/**
 * 删除节点
 */
function removeVnodes(parentElm, vnodes, startIdx, endIdx) {
    for (; startIdx <= endIdx; ++startIdx) {
        const ch = vnodes[startIdx];
        if (isDef(ch)) {
            if (isDef(ch.tag)) {
                removeAndInvokeRemoveHook(ch);
            } else {
                // 文本节点
                parentElm.removeChild(ch.el);
            }
        }
    }
}

/**
 * 创建元素
 */
function createElm(vnode, parentElm, refElm) {
    const el = document.createElement(vnode.tag);
    vnode.el = el;
    if (vnode.children) {
        if (Array.isArray(vnode.children)) {
            vnode.children.forEach(child => {
                createElm(child, el);
            });
        } else {
            el.textContent = vnode.children;
        }
    }
    if (parentElm) {
        if (refElm) {
            parentElm.insertBefore(el, refElm);
        } else {
            parentElm.appendChild(el);
        }
    }
    return el;
}

// 辅助函数
function isDef(v) {
    return v !== undefined && v !== null;
}

function isUndef(v) {
    return v === undefined || v === null;
}

function findIdxInOld(node, oldCh, start, end) {
    for (let i = start; i <= end; i++) {
        const c = oldCh[i];
        if (isDef(c) && sameVnode(node, c)) {
            return i;
        }
    }
}
```

### 3、Vue3 Diff算法

#### 3.1、关键策略
>[!tip]
> **全新的编译策略和运行时优化，包括对 Diff 算法的改进**
>
> **核心优化**：
> 1. `静态节点提升`：对静态节点进行提升，这些节点在更新时不会被重新创建，而是直接复用，减少渲染成本
> 2. `支持碎片化(Fragment)`：Vue3支持碎片化，允许组件有多个根节点，这在Vue2中是不支持的
> 3. `区块树(Block Tree)`：可以跳过静态内容，快速定位到动态节点，减少了Diff时的比较次数
> 4. `编译时优化`：Vue3在编译时会对模板进行静态提升，将不会变化的节点和属性提取出来，避免在每次渲染时都重新创建
> 5. `最长递增子序列算法`：使用LIS算法优化节点移动，减少DOM操作

#### 3.2、无key的Diff流程
>[!tip]
> **处理无key的列表更新**：
> 1. **节点替换**：patch时不同节点会进行替换
> 2. **新增节点**：多余的节点进行新增
> 3. **删除节点**：缺少了原节点会进行删除
> 4. **按索引比较**：直接按索引位置进行比较，效率较低

#### 3.3、有key的Diff流程
>[!tip]
> **五步优化算法流程**：
> 1. **前序对比**：从头部开始，找到相同的前缀节点
> 2. **尾序对比**：从尾部开始，找到相同的后缀节点
> 3. **新增处理**：新节点如果多出来，进行挂载
> 4. **删除处理**：旧节点如果多出来，进行卸载
> 5. **乱序处理**（核心优化）：
>    - 构建新节点的key到索引的映射关系
>    - 记录新节点在旧节点中的位置数组（source数组）
>    - 通过最长递增子序列（LIS）算法找出不需要移动的节点
>    - 只移动不在LIS中的节点，大幅减少DOM操作


### 4、Vue2与Vue3 Diff算法对比

>[!tip]
> **核心区别**：
> - **Vue2**：基于`递归的双指针`的 diff 算法，采用双端比较策略
> - **Vue3**：基于`最长递增子序列(LIS)`的 diff 算法，使用五步优化流程
>
> **性能对比**：
> 1. **静态节点处理**：Vue2会对整个组件树进行完整遍历，Vue3会跳过静态子树，只更新动态节点
> 2. **列表渲染**：Vue2在元素重新排序时效率较低，Vue3通过LIS算法大幅减少DOM移动操作
> 3. **编译优化**：Vue3在编译时进行静态提升和区块树优化，减少运行时比较次数
> 4. **整体性能**：Vue3的Diff算法相比Vue2在性能上有明显提升，特别是在复杂列表场景下

#### 4.2、Vue3 diff算法实现
>[!tip]
> **核心思想**：
> - Vue3使用`最长递增子序列(LIS)`算法优化节点移动
> - 通过五步优化流程：前序对比 → 尾序对比 → 新增处理 → 删除处理 → 乱序处理
> - 在乱序处理中，通过LIS算法找出不需要移动的节点，只移动必要的节点，大幅减少DOM操作

::: details 点击查看Vue3 diff算法实现
```js
/**
 * 判断两个虚拟节点是否为相同节点
 */
function isSameVNodeType(n1, n2) {
    return n1.type === n2.type && n1.key === n2.key;
}

/**
 * Vue3 Diff算法核心实现（五步优化流程）
 * @param {Array} c1 - 旧子节点数组
 * @param {Array} c2 - 新子节点数组
 * @param {HTMLElement} container - 容器元素
 */
function patchKeyedChildren(c1, c2, container) {
    let i = 0; // 前序对比起始索引
    const l2 = c2.length;
    let e1 = c1.length - 1; // 旧列表结束索引
    let e2 = l2 - 1; // 新列表结束索引

    // 步骤1：前序对比 - 从头部开始找到相同的前缀
    while (i <= e1 && i <= e2) {
        const n1 = c1[i];
        const n2 = c2[i];
        if (isSameVNodeType(n1, n2)) {
            patch(n1, n2, container);
        } else {
            break;
        }
        i++;
    }

    // 步骤2：尾序对比 - 从尾部开始找到相同的后缀
    while (i <= e1 && i <= e2) {
        const n1 = c1[e1];
        const n2 = c2[e2];
        if (isSameVNodeType(n1, n2)) {
            patch(n1, n2, container);
        } else {
            break;
        }
        e1--;
        e2--;
    }

    // 步骤3：处理新增节点
    if (i > e1) {
        if (i <= e2) {
            const nextPos = e2 + 1;
            const anchor = nextPos < l2 ? c2[nextPos].el : null;
            while (i <= e2) {
                patch(null, c2[i], container, anchor);
                i++;
            }
        }
    }
    // 步骤4：处理删除节点
    else if (i > e2) {
        while (i <= e1) {
            unmount(c1[i]);
            i++;
        }
    }
    // 步骤5：处理乱序情况（核心优化 - 使用LIS算法）
    else {
        const s1 = i; // 旧列表需要处理的起始位置
        const s2 = i; // 新列表需要处理的起始位置

        // 5.1 建立新节点的key到索引的映射
        const keyToNewIndexMap = new Map();
        for (let i = s2; i <= e2; i++) {
            const nextChild = c2[i];
            if (nextChild.key != null) {
                keyToNewIndexMap.set(nextChild.key, i);
            }
        }

        // 5.2 记录新节点在旧节点中的位置（source数组）
        let patched = 0; // 已处理的节点数
        const toBePatched = e2 - s2 + 1; // 需要处理的新节点数
        const newIndexToOldIndexMap = new Array(toBePatched).fill(0);

        // 遍历旧节点，找出可复用的节点
        for (let i = s1; i <= e1; i++) {
            const prevChild = c1[i];
            if (patched >= toBePatched) {
                // 所有新节点都已处理，剩余旧节点需要删除
                unmount(prevChild);
                continue;
            }

            let newIndex;
            if (prevChild.key != null) {
                newIndex = keyToNewIndexMap.get(prevChild.key);
            } else {
                // 没有key，需要遍历查找
                for (let j = s2; j <= e2; j++) {
                    if (newIndexToOldIndexMap[j - s2] === 0 && isSameVNodeType(prevChild, c2[j])) {
                        newIndex = j;
                        break;
                    }
                }
            }

            if (newIndex === undefined) {
                // 旧节点在新列表中不存在，需要删除
                unmount(prevChild);
            } else {
                // 记录新节点在旧节点中的位置（+1避免0值冲突）
                newIndexToOldIndexMap[newIndex - s2] = i + 1;
                // 更新节点
                patch(prevChild, c2[newIndex], container);
                patched++;
            }
        }

        // 5.3 使用最长递增子序列算法优化移动
        const increasingNewIndexSequence = getSequence(newIndexToOldIndexMap);
        let j = increasingNewIndexSequence.length - 1;

        // 从后往前遍历新节点，进行移动和挂载
        for (let i = toBePatched - 1; i >= 0; i--) {
            const nextIndex = s2 + i;
            const nextChild = c2[nextIndex];
            const anchor = nextIndex + 1 < l2 ? c2[nextIndex + 1].el : null;

            if (newIndexToOldIndexMap[i] === 0) {
                // 新节点，需要挂载
                patch(null, nextChild, container, anchor);
            } else {
                // 节点需要移动
                if (j < 0 || i !== increasingNewIndexSequence[j]) {
                    // 不在LIS中，需要移动
                    move(nextChild, container, anchor);
                } else {
                    // 在LIS中，不需要移动
                    j--;
                }
            }
        }
    }
}

/**
 * 最长递增子序列算法（贪心 + 二分查找）
 * @param {Array} arr - 输入数组（newIndexToOldIndexMap）
 * @returns {Array} - 最长递增子序列的索引数组
 */
function getSequence(arr) {
    const p = arr.slice(); // 保存前驱节点
    const result = [0]; // 保存递增序列的索引
    let i, j, u, v, c;
    const len = arr.length;

    for (i = 0; i < len; i++) {
        const arrI = arr[i];
        if (arrI !== 0) {
            j = result[result.length - 1];
            if (arr[j] < arrI) {
                // 如果当前值大于结果数组最后一个值，直接追加
                p[i] = j;
                result.push(i);
                continue;
            }
            // 二分查找插入位置
            u = 0;
            v = result.length - 1;
            while (u < v) {
                c = (u + v) >> 1;
                if (arr[result[c]] < arrI) {
                    u = c + 1;
                } else {
                    v = c;
                }
            }
            if (arrI < arr[result[u]]) {
                if (u > 0) {
                    p[i] = result[u - 1];
                }
                result[u] = i;
            }
        }
    }
    u = result.length;
    v = result[u - 1];
    // 回溯构建最长递增子序列
    while (u-- > 0) {
        result[u] = v;
        v = p[v];
    }
    return result;
}

 * 移动节点
 */
function move(vnode, container, anchor) {
    const { el } = vnode;
    container.insertBefore(el, anchor);
}

/**
 * 卸载节点
 */
function unmount(vnode) {
    const { el } = vnode;
    if (el && el.parentNode) {
        el.parentNode.removeChild(el);
    }
}

/**
 * 更新节点
 */
function patch(n1, n2, container, anchor) {
    if (n1 === null) {

        mountElement(n2, container, anchor);
    } else if (n2 === null) {
```

### 5、最长递增子序列
>[!tip] Longest Increasing Subsequence
>- 简称LIS ：要求在一个给定的序列中找到最长的严格递增的子序列。
>
> 方法：
>
> 1. 动态规划
> 2. 贪心+二分查找

::: details 查看

```js
function LIS(nums) {
  if (nums.length === 0) {
    return [];
  }
  let results = [[nums[0]]];
  for (let i = 1; i < nums.length; i++) {
    const n = nums[i];
    _update(n);
  }
  function _update(n) {
    for (let i = results.length - 1; i >= 0; i--) {
      const line = results[i];
      const tail = line[line.length - 1];
      if (n > tail) {
        results[i + 1] = [...line, n];
        break;
      } else if (n < tail && i === 0) {
        results[i] = [n];
      }
    }
  }
  return results[results.length - 1];
}
```

## 六、响应式原理

### 1、Vue2响应式原理

>[!tip]
> **核心机制**：`Object.defineProperty`
> - `Object.defineProperty`只能劫持对象的属性，不能劫持数组的索引
> - **原理**：获取数据时触发`getter`收集依赖，修改数据时触发`setter`更新依赖

**工作流程**
1. **依赖收集**：在组件渲染时，访问响应式数据会触发 `getter`，将当前组件的 `Watcher` 添加到依赖列表中
2. **依赖更新**：当数据发生变化时，触发 `setter`，通知所有依赖该数据的 `Watcher` 进行更新

**不足**
>[!warning]Vue2响应式的局限性
> 1. **对象限制**：只能劫持已存在的属性，新增的属性需要使用`Vue.set`或`$set`
> 2. **数组限制**：只能劫持数组的7种方法（push、pop、shift、unshift、splice、sort、reverse），直接通过索引修改数组项无法触发更新
> 3. **性能考虑**：`Object.defineProperty`虽然能对数组进行劫持，但性能开销大，Vue2选择了性能与功能之间的平衡

**示例**
```js
// Vue2 响应式实现原理（简化版）
function defineReactive(obj, key, val) {
  const dep = new Dep() // 依赖收集器
  
  Object.defineProperty(obj, key, {
    get() {
      // 收集依赖
      if (Dep.target) {
        dep.addSub(Dep.target)
      }
      return val
    },
    set(newVal) {
      if (newVal === val) return
      val = newVal
      // 触发更新
      dep.notify()
    }
  })
}
```

### 2、Vue3响应式原理

>[!tip]
> **核心机制**：`Proxy` + `Reflect`
> - `Proxy`可以代理整个对象，拦截对象的各种操作（get、set、has、deleteProperty等）
> - 使用`Reflect`来操作对象，保证上下文正确性
> - 通过`WeakMap`存储依赖关系，避免内存泄漏

**核心概念**

1. **依赖收集（Track）**
   - 在属性访问时，通过`track`函数将当前的副作用函数（如组件的渲染函数、计算属性的求值函数等）与被访问的属性建立关联
   - 将副作用函数存储在一个依赖集合（`WeakMap`）中

2. **依赖更新（Trigger）**
   - 当数据发生变化时，通过`trigger`函数遍历依赖集合
   - 调用所有相关的副作用函数，使得视图更新

**优势对比**

| 特性 | Vue2 (Object.defineProperty) | Vue3 (Proxy) |
|------|-------------------------------|--------------|
| 对象劫持 | 只能劫持已存在的属性 | 可以劫持整个对象 |
| 数组支持 | 只能劫持7种方法 | 可以劫持所有操作 |
| 新增属性 | 需要`$set` | 自动支持 |
| 性能 | 需要遍历所有属性 | 按需代理，性能更好 |
| 嵌套对象 | 需要递归处理 | 自动处理 |

### 3、实现reactive（简化版）

>[!tip]
> 使用`Proxy`和`Reflect`实现基础的响应式功能

::: details 点击查看完整实现
```js
// 存储依赖关系的 WeakMap
const targetMap = new WeakMap()

// 当前激活的副作用函数
let activeEffect = null

/**
 * 依赖收集函数
 */
function track(target, key) {
  if (!activeEffect) return
  
  // 获取 target 对应的依赖 Map
  let depsMap = targetMap.get(target)
  if (!depsMap) {
    targetMap.set(target, (depsMap = new Map()))
  }
  
  // 获取 key 对应的依赖 Set
  let dep = depsMap.get(key)
  if (!dep) {
    depsMap.set(key, (dep = new Set()))
  }
  
  // 添加当前副作用函数到依赖集合
  dep.add(activeEffect)
}

/**
 * 依赖触发函数
 */
function trigger(target, key) {
  const depsMap = targetMap.get(target)
  if (!depsMap) return
  
  const dep = depsMap.get(key)
  if (dep) {
    // 执行所有依赖该属性的副作用函数
    dep.forEach(effect => effect())
  }
}

/**
 * 创建响应式对象
 */
export function reactive<T extends object>(target: T): T {
  return new Proxy(target, {
    get(target, key, receiver) {
      // 使用 Reflect 保证上下文正确性
      const res = Reflect.get(target, key, receiver)
      
      // 依赖收集
      track(target, key)
      
      // 如果值是对象，递归处理
      if (typeof res === 'object' && res !== null) {
        return reactive(res)
      }
      
      return res
    },
    
    set(target, key, value, receiver) {
      // 使用 Reflect 设置值
      const res = Reflect.set(target, key, value, receiver)
      
      // 触发依赖更新
      trigger(target, key)
      
      return res
    },
    
    has(target, key) {
      track(target, key)
      return Reflect.has(target, key)
    },
    
    deleteProperty(target, key) {
      const res = Reflect.deleteProperty(target, key)
      trigger(target, key)
      return res
    }
  })
}
```

### 4、实现副作用函数（Effect）

>[!tip]
> **副作用函数**：当响应式数据发生变化时，需要执行的函数
> - 组件的渲染函数
> - 计算属性的求值函数
> - 监听器的回调函数

**基础实现**
::: details 点击查看完整实现
```js
/**
 * 副作用函数
 * @param fn 需要执行的函数
 */
function effect(fn) {
  // 将当前函数设置为激活的副作用函数
  activeEffect = fn
  
  // 执行函数，触发依赖收集
  fn()
  
  // 清空激活的副作用函数
  activeEffect = null
}

// 使用示例

// 创建副作用函数

  console.log('count:', state.count)
})

// 修改数据，会自动触发副作用函数

state.count++ // 输出: count: 2
```

```js
/**
 * 副作用函数类
 */
class ReactiveEffect {
  constructor(fn, scheduler) {
    this.fn = fn
    this.scheduler = scheduler
    this.deps = [] // 存储所有依赖此 effect 的依赖集合
  }
  
  run() {
    activeEffect = this
    const result = this.fn()
    activeEffect = null
    return result
  }
  
  stop() {
    // 从所有依赖集合中移除当前 effect
    this.deps.forEach(dep => dep.delete(this))
    this.deps = []
  }
}

/**
 * 创建副作用函数
 */
function effect(fn, options = {}) {
  const _effect = new ReactiveEffect(fn, options.scheduler)
  
  // 立即执行一次
  _effect.run()
  
  // 返回停止函数
  const runner = _effect.run.bind(_effect)
  runner.effect = _effect
  runner.stop = () => _effect.stop()
  
  return runner
}

// 使用示例
const state = reactive({ count: 0, name: 'Vue' })

// 基础用法
const stop = effect(() => {
  console.log('count:', state.count)
})

state.count++ // 输出: count: 1

// 停止响应
stop.stop()
state.count++ // 不会输出

// 带调度器的用法
effect(
  () => {
    console.log('name:', state.name)
  },
  {
    scheduler(fn) {
      // 自定义调度逻辑，比如防抖
      setTimeout(fn, 100)
    }
  }
)
```

### 5、响应式原理总结

>[!tip]
> **Vue3响应式系统的核心流程**：
> 
> 1. **初始化阶段**：
>    - 使用`Proxy`代理对象，拦截各种操作
>    - 使用`WeakMap`存储依赖关系
> 
> 2. **依赖收集阶段**：
>    - 访问响应式数据时，触发`get`拦截器
>    - 调用`track`函数，将当前副作用函数添加到依赖集合
> 
> 3. **依赖更新阶段**：
>    - 修改响应式数据时，触发`set`拦截器
>    - 调用`trigger`函数，执行所有相关的副作用函数
> 
> 4. **优势**：
>    - 支持新增属性，无需`$set`
>    - 支持数组索引操作
>    - 性能更好，按需代理
>    - 代码更简洁，易于维护

**流程图**
```
访问响应式数据
    ↓
触发 get 拦截器
    ↓
调用 track 收集依赖
    ↓
将副作用函数存储到 WeakMap
    ↓
修改响应式数据
    ↓
触发 set 拦截器
    ↓
调用 trigger 触发更新
    ↓
执行所有相关的副作用函数
    ↓
视图更新
```

```js
    <button @click="modifyInfo">点击按钮修改信息</button> 
  </div> 
</template>

<script setup>
import { shallowRef, triggerRef } from 'vue'
    
    const info = shallowRef({
      name: '张三',
      age: 20,
      
    })

    const modifyInfo = () => {
        info.value.name = '李四'
        info.value.age = 23 
        triggerRef(info)
    }  
</script>

```
:::

### 5、customRef

>[!tip]
> 创建一个`自定义的 ref`，显式声明对其依赖追踪和更新触发的控制方式。

**示例**
::: details 点击查看示例
```js
import { customRef } from 'vue';

// customRef用于自定义Ref
function MyRef(value) {
    // 该函数默认带参数 track 和 trigger 两个方法。
    return customRef((track, trigger) => {
   
      return {
        // 该对象需要包含 get 和 set 方法。
        get() {
          // 追踪数据变化
          track() // 收集依赖
          return value
        },
        // set 传入一个值作为新值，通常用于取代value
        set(newValue) {
          value = newValue
          // 触发响应，更新视图
          trigger() // 触发依赖更新
        }
      }
    })
}

```

## 八、Reactive全家桶

>[!tip]Reactive全家桶
>1. `reactive`：接受一个对象并返回一个响应式且可变的 reactive 对象
>2. `shallowReactive`：浅层次的响应，只有第一层属性是响应式的
>3. `readonly`：接受一个对象（响应式或普通）或 ref，返回一个原值的只读代理
>4. `shallowReadonly`：浅层只读，只有第一层属性是只读的
>5. `isReactive`：检查一个对象是否是由 `reactive` 创建的响应式代理
>6. `isReadonly`：检查传入的值是否为只读对象
>7. `isProxy`：检查一个对象是否是由 `reactive` 或 `readonly` 创建的代理

### 1、reactive

>[!tip]
> 接受一个对象（`Array`、`Object`、`Map`、`Set`）并返回一个`响应式且可变`的 reactive 对象。
> - 使用 `Proxy` 实现响应式
> - 只能用于引用类型，不能用于基本类型

**示例**
```js
import { reactive } from 'vue'

// 对象
const state = reactive({
    name: '张三',
    age: 20
})

// 数组
const list = reactive(['a', 'b', 'c'])

// Map
const map = reactive(new Map([['key', 'value']]))

// Set
const set = reactive(new Set([1, 2, 3]))
```

#### 1.1、与ref的区别

>[!tip]
> **reactive 与 ref 的区别**：
> 1. **类型支持**：`ref`支持所有类型（基本类型和引用类型），`reactive`只支持引用类型（`Array`、`Object`、`Map`、`Set`）
> 2. **访问方式**：`ref`取值时需要加`.value`获取，`reactive`不需要，直接访问属性
> 3. **响应式原理**：两者都使用 `Proxy`，但 `ref` 会对基本类型进行包装
> 4. **使用场景**：`ref` 适合单个值，`reactive` 适合对象和数组

**示例对比**
```js
// ref 用法
const count = ref(0)
console.log(count.value) // 需要 .value

// reactive 用法
const state = reactive({ count: 0 })
console.log(state.count) // 直接访问
```

#### 1.2、注意点

>[!important]重要提示
> `reactive`不能直接赋值整个对象的值，否则会对Proxy代理进行`覆盖`，导致失去响应式，影响视图更新。

**错误示例**
```js
let state = reactive({ name: '张三' })
// ❌ 错误：直接赋值会失去响应式
state = { name: '李四' }
```

**解决方案**

**方案1：数组使用解构展开**
::: details 点击查看示例
```vue
<template>
  <div>
    <ul>
      <li v-for="item in list" :key="item">{{ item }}</li>
    </ul>
    <button @click="add">添加数据</button>
  </div>
</template>

<script setup>
import { reactive } from 'vue'

let list = reactive([])

const add = () => {
  setTimeout(() => {
    let res = ['EDG', 'FPX', 'IG']
    // ✅ 正确：使用解构展开
    list.push(...res)
    // 或者
    // list.splice(0, list.length, ...res)
  }, 1000)
}
</script>
```
:::

**方案2：对象赋值其属性**
::: details 点击查看示例
```vue
<template>
  <div>
    <ul>
      <li v-for="item in state.arr" :key="item">{{ item }}</li>
    </ul>
    <button @click="update">更新数据</button>
  </div>
</template>

<script setup>
import { reactive } from 'vue'

let state = reactive({
  arr: []
})

const update = () => {
  setTimeout(() => {
    let res = ['EDG', 'FPX', 'IG']
    // ✅ 正确：通过属性赋值
    state.arr = res
  }, 1000)
}
</script>
```
:::

**方案3：使用 Object.assign**
::: details 点击查看示例
```js
let state = reactive({ name: '张三', age: 20 })

// ✅ 正确：使用 Object.assign 合并对象
Object.assign(state, { name: '李四', age: 25 })
```
:::

### 2、shallowReactive

>[!tip]
> **浅层次的响应式**
> - `shallowReactive`是`reactive`的浅层作用形式
> - 响应式只到其变量的第一层属性，深层嵌套的属性不是响应式的
> - 只有对第一层属性的访问是响应式的，深层属性的修改不会触发视图更新

**示例**
::: details 点击查看示例
```vue
<template>
  <div>
    <p>foo: {{ state.foo }}</p>
    <p>num: {{ state.foo.num }}</p>
    <p>bar: {{ state.foo.num.bar }}</p>
    <button @click="changeFirst">修改第一层</button>
    <button @click="changeDeep">修改深层</button>
  </div>
</template>

<script setup>
import { shallowReactive } from 'vue'

let state = shallowReactive({
  foo: {
    num: {
      bar: 1
    }
  }
})

const changeFirst = () => {
  // ✅ 会触发视图更新（第一层）
  state.foo = { num: { bar: 2 } }
}

const changeDeep = () => {
  // ❌ 不会触发视图更新（深层）
  state.foo.num.bar = 3
}
</script>
```
:::

**使用场景**
>[!tip]
> 适用于只需要第一层响应式的场景，可以提升性能，减少不必要的响应式转换。

### 3、readonly

>[!tip]
> 接受一个对象（响应式或普通）或 ref，返回一个原值的`只读代理`
> - 只读代理是深层的：对任何嵌套属性的访问都将是只读的
> - 尝试修改只读对象会收到警告

**示例**
::: details 点击查看示例
```js
import { reactive, readonly } from 'vue'

const original = reactive({ count: 0 })
const copy = readonly(original)

// ✅ 修改原对象会触发 copy 的响应式更新
original.count++

// ❌ 修改 copy 会收到警告
copy.count++ // [Vue warn] Set operation on key "count" failed: target is readonly.
```
:::

### 4、shallowReadonly

>[!tip]
> **浅层只读**
> - 只有第一层属性是只读的
> - 深层属性仍然可以修改

**示例**
::: details 点击查看示例
```js
import { shallowReadonly } from 'vue'

const state = shallowReadonly({
  foo: {
    bar: 1
  }
})

// ❌ 不能修改第一层
state.foo = {} // [Vue warn] Set operation on key "foo" failed: target is readonly.

// ✅ 可以修改深层
state.foo.bar = 2 // 可以修改
```
:::

>[!tip]

## 九、to系列

>[!tip]to系列全家桶
>1. `toRef`：为源响应式对象上的某个属性创建一个 ref，保持与源属性的同步
>2. `toRefs`：将一个响应式对象转换为一个普通对象，这个普通对象的每个属性都是指向源对象相应属性的 ref
>3. `toRaw`：返回 reactive 或 readonly 代理的原始对象
>4. `markRaw`：标记一个对象，使其永远不会被转换为代理，返回对象本身

### 1、toRef

>[!tip]
> **功能**：为源响应式对象上的某个属性创建一个 ref，保持与源属性的同步
> - 只能修改响应式的值，非响应式对象视图不会更新
> - 创建的 ref 与其源属性保持同步：改变源属性的值将更新 ref，反之亦然

**示例**
::: details 点击查看示例
```vue
<template>
  <div>
    <p>姓名：{{ name }}</p>
    <p>年龄：{{ age }}</p>
    <p>爱好：{{ hobby }}</p>
    <button @click="changeHobby">修改爱好</button>
    <button @click="changeName">修改姓名</button>
  </div>
</template>

<script setup>
import { reactive, toRef } from 'vue'

// ✅ 响应式对象
const man = reactive({
  name: '张三',
  age: 22,
  hobby: 'football'
})

// 使用 toRef 创建单个属性的 ref
const hobby = toRef(man, 'hobby')
const name = toRef(man, 'name')

const changeHobby = () => {
  // 修改 ref 会同步到原对象
  hobby.value = 'basketball'
  console.log(man.hobby) // 'basketball'
}

const changeName = () => {
  // 修改原对象也会同步到 ref
  man.name = '李四'
  console.log(name.value) // '李四'
}
</script>
```

**非响应式对象示例**
```vue
<template>
  <div>
    <p>爱好：{{ hobby }}</p>
    <button @click="changeHobby">修改爱好（不会更新视图）</button>
  </div>
</template>

<script setup>
import { toRef } from 'vue'

// ❌ 非响应式对象
const man = {
  name: '张三',
  hobby: 'football'
}

const hobby = toRef(man, 'hobby')

const changeHobby = () => {
  hobby.value = 'basketball'
  // 视图不会更新，因为源对象不是响应式的
}
</script>
```
:::

### 2、toRefs

>[!tip]
> **功能**：将一个响应式对象转换为一个普通对象，这个普通对象的每个属性都是指向源对象相应属性的 ref
> - 只能修改响应式的值，非响应式对象视图不会更新
> - 常用于解构响应式对象，保持响应式连接
> - 每个属性的 ref 都与其源属性保持同步

**示例**
::: details 点击查看示例
```vue
<template>
  <div>
    <p>姓名：{{ name }}</p>
    <p>年龄：{{ age }}</p>
    <p>爱好：{{ hobby }}</p>
    <button @click="updateInfo">更新信息</button>
  </div>
</template>

<script setup>
import { reactive, toRefs } from 'vue'

// 响应式对象
const state = reactive({
  name: '张三',
  age: 22,
  hobby: 'football'
})

// 使用 toRefs 解构，保持响应式
const { name, age, hobby } = toRefs(state)

const updateInfo = () => {
  // 修改 ref 会同步到原对象
  name.value = '李四'
  age.value = 25
  hobby.value = 'basketball'
  
  console.log(state.name) // '李四'
  console.log(state.age)  // 25
}
</script>
```

**对比：不使用 toRefs 的情况**
```vue
<script setup>
import { reactive } from 'vue'

const state = reactive({
  name: '张三',
  age: 22
})

// ❌ 直接解构会失去响应式
const { name, age } = state

// 修改不会触发视图更新
name = '李四' // 无效
</script>
```

**在组合式函数中使用**
```js
// composables/useUser.js
import { reactive, toRefs } from 'vue'

export function useUser() {
  const state = reactive({
    name: '',
    age: 0
  })
  
  const updateUser = (userInfo) => {
    state.name = userInfo.name
    state.age = userInfo.age
  }
  
  // 返回 toRefs，保持响应式
  return {
    ...toRefs(state),
    updateUser
  }
}

// 使用
import { useUser } from './composables/useUser'

const { name, age, updateUser } = useUser()
// name 和 age 仍然是响应式的
```
:::

### 3、toRaw

>[!tip]
> **功能**：返回 reactive 或 readonly 代理的原始对象
> - 可以用于临时读取而不引起代理访问/跟踪开销
> - 可以用于写入而不触发更改
> - 不建议持有对原始对象的持久引用，请谨慎使用

**示例**
::: details 点击查看示例
```vue
<template>
  <div>
    <p>响应式对象：{{ JSON.stringify(state) }}</p>
    <p>原始对象：{{ JSON.stringify(raw) }}</p>
    <button @click="modifyRaw">修改原始对象</button>
    <button @click="modifyReactive">修改响应式对象</button>
  </div>
</template>

<script setup>
import { reactive, toRaw } from 'vue'

const state = reactive({
  name: '张三',
  age: 22
})

// 获取原始对象
const raw = toRaw(state)

const modifyRaw = () => {
  // 修改原始对象不会触发响应式更新
  raw.name = '李四'
  raw.age = 25
  // 视图不会更新
}

const modifyReactive = () => {
  // 修改响应式对象会触发更新
  state.name = '王五'
  state.age = 30
  // 视图会更新
}
</script>
```

**使用场景**
```js
import { reactive, toRaw } from 'vue'

const state = reactive({ count: 0 })

// 场景1：传递给第三方库（不需要响应式）

  process(data) {
    // 接收原始对象，避免响应式开销
    const rawData = toRaw(data)
    // 处理数据...
  }
}

thirdPartyLib.process(state)

// 场景2：深拷贝
const copy = JSON.parse(JSON.stringify(toRaw(state)))
```

### 4、markRaw

>[!tip]
> **功能**：标记一个对象，使其永远不会被转换为代理，返回对象本身
> - 标记后的对象永远不会被转换为响应式代理
> - 适用于第三方类实例、Vue 组件实例等不需要响应式的对象
> - 可以提升性能，避免不必要的响应式转换

**示例**
::: details 点击查看示例
```vue
<template>
  <div>
    <p>列表长度：{{ list.length }}</p>
    <p>第三方对象：{{ thirdPartyObj.value }}</p>
    <button @click="addItem">添加项</button>
  </div>
</template>

<script setup>
import { reactive, markRaw } from 'vue'

// 第三方类实例
class ThirdPartyClass {
  constructor(value) {
    this.value = value
  }
}

const thirdPartyObj = new ThirdPartyClass('test')

// 标记为原始对象，不会被转换为代理
const markedObj = markRaw(thirdPartyObj)

const state = reactive({
  list: [],
  thirdPartyObj: markedObj // 不会被转换为响应式
})

const addItem = () => {
  state.list.push('item')
  // thirdPartyObj 保持为原始对象，不会被代理
}
</script>
```

**常见使用场景**
```js
import { reactive, markRaw } from 'vue'

// 场景1：第三方类实例
class Chart {
  constructor() {
    this.data = []
  }
  update() { /* ... */ }
}

const chart = markRaw(new Chart())
const state = reactive({
  chart // chart 不会被转换为代理
})

// 场景2：Vue 组件实例

const component = markRaw(MyComponent)
const state = reactive({
  currentComponent: component
})

// 场景3：大型不可变数据结构

  // 大量数据...
})

const state = reactive({
  data: largeData // 不会被转换为响应式，提升性能
})
```
:::

### 5、to系列对比总结


 **使用场景对比**：
 
 | API | 用途 | 返回值 | 是否保持响应式 |
 |-----|------|--------|----------------|
 | `toRef` | 创建单个属性的 ref | Ref | ✅ 是 |
 | `toRefs` | 创建所有属性的 ref | 普通对象（属性为 ref） | ✅ 是 |
 | `toRaw` | 获取原始对象 | 原始对象 | ❌ 否 |
 | `markRaw` | 标记对象不可代理 | 原对象 | ❌ 否 |

>[!tip]最佳实践
> 1. 解构响应式对象时使用 `toRefs` 保持响应式
> 2. 需要传递原始对象给第三方库时使用 `toRaw`
> 3. 不需要响应式的对象（如第三方类实例）使用 `markRaw` 标记
> 4. 组合式函数中返回响应式数据时使用 `toRefs`



## 十、Computed

>[!tip]Computed计算属性
>计算属性是基于响应式依赖进行缓存的，只有当依赖发生变化时才会重新计算。相比方法调用，计算属性有缓存机制，性能更好。

### 1、定义

>[!tip]
> **计算属性**：当依赖的响应式数据发生改变时，才会触发它的重新计算；如果依赖的值不改变，直接使用缓存中的属性值。
> - 具有缓存机制，只有依赖变化时才重新计算
> - 适合用于复杂计算和数据处理
> - 可以设置 getter 和 setter

**与方法的区别**

| 特性 | 计算属性 | 方法 |
|------|---------|------|
| 缓存 | ✅ 有缓存 | ❌ 无缓存 |
| 调用方式 | 作为属性访问 | 需要调用函数 |
| 性能 | 依赖不变时不执行 | 每次调用都执行 |
| 适用场景 | 复杂计算、数据转换 | 事件处理、副作用操作 |

### 2、底层原理

>[!note]
> **Computed 的工作机制**：
> 
> 1. **依赖收集**：
>    - 当访问计算属性时，会触发 `get` 函数
>    - 在 `get` 函数内部调用 `track` 函数收集依赖
>    - 将当前计算属性的 `Watcher` 与所依赖的响应式数据建立关联
> 
> 2. **缓存机制**：
>    - 计算属性会缓存计算结果，使用 `dirty` 标志位标记是否需要重新计算
>    - 当依赖的响应式数据发生变化时，会触发 `trigger` 函数
>    - `Watcher` 收到更新通知后，将 `dirty` 设置为 `true`
>    - 下次访问时，如果 `dirty` 为 `true`，则重新计算；否则直接返回缓存值
> 
> 3. **性能优化**：
>    - 只有当依赖变化时才重新计算，避免不必要的计算
>    - 多个地方使用同一个计算属性时，只计算一次

### 3、函数式写法（只读）

>[!tip]
> **只读计算属性**：传入一个 getter 函数，返回一个只读的 ref 对象
> - 只能读取，不能修改
> - 最常用的写法

**示例**
::: details 点击查看完整示例
```vue
<template>
  <div>
    <div>姓：<input v-model="firstname" type="text" /></div>
    <div>名：<input v-model="lastname" type="text" /></div>
    <div>全名：{{ fullName }}</div>
    <div>姓名长度：{{ nameLength }}</div>
  </div>
</template>

<script setup lang="ts">
import { ref, computed } from 'vue'

const firstname = ref('张')
const lastname = ref('三')

// 函数式写法 - 只读
const fullName = computed(() => {
  return firstname.value + '-' + lastname.value
})

// 复杂计算示例
const nameLength = computed(() => {
  return fullName.value.length
})
</script>
```
:::

**特点**
- ✅ 简洁易读
- ✅ 自动缓存
- ❌ 不能设置值

### 4、选项式写法（可读可写）

>[!tip]
> **可读可写计算属性**：传入一个包含 `get` 和 `set` 的对象
> - 可以读取和修改
> - 修改时会触发 `set` 函数

**示例**
::: details 点击查看完整示例
```vue
<template>
  <div>
    <div>姓：<input v-model="firstname" type="text" /></div>
    <div>名：<input v-model="lastname" type="text" /></div>
    <div>全名：{{ fullName }}</div>
    <div>
      <button @click="changeName">修改全名为：李-四</button>
    </div>
  </div>
</template>

<script setup lang="ts">
import { ref, computed } from 'vue'

const firstname = ref('张')
const lastname = ref('三')

// 选项式写法 - 可读可写
const fullName = computed<string>({
  get() {
    return firstname.value + '-' + lastname.value
  },
  set(newVal: string) {
    const [first, last] = newVal.split('-')
    firstname.value = first
    lastname.value = last
  }
})

const changeName = () => {
  // 可以设置计算属性的值
  fullName.value = '李-四'
}
</script>
```
:::

**使用场景**
- 需要双向绑定的计算属性
- 需要根据计算属性的值反向更新依赖数据

### 5、Computed vs Watch

>[!tip]
> **计算属性 vs 监听器**：
> 
> | 特性 | Computed | Watch |
> |------|---------|-------|
> | 用途 | 计算派生值 | 执行副作用 |
> | 返回值 | 有返回值 | 无返回值 |
> | 缓存 | ✅ 有缓存 | ❌ 无缓存 |
> | 同步/异步 | 同步 | 支持异步 |
> | 适用场景 | 数据转换、过滤 | 数据变化时的操作 |

**选择建议**
- 需要根据其他数据计算出一个值 → 使用 `computed`
- 需要在数据变化时执行操作（如请求、日志） → 使用 `watch`

### 6、源码剖析

>[!tip]
> **Computed 实现原理**（简化版）

**核心流程**

1. **参数格式化**：
   ```js
   function computed(getterOrOptions) {
     let getter, setter
     
     if (typeof getterOrOptions === 'function') {
       // 函数式：只读
       getter = getterOrOptions
       setter = () => {
         console.warn('Write operation failed: computed value is readonly')
       }
     } else {
       // 选项式：可读可写
       getter = getterOrOptions.get
       setter = getterOrOptions.set
     }
   }
   ```

2. **ComputedRefImpl 类**：
   ```js
   class ComputedRefImpl {
     constructor(getter, setter) {
       this._getter = getter
       this._setter = setter
       this._value = undefined
       this._dirty = true  // 脏值标志，true表示需要重新计算
       this._effect = new ReactiveEffect(getter, () => {
         // 依赖变化时，将 dirty 设置为 true
         if (!this._dirty) {
           this._dirty = true
           triggerRefValue(this)  // 触发更新
         }
       })
     }
     
     get value() {
       // 依赖收集
       trackRefValue(this)
       
       // 脏值检测
       if (this._dirty) {
         this._dirty = false
         // 重新计算值
         this._value = this._effect.run()
       }
       
       return this._value
     }
     
     set value(newValue) {
       this._setter(newValue)
     }
   }
   ```

3. **脏值检测机制**：
   - `dirty = true`：依赖已改变，需要重新计算
   - `dirty = false`：依赖未改变，直接返回缓存值

**完整实现示例**
::: details 点击查看完整实现
```js
import { ReactiveEffect, trackRefValue, triggerRefValue } from './reactivity'

class ComputedRefImpl {
  constructor(getter, setter, isReadonly) {
    this._setter = setter
    this._dirty = true
    this._value = undefined
    this._effect = new ReactiveEffect(getter, () => {
      if (!this._dirty) {
        this._dirty = true
        triggerRefValue(this)
      }
    })
    this._effect.computed = this
  }
  
  get value() {
    trackRefValue(this)
    if (this._dirty) {
      this._dirty = false
      this._value = this._effect.run()
    }
    return this._value
  }
  
  set value(newValue) {
    this._setter(newValue)
  }
}

export function computed(getterOrOptions) {
  let getter
  let setter
  
  const onlyGetter = typeof getterOrOptions === 'function'
  
  if (onlyGetter) {
    getter = getterOrOptions
    setter = () => {
      console.warn('Write operation failed: computed value is readonly')
    }
  } else {
    getter = getterOrOptions.get
    setter = getterOrOptions.set
  }
  
  return new ComputedRefImpl(getter, setter, onlyGetter)
}
```
:::

### 7、最佳实践

>[!tip]
> **使用建议**：
> 
> 1. **优先使用计算属性**：对于需要根据其他数据计算的值，优先使用 `computed` 而不是 `watch`
> 2. **避免副作用**：计算属性应该是纯函数，不应该有副作用（如修改外部状态、发起请求等）
> 3. **合理使用缓存**：利用计算属性的缓存机制，避免重复计算
> 4. **避免在计算属性中修改依赖**：这会导致无限循环
> 5. **复杂计算使用计算属性**：对于复杂的计算逻辑，使用计算属性可以提高性能

**错误示例**
```js
// ❌ 错误：在计算属性中有副作用
const badComputed = computed(() => {
  console.log('计算中...')  // 副作用
  fetchData()  // 副作用
  return someValue
})

// ❌ 错误：修改依赖导致循环
const circularComputed = computed(() => {
  count.value++  // 会导致无限循环
  return count.value
})
```

**正确示例**
```js
// ✅ 正确：纯函数计算
const goodComputed = computed(() => {
  return items.value.filter(item => item.active).length
})

// ✅ 正确：复杂计算
const complexComputed = computed(() => {
  return expensiveCalculation(data.value)
})
```



## 十一、watch

>[!tip]watch 监听器
>侦听特定的数据源，并在数据源变化时执行回调函数。适合在数据变化时执行副作用操作（如请求数据、操作DOM等）。

### 1、基本用法

>[!tip]
> **watch 函数签名**：
> ```ts
> watch(source, callback, options?)
> ```
> 
> **参数说明**：
> 1. **监听源（source）**：
>    - `ref` 声明的响应式数据
>    - `reactive` 声明的响应式数据
>    - 数据源组成的`数组`（监听多个数据源）
>    - `getter` 函数（返回一个值）
> 2. **回调函数（callback）**：`(newValue, oldValue) => void`
> 3. **配置项（options）**：
>    - `immediate: true` - 是否立即执行一次
>    - `deep: true` - 是否深度监听（`reactive` 默认开启深度监听）

### 2、监听 ref

**示例**
::: details 点击查看完整示例
```vue
<template>
  <div>
    <p>计数：{{ count }}</p>
    <button @click="count++">增加</button>
  </div>
</template>

<script setup>
import { ref, watch } from 'vue'

const count = ref(0)

// 监听单个 ref
watch(count, (newValue, oldValue) => {
  console.log(`count 从 ${oldValue} 变为 ${newValue}`)
})
</script>
```
:::

### 3、监听 reactive

>[!warning]
> 监听 `reactive` 对象时，`newValue` 和 `oldValue` 是同一个对象（因为引用相同）

**示例**
::: details 点击查看完整示例
```vue

  <div>
    <p>姓名：{{ user.name }}</p>
    <p>年龄：{{ user.age }}</p>
    <button @click="user.age++">增加年龄</button>
  </div>
</template>

<script setup>
import { reactive, watch } from 'vue'

const user = reactive({
  name: '张三',
  age: 20
})

// 监听整个 reactive 对象
watch(user, (newValue, oldValue) => {
  // newValue 和 oldValue 是同一个对象
  console.log('user 发生变化', newValue)
})

// 推荐：监听对象的某个属性
watch(() => user.age, (newValue, oldValue) => {
  console.log(`年龄从 ${oldValue} 变为 ${newValue}`)
})
</script>
```
:::

### 7、停止监听

**示例**
::: details 点击查看完整示例

```vue
  // 当 count 达到 10 时停止监听
  if (newValue >= 10) {
    stopWatch()
  }

  stopWatch()
})
```

### 8、底层原理

>[!tip]
> **watch 的工作机制**：
> 
> 1. **依赖收集**：
>    - Vue 会找到被监听的数据属性所对应的 `getter`
>    - 读取数据时会触发 `getter` 函数
>    - 在这个过程中，`watch` 回调函数会被收集为数据属性的一个依赖
> 
> 2. **依赖更新通知**：
>    - 当被监听的数据属性发生变化时，Vue 会调用 `setter` 函数
>    - 通知所有依赖于这个数据属性的 `watch` 回调函数
>    - 传入新值和旧值，执行回调函数

## 十二、watchEffect

>[!tip]watchEffect 自动追踪依赖
>立即执行传入的函数，同时响应式追踪其依赖，并在依赖变更时重新执行该函数。相比 `watch`，`watchEffect` 会自动追踪函数内部使用的响应式数据。

### 1、基本用法

**示例**
::: details 点击查看完整示例
```vue
<template>
  <div>
    <p>计数：{{ count }}</p>
    <p>双倍：{{ double }}</p>
    <button @click="count++">增加</button>
  </div>
</template>

<script setup>
import { ref, watchEffect } from 'vue'

const count = ref(0)
const double = ref(0)

// watchEffect 会自动追踪 count 的变化
watchEffect(() => {
  double.value = count.value * 2
  console.log(`count: ${count.value}, double: ${double.value}`)
})
// 页面加载时会立即执行一次
</script>
```
:::

### 2、watchEffect vs watch

| 特性 | watch | watchEffect |
|------|-------|-------------|
| 执行时机 | 默认惰性（数据变化时） | 立即执行 |
| 依赖追踪 | 需要明确指定监听源 | 自动追踪函数内使用的响应式数据 |
| 新旧值 | 可以获取新旧值 | 无法获取旧值 |
| 适用场景 | 需要明确监听的数据源 | 需要自动追踪多个依赖 |

### 3、停止监听

**示例**
::: details 点击查看完整示例
```vue
<script setup>
import { ref, watchEffect, onUnmounted } from 'vue'

const count = ref(0)

// watchEffect 返回停止函数
const stopEffect = watchEffect(() => {
  console.log(`count: ${count.value}`)
  
  if (count.value >= 10) {
    stopEffect() // 停止监听
  }
})

// 组件卸载时停止
onUnmounted(() => {
  stopEffect()
})
</script>
```
:::

### 4、清除副作用

>[!tip]
> `watchEffect` 的回调函数可以接收一个 `onInvalidate` 函数，用于清除副作用

**示例**
::: details 点击查看完整示例
```vue
<script setup>
import { ref, watchEffect } from 'vue'

const searchQuery = ref('')

watchEffect((onInvalidate) => {
  const timer = setTimeout(() => {
    console.log('搜索:', searchQuery.value)
    // 执行搜索操作...
  }, 500)
  
  // 清除副作用（在下次执行前或停止监听时调用）
  onInvalidate(() => {
    clearTimeout(timer)
  })
})
</script>
```
:::

### 5、配置选项

**flush：控制执行时机**
::: details 点击查看完整示例
```vue
<script setup>

// flush: 'pre' - 在组件更新前执行（默认）

  console.log('pre:', count.value)
}, { flush: 'pre' })

// flush: 'post' - 在组件更新后执行

  console.log('post:', count.value)
}, { flush: 'post' })

// flush: 'sync' - 同步执行（不推荐，可能导致性能问题）

  console.log('sync:', count.value)
}, { flush: 'sync' })
</script>
```

```vue
  count.value++
})
</script>

<!-- 后代组件 -->
<script setup>
import { inject } from 'vue'

const count = inject('count')
const increment = inject('increment')

// count 是响应式的，会自动更新
</script>
```
:::

### 5、组件通信方式对比

| 通信方式 | 适用场景 | 优点 | 缺点 |
|---------|---------|------|------|
| **Props** | 父传子 | 简单直接，类型安全 | 只能父传子，逐层传递麻烦 |
| **Emits** | 子传父 | 简单直接，事件驱动 | 只能子传父 |
| **Provide/Inject** | 跨级传值 | 避免逐层传递 | 数据流向不明确，难以追踪 |
| **EventBus** | 任意组件 | 灵活，解耦 | 难以追踪，容易造成混乱 |
| **Vuex/Pinia** | 全局状态 | 集中管理，易于追踪 | 需要额外学习，小型项目可能过度设计 |

### 6、最佳实践

>[!tip]
> **组件通信建议**：
> 
> 1. **优先使用 Props 和 Emits**：对于父子组件通信，优先使用 props 和 emits
> 2. **跨级传值用 Provide/Inject**：避免 props 逐层传递，使用 provide/inject
> 3. **全局状态用状态管理**：对于多个组件共享的状态，使用 Vuex 或 Pinia
> 4. **避免过度使用 Provide/Inject**：只在必要时使用，保持数据流向清晰
> 5. **使用 TypeScript**：为 props、emits、inject 添加类型，提高代码质量
