#### 1.3.1、重写双向数据绑定
>[!TIP]
>- `Vue2`基于`Object.defineProperty()`实现
>
>- `Vue3` 基于`Proxy`实现
>
> `proxy`与`Object.defineProperty(obj, prop, desc)`方式相比有以下`优势`：
>
>  1. 丢掉麻烦的备份数据
>  2. 省去for in 循环
>  3. 可以监听数组变化
>  4. 代码更简化
>  5. 可以监听动态新增的属性；
>  6. 可以监听删除的属性 ；
>  7. 可以监听数组的索引和 length 属性；

```js
 
    let proxyObj = new Proxy(obj,{
        get : function (target,prop) {
            return prop in target ? target[prop] : 0
        },
        set : function (target,prop,value) {
            target[prop] = 888;
        }
    })
```

## 四、SFC语法规范
::: tip SFC
 `*.vue`文件都由三种类型的顶层语法块所组成：`<template>`、`<script>`、`<style>`

 1.`<template>`

 - 每个 `*.vue` 文件最多可同时包含一个顶层 `<template>` 块。
 - 其中的内容会被提取出来并传递给 `@vue/compiler-dom`，预编译为 `JavaScript` 的渲染函数，并附属到导出的组件上作为其 `render` 选项。

 2.`<script>`

 - 每一个 `*.vue` 文件可以有多个 `<script>` 块 (不包括[`<script setup>`](https://cn.vuejs.org/api/sfc-script-setup))。
 - 该脚本将作为 ES Module 来执行。
 - 其`默认导出`的内容应该是 Vue 组件选项对象，它要么是一个普通的对象，要么是 [defineComponent](https://v3.cn.vuejs.org/api/global-api.html#definecomponent) 的返回值。

 3.`<script setup>`

 - 每个 `*.vue` 文件最多只能有一个` <script setup>` 块 (不包括常规的` <script>`)

 - 该脚本会被预处理并作为组件的 `setup()` 函数使用，也就是说它会在每个组件实例中执行。`<script setup>` 的顶层绑定会自动暴露给模板。更多详情查看 `<script setup>` 文档。

 4.`<style>`

 - 一个 `*.vue` 文件可以包含多个 `<style>` 标签。
 - `<style> `标签可以通过` scoped` 或` module attribute` (更多详情查看 SFC 样式特性) 将样式封装在当前组件内。多个不同封装模式的 `<style> `标签可以在同一个组件中混
:::

### 6.2、Vue2 Diff算法
>[!tip]
> 整体策略：`深度优先，同层比较`。
>
> 关键特性：
>1. `同级比较`: 只比较同一层级的节点。
>2. `双端比较`：采用双端比较策略，从列表的两端（头部和尾部）开始比较，以尽量减少节点的移动次数。
>3. `更新策略`：当头尾比较无法匹配时，Vue2 会尝试复用旧节点，通过更新节点的属性或子节点来匹配新的虚拟节点，同时将其移动到正确的位置，以减少 DOM 操作次数。

#### 6.2.1、Vue2 Diff基本原理

> 1. 首先进行新旧节点头尾对比，头与头，尾与尾对比，寻找为移动的节点。
> 2. 新旧节点头尾对比完成后，进行交叉对比，头与尾，尾与头对比，这一步是寻找移动后可复用的节点。
> 3. 在剩余的新旧节点中对比寻找可复用节点，创建一个旧节点keyToIndex的哈希表map记录key，然后继续遍历新节点索引通过key查找可复用的旧节点。

### 6.3、Vue3 Diff算法

#### 6.3.1、Vue3 Diff基本原理
>[!tip]
>  **全新的编译策略和运行时优化，包括对 Diff 算法的改进**
>
>  1. `双端比较优化`:对于相同节点的处理更加高效。
>  2. `静态节点提升`:对静态节点进行提升，这些节点在更新时不会被重新创建，而是直接复用，减少渲染成本。
>  3. `支持碎片化(Fragment)`:Vue3支持碎片化，允许组件有多个根节点，这在Vue2中是不支持的。
>  4. `区块树(Block Tree)`:可以跳过静态内容，快速定位到动态节点，减少了Diff时的比较次数。
>  5. `编译时优化`：Vue3在编译时会对模板进行静态提升，将不会变化的节点和属性提取出来，避免在每次渲染时都重新创建，以此减少DOM树的创建和销毁。


#### 6.3.2、Vue3 无key的Diff算法

> 1. patch的时候不同节点会进行替换。
> 2. 多余的节点进行新增。
> 3. 缺少了原节点会进行删除。



#### 6.3.3、Vue3 有key的Diff算法

> 1. 前序对比算法。
> 2. 尾序对比算法。
> 3. 新节点如果多出来，就是挂载。
> 4. 旧节点如果多出来，就是卸载。
> 5. 特殊情况乱序。
>
>    1. 构建新节点的映射关系。
>    2. 记录新节点在旧节点中的位置数组。
>    3. 多余旧节点就进行删除。
>    4. 新节点不包含的旧节点也删除。
>    5. 节点出现交叉，说明是要移动，去求最长递增子序列。
>       - 求最长递增子序列升序（贪心+二分查找）。
>    6. 如果当前遍历的这个节点不在子序列，说明要进行移动，如果节点在子序列中直接跳过。


### 6.4、vue2与vue3 diff算法的区别

> [!TIP]
> - Vue 2 使用的是基于`递归的双指针`的 diff 算法， Vue 3 使用的是基于`数组的动态规划`的 diff 算法,Vue 3 的算法效率更高，因为它使用了一些优化技巧，例如按需更新、静态标记等。
>- Vue 2 的 diff 算法会对整个组件树进行完整的遍历和比较，而 Vue 3 的 diff 算法会跳过静态子树的比较，只对动态节点进行更新。这减少了不必要的比较操作，提高了性能。
>- Vue 2 的 diff 算法对于列表渲染（v-for）时的元素重新排序会比较低效，需要通过给每个元素设置唯一的 key 来提高性能。而 Vue 3 的 diff 算法在列表渲染时，通过跟踪元素的移动，可以更好地处理元素的重新排序，无需设置 key。
>- Vue 3 的 diff 算法对于静态节点的处理更加高效，静态节点只会在首次渲染时被处理，后续更新时会直接跳过比较和更新操作，减少了不必要的计算。

> 1. Vue3 的 Diff 算法相比 Vue2 在性能上有明显的提升。
> 2. 对静态节点和动态节点的处理更加高效。
> 3. Vue3 的`区块树优化`也减少了不必要的节点比较，进一步提高了性能。

#### 6.4.1、Vue2 diff算法具体实现
> [!TIP]
> - Vue2 使用的是基于`递归的双指针`的 diff 算法，其核心思想是：
>   - 首先，创建一个`vnode`树，`vnode`树是由组件的`template`编译生成的，`vnode`树的每个节点都包含了`tag`、`data`、`children`等信息。
>   - 然后，对`vnode`树进行`diff`操作，`diff`操作会递归地比较新旧`vnode`树的每个节点，并生成一个`patch`对象，描述了如何将旧`vnode`树转变成新`vnode`树。
>   - 最后，将`patch`对象应用到真实的`DOM`上，完成视图更新。
> - Vue2 的`diff`算法的实现比较简单，但是对于复杂的场景，比如`列表渲染`、`动态组件`等，`diff`算法的效率会比较低。
::: details 点击查看Vue2 diff算法实现
```js
function patchVnode(oldVnode, newVnode) {
    if (oldVnode === newVnode) {
        return;
    }
    const { tag, data, children } = newVnode;
    if (oldVnode.tag !== tag) {
        const el = document.createElement(tag);
        patch(oldVnode, el);
        parent.replaceChild(el, oldVnode.el);
    } else {
        const el = oldVnode.el;
        const oldData = oldVnode.data;
        const newData = data || {};
        if (oldData.class !== newData.class) {
            el.className = newData.class;
        }
        if (oldData.style !== newData.style) {
            el.style.cssText = newData.style;
        }
        if (children) {
            if (Array.isArray(children)) {
                updateChildren(el, children, oldVnode.children);
            } else {
                el.textContent = children;
            }
        }
    }
}

function updateChildren(parent, newChildren, oldChildren) {
    let oldStart = 0;
    let newStart = 0;
    let oldEnd = oldChildren.length - 1;
    let newEnd = newChildren.length - 1;
    let oldStartVnode = oldChildren[0];
    let newStartVnode = newChildren[0];
    let oldEndVnode = oldChildren[oldEnd];
    let newEndVnode = newChildren[newEnd];
    while (oldStart <= oldEnd && newStart <= newEnd) {
        if (!oldStartVnode) {
            oldStartVnode = oldChildren[++oldStart];
        } else if (!oldEndVnode) {
            oldEndVnode = oldChildren[--oldEnd];
        } else if (sameVnode(oldStartVnode, newStartVnode)) {
            patchVnode(oldStartVnode, newStartVnode);
            oldStartVnode = oldChildren[++oldStart];
            newStartVnode = newChildren[++newStart];
        } else if (sameVnode(oldEndVnode, newEndVnode)) {
            patchVnode(oldEndVnode, newEndVnode);
            oldEndVnode = oldChildren[--oldEnd];
            newEndVnode = newChildren[--newEnd];
        } else if (sameVnode(oldStartVnode, newEndVnode)) {
            patchVnode(oldStartVnode, newEndVnode);
            parent.insertBefore(oldStartVnode.el, oldEndVnode.el.nextSibling);
            oldStartVnode = oldChildren[++oldStart];
            newEndVnode = newChildren[--newEnd];
        } else if (sameVnode(oldEndVnode, newStartVnode)) {
            patchVnode(oldEndVnode, newStartVnode);
            parent.insertBefore(oldEndVnode.el, oldStartVnode.el);
            oldEndVnode = oldChildren[--oldEnd];
            newStartVnode = newChildren[++newStart];
        } else {
            if (oldStartVnode.tag === "option") {
                patchVnode(oldStartVnode, newStartVnode);
                newStartVnode = newChildren[++newStart];
            } else {
                const oldKey = oldStartVnode.key;
                const newKey = newStartVnode.key;
                if (!newKey) {
                    patchVnode(oldStartVnode, newStartVnode);
                    newStartVnode = newChildren[++newStart];
                } else if (!oldKey) {
                    patchVnode(oldStartVnode, newStartVnode);
                    oldStartVnode = oldChildren[++oldStart];
                } else if (oldKey === newKey) {
                    patchVnode(oldStartVnode, newStartVnode);
                    oldStartVnode = oldChildren[++oldStart];
                    newStartVnode = newChildren[++newStart];
                } else {
                    const index = newChildren.findIndex((vnode) => vnode.key === newKey);
                    if (index > -1) {
                        patchVnode(oldStartVnode, newChildren[index]);
                        newStartVnode = newChildren[++newStart];
                    } else {
                        patchVnode(oldStartVnode, newStartVnode);
                        oldStartVnode = oldChildren[++oldStart];
                    }
                }
            }
        }
    }
    if (oldStart <= oldEnd || newStart <= newEnd) {
        if (oldStart > oldEnd) {
            const refNode = newChildren[newEnd + 1] ? newChildren[newEnd + 1].el : null;
            addVnodes(parent, refNode, newChildren, newStart, newEnd);
        } else {
            removeVnodes(parent, oldChildren, oldStart, oldEnd);
        }
    }
}
```

#### 6.4.2、Vue3 diff算法具体实现
> [!TIP]
> - Vue3 使用的是基于`数组的动态规划`的 diff 算法，其核心思想是：
>   - 首先，创建一个`vnode`数组，`vnode`数组是由组件的`template`编译生成的，`vnode`数组的每个节点都包含了`tag`、`data`、`children`等信息。
>   - 然后，对`vnode`数组进行`diff`操作，`diff`操作会生成一个`patch`数组，描述了如何将旧`vnode`数组转变成新`vnode`数组。
>   - 最后，将`patch`数组应用到真实的`DOM`上，完成视图更新。
> - Vue3 的`diff`算法的实现比较复杂，但是对于复杂的场景，比如`列表渲染`、`动态组件`等，`diff`算法的效率会比较高。
::: details 点击查看Vue3 diff算法实现
```js
function patch(oldVnode, newVnode) {
    const el = (oldVnode && oldVnode.el) || document.createElement(newVnode.tag);
    const parent = el.parentNode;
    if (oldVnode) {
        update(oldVnode, newVnode);
    } else {
        create(newVnode);
    }
    parent.insertBefore(el, el.nextSibling);
}

function update(oldVnode, newVnode) {
    if (oldVnode.tag !== newVnode.tag) {
        const el = oldVnode.el;
        const parent = el.parentNode;
        parent.removeChild(el);
        create(newVnode);
        parent.insertBefore(el, el.nextSibling);
    } else {
        updateChildren(oldVnode.el, oldVnode.children, newVnode.children);
        updateData(oldVnode.el, oldVnode.data, newVnode.data);
    }
}

function updateChildren(parent, oldChildren, newChildren) {
    const oldStartIndex = 0;
    const newStartIndex = 0;
    const oldEndIndex = oldChildren.length - 1;
    const newEndIndex = newChildren.length - 1;
    let oldStartVnode = oldChildren[oldStartIndex];
    let newStartVnode = newChildren[newStartIndex];
    let oldEndVnode = oldChildren[oldEndIndex];
    let newEndVnode = newChildren[newEndIndex];
    let oldKeyToIndexMap = {};
    let newKeyToIndexMap = {};
    let i, j;
    for (i = oldStartIndex; i <= oldEndIndex; i++) {
        oldKeyToIndexMap[oldChildren[i].key] = i;
    }
    for (j = newStartIndex; j <= newEndIndex; j++) {
        newKeyToIndexMap[newChildren[j].key] = j;
    }
    while (oldStartIndex <= oldEndIndex && newStartIndex <= newEndIndex) {
        if (!oldStartVnode) {
            oldStartVnode = oldChildren[++oldStartIndex];
        } else if (!oldEndVnode) {
            oldEndVnode = oldChildren[--oldEndIndex];
        } else if (sameVnode(oldStartVnode, newStartVnode)) {
            patch(oldStartVnode, newStartVnode);
            oldStartVnode = oldChildren[++oldStartIndex];
            newStartVnode = newChildren[++newStartIndex];
        } else if (sameVnode(oldEndVnode, newEndVnode)) {
            patch(oldEndVnode, newEndVnode);
            oldEndVnode = oldChildren[--oldEndIndex];
            newEndVnode = newChildren[--newEndIndex];
        } else if (sameVnode(oldStartVnode, newEndVnode)) {
            patch(oldStartVnode, newEndVnode);
            parent.insertBefore(oldStartVnode.el, oldEndVnode.el.nextSibling);
            oldStartVnode = oldChildren[++oldStartIndex];
            newEndVnode = newChildren[--newEndIndex];
        } else if (sameVnode(oldEndVnode, newStartVnode)) {
            patch(oldEndVnode, newStartVnode);
            parent.insertBefore(oldEndVnode.el, oldStartVnode.el);
            oldEndVnode = oldChildren[--oldEndIndex];
            newStartVnode = newChildren[++newStartIndex];
        } else {
            if (oldStartVnode.key === newEndVnode.key) {
                patch(oldStartVnode, newEndVnode);
                parent.insertBefore(oldStartVnode.el, oldEndVnode.el.nextSibling);
                oldStartVnode = oldChildren[++oldStartIndex];
                newEndVnode = newChildren[--newEndIndex];
            } else if (oldEndVnode.key === newStartVnode.key) {
                patch(oldEndVnode, newStartVnode);
                parent.insertBefore(oldEndVnode.el, oldStartVnode.el);
                oldEndVnode = oldChildren[--oldEndIndex];
                newStartVnode = newChildren[++newStartIndex];
            } else {
                if (oldStartVnode.key && newEndVnode.key) {
                    if (oldStartVnode.key === newEndVnode.key) {
                        patch(oldStartVnode, newEndVnode);
                        parent.insertBefore(oldStartVnode.el, oldEndVnode.el.nextSibling);
                        oldStartVnode = oldChildren[++oldStartIndex];
                        newEndVnode = newChildren[--newEndIndex];
                    } else {
                        const oldIndex = oldKeyToIndexMap[newStartVnode.key];
                        if (oldIndex !== undefined) {
                            patch(oldChildren[oldIndex], newStartVnode);
                            parent.insertBefore(oldChildren[oldIndex].el, oldStartVnode.el);
                            newStartVnode = newChildren[++newStartIndex];
                        } else {
                            patch(oldStartVnode, newStartVnode);
                            newStartVnode = newChildren[++newStartIndex];
                        }
                    }
                } else if (oldEndVnode.key && newStartVnode.key) {
                    if (oldEndVnode.key === newStartVnode.key) {
                        patch(oldEndVnode, newStartVnode);
                        parent.insertBefore(oldEndVnode.el, oldStartVnode.el);
                        oldEndVnode = oldChildren[--oldEndIndex];
                        newStartVnode = newChildren[++newStartIndex];
                    } else {
                        const oldIndex = oldKeyToIndexMap[newEndVnode.key];
                        if (oldIndex !== undefined) {
                            patch(oldChildren[oldIndex], newEndVnode);
                            parent.insertBefore(oldChildren[oldIndex].el, oldEndVnode.el.nextSibling);
                            newEndVnode = newChildren[--newEndIndex];
                        } else {
                            patch(oldEndVnode, newEndVnode);
                            newEndVnode = newChildren[--newEndIndex];
                        }
                    }
                } else {
                    patch(oldStartVnode, newStartVnode);
                    newStartVnode = newChildren[++newStartIndex];
                }
            }
        }
    }
    if (oldStartIndex <= oldEndIndex || newStartIndex <= newEndIndex) {
        if (oldStartIndex > oldEndIndex) {
            const refNode = newChildren[newEndIndex + 1] ? newChildren[newEndIndex + 1].el : null;
            addVnodes(parent, refNode, newChildren, newStartIndex, newEndIndex);
        } else {
            removeVnodes(parent, oldChildren, oldStartIndex, oldEndIndex);
        }
    }
}

function addVnodes(parent, refNode, vnodes, startIdx, endIdx) {
    for (; startIdx <= endIdx; ++startIdx) {
        const vnode = vnodes[startIdx];
        parent.insertBefore(create(vnode), refNode);
    }
}

function removeVnodes(parent, vnodes, startIdx, endIdx) {
    for (; startIdx <= endIdx; ++startIdx) {
        const vnode = vnodes[startIdx];
        if (vnode.el) {
            parent.removeChild(vnode.el);
        }
    }
}

function create(vnode) {
    const el = document.createElement(vnode.tag);
    updateData(el, {}, vnode.data);
    if (vnode.children) {
        if (Array.isArray(vnode.children)) {
            addVnodes(el, null, vnode.children, 0, vnode.children.length - 1);
        } else {
            el.textContent = vnode.children;
        }
    }
    return el;
}

function updateData(el, oldData, newData) {
    for (const key in newData) {
        const value = newData[key];
        if (key === "class") {
            el.className = value;
        } else if (key === "style") {
            el.style.cssText = value;
        } else if (key[0] === "o" && key[1] === "n") {
            const eventName = key.slice(2).toLowerCase();
            if (oldData[key] !== value) {
                el.removeEventListener(eventName, oldData[key]);
                el.addEventListener(eventName, value);
            }
        } else if (key !== "key") {
            el.setAttribute(key, value);
        }
    }
    for (const key in oldData) {
        if (newData[key] === undefined) {
            el.removeAttribute(key);
        }
    }
} 

function sameVnode(oldVnode, newVnode) {
    return (
        oldVnode.tag === newVnode.tag &&
        oldVnode.key === newVnode.key &&
        oldVnode.isComment === newVnode.isComment
    );
}
```

#### 6.5.1、最长递增子序列

> Longest Increasing Subsequence，简称LIS ：要求在一个给定的序列中找到最长的严格递增的子序列。
>
> 方法：
>

> 2. 贪心+二分查找



```js
function LIS(nums) {
  if (nums.length === 0) {
    return [];
  }
  let results = [[nums[0]]];
  for (let i = 1; i < nums.length; i++) {
    const n = nums[i];
    _update(n);
  }
  function _update(n) {
    for (let i = results.length - 1; i >= 0; i--) {
      const line = results[i];
      const tail = line[line.length - 1];
      if (n > tail) {
        results[i + 1] = [...line, n];
        break;
      } else if (n < tail && i === 0) {
        results[i] = [n];
      }
    }
  }
  return results[results.length - 1];
}
```

## 十、响应式原理

### 10.1、Vue2响应式原理

> - `Vue2`使用的是`Object.defineProperty`
>   - `Object.defineProperty`只能劫持对象的属性，不能劫持数组的索引。
>   - 原理：获取数据时触发`getter`属性收集依赖，修改数据时触发`setter`属性更新依赖。
> - `Vue3`使用的是`Proxy`
>   - `Proxy`可以代理整个对象，拦截对象的各种操作。
>   - 原理：
>     1. 依赖收集: 在属性访问时，会进行依赖收集。通过track函数将当前的副作用函数（如组件的渲染函数、计算属性的求值函数等）与被访问的属性建立关联，将副作用函数存储在一个依赖集合中。
>     2. 依赖更新: 当数据发生变化时，会触发依赖更新。通过trigger函数遍历依赖集合，调用副作用函数，使得视图更新。

#### 10.1.1、Vue2.0不足

> 1. 对象只能劫持设置好的数据，新增的数据需要使用`$set`。
> 2. 数组只能操作七种方法，修改某一项值无法劫持。
> `Object.defineProperty`是能做到对数组的修改，只是有非常大的性能问题，所以只能做性能与操作之间的平衡。

## 十一、Computed计算属性

### 11.1、定义
> 当依赖的属性的值发生改变时，才会触发它的更改，如果依赖的值不改变，使用的是缓存中的属性值。
### 11.2、底层原理
> 1. 依赖收集： 当 Vue 实例初始化时，会对 Computed 计算属性中涉及的响应式数据进行依赖收集，在访问计算属性时，会触发get函数，在这个函数内部会调用track函数来收集依赖。
> 2. 建立依赖关系： 每个计算属性都有一个对应的Watcher实例，它会在收集依赖的过程中，将自身与所依赖的响应式数据建立关联。
> 3 缓存机制： 
>    1. `计算属性的缓存`：计算属性会缓存其计算结果，只有在其依赖的响应式数据发生变化时，才会重新计算。在计算属性的Watcher实例中，有一个标志位用于记录计算属性是否已经被计算过，以及一个变量用于存储计算结果。
>    2. `判断是否需要重新计算`：当依赖的响应式数据发生变化时，会触发set函数，进而触发trigger函数通知相关的Watcher实例进行更新。Watcher实例在收到更新通知后，会根据缓存标志和依赖数据的变化情况，判断是否需要重新计算。如果计算属性依赖的数据没有变化，就直接返回缓存中的结果，而不会重新执行计算函数。

### 11.3、源码剖析

> 1. 如果 computed 的第一个参数是函数，说明是`只读`的传入形式，将参数赋值给 getter, setter为空或在开发环境抛出警告。
> 2. 否则则为选项式传参，直接去第一个参数里面读 get 和 set 并赋值。


> 1. `格式化参数`。
>    1. 如果 computed 的第一个参数是函数，说明是`只读`的传入形式，将参数赋值给 `getter`。setter为空或在开发环境抛出警告。
>    2. 如果computed的第一个参数是对象，说明是可读可写的形式。
> 2. 将get和set传给`ComputedRefImpl类`，默认声明了一个`value`和``dirty=true`（需要重新计算值）。
> 3. `get`中劫持了`value`,然后使用`toRaw`脱离`Proxy代理`，再判断`dirty`是否为true（脏值检测）
>    1. `dirty`为`true` 依赖改变，需要重新计算。
>    2. `dirty`为`false` 依赖不变，直接返回上一次的值。





## 十二、watch侦听器
>[!tip]
> 侦听特定的数据源，并在单独的回调函数中执行副作用。
>
> 接受三个参数
>
> 1. `监听源`
>    1. `ref`声明的响应式数据
>    2. `reactive`声明的响应式数据
>    3. 数据源组成的`数组`
>    4. `回调函数`（监听单个数据源）
> 2. 回调函数`Call Back(newValue,oldvalue)`
> 3. `options`配置项 （对象）
>    1. `immediate : true ` // 是否立即调用一次
>    2. `deep: true ` // 是否开启深度监听       `reavtive`声明的变量`默认开启深度监听`。

### 12.1、底层原理
>[!tip]
> 依赖收集和更新通知
>
> 1. 依赖收集：Vue会先找到被监听的数据属性所对应的`getter`，读取数据时会触发`getter`函数，在这个过程中，`watch`回调函数就会被收集为数据属性的一个依赖。
> 2. 依赖更新通知：当被监听的数据属性发生变化时，`Vue`会调用`setter`函数，通知所有依赖于这个数据属性的`watch`回调函数，并传入新值和旧值。
