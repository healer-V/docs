# 文档规范索引

本目录集中存放仓库所有需要长期维护并提交到远程的文档规范。根目录 `AGENTS.md` 只保留项目定位、任务路由和硬性规则速览，细则都在这里，并且**每条规则只写在一个文件中**，其他位置只放链接。

项目的核心定位是帮助读者从 0 系统学习一门语言或技术。各项规范共同保证当前技术的基础知识得到解释、内容按理解依赖递进、使用示例可以复现，并以读者能够独立完成声明范围内的任务作为学习结果。

## 一、目录结构

| [writing/markdown-format.md](./writing/markdown-format.md) | 格式：Frontmatter、标题编号、代码块、表格、容器、代码组、长代码折叠、链接与图片 |

## 二、规范优先级

文档任务按以下优先级执行：

1. 用户在当前任务中的明确要求；
2. 距离目标文件最近的目录级 `AGENTS.md`；
3. 根目录 `AGENTS.md`；
4. 本目录中与当前任务对应的规范；
5. 目标模块已确认的模块蓝图；
6. 目标文件已有且不与上述要求冲突的局部风格。

模块蓝图只能细化当前模块的知识范围、版本和文章职责，不能放宽 `AGENTS.md` 与本目录规范中的安全、事实、格式和工程要求。

## 三、任务路由

开始文档工作前先识别任务类型，再读取下表中的文件。只涉及当前文章的局部修改时，按受影响内容应用规范，不扩大治理范围。

| 任务类型 | 必读规范 | 开始正文前的门禁 |
|----------|----------|------------------|
| 新建技术模块 | 知识体系、目录规划、阶段流程、文章生成、写作三件套、质量门禁 | 模块蓝图和样板文章均已确认 |
| 全文重构技术模块 | 与新建技术模块相同，并审计现有目录、sidebar 和链接 | 迁移范围、模块蓝图和样板文章均已确认 |
| 规划章节目录或逐篇大纲 | 知识体系、目录规划、阶段流程 | 知识项清单和依赖关系已经完成 |
| 新建或全文重写单篇文章 | 当前模块蓝图、文章生成、写作三件套、质量门禁 | 文章职责卡已经确认或能从既有蓝图唯一确定 |
| 局部修改历史文章 | 写作三件套中与修改内容相关的规则、质量门禁 | 修改范围明确，不借机治理无关内容 |
| 批量质量治理 | 当前模块蓝图、质量门禁、文章生成中的历史文档治理 | 治理范围和迁移规则已经确认 |

“写作三件套”指 `writing/` 下的正文组织、格式和示例三份规范。当前模块不存在蓝图时，新建模块、全文重构模块和目录规划任务必须先使用[模块蓝图模板](./templates/module-blueprint-template.md)创建蓝图。

## 四、标准执行顺序

系统教程使用以下顺序：

```text
任务建档
→ 识别知识方向与版本基线
→ 建立知识项清单和依赖关系
→ 聚合章节并生成文章职责卡
→ 用户确认模块蓝图
→ 生成并确认样板文章
→ 按章节批量生成和检查
→ 执行整体验收
```

目录顺序通过知识依赖、章节编号、文章编号和 sidebar 表达。正文不得使用“上一篇已经学习”“下一篇将介绍”“本章学习路线”等话术人为制造连续性。

## 五、阶段输出

| 阶段 | 使用模板 | 必须输出 |
|------|----------|----------|
| 模块蓝图 | [模块蓝图模板](./templates/module-blueprint-template.md) | 教学契约、方向分类、版本、来源、知识项、依赖、章节、职责卡、覆盖矩阵和验证方案 |
| 单篇规划 | [文章职责卡模板](./templates/article-responsibility-card-template.md) | 唯一问题、类型、范围、深度、证据、验证和重复归属 |
| 样板校准 | [样板评审模板](./templates/sample-review-template.md) | 方向、深度、粒度、事实、示例、表达和可复制性结论 |
| 最终验收 | [质量门禁](./process/quality-gates.md) | 内容覆盖、示例验证、工程验证、未验证项和变更范围 |

## 六、停止条件

出现以下任一情况时，必须停止当前阶段并处理问题，不能带着未解决问题继续批量生成：

- 知识方向无法确定，或者主方向与辅助方向职责冲突；
- 主版本基线不明确，官方资料对应多个不兼容版本；
- 知识项存在未归属、重复归属或循环依赖；
- 模块蓝图或样板文章尚未获得用户确认；
- 核心结论缺少可靠来源；
- 核心示例无法验证；
- 正文范围实质偏离已确认蓝图；
- 工作区已有改动与计划修改范围无法兼容。

停止不等于交付完成。问题解决后必须从发生失败的门禁重新检查。

## 七、规范边界

- 本规范不要求所有知识方向使用相同章节名称；
- 本规范不使用文章数量、字数或标题数量代替内容完整性；
- 本规范不允许从固定目录模板直接生成正文；
- 本规范不自动迁移历史文档，迁移范围由当前任务决定；
- 本规范不授权自动提交、推送、发布或部署。

## 八、规范维护

1. 新增或修改规则时，先在本索引确定唯一归属文件，再写入该文件；其他文件只引用，不复述。
2. 规则能够机械判定时，同步更新 `scripts/docs/check-content.mjs`，并在[质量门禁](./process/quality-gates.md)的机器检查中登记。
3. 移动或改名规范文件时，同步更新 `AGENTS.md`、本索引、模板和蓝图中的相对链接。
4. 规则含义发生变化时，在交付说明中列出差异，由用户确认后生效。
