# 文档生成质量门禁

质量门禁用于判断教程是否能够交付。所有硬性门禁都必须通过，不使用总分抵消事实错误、知识漏项、无效示例或构建失败。

## 一、门禁等级

| 等级 | 含义 | 处理方式 |
|------|------|----------|
| 硬性门禁 | 事实、范围、结构、示例或工程的交付条件 | 任一失败都不得进入下一阶段或标记完成 |
| 质量复查 | 内容密度、表达、示例选择和维护性判断 | 必须逐项给出结论并修正实质问题 |
| 增强建议 | 不影响当前目标的可选改进 | 记录但不得擅自扩大修改范围 |

## 二、阶段硬性门禁

| 门禁 | 必须通过的检查 | 失败处理 |
|------|----------------|----------|
| 方向识别 | 主方向、辅助方向、前置知识、排除范围明确 | 停止目录规划 |
| 版本基线 | 主版本、运行环境、关键依赖和差异处理明确 | 停止知识项生成 |
| 蓝图 | 知识项无漏项、依赖无循环、归属唯一、目录有依据 | 不得写目标正文 |
| 事实 | 关键结论有可靠来源，时效与版本一致 | 移出已确认内容或补充证据 |
| 样板 | 方向、深度、粒度、证据、表达和验证合格 | 不得批量生成 |
| 单篇 | 职责卡、内容闭环、示例结果、边界和来源合格 | 不得进入下一篇 |
| 章节 | 知识覆盖、跨篇去重、术语和场景一致 | 不得进入下一章 |
| 工程 | 格式、链接、sidebar、资源和构建通过 | 不得交付 |
| 整体 | 最终能力、版本、生产边界和变更范围闭合 | 不得标记完成 |

## 三、蓝图语义检查

- [ ] 知识方向分类与模块实际职责一致；
- [ ] 跨方向前置知识没有混入当前方向基础；
- [ ] 主版本官方核心主题已经映射到知识项；
- [ ] 不适用和排除内容具有具体理由；
- [ ] 所有适用知识项具有唯一文章归属；
- [ ] 所有前置 ID 存在且依赖关系无循环；
- [ ] 章节名称准确、精简地概括共同技术职责，没有堆砌知识清单或空泛修饰；
- [ ] 文章标题准确、精简地概括唯一学习问题，保留必要限定，不机械照抄职责卡的完整问句；
- [ ] 最终能力具有支撑知识项和验证方式；
- [ ] 样板文章能够代表模块主要难度和证据要求。

编程语言模块必须检查语言自身的基础语法和类型模型；框架模块必须检查框架专用表达、核心抽象和运行模型，不得要求框架重新讲解宿主语言的完整基础语法。

## 四、单篇语义检查

下列编号用于单篇交付与复审记录；具体写法分别引用[文章契约](../article/article-generation.md)、[正文组织](../writing/content-organization.md)、[Markdown 格式](../writing/markdown-format.md)及[示例验证](../writing/code-examples.md)。本节其余清单用于逐项取证，不另外定义生成规则。

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| A01 | 职责与边界 | 唯一问题清楚，主讲知识覆盖，未扩展排除范围 |
| A02 | 事实与版本 | 核心结论有依据，主版本一致，差异明确 |
| A03 | 类型与深度 | 满足当前类型的必需内容与目标能力 |
| A04 | 组织与小节完整性 | 入口问题、核心模型、主问题、证据和收束形成连续判断路径；层级表达真实从属关系，既检查已有小节，也检查必要子主题缺失，无人为加层、平铺堆叠、空薄小节或重复；核心主题有解释与证据支撑 |
| A05 | 示例链路 | 从本篇定义的空目录出发，依赖、实现、入口、结果与失败边界闭合；目录层级有知识或工具依据，没有仓库示例目录引用及隐式文件依赖；代码、命令和页面展示一致 |
| A06 | 验证真实性 | 已运行、仅编译、局部、伪代码和未验证状态准确 |
| A07 | 代码注释 | 新增函数、方法和回调有职责与返回说明；多入参有完整文档注释 |
| A08 | 格式与表达 | 结构合法，各级标题准确精简、必要限定完整；正文、步骤、表格、容器和折叠内容职责清楚，没有连续大型表格或装饰性分层；操作的命令、结果、解释与失败处理相邻；超过10行代码默认折叠，核心解释可见，无课程式模板填充 |
| A09 | 链接与资源 | 相对链接、图片与必要锚点有效，无敏感内容 |
| A10 | 跨篇一致性 | 知识主讲唯一，版本、术语、场景与相邻内容一致 |
| A11 | 工程验证 | 当前修改所需的构建、导航与页面检查通过 |
| A12 | 修改范围 | 没有覆盖用户改动或引入无关改名、删除和重构 |

### 1. 职责与完整性

- [ ] 正文没有偏离职责卡的唯一问题；
- [ ] 主文章类型与内容结构和证据一致；
- [ ] 达到声明的认识、使用、解释、设计或诊断深度；
- [ ] 主问题与子问题关系明确，同级主题粒度合理；必要时才增加三级、四级标题，没有统一配额或空泛父层；
- [ ] 已检查必要子主题缺失，不能因没有三级标题而跳过完整性审查；保留浅层结构或调整层级具有内容依据；
- [ ] 核心小节说明了必要的原因、机制、应用、边界或判断；
- [ ] 讲解顺序符合知识依赖或诊断过程，必要概念和条件在使用前或使用处说明；
- [ ] 段落只推进一个中心意思，无多主题文字堆砌或连续单句知识要点；
- [ ] 不存在空小节、骨架化小节和同义重复；
- [ ] 明确不覆盖的内容没有被临时塞入正文。

### 2. 事实与版本

- [ ] 关键 API、配置、默认行为和限制具有官方依据；
- [ ] 正文行为符合模块主版本；
- [ ] 版本差异具有明确标签和集中归属；
- [ ] 未将私有实现字段写成公共 API；
- [ ] 未使用“可能”“大概”“也许”代替必要验证；
- [ ] 未编造来源、配置、命令、日志和运行结果。

### 3. 示例与证据

- [ ] 示例直接证明文章核心结论；
- [ ] 示例前说明用途、环境或触发条件；
- [ ] 示例后说明返回值、状态、日志、指标或页面结果；
- [ ] 完整实现与重复出现的局部片段一致，没有因折叠而省略执行或验证责任；
- [ ] 依赖、配置、命令、数据和版本保持一致；
- [ ] 示例以本篇定义的空目录为起点，必要代码、构建配置、数据与工具准备完整，不依赖文档仓库结构或其他章节工程；
- [ ] 正文、注释、目录树、命令、链接、折叠标题与相关公开记录没有仓库示例目录引用或内容入口；
- [ ] 单文件示例直接使用文件名，保留的包与目录层级具有知识或工具依据；路径、代码、命令、输出与排错说明一致，已核对实际页面；
- [ ] 独立性验证只使用本篇给出的文件和步骤，没有从维护工程复制未展示内容补齐依赖；
- [ ] 错误示例包含现象、原因、证据和处理；
- [ ] 无法验证的部分具有具体原因和影响范围；
- [ ] 新增函数、方法和回调符合根目录代码注释规范。

### 4. 表达与边界

- [ ] 一级标题后直接进入当前知识；
- [ ] 各级标题准确精简，解释放正文，技术术语和必要边界完整，没有按统一字数截断或生造缩写；
- [ ] 没有学习目标、学习路线、前文回顾和下一篇预告；
- [ ] 没有用表格、流程图或代码块重复展示文章目录；
- [ ] 前置知识通过最小说明和有效链接处理；
- [ ] 表格、列表、代码和容器服务于内容，不作装饰；
- [ ] 已逐节检查文字阅读层次；需要关注的前提、建议、误区与风险使用匹配的info、tip、warning或danger，标题说明具体判断；
- [ ] 容器保留条件与必要解释，前提和危险警告在操作前；没有整节套容器、连续堆叠、重复结论或仅凭代码折叠宣称可读；
- [ ] 术语、大小写、字段、业务对象和示例命名一致；
- [ ] 术语和缩写首次使用有必要解释，数值单位与边界明确，代词能就近唯一定位；
- [ ] 超过10行的代码块位于默认折叠的details中；包含注释和空行，不计首尾围栏及末尾普通换行；
- [ ] 折叠标题具体，核心概念、条件、关键逻辑解释和结果判断在折叠外可读；
- [ ] 代码组正确嵌套，没有用删注释、压缩语句或机械拆块规避行数要求；
- [ ] 没有把复杂解释塞进表格单元格、整段加粗或连续堆叠容器；
- [ ] 每句话都提供规则、机制、条件、取值、反例或证据；没有“关键词：一句断言”式清单、收益口号、无关年表、无依据评价和收尾套话，`excerpt` 不是列表拼接。

### 5. 阅读路径与注意力

- [ ] 开篇用真实问题、技术现象或操作结果建立阅读入口，并直接给出核心判断；
- [ ] 文章存在一个能够承载后续内容的对象关系、状态、时序、决策依据或贯穿场景；
- [ ] 二级标题形成连续的主问题路径，三级和四级标题只承担需要独立解释的从属问题；
- [ ] 只浏览标题、各节首段和提示容器时，能够还原正文的主要判断过程；
- [ ] 概念、机制、操作和失败分支具有可辨认的信息权重，没有全部平铺为同级标题；
- [ ] 操作、测试或排障中的目标、条件、命令、结果、解释和失败处理保持相邻；
- [ ] 表格只用于稳定的同维度比较，没有把连续步骤、长段机制或整篇主线压入单元格；
- [ ] 页面没有连续大型表格、连续容器或大段纯文字造成的单一阅读节奏；
- [ ] 结尾使用验收结果、判断案例、反例或恢复复测收束，并说明证据边界；
- [ ] 信息层次来自内容关系，不依赖标题、表格、加粗和容器的数量配额。

## 五、章节与模块检查

### 1. 知识覆盖

将模块蓝图中的知识项逐一映射到正文：

| 状态 | 判定 |
|------|------|
| 已覆盖 | 目标文章达到声明深度并具有要求的证据 |
| 部分覆盖 | 已出现相关内容，但深度、边界或证据不足 |
| 未覆盖 | 正文没有承担该知识项 |
| 不适用 | 蓝图已经记录不适用理由 |

存在“部分覆盖”或“未覆盖”的必需知识项时，模块不能通过完整性门禁。

### 2. 跨篇重复

重复检查不能只搜索相同文字，还要判断语义归属：

- 相同概念是否在多篇文章中被完整定义；
- 相同代码是否只更换变量名后重复出现；
- 相同错误和边界是否由多篇文章重复承担；
- 概述文章是否提前展开后续 API 和工程细节；
- 工程文章是否重新讲解核心基础，而不是引用主讲文章。

发现重复时，确定一个主讲文章。其他文章保留完成自身目标所需的最小说明，并添加有意义的相对链接。

### 3. 顺序与一致性

- [ ] 章节和文章顺序符合依赖关系；
- [ ] 文件夹和文件编号连续；
- [ ] sidebar 顺序与真实目录一致；
- [ ] 同章统一场景没有无理由更换对象、字段和端口；
- [ ] 同一术语没有出现多个互相冲突的译名；
- [ ] 版本和依赖没有在批量生成过程中漂移。

## 六、机器检查

机器检查至少覆盖：

- Frontmatter 语法、必填字段和日期格式；
- `title` 与唯一一级标题一致；
- 二级、三级和四级标题层级与编号；
- 全篇浅层标题、单节混合多个主题和单个子节等结构候选；只提示逐篇语义复审，不作为自动失败或增加标题的条件；
- 入口问题、核心模型、主问题路径、证据路径和收束方式缺失候选；
- 空小节、骨架化小节和连续薄弱小节候选；
- 连续三条以上“加粗关键词：短句”的空话清单候选；
- 多主题长段落、逐句换行与连续单句知识要点候选；
- 连续大型表格、连续容器、命令与预期结果距离过远等注意力层级候选；
- 文字容器类型、标题与段落分布，以及正文仅含段落和代码的候选；数量与分布仅提示人工复查，不按配额自动加框；
- Markdown 表格、容器和代码块闭合；
- 代码块语言标识；
- 文档仓库路径、跨章节脚本、未展示的自定义类或既有产物依赖候选，并结合空目录复现逐项判断；
- 仓库示例目录的路径、链接和取用说明，扫描范围包含代码注释、目录树、命令、折叠标题及相关公开记录；不得通过改路径或换名称规避；
- 按内容实际行数检查超过10行的代码块，确认Markdown的details包裹关系，以及渲染后details/summary、默认折叠与代码组结构；
- 脱离章节上下文后无法识别主题的泛化标题候选；概述类文章应保留技术名称；
- 内部链接、图片路径和 sidebar 文件存在性；
- 章节文件夹与文章文件编号；
- 禁止的课程式元叙述候选；
- VitePress 完整构建。

语义类脚本扫描只能生成候选问题。知识层级、骨架化、重复、段落拆分和内容深度必须由 AI 结合职责卡复核，不能按字数、句数或标题数量自动填充。验收须同时覆盖“已有小节是否空薄”和“必要子主题是否缺失”，记录保留结构、重组层级或补足解释的具体依据。代码块超过10行必须折叠则是明确格式门禁，不能以语义评分抵消。具体判断见[技术文章生成与验收规范](../article/article-generation.md)。

其中 Frontmatter 与一级标题、标题编号、代码语言、超过10行未折叠、`detail` 误写、仓库示例目录引用（含代码块内的路径注释）、空小节与骨架化候选、空话清单候选（`filler-list` 警告）、泛化标题（`generic-title` 警告）、目录与文件编号，以及未被 sidebar 或顶部导航引用的孤立页面（`orphan` 警告）已由 `scripts/docs/check-content.mjs` 实现：`pnpm docs:check <模块路径>` 列出问题，`pnpm docs:check:strict <模块路径>` 在存在错误时以 1 退出。脚本未覆盖的项目仍按本节逐项检查。

## 七、异常处理

| 异常 | 必须采取的行为 |
|------|----------------|
| 知识方向存在歧义 | 暂停规划，基于模块目标选择主方向并说明依据 |
| 官方资料版本冲突 | 回到主版本基线核对，不混写多个版本默认行为 |
| 核心示例无法运行 | 记录环境和阻塞原因，不伪造输出，不通过示例门禁 |
| 蓝图发现漏项 | 更新知识项、依赖、归属和覆盖矩阵，再确认影响范围 |
| 文章持续膨胀 | 回到唯一问题和主类型重新拆分 |
| 相邻文章重复 | 确定唯一主讲位置，其他文章缩减为最小上下文 |
| 工作区改动重叠 | 保留用户改动并基于当前状态调整，无法兼容时请求确认 |
| 构建内存不足 | 保留原始错误，在资源允许范围内提高 Node 堆上限重试，并记录实际命令 |

## 八、评审与交付记录

### 1. 样板评审记录 {#sample-review}

记录实际证据和问题位置，不用“整体良好”代替结论。按第三、四节检查方向与边界、职责深度、事实版本、示例和表达，再填写以下记录：

| 项目 | 必须记录的内容 |
|------|----------------|
| 样板身份 | 模块与版本、蓝图路径、文章 ID/标题/路径、主类型、目标深度及选择理由 |
| 方向与内容 | 当前方向基础、必要前置、必须覆盖与排除范围、唯一问题、粒度、必要子主题和目标深度的实际证据 |
| 事实与示例 | 关键来源、版本差异归属、运行环境、命令、实际观察、失败处理及未验证边界 |
| 组织与表达 | 阅读顺序、段落、标题层级、容器语义、长代码折叠与折叠外解释的检查结果 |
| 问题与修订 | 严重程度（阻断/重要/一般）、问题、影响、修订位置、处理结果和复验依据 |
| 后续校准 | 深度、粒度与层级、段落顺序、容器、代码折叠、场景、证据、术语、命名与版本表达的可复用结论 |
| 推进结论 | 样板通过或修改后复审、蓝图调整范围、第二样板必要性、是否建议批量生成、用户确认状态 |

阻断问题修复前不进入用户确认；样板质量通过且用户已明确确认后，才能进入批量生成。第二样板的理由与确认仍按[阶段流程](./workflow.md)执行。

### 2. 最终验收记录

最终回复或验收文档必须包含：

| 项目 | 必须报告的内容 |
|------|----------------|
| 文件范围 | 新增、修改、移动、删除哪些文件 |
| 内容职责 | 对应文章 ID、主讲知识项和目标深度是否达到 |
| 版本与来源 | 采用什么基线，核对了哪些关键依据 |
| 示例验证 | 实际命令、工作目录、环境、退出结果与关键观察；未执行则如实说明 |
| 内容检查 | 语义层级及保留或调整理由、目标深度的解释与证据、讲解顺序、骨架化候选、文字容器、长代码折叠和示例一致性的处理结果 |
| 工程检查 | 实际执行的格式、链接、导航、构建或页面检查及结果 |
| 未完成事项 | 具体原因、影响范围和继续所需条件，没有则写无 |

不能只报告“文档已生成”或“构建成功”。构建、内容和示例必须分别给出结论。

## 九、交付前检查

最终检查复用前述门禁，不再维护另一份内容、格式或工程规则副本：

- [ ] 蓝图语义检查、A01—A12 单篇门禁以及当前范围适用的章节与模块检查均有结论；样板任务已经记录评审及确认状态。
- [ ] 写作规范中的正文组织、Markdown 格式及示例验证检查完成，机器候选已逐项人工判断；未运行项没有冒充实测。
- [ ] 新建或全文重构模块按目录规范使用章节文件夹和连续编号；修改前后的链接、资源和导航已经核对。
- [ ] 涉及文章标题、路径、sidebar 或导航文案变更时，全局同步蓝图、引用、锚点和现有浏览器断言，并按[构建手册](../engineering/site-build-runbook.md)完成构建、合并与浏览器回归；旧地址和旧锚点直接作废。
- [ ] 涉及配置、导航或扩展语法时已执行必要构建；原有用户改动和本次修改范围已核对，没有无关重构。
- [ ] 最终记录区分内容、示例、格式和工程结果，列明未完成事项及实际原因；任何硬性门禁失败均不标记完成。
