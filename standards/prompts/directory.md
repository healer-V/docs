# 目录规划指令

以下指令配合[技术方向知识目录生成规范](../knowledge/directory-planning.md)使用，方括号字段在实际任务中替换。

## 一、完整目录规划指令

以下代码块是任务模板，方括号中的文字是需要替换的输入字段。未知字段保留“请从现有资料核对”，由执行者核对；正式蓝图中不得遗留模板占位。

::: details 查看目录规划指令

```text
请依据《技术方向知识目录生成规范》，为指定方向生成可评审的知识目录蓝图。

任务输入：
- 方向名称：[填写具体名称]
- 规划层级：[领域 / 技术模块 / 模块内主题]
- 任务类型：[新建 / 全文重构 / 仅目录规划 / 局部补足]
- 目标读者：[填写通用基础与当前方向起点]
- 最终能力：[填写希望能够执行和判断的事情]
- 主版本及维护线：[填写；未知时请从既有蓝图与官方资料核对]
- 目标模块目录：[填写；未知时先给出有依据的候选]
- 已有蓝图和正文：[填写文件位置，或写无]
- 本次排除范围：[填写不需要的主题，或由现有目标推导并说明]
- 输出位置：[用户指定位置；未指定时遵循当前项目约定]

执行要求：
1. 先读取适用 AGENTS.md、分层文档规范、真实文件、nav/sidebar、既有蓝图和 Git 状态。
2. 判断规划层级、主知识方向、读者起点、版本、外部前置与范围排除。
3. 核对主版本官方来源；先生成知识项，再建立并检查理解依赖。
4. 按依赖聚合章节，为每篇文章填写完整职责卡，再形成目录和覆盖矩阵；章节名称与文章标题准确精简，保留必要限定，不堆砌知识清单或按固定字数截断。
5. 每个必需知识项只能有一个完整主讲位置，所有最终能力必须有验证方式。
6. 章节文件夹使用两位连续编号；章内文章独立从 01 编号。复用已有路径并说明迁移影响。
7. 明确现有、规划、覆盖与验证状态，不以文件数或标题数证明完成度。
8. 输出完整蓝图、样板选择、文件导航影响、验证方案和 D01—D10 自检结果。
9. 本轮只交付目录蓝图，不创建空正文、不批量移动文件、不更新正式 sidebar。
10. 核心歧义无法从资料解决时提出精确问题，并继续完成不受影响的审计。

请直接完成规划和自检后交付，不只输出一棵目录树。
```

:::

## 二、对已有目录执行评审

以下指令适用于检查既有模块目录；它不自动授权全量内容迁移。

::: details 查看目录评审指令

```text
请依据《技术方向知识目录生成规范》评审指定模块的现有目录。

输入：目标模块目录 [填写路径]；已有蓝图 [填写路径或无]；主版本 [填写或请核对]。

先读取正文、实际文件、nav/sidebar 和已有改动，再检查知识范围、外部前置、
依赖顺序、唯一主讲、文章粒度、名称准确性与简洁度、版本和验证能力。

输出：
1. 已有内容与规划条目的区分；
2. 知识遗漏、重复、错位和粒度问题，逐项提供正文或配置依据；
3. 修订后的模块契约、知识项、依赖、目录、职责卡和覆盖矩阵；
4. 路径及引用影响、受影响站内链接与锚点引用的更新方案；
5. 样板选择、自检结果和待确认范围。

不要根据文件名直接判定知识已覆盖；不要在本轮执行改名、删文或导航迁移。
```

:::
