# 运维 Bash 与 Shell 模块蓝图

本蓝图细化已确认的[运维与 DevOps 领域设计](./directory.md)中 `02-bash-shell` 模块。它只规划新教程，不将 `content/operation/01-shell/` 的四篇旧正文改名或按标题映射到新目录；旧首页和原 URL 保留。**二十三篇均为规划文章，当前没有可发布的新正文或导航链接。**

## 一、教学契约与现状

| 字段 | 决定 |
|------|------|
| 任务类型 | 现有 Shell 模块的全文重构蓝图；本轮只交付规划 |
| 模块名称与目标 | Bash 与 Shell；`content/operation/02-bash-shell/` |
| 主知识方向 | 编程语言：Bash 是可编写和执行脚本的命令语言，必须讲清自身语法、参数、数据、控制流、函数和执行行为 |
| 辅助方向 | 工程工具：GNU 文本工具与 ShellCheck 只服务于脚本输入输出和质量验证，不扩写为工具大全 |
| 读者基线 | 会使用计算机文件和终端；无需已学过其他编程语言。Linux 终端、路径和基本文件操作在当前篇给最小上下文，完整主讲归 Linux 模块 |
| 主版本 | GNU Bash 5.3，示例环境 Ubuntu Server 26.04.1 LTS；默认使用 Bash，不把 `sh` 或 macOS 的行为混入主线 |
| 最终能力 | 独立编写带参数的脚本；解释引用、展开、退出状态与管道结果；处理可控文本；测试失败分支；在隔离目录完成日志分析、巡检和可恢复备份 |
| 排除 | Linux 主机配置、`systemd`/cron 调度、Nginx 日志格式定义、跨主机配置管理、发布策略与监控平台分别归对应模块 |

旧目录实际为 `index.md` 和 `01-basics.md`、`02-control-flow.md`、`03-text-processing.md`、`04-practical-scripts.md`。首页只有 `## shell`；四篇正文分别混合了脚本入口与语法、控制流与函数、三种文本工具、数组与备份/巡检/定时任务等多个独立问题。现有 sidebar 另列从 `05-script-structure.md` 到 `20-enterprise-template.md` 等尚无正文的链接；旧文章中还有直接面向 `/var/log`、`/etc`、部署目标或递归清理的示例。新教程重新设计可回退的测试数据，不以旧示例的命令和输出作为已核实事实。`nav.js`、`sidebar/operation.js` 有用户未提交改动，本阶段不编辑它们。

| 方向覆盖层次 | 本模块责任 | 边界 |
|--------------|------------|------|
| 环境与入口 | Bash、脚本文件、解释器、执行方式和首个输出 | 不教操作系统安装 |
| 词法、表达式与数据 | 引用、展开、变量、参数、数组、算术及状态值 | Bash 无 Java 式静态类型、类与对象，不补不存在的语法 |
| 控制与组合 | 条件、循环、函数、`source`、重定向与管道 | 外部命令只讲组合所需接口 |
| 运行机制 | 子 Shell、子进程、后台任务、信号、状态传播 | 不替代 Linux 进程管理全文 |
| 工程与质量 | 输入边界、失败处理、测试、ShellCheck、可恢复脚本 | 不把 `set -e` 当作通用错误处理保证 |

| 跨模块前置 | 要求深度与入口 | 当前模块的处理 |
|--------------|-----------------|----------------|
| Linux 终端和文件路径 | 会打开终端并辨认当前目录；站内新入口规划于 [Linux 蓝图](./01-linux.md)第一、二章，当前未发布 | 每篇示例用临时测试目录，并就地说明所需命令；不链接未发布正文 |
| Linux 进程与权限 | 认识进程、信号和文件权限；同一蓝图第三、四章规划 | 只解释脚本如何传递状态及清理自己创建的文件，不重复账号与服务管理 |
| 日志与服务场景 | 认识日志行和状态检查；实际日志格式由对应产品决定 | 使用本文生成的合成数据，不读取生产日志或假定 Nginx 固定字段位置 |
