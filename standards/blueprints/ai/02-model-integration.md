# 模型接入模块蓝图

“模型接入”负责把模型能力转换为应用可调用、可判断、可恢复的接口。模块以通用协议原理为主线，以 OpenAI Responses API 和 Python SDK 为可运行主实现；正文不能把 SDK 的便捷属性当成完整响应，也不能把模型提出工具调用等同于应用已经执行工具。

本蓝图只定义知识责任、目录、证据和实施边界。样板已通过验收并获得用户确认；第 1 章正文完成后已删除临时模块首页，模块与章节均不保留 `index.md`。

## 一、模块教学契约

| 字段 | 内容 |
|------|------|
| 模块名称 | 模型接入 |
| 目标目录 | `content/ai/02-model-integration/` |
| 主知识方向 | AI 工程中的模型接口与集成；围绕输入输出契约、响应生命周期、能力协议和失败恢复组织 |
| 辅助知识方向 | HTTP 与事件驱动集成、软件测试；只覆盖理解 SSE、Webhook、超时、重试和契约测试所需内容 |
| 读者基线 | 已完成“AI 应用基础”，能运行 Python 脚本，理解 JSON、函数、异常和环境变量 |
| 当前方向起点 | 从 Responses API 的输入项、内容类型和响应对象开始，不重复首次调用环境教程 |
| 主版本基线 | Python 3.12.14、OpenAI Python SDK 3.19.2、OpenAI Responses API；事实以 2026-09-28 官方文档为准 |
| 最终能力 | 能构造兼容的模型请求，判断同步、流式和后台响应状态，消费结构化结果，完成工具调用回传，接入图像、文档和音频，并以错误分类、重试、幂等和契约测试封装可靠客户端 |
| 范围排除 | Prompt 设计归 AI03，检索归 AI04，Agent 控制循环归 AI05，提供商路由与业务会话归 AI07，系统评测归 AI08，安全治理归 AI09，并发、缓存、成本和部署归 AI10 |

::: info 主实现与通用原理
正文先解释输入项、事件、状态和工具回传等通用接口概念，再使用 OpenAI Responses API 给出完整证据。其他提供商只在确有差异时作为边界说明，不并列维护多套实现。
:::

## 二、知识方向与边界

### 1. 方向覆盖模型

| 覆盖层次 | 状态 | 当前模块需要检查的内容 | 判定依据 |
|----------|------|------------------------|----------|
| 输入输出契约 | 适用 | 输入项、内容类型、请求选项、响应项、状态和用量 | Responses API 请求与响应模型 |
| 响应生命周期 | 适用 | 同步、流式、取消、超时、后台执行、Webhook | 流式、后台模式和 Webhook 官方指南 |
| 能力协议 | 适用 | JSON Schema、函数工具、图像、文件和音频 | 结构化输出、工具和多模态官方指南 |
| 失败恢复 | 适用 | 错误分类、重试条件、退避、幂等和请求关联 | 错误码、限流和 Webhook 投递规则 |
| 工程封装 | 适用 | 客户端边界、领域对象和契约测试 | 可替换外部 API 的工程验证需求 |
| Prompt 与知识组装 | 不适用 | 指令质量、上下文选择、RAG | 分别归 AI03 与 AI04 |
| 工作流与生产治理 | 部分适用 | 只说明接口层边界，不展开循环、网关和容量治理 | 分别归 AI05、AI07 与 AI10 |

### 3. 排除内容

| 排除主题 | 排除原因 | 正确归属 | 防止混入的边界 |

| RAG 文件解析与检索 | 文件作为模型输入不等于建立检索系统 | AI04 RAG 应用 | 只讲文件输入能力和限制 |

| 提示注入与权限隔离 | 属于安全治理 | AI09 安全与治理 | 工具示例只保留输入校验和最小权限提醒 |
| 并发、缓存与成本优化 | 属于运行容量和经济性治理 | AI10 性能与部署 | 限流只作为错误与重试条件说明 |
