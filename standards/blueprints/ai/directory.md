# AI 应用开发知识目录设计

AI 知识域面向具备一门编程语言和 HTTP/JSON 基础、但尚未系统开发过 AI 应用的读者。学习主线从模型调用开始，经过上下文、RAG、Agent 与框架编排，最后进入应用架构、评测、安全和生产运行，使读者能够独立构建、验证并维护一个 AI 应用。

本文是**已确认的领域级目录设计**，不是十个模块的完整教学蓝图，也不表示全部文章已经写成。每个模块进入正文前仍须分别确定主版本、官方来源、知识项、依赖、逐篇职责卡、覆盖矩阵和样板文章。2026-09-28 确认生命周期主线；2026-11-15 复核十章目录，并确认 DeepSeek Harness 作为进阶预留而不进入核心路径。

::: info 计数口径
本文以当前 `.vitepress/themeConfig/catalogs/ai.js` 与目录测试的实际数据为准：**10 个模块、61 个章节、162 篇核心文章**。早期设计文档中的“60 章节、158 篇”是第 3 章扩充前的历史数字，不再作为验收依据。
:::

## 一、目标与边界

| 项目 | 设计决定 |
|------|----------|
| 领域定位 | AI 应用开发；以应用从原型到生产的生命周期组织，不按模型厂商或单一框架组织 |
| 读者基线 | 具备一门编程语言、HTTP、JSON 基础；不要求机器学习或深度学习背景 |
| 模块数量 | 10 个，按学习依赖分为基础与接入、知识与智能体、工程与治理三组 |
| 章节结构 | 每模块 3—7 个两位编号的英文章节目录，章内文章从 `01` 连续编号 |
| 核心规模 | 61 个章节、162 篇文章；当前已写 55 篇，缺口 107 篇 |
| 领域导读 | 规划 `content/ai/index.md`，说明学习路径、前置与模块关系；不计入章节 |
| 正文范围 | 本文只确定目录与职责，不创建或改写正文，不调整正式导航 |
| 旧路径 | 已确认的 AI 路径保持不变；未完成文章不生成链接，不创建空占位文件 |
| 进阶预留 | DeepSeek Harness 作为第 6 章 6.8 的 3 篇扩展，暂不进入核心目录与 catalog |

领域范围以调用托管模型 API 的应用为中心。机器学习数学、传统机器学习、深度学习训练、预训练与微调算法、分布式训练、GPU 集群、量化与自托管推理引擎不在本领域展开；这些内容如需系统讲解，应另设“模型推理基础设施”方向。

## 四、学习依赖与路径

| 阶段 | 必修模块 | 可并行内容 | 阶段结果 |

| 2. 构建核心能力 | 04、05 | RAG 与 Agent 可在共同基础后并行 | 能实现知识问答或工具型 Agent |
