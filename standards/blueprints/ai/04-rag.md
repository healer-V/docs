# RAG 应用模块蓝图

检索增强生成（Retrieval-Augmented Generation，RAG）把外部资料检索和模型生成组合为应用链路。该模块的责任是让读者判断资料是否适合进入知识库，形成可追溯证据，区分检索失败与生成失败，并维护知识版本及访问权限。

本文件记录 AI04 当前七章十八篇目录草案及正文进度。用户先确认“证据组织与生成”样板并授权续写，随后于 2026-09-29 明确要求不要把 AI 生成的蓝图当作正确性依据。正文以知识依赖、可靠来源和可复现示例核验，规划允许据此调整。当前已完成前四章十篇与样板，累计十一篇正文，其余七篇尚未生成；规划数量与覆盖计数不证明文档正确。

## 一、模块教学契约

| 字段 | 内容 |
|------|------|
| 模块 | RAG 应用，`AI04` |
| 目标目录 | `content/ai/04-rag/` |
| 主方向 | AI 工程中的知识检索应用；围绕资料、检索、证据、回答及维护生命周期组织 |
| 辅助方向 | 文档处理、信息检索、数据存储与测试；只解释形成 RAG 闭环所需能力 |
| 读者基线 | 会运行 Python，理解 JSON、模型请求及基本上下文；尚未开发过 RAG |
| 当前方向起点 | 从外部知识为什么需要检索、文档与片段的区别、检索结果如何成为证据讲起 |
| 主版本 | Python 3.12.14；生成使用 OpenAI Python SDK 3.19.2 与 Responses API；本地嵌入使用 FastEmbed 0.7.4、NumPy 2.2.6、ONNX Runtime 1.30.0、tokenizers 0.23.2、huggingface-hub 0.36.0 |
| 本地检索 | Python 标准库 `sqlite3` 与 FTS5；当前验证环境 SQLite 3.53.1，使用前检查 FTS5 可用性 |
| 模型实现 | 生成延续现有 Responses 接入；嵌入采用真实本地 `BAAI/bge-small-zh-v1.5` ONNX 制品，512 维，不要求生成端点同时支持嵌入 |
| 最终能力 | 能设计知识边界、处理及更新资料、比较检索策略、生成带可核对来源的回答、定位质量损失，并撤回不再可见的内容 |
| 范围排除 | 不教授模型训练、完整向量数据库运维、通用爬虫平台、Agent 规划或框架 API；这些内容不作为 RAG 入门的隐含要求 |

SQLite 与 NumPy 用于小规模、可检查的演示。精确扫描的性能不代表大规模向量索引；嵌入向量、相似度和近似索引仍需分别解释，不能因样板使用关键词检索而遗漏向量检索。
