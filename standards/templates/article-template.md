# 技术文章正文模板

本模板只规定正文的输出形状，不新增规则。生成新文章时，先按[知识文档生成范式](../article/knowledge-document-paradigm.md)完成职责、证据和文章形状判断，再用本模板输出正文。写作前按任务读取[文章生成规范](../article/article-generation.md)、[正文组织与表达规范](../writing/content-organization.md)、[Markdown 与 VitePress 格式规范](../writing/markdown-format.md)和[示例与验证规范](../writing/code-examples.md)；规则冲突时以规范和当前模块蓝图为准。

尖括号字段必须替换为当前主题的内容，示例中的占位文字必须删除。模板不要求每篇使用全部章节，也不设标题数量、字数、表格数量或代码块数量配额。

## 一、适用类型

本模板面向以知识讲解为主的三类文章。接入教程、测试与排障、设计与实践按[七类主文章契约](../article/article-generation.md)组织主体，但可以复用本章的知识单元和参数状态表。

| 主类型 | 适用文章 | 主体证据 | 收尾 |
|--------|----------|----------|------|
| 概念与结构 | 文档结构、元素职责、内容模型 | 场景、关系或状态、一个可打开的示例 | 失败表或验证记录 |
| 语法与 API | 元素、属性、表单控件 | 参数表、最小片段、可观察结果 | 错误用法与版本边界 |
| 速查与参考 | 属性速查、版本对比 | 状态表、最小用法、完整讲解链接 | 限制与来源 |

## 二、整篇骨架

:::: details 查看整篇文章骨架

````markdown
---
title: "<与正文一级标题完全一致>"
tags:
  - "<稳定技术词，最多 4 个>"
excerpt: "<50～120 字：本篇解决什么问题、给出什么判断>"
date: <YYYY-MM-DD>
---

# <文章标题>

<2～4 段：当前对象是什么、解决什么问题、核心模型和版本基线。>
<不写学习目标、课程安排、“上一篇”“下一篇”或文章目录复述。>

## 一、<第一个主问题>

### 1. <需要独立解释的子问题>

<知识单元，见第三节。>

## 二、<第二个主问题>

### 1. <子问题>

<知识单元，见第三节。>

## 三、<常见错误与判断>

| 现象 | 定位证据 | 修复与复测 |
|------|----------|------------|
| <读者看到的错误结果> | <用哪个面板、命令或读数确认> | <改哪里，如何复测> |

<验证记录：环境、版本、日期、实际观察，以及本次没有证明的内容。>
````

::::

二级标题按主问题划分，数量由内容决定，不套“概述、原理、用法、实践、总结”的固定序列。第三个二级标题可以是错误表、决策表或边界说明，不必三篇同构。

一个二级标题下出现多个需要分别定位的子问题时，用三级标题拆开，不要把所有内容平铺在同一层。需要突出可复用判断、前提或失败边界时，按[文字容器规范](../writing/content-organization.md)选择 `info`、`tip`、`warning` 或 `details`；容器之间保留正文，不连续堆叠。

## 三、知识单元

每个三级标题下使用同一个信息顺序：结论、状态表、最小示例、预期观察、失败边界。顺序固定，标题不固定；内容较少时可以合并段落，但不能缺少“为什么”和“写错会怎样”。

:::: details 查看知识单元模板

````markdown
### 1. <元素或属性名称>

<1～3 句：它是什么、解决什么问题、由谁在什么阶段使用。>
<必须给出机制或后果，不能只把标题换一种说法。>

| <属性或取值> | <行为> | <状态> |
|--------------|--------|--------|
| `<取值>` | <改变什么、影响哪个阶段> | 现行 |
| `<取值>` | <改变什么> | <HTML5 废弃，替代写法> |

<示例用途与执行条件：读者在空目录创建哪个文件，用什么入口打开。>

```html
<table border="1">
  <tr>
    <th colspan="2">联系方式</th>
  </tr>
  <tr>
    <td>邮箱</td>
    <td>name@example.com</td>
  </tr>
</table>
```

<预期观察：打开后应看到什么；在元素面板或控制台中应读到什么。>

<失败边界：写错时浏览器如何表现、用什么证据判断、正确处理是什么。>
````

::::

| 组成部分 | 必须回答的问题 | 不通过的信号 |
|----------|----------------|--------------|
| 结论 | 它是什么、为什么这样设计、写错会导致什么 | 只复述标题，或只有“非常重要”“提高可维护性” |
| 状态表 | 有哪些取值、各自改变什么、当前是否可用 | 只列名称和描述，不标废弃与替代写法 |
| 最小示例 | 在哪个文件、从哪里打开、省略了什么 | 示例无法独立运行，或引用仓库示例目录 |
| 预期观察 | 页面、面板、命令或校验器应给出什么 | 只写“运行成功”，没有可核对的观察项 |
| 层次 | 多个子问题是否用三级标题分开，重点是否用容器突出 | 所有内容平铺在同一层，或容器连续堆叠代替正文 |
| 失败边界 | 错误的可观察表现、判断依据和正确做法 | 只贴报错，或把限制集中到文章末尾 |

## 四、参数表与状态

表格承担同维度查询：取值、行为、默认值、适用版本。原因、时序和取舍放在表格前后的正文里，不塞进单元格。

属性表还要说明“怎么用”：属性属于哪个元素、在什么场景使用。只有名称和描述的表不足以支撑判断。

涉及版本差异或废弃状态时，表格必须有状态列，或在该表下方统一说明适用版本。状态至少区分以下四类，并给出替代写法：

| 状态 | 含义 | 表格中必须补充 |
|------|------|----------------|
| 现行 | 当前标准中可用 | 无 |
| 废弃 | 仍可能被浏览器识别，但不应用于新代码 | 替代的 CSS 属性、元素或 API |
| 已移除 | 当前标准不再定义，行为不可依赖 | 迁移方式或删除建议 |
| 非标准 | 仅特定浏览器或历史实现支持 | 支持范围与不采用的理由 |

对比下面两种写法，信息量差别不在篇幅，而在读者能否判断“现在还能不能用”：

| 旧写法 | 优化后 |
|--------|--------|
| `align`：表格的水平对齐方式 | `align`：控制表格水平对齐；HTML5 废弃，改用 CSS `margin-inline: auto` 或 `text-align` |
| `cellpadding`：单元格内容与边框之间的内边距 | `cellpadding`：控制单元格内边距；HTML5 废弃，改用 `td { padding: … }` |

## 五、示例与观察

每篇至少有一条与主题直接相关的最小可复现链路：读者新建空目录、创建文中给出的文件、按文中入口打开或执行，并观察到文中描述的结果。其余知识点使用局部片段，片段要说明所属文件、已有上下文和省略内容。

| 对象 | 写法要求 |
|------|----------|
| 完整示例 | 给出文件名、保存编码、打开或执行方式、预期页面或读数 |
| 局部片段 | 说明它属于哪个文件、依赖哪些前置内容、省略了什么 |
| 注释 | 说明关键属性的作用；只写在元素前、代码块上方或独立行，不能写在起始标签的属性之间 |
| 长代码 | 超过 10 行用 `::: details 具体用途` 折叠；用途、关键逻辑和结果判断留在折叠外 |
| 验证状态 | 实际运行、仅编译、局部核对、示意和未验证分别标注，不把预期结果写成实测结果 |

预期观察尽量选择可核对的证据，而不是主观描述。例如读取浏览器对外报告的值：

| 文件 | 表达式 | 返回值 | 说明 |
|------|--------|--------|------|
| `hello.html` | `document.compatMode` | `CSS1Compat` | 使用简短 DOCTYPE，处于标准模式 |
| `no-doctype.html` | `document.compatMode` | `BackCompat` | 缺失 DOCTYPE，处于怪异模式 |

## 六、开篇、收尾与摘要

一级标题后直接说明当前对象、问题和核心判断。开篇用 2～4 个短段落建立模型，不写课程路线、学习目标或知识清单。

结尾使用失败表、反例、决策表或验证记录，说明当前证据证明了什么、没有证明什么。不写“通过本文的学习”“在实际开发中我们应该”这类总结。

`excerpt` 手写为 50～120 字的一句话，说明本篇解决的问题和核心内容，不用正文首句拼接。标题中的中英文之间保留空格，例如“HTML 概述”“HTML5 表单增强”。

## 七、拆分与覆盖

一篇只回答一个主要问题，标题与这个问题一致。单个文件同时承担容器、控件、验证、提交和样式时，按问题拆分，不按属性逐条拆分。

模块级维护覆盖状态，只有“讲清”计为覆盖：

| 状态 | 判定 |
|------|------|
| 讲清 | 有解释、示例或证据、边界，读者能据此判断 |
| 提及 | 只在示例、列表或一句话中出现，没有展开 |
| 未覆盖 | 正文没有出现，或只在外部链接中指向 |

同一主题只保留一个主讲位置。其他文章需要时给出最小上下文和链接，不复制整套示例。拆分后仍保持“一篇一问”，不为凑篇幅扩写常识。

## 八、交付前自检

- [ ] 文章只回答一个问题，标题与 `title` 和正文一级标题一致；
- [ ] 开篇直接进入主题，没有学习目标、课程安排或目录复述；
- [ ] 每个二级标题下按子问题使用三级标题，内容没有平铺在同一层；
- [ ] 需要强调的判断使用 `info`、`tip` 或 `warning` 容器，容器之间保留正文，没有连续堆叠；
- [ ] 每个知识单元的结论包含机制或后果，不是同义改写；
- [ ] 属性表说明了含义、取值与使用方式；
- [ ] 涉及版本差异或废弃状态的表有状态列或统一的版本说明；
- [ ] 至少有一条从空目录出发的最小可复现链路，入口与预期观察齐全；
- [ ] 局部片段说明了所属文件、上下文和省略内容；
- [ ] 示例中的关键属性有注释说明，注释没有写进起始标签内部；
- [ ] 超过 10 行的代码已折叠，折叠外保留用途、关键逻辑和结果判断；
- [ ] 收尾是失败表、反例或验证记录，不是总结套话；
- [ ] `excerpt` 为手写的 50～120 字，不是正文首句拼接；
- [ ] 重复主题只链接主讲文章，没有复制整套讲解；
- [ ] 未实际验证的结论、示例和环境已明确标注。

## 九、与旧模板的对应关系

| 旧写法 | 优化后 |
|--------|--------|
| `::: tip XX定义` 下的“**关键词**：一句断言”清单 | 1～3 句带机制或后果的结论，必要内容改入表格 |
| 只列名称和描述的属性表 | 增加行为列与状态列，废弃项给出替代写法 |
| 完整示例后直接进入下一个知识点 | 补充预期观察和失败边界 |
| 每篇都以“总结”收尾 | 改为失败表、反例或验证记录 |
| `excerpt` 由正文首句拼接 | 手写 50～120 字摘要 |
| 一篇内堆叠多套完整示例 | 一条最小闭环加局部片段 |
| 按属性逐条拆成极短文章 | 按问题拆分，一篇只回答一个问题 |
