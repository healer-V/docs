# 文档生成规范索引

本目录负责约束 AI 如何规划和生成系统性完整教程。根目录 `AGENTS.md` 仍然负责 Markdown、代码示例、目录编号、链接和工程检查等仓库通用规则；本目录补充知识方向识别、模块蓝图、文章职责、分阶段生成和语义质量检查。

项目的核心定位是帮助读者从 0 系统学习一门语言或技术。各项规范共同保证当前技术的基础知识得到解释、内容按理解依赖递进、使用示例可以复现，并以读者能够独立完成声明范围内的任务作为学习结果。读者起点与跨技术前置边界见[知识体系规范](./knowledge-system.md)。

## 一、规范优先级

文档任务按以下优先级执行：

1. 用户在当前任务中的明确要求；
2. 距离目标文件最近的目录级 `AGENTS.md`；
3. 根目录 `AGENTS.md`；
4. 本目录中与当前任务阶段对应的专业规范；
5. 任务对应的目录或正文执行规范；
6. 目标模块已确认的模块蓝图；
7. 目标文件已有且不与上述要求冲突的局部风格。

模块蓝图只能细化当前模块的知识范围、版本和文章职责，不能放宽根目录 `AGENTS.md` 的安全、事实、格式和工程要求。

## 二、任务路由

开始文档工作前，必须先识别任务类型，读取对应执行规范，再完整读取下方专业规范表中列出的文件。执行规范提供完整操作约束和可复用指令，专业规范负责对应阶段的详细事实与质量要求。

| 执行入口 | 适用任务 | 主要交付 |
|----------|----------|----------|
| [技术方向知识目录生成规范](./knowledge-directory-generation.md) | 方向与模块规划、章节及逐篇大纲、既有目录评审 | 读者和版本契约、知识项、依赖、目录、职责卡、覆盖矩阵、样板与迁移计划 |
| [技术文章生成与验收规范](./article-generation.md) | 单篇新建、全文重写、局部修订、样板生成、逐章续写及正文质量治理 | 正文、必要资源、示例验证、内容与工程验收、精确变更范围 |

这两份仓库执行规范是后续维护入口，分析目录中的整理稿保留为日期快照。它们统一遵循“从 0 系统学习一门语言或技术”的核心定位，兼顾长期复用和对外分享，不替代模块蓝图与样板确认，也不将模板中的字段当作正式交付内容。

专业规范按以下任务类型加载；只涉及当前文章的局部修改时，执行规范和文章契约均按受影响内容应用，不扩大治理范围。

| 任务类型 | 必读规范 | 开始正文前的门禁 |
|----------|----------|------------------|
| 新建技术模块 | [知识体系](./knowledge-system.md)、[模块蓝图](./module-blueprint.md)、[生成流程](./generation-workflow.md)、[文章契约](./article-contracts.md)、[质量门禁](./quality-gates.md) | 模块蓝图和样板文章均已确认 |
| 全文重构技术模块 | 与新建技术模块相同，并审计现有目录、sidebar 和链接 | 迁移范围、模块蓝图和样板文章均已确认 |
| 规划章节目录或逐篇大纲 | [知识体系](./knowledge-system.md)、[模块蓝图](./module-blueprint.md)、[生成流程](./generation-workflow.md) | 知识项清单和依赖关系已经完成 |
| 新建单篇文章 | 当前模块蓝图、[文章契约](./article-contracts.md)、[质量门禁](./quality-gates.md) | 文章职责卡已经确认或能从既有蓝图唯一确定 |
| 全文重写单篇文章 | 与新建单篇文章相同，并读取相邻文章 | 不改变当前模块知识归属 |
| 局部修改历史文章 | [文章契约](./article-contracts.md)中与修改类型相关的规则、[质量门禁](./quality-gates.md) | 修改范围明确，不借机治理无关内容 |
| 批量质量治理 | 当前模块蓝图、[质量门禁](./quality-gates.md)、根目录 `AGENTS.md` 的历史治理规则 | 治理范围和迁移规则已经确认 |

当前模块不存在蓝图时，新建模块、全文重构模块和目录规划任务必须先使用[模块蓝图模板](./templates/module-blueprint-template.md)创建蓝图。单篇局部修改不强制补建整个模块蓝图，但不得改变相邻文章的知识边界。

## 三、标准执行顺序

系统教程使用以下顺序：

```text
任务建档
→ 识别知识方向与版本基线
→ 建立知识项清单和依赖关系
→ 聚合章节并生成文章职责卡
→ 用户确认模块蓝图
→ 生成并确认样板文章
→ 按章节批量生成和检查
→ 执行整体验收
```

目录顺序通过知识依赖、章节编号、文章编号和 sidebar 表达。正文不得使用“上一篇已经学习”“下一篇将介绍”“本章学习路线”等话术人为制造连续性。

## 四、阶段输出

| 阶段 | 使用模板 | 必须输出 |
|------|----------|----------|
| 模块蓝图 | [模块蓝图模板](./templates/module-blueprint-template.md) | 教学契约、方向分类、版本、来源、知识项、依赖、章节、职责卡、覆盖矩阵和验证方案 |
| 单篇规划 | [文章职责卡模板](./templates/article-responsibility-card-template.md) | 唯一问题、类型、范围、深度、证据、验证和重复归属 |
| 样板校准 | [样板评审模板](./templates/sample-review-template.md) | 方向、深度、粒度、事实、示例、表达和可复制性结论 |
| 最终验收 | [质量门禁](./quality-gates.md) | 内容覆盖、示例验证、工程验证、未验证项和变更范围 |

## 五、停止条件

出现以下任一情况时，必须停止当前阶段并处理问题，不能带着未解决问题继续批量生成：

- 知识方向无法确定，或者主方向与辅助方向职责冲突；
- 主版本基线不明确，官方资料对应多个不兼容版本；
- 知识项存在未归属、重复归属或循环依赖；
- 模块蓝图或样板文章尚未获得用户确认；
- 核心结论缺少可靠来源；
- 核心示例无法验证；
- 正文范围实质偏离已确认蓝图；
- 工作区已有改动与计划修改范围无法兼容。

停止不等于交付完成。问题解决后必须从发生失败的门禁重新检查。

## 六、规范边界

- 本规范不要求所有知识方向使用相同章节名称；
- 本规范不使用文章数量、字数或标题数量代替内容完整性；
- 本规范不允许从固定目录模板直接生成正文；
- 本规范不自动迁移历史文档，迁移范围由当前任务决定；
- 本规范不授权自动提交、推送、发布或部署。
